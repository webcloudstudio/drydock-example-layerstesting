# FEATURE: Load Accounts

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | The shared `ledger load` command with its validators, and the accounts loader that stores a valid file in full or not at all. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-LedgerCli.md |
| Provides | ledger load, ledger load accounts |
| Consumes | ledger, accounts |

## Questions

- None.

## Purpose

`ledger load <table> <csv>` loads `accounts`, `categories`, or `transactions` from a CSV file whose
header equals the table's columns in order. This story creates the shared `load` command (argument
checks, table dispatch, file reading, header check, the registry that later table loaders join) and
the shared code and name validators, and registers the `accounts` loader.

## Behavior

- Exactly two arguments (table, csv path) are required; any other count is a usage error, exit 2.
- An unknown table is a usage error, exit 2.
- A file that cannot be read is an operational failure, exit 1.
- The first line must equal the table's columns in order (`account,name` for accounts). A mismatch is
  rejected, exit 3 (Plan decision Q-003).
- Codes are 1 to 12 characters from `A-Z` and `0-9`. Names are 1 to 40 characters and contain no comma
  or newline.
- Every row is validated, and duplicate keys are detected both within the file and against stored
  accounts, before the first write. Any failure exits 3, writes nothing to standard output, writes one
  diagnostic line to standard error, and stores none of the rows.
- On success all rows are stored in one persistence-library transaction. Standard output is
  `table,loaded` followed by `accounts,<rows>`. A file with a valid header and no data rows stores
  nothing, writes `accounts,0`, and exits 0.
- The shared validators (`validate_code`, `validate_text`) are importable by later stories.

## Database Interface

- `FEATURE-ACCOUNT-001` — write: store an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-ACCOUNT-002` — read: detect an existing account by code - supplies: `account` - returns: `account`, `name`

## Programmatic Acceptance

=== AC load-accounts-success ===
Intent: A valid accounts file exits 0, reports the loaded count in the specified two-row CSV, and every row is readable afterward.

import csv
import io
import os
import tempfile
from cli.testing import cli_runner
from persistence.testing import db_session

rows = [["ZQL01", "Load One"], ["ZQL02", "Load Two"], ["ZQL03", "Load Three"]]
with tempfile.TemporaryDirectory() as tmp:
    path = os.path.join(tmp, "accounts.csv")
    with open(path, "w", newline="") as f:
        w = csv.writer(f, lineterminator="\n")
        w.writerow(["account", "name"])
        w.writerows(rows)
    with db_session() as db:
        before = len(db.accounts.list())
        code, out, err = cli_runner("load", "accounts", path)
        print(out, err)
        assert code == 0
        parsed = list(csv.reader(io.StringIO(out)))
        assert parsed == [["table", "loaded"], ["accounts", str(len(rows))]]
        assert len(db.accounts.list()) == before + len(rows)
        for acct, name in rows:
            stored = db.accounts.get(account=acct)
            assert stored is not None
            assert stored.name == name

# FEATURE: Load Transactions

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | The transactions loader with amount, date, memo, reference, and non-negative balance validation, plus the shared validators later stories reuse. |
| Depends On | FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, FEATURE-LedgerCli.md, DATABASE.md |
| Provides | ledger load transactions |
| Consumes | ledger load, accounts, categories, transactions |

## Questions

- None.

## Purpose

Register `transactions` with the shared load dispatcher. Each stored transaction keeps the `txn_id`
from its file. This story also provides the shared validators `parse_amount`, `validate_date`,
`validate_memo`, and a balance check that `txn post`, `txn amend`, `txn delete`, and `transfer`
import.

## Behavior

- The header must be `txn_id,date,account,category,amount,memo`; a mismatch exits 3.
- `txn_id` is an integer. A duplicate id inside the file, or one already stored, is rejected.
- Amounts match `-?DIGITS[.D[D]]`: at most two decimal places and never zero. They are converted to
  integer cents by string and integer arithmetic only; floating point is never used.
- Dates are real Gregorian calendar dates written `YYYY-MM-DD`; February 29 is valid only in a leap
  year and `2026-02-30` is rejected.
- Memos are 0 to 60 characters with no comma or newline.
- Each row's account and category must exist in the store.
- The balance rule (Plan decision Q-002): for every account the batch touches, the stored balance plus
  the sum of the batch's amounts for that account must not be below zero. The final balance is
  checked, so file order within the batch does not matter.
- Everything is checked before the first write. Any failure exits 3, writes nothing to standard
  output, and stores none of the rows. Success stores all rows in one transaction and writes
  `table,loaded` then `transactions,<rows>`.
- Loading the staged accounts, categories, and transactions seed files in that order into an empty
  ledger accepts 4, 7, and 120 rows.

## Database Interface

- `FEATURE-TXN-001` — write: store a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-002` — read: detect an existing transaction id - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-005` — read: sum stored amounts per account - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`, `name`
- `FEATURE-CATEGORY-002` — read: confirm the category exists - supplies: `category` - returns: `category`, `description`

# FEATURE: Account Get

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | The `ledger account get` command that shows one account with its transaction count and computed balance. |
| Depends On | FEATURE-AccountAdd.md, FEATURE-LedgerCli.md, DATABASE.md |
| Provides | ledger account get |
| Consumes | ledger, accounts, transactions |

## Questions

- None.

## Purpose

Register `get <code>` in the `account` group. It also supplies the shared account-row builder used by
`add`, `rename`, and the balances report: the transaction count and the balance are computed from the
account's stored transactions in integer cents.

## Behavior

- Exactly one argument after `get`; any other count is a usage error, exit 2.
- An absent account exits 4 with empty standard output.
- Success writes `account,name,transactions,balance` then the account row. `transactions` is the
  number of the account's transactions; `balance` is the sum of their amounts written with exactly two
  decimals and a leading `-` when negative.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: fetch the account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-005` — read: list the account's transactions to count and sum - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
