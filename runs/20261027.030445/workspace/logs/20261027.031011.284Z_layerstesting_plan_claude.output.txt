# ARCHITECTURE: LayersTesting

| Field       | Value |
|-------------|-------|
| Version     | 20261027 V1 |
| Description | Modules, boundaries, and technical decisions for the LayersTesting command-line cash ledger. |
| Provides    | python-foundation |

## Questions

- None.

## Purpose

LayersTesting is a command-line cash ledger. The executable `ledger` at the application root keeps accounts, categories, and cash transactions in SQLite. Every command validates all inputs and rules before its first write, then writes all of its changes or none. Reports are computed from stored rows at the time of the command.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Python 3.11+ | Implementation language for every module. |
| SQLite | The database, reached only through the shipped `persistence` package. |
| CLI | The `ledger` executable and the `cli` package. |
| pytest | Test runner behind `bin/test.sh` and the `tests/` suite. |
| POSIX sh | `bin/test.sh`, the `ledger` launcher, and the supplied grader. |

## Project Layout

| Path | Role |
|---|---|
| `ledger` | Executable launcher at the application root; uses the `.venv` interpreter when present, else `python3`; calls `cli.main` and exits with its return value. |
| `pyproject.toml`, `uv.lock` | Dependency manifest and committed lock. The environment is `.venv` created by `uv venv`. |
| `conftest.py` | Exposes the `db_session` and `cli_runner` fixtures. |
| `bin/` | Launchers, including `bin/test.sh`. |
| `persistence/` | Generated by Drydock from `DATABASE.md`; never written by hand. |
| `ledgerapp/` | Shared application modules: `config.py`, `errors.py`, `money.py`, and later `validators.py`. |
| `cli/` | Entry point `main`, `registry.py`, `output.py`, `testing.py`, and `commands/`. |
| `cli/commands/` | One module per command group. Every module in the package is imported automatically, so a story adds a command by adding a module. |
| `tests/` | The application's own pytest suite. |

## Module Ownership

| Boundary | Owning module | May access |
|---|---|---|
| Persistence | `persistence` (generated) | The SQLite driver. Nothing else imports a driver. |
| Configuration | `ledgerapp/config.py` | Environment variables `DATABASE_URL`, `DATABASE_PATH`; opens the store through `persistence.open_database`. |
| Money | `ledgerapp/money.py` | Parses and formats integer cents. No floating point at any layer. |
| Errors and exit codes | `ledgerapp/errors.py` | Defines the error classes and their exit codes. |
| Command dispatch and output | `cli/` | Calls handlers; owns stdout and stderr writing. |
| Command handlers | `cli/commands/*` | `db.<table>.<operation>(...)` only. No SQL, table names, or driver imports. |

## Technical Decisions

- Handlers are plain functions `handler(args, db)` that validate every input and rule before their first write and return a list of CSV rows (each a list of strings) or `None`.
- Multi-row writes (load, transfer, init) validate completely first, then write inside one transaction of the shipped persistence library, so a failure leaves no partial rows.
- Amounts are integer cents everywhere; output formatting is done with integer arithmetic.
- Application code never reads `sources/run.sh` or any seed file; seed files reach the database only through `ledger load`.
- No DDL runs at runtime. The schema is applied at the DATABASE step; `init` empties tables through the `delete_all` operations.
- Diagnostics go to standard error and are never compared.

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Operational failure: the database cannot be opened or a named file cannot be read |
| 2 | Usage error |
| 3 | Rejected |
| 4 | Not found |

# FEATURE: Database Selection

| Field       | Value |
|-------------|-------|
| Version     | 20261027 V1 |
| Description | Resolve the database location from configuration and open the store through the shipped persistence library. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | config.database_path, config.open_store |

## Questions

- None.

## Purpose

Every command reads its database location from one place. `ledgerapp/config.py` resolves it and opens the store.

## Behavior

- `database_path() -> str` reads the environment at each call. It returns `DATABASE_URL` when set and non-empty, with one leading `sqlite://` prefix removed if present. Otherwise it returns `DATABASE_PATH` when set and non-empty. Otherwise it returns `data/app.db`.
- `open_store()` opens the resolved path through `persistence.open_database` and returns the `Database`. For the default path only, it first creates the parent directory if absent. For any other path no directory is created.
- When the database cannot be opened, `open_store()` raises `ledgerapp.errors.StoreUnavailable` (exit code 1). The CLI maps it to exit 1 with nothing on standard output and no record changed.
- This module imports no database driver and applies no DDL.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Ledger CLI Foundation

| Field       | Value |
|-------------|-------|
| Version     | 20261027 V1 |
| Description | The ledger executable, the cli package entry point, command dispatch, CSV output, money handling, and exit-code mapping. |
| Depends On  | ARCHITECTURE.md, FEATURE-DatabaseSelection.md |
| Provides    | ledger, cli.main |
| Consumes    | config.open_store |

## Questions

- None.

## Purpose

Provide the shared command machinery every later command story registers into.

## Interface

- `ledger` at the application root: a POSIX sh launcher that runs `cli.main` with the `.venv` interpreter when present, else `python3`, and exits with the returned code.
- `cli.main(argv: list[str] | None = None) -> int`. `None` means `sys.argv[1:]`.
- `cli.testing.cli_runner(*args) -> (exit_code, stdout, stderr)` per the CLI Foundation Contract. `main` resolves `sys.stdout` and `sys.stderr` at call time so redirection works.
- `cli.registry.register(path: tuple[str, ...], handler, needs_store: bool = True)`; a handler is `handler(args: list[str], db) -> list[list[str]] | None`. Modules in `cli/commands/` are imported automatically, so adding a module registers its commands.
- `cli.output`: renders rows as CSV: comma-separated, no quoting, `\n` line endings.
- `ledgerapp.errors`: `LedgerError` with an `exit_code`; `StoreUnavailable` (1), `FileUnreadable` (1), `UsageError` (2), `Rejected` (3), `NotFound` (4).
- `ledgerapp.money`: `parse_amount(text) -> int` converts `-?DIGITS[.D[D]]` with at most two decimals, never zero, to integer cents using integer arithmetic and raises `Rejected` otherwise; `format_cents(cents: int) -> str` writes exactly two decimals, a leading `-` when negative, and no thousands separator.

## Dispatch

1. Resolve the command by the longest registered prefix of the arguments. No arguments, an unknown command, or a known group with a missing or unknown subcommand raises `UsageError` before the store is opened.
2. When `needs_store`, open the store with `config.open_store()`; failure exits 1.
3. Call the handler with the remaining arguments. Output is written only after the handler returns, so a failing command writes nothing to standard output.
4. A `LedgerError` writes one diagnostic line naming the problem to standard error and returns its exit code. Any other exception writes one line to standard error and returns 1.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Ledger Init

| Field       | Value |
|-------------|-------|
| Version     | 20261027 V1 |
| Description | The `ledger init` command resets the ledger to empty. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-LedgerCli.md |
| Provides    | ledger init |
| Consumes    | ledger |

## Questions

- None.

## Purpose

`ledger init` prepares an empty ledger for loading and use and removes existing ledger records when rerun.

## Behavior

- Takes no arguments; any argument is a usage error (exit 2).
- Removes every transaction first, then every category and every account, in one persistence-library transaction, so foreign keys hold and the unit is atomic.
- Writes nothing to standard output and exits 0. Rerunning it removes all records again.
- Applies no DDL. If the database cannot be opened it exits 1 and changes nothing.
- The handler returns `None` and is registered as `("init",)`.

## Database Interface

- `FEATURE-TXN-006` — write: delete every transaction - supplies: `min_txn_id`
- `FEATURE-CATEGORY-006` — write: delete every category - supplies: `min_category`
- `FEATURE-ACCOUNT-006` — write: delete every account - supplies: `min_account`

## Programmatic Acceptance

# FEATURE: Ledger Count

| Field       | Value |
|-------------|-------|
| Version     | 20261027 V1 |
| Description | The `ledger count` command reports the number of rows in each table. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-LedgerCli.md |
| Provides    | ledger count |
| Consumes    | ledger |

## Questions

- None.

## Purpose

`ledger count` shows how many accounts, categories, and transactions are stored.

## Behavior

- Takes no arguments; any argument is a usage error (exit 2).
- Writes the header `table,rows`, then the rows `accounts`, `categories`, `transactions` in that order, each with its stored row count. Counts come from the list operations of the database, never from embedded numbers.
- Exits 0. When the database cannot be opened it exits 1 with empty standard output and changes nothing.
- The handler is registered as `("count",)` and returns the CSV rows.

## Database Interface

- `FEATURE-ACCOUNT-005` — read: list accounts ordered by code - returns: `account`, `name`
- `FEATURE-CATEGORY-005` — read: list categories ordered by code - returns: `category`, `description`
- `FEATURE-TXN-005` — read: list transactions - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

=== AC count-reports-stored-rows ===
Intent: count writes the header and the three tables in the declared order, with counts equal to what the store holds after setup.

import csv
import io

    )
    want = {
        "accounts": len(db.accounts.list()),
        "categories": len(db.categories.list()),
        "transactions": len(db.transactions.list()),

    for name, n in rows[1:]:

    assert want["accounts"] >= 1
    assert want["transactions"] >= 1
