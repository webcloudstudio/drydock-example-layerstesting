FEATURE: Load Transactions

FieldValue
Version20261027 V1
DescriptionThe transactions loader with amount, date, memo, reference, and non-negative balance validation, plus the shared validators later stories reuse.
Depends OnFEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, FEATURE-LedgerCli.md, DATABASE.md
Providesledger load transactions
Consumesledger load, accounts, categories, transactions

Purpose

Register transactions with the shared load dispatcher. Each stored transaction keeps the txn_id from its file. This story also provides the shared validators parse_amount, validate_date, validate_memo, and a balance check that txn post, txn amend, txn delete, and transfer import.

Behavior

  • The header must be txn_id,date,account,category,amount,memo; a mismatch exits 3.
  • txn_id is an integer. A duplicate id inside the file, or one already stored, is rejected.
  • Amounts match -?DIGITS[.D[D]]: at most two decimal places and never zero. They are converted to

integer cents by string and integer arithmetic only; floating point is never used.

  • Dates are real Gregorian calendar dates written YYYY-MM-DD; February 29 is valid only in a leap

year and 2026-02-30 is rejected.

  • Memos are 0 to 60 characters with no comma or newline.
  • Each row's account and category must exist in the store.
  • The balance rule (Plan decision Q-002): for every account the batch touches, the stored balance plus

the sum of the batch's amounts for that account must not be below zero. The final balance is checked, so file order within the batch does not matter.

  • Everything is checked before the first write. Any failure exits 3, writes nothing to standard

output, and stores none of the rows. Success stores all rows in one transaction and writes table,loaded then transactions,<rows>.

  • Loading the staged accounts, categories, and transactions seed files in that order into an empty

ledger accepts 4, 7, and 120 rows.

Database Interface

  • FEATURE-TXN-001 — write: store a transaction - supplies: txn_id, date, account, category, amount, memo - returns: txn_id, date, account, category, amount, memo
  • FEATURE-TXN-002 — read: detect an existing transaction id - supplies: txn_id - returns: txn_id, date, account, category, amount, memo
  • FEATURE-TXN-005 — read: sum stored amounts per account - supplies: account - returns: txn_id, date, account, category, amount, memo
  • FEATURE-ACCOUNT-002 — read: confirm the account exists - supplies: account - returns: account, name
  • FEATURE-CATEGORY-002 — read: confirm the category exists - supplies: category - returns: category, description

=== AC load-transactions-success ===
Intent: A valid file for existing accounts and categories exits 0, reports the count, keeps each file txn_id, and stores amounts as integer cents.

import csv import io import os import tempfile from decimal import Decimal from cli.testing import cli_runner from persistence.testing import db_session

acct = "ZQX01" cat = "ZQX01" rows = [ ["910001", "2026-05-01", acct, cat, "100.50", "first"], ["910002", "2026-05-02", acct, cat, "-20.25", ""], ] with tempfile.TemporaryDirectory() as tmp: path = os.path.join(tmp, "txns.csv") with open(path, "w", newline="") as f: w = csv.writer(f, lineterminator="\n") w.writerow(["txn_id", "date", "account", "category", "amount", "memo"]) w.writerows(rows) with db_session() as db: db.accounts.create(account=acct, name="Load Txn") db.categories.create(category=cat, description="Load Txn") code, out, err = cli_runner("load", "transactions", path) print(out, err) assert code == 0 parsed = list(csv.reader(io.StringIO(out))) assert parsed == [["table", "loaded"], ["transactions", str(len(rows))]] for r in rows: stored = db.transactions.get(txn_id=int(r[0])) assert stored is not None assert stored.date == r[1] assert stored.account == r[2] assert stored.category == r[3] assert stored.amount == int(Decimal(r[4]) * 100) assert stored.memo == r[5] === END AC load-transactions-success ===

User Acceptance

  • None.

Guardrails

  • Money is integer cents at every layer; no floating point in parsing, summing, or formatting.
  • A rejected load changes no stored record.
  • Application code never reads a seed file or sources/run.sh; seed files arrive only through this command.
  • Persistence is reached only through the persistence package.
