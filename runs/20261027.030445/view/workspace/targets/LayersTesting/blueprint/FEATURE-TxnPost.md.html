FEATURE: Transaction Post

FieldValue
Version20261027 V1
DescriptionImplements ledger txn post, which validates a new cash transaction in full and stores it with the next transaction id.
Depends OnFEATURE-LoadTransactions.md, FEATURE-AccountGet.md, FEATURE-LedgerCli.md, DATABASE.md
Providesledger txn post
Consumesledger, accounts, categories, transactions

Purpose

Record one receipt (positive) or payment (negative) against an account and category, assigning its id automatically.

Trigger

ledger txn post <account> <category> <amount> <date> [<memo>] invoked from the command line.

Sequence

  1. Require four or five arguments after post; otherwise raise the shared usage error (exit 2).
  2. Validate the amount with the shared parser: -?DIGITS[.D[D]], at most two decimals, never zero; convert to integer cents with no floating point.
  3. Validate the date as a real Gregorian calendar date YYYY-MM-DD (February 29 only in leap years).
  4. Validate the memo (0 to 60 characters, no comma, no newline); an omitted memo is stored as the empty string.
  5. Confirm the account and the category exist; either missing exits 3.
  6. Compute the account's balance from its stored transactions and confirm balance plus amount is not below zero.
  7. Assign txn_id as one more than the largest stored id, or 1 when no transaction exists.
  8. Only after every check passes, create the row and write the header txn_id,date,account,category,amount,memo and the new row with the amount at exactly two decimals.

Any failure in steps 2 to 6 exits 3 and writes nothing.

Database Interface

  • FEATURE-ACCOUNT-002 — read: confirm the account exists - supplies: account - returns: account
  • FEATURE-CATEGORY-002 — read: confirm the category exists - supplies: category - returns: category
  • FEATURE-TXN-005 — read: list transactions to compute the balance and the largest id - supplies: account - returns: txn_id, amount
  • FEATURE-TXN-001 — write: create the transaction - supplies: txn_id, date, account, category, amount, memo - returns: txn_id, date, account, category, amount, memo

Behavior Rules

  • Amounts are integer cents at every layer.
  • A rejected post changes no stored record.
  • Output uses \n line endings and no quoting.

Programmatic Acceptance

=== AC txn-post-success ===
Intent: Posting a valid transaction exits 0, writes the new row with the next id, and a separate read returns every stored column.

import csv import io from persistence.testing import db_session from cli.testing import cli_runner

acct = "ZTP1" cat = "ZTP1" amount_text = "45.50" cents = 4550 date = "2026-04-01" memo = "walk in sale" with db_session() as db: db.accounts.create(account=acct, name="Post Account") db.categories.create(category=cat, description="Post Category") before = [r.txn_id for r in db.transactions.list()] expected_id = (max(before) + 1) if before else 1 exit_code, out, err = cli_runner("txn", "post", acct, cat, amount_text, date, memo) print(exit_code, out, err) assert exit_code == 0 rows = list(csv.reader(io.StringIO(out))) assert rows[0] == ["txn_id", "date", "account", "category", "amount", "memo"] assert rows[1] == [str(expected_id), date, acct, cat, amount_text, memo] back = db.transactions.get(txn_id=expected_id) assert back is not None assert back.date == date assert back.account == acct assert back.category == cat assert back.amount == cents assert back.memo == memo === END AC txn-post-success ===

=== AC txn-post-date-rules ===
Intent: Impossible dates and February 29 in non-leap Gregorian years are rejected with exit 3, while February 29 in a leap year is accepted.

from persistence.testing import db_session from cli.testing import cli_runner

acct = "ZTP8" cat = "ZTP8" rejected = ["2026-02-30", "2026-02-29", "2100-02-29", "2026-13-01", "2026-4-1"] accepted = ["2024-02-29", "2000-02-29"] with db_session() as db: db.accounts.create(account=acct, name="Dates") db.categories.create(category=cat, description="Dates") before = len(db.transactions.list()) for bad in rejected: exit_code, out, err = cli_runner("txn", "post", acct, cat, "1.00", bad) print(bad, exit_code, out, err) assert exit_code == 3 assert out == "" assert len(db.transactions.list()) == before for good in accepted: exit_code, out, err = cli_runner("txn", "post", acct, cat, "1.00", good) print(good, exit_code, out, err) assert exit_code == 0 assert len(db.transactions.list()) == before + len(accepted) === END AC txn-post-date-rules ===
