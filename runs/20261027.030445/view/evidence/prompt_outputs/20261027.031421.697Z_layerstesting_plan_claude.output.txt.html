# FEATURE: Account Rename

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger account rename`, which changes only an account's name and writes the updated account row. |
| Depends On | FEATURE-AccountGet.md, FEATURE-LedgerCli.md, DATABASE.md |
| Provides | ledger account rename |
| Consumes | ledger, accounts |

## Questions

- None.

## Purpose

Let the shop correct the display name of an existing account without touching its code or its transactions.

## Trigger

`ledger account rename <code> <name>` invoked from the command line.

## Sequence

1. Require exactly two arguments after `rename`; otherwise raise the shared usage error (exit 2).
2. Look up the account by code. An absent code exits 4. This check runs before the name is validated.
3. Validate the name: 1 to 40 characters, no comma, no newline. An invalid name exits 3 and changes nothing.
4. Update only the name through the persistence library.
5. Compute the account's transaction count and balance in integer cents from its stored transactions.
6. Write the header `account,name,transactions,balance` and the updated row, balance with exactly two decimals.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: look up the account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-ACCOUNT-003` — write: rename the account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-TXN-005` — read: list the account's transactions to count and sum them - supplies: `account` - returns: `txn_id`, `amount`

## Behavior Rules

- Only the name changes; the code and transactions are untouched.
- A failing command writes nothing to standard output and one diagnostic line to standard error.
- Money is integer cents at every layer; no floating point.

## Programmatic Acceptance

# FEATURE: Transaction Post

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger txn post`, which validates a new cash transaction in full and stores it with the next transaction id. |
| Depends On | FEATURE-LoadTransactions.md, FEATURE-AccountGet.md, FEATURE-LedgerCli.md, DATABASE.md |
| Provides | ledger txn post |
| Consumes | ledger, accounts, categories, transactions |

## Questions

- None.

## Purpose

Record one receipt (positive) or payment (negative) against an account and category, assigning its id automatically.

## Trigger

`ledger txn post <account> <category> <amount> <date> [<memo>]` invoked from the command line.

## Sequence

1. Require four or five arguments after `post`; otherwise raise the shared usage error (exit 2).
2. Validate the amount with the shared parser: `-?DIGITS[.D[D]]`, at most two decimals, never zero; convert to integer cents with no floating point.
3. Validate the date as a real Gregorian calendar date `YYYY-MM-DD` (February 29 only in leap years).
4. Validate the memo (0 to 60 characters, no comma, no newline); an omitted memo is stored as the empty string.
5. Confirm the account and the category exist; either missing exits 3.
6. Compute the account's balance from its stored transactions and confirm balance plus amount is not below zero.
7. Assign `txn_id` as one more than the largest stored id, or 1 when no transaction exists.
8. Only after every check passes, create the row and write the header `txn_id,date,account,category,amount,memo` and the new row with the amount at exactly two decimals.

Any failure in steps 2 to 6 exits 3 and writes nothing.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORY-002` — read: confirm the category exists - supplies: `category` - returns: `category`
- `FEATURE-TXN-005` — read: list transactions to compute the balance and the largest id - supplies: `account` - returns: `txn_id`, `amount`
- `FEATURE-TXN-001` — write: create the transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Behavior Rules

- Amounts are integer cents at every layer.
- A rejected post changes no stored record.
- Output uses `\n` line endings and no quoting.

## Programmatic Acceptance

# FEATURE: Transaction Amend

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger txn amend`, which changes only a transaction's amount while keeping every account balance non-negative. |
| Depends On | FEATURE-TxnPost.md, FEATURE-LedgerCli.md, DATABASE.md |
| Provides | ledger txn amend |
| Consumes | ledger, transactions |

## Questions

- None.

## Purpose

Correct the amount of a recorded transaction without altering its date, account, category, or memo.

## Trigger

`ledger txn amend <id> <amount>` invoked from the command line.

## Sequence

1. Require exactly two arguments after `amend`; otherwise raise the shared usage error (exit 2).
2. Parse the id as an integer (non-integer exits 3) and look up the transaction. An absent id exits 4; this check runs before the amount is validated.
3. Validate the amount with the shared parser (`-?DIGITS[.D[D]]`, at most two decimals, never zero) into integer cents. Invalid exits 3.
4. Compute the owning account's balance from its stored transactions, replace the old amount with the new one, and confirm the result is not below zero. Otherwise exit 3.
5. Only after every check passes, update the amount and write the header `txn_id,date,account,category,amount,memo` and the updated row.

## Database Interface

- `FEATURE-TXN-002` — read: get the transaction by id - supplies: `txn_id` - returns: `txn_id`, `account`, `amount`
- `FEATURE-TXN-005` — read: list the account's transactions to compute the resulting balance - supplies: `account` - returns: `txn_id`, `amount`
- `FEATURE-TXN-003` — write: change the amount - supplies: `txn_id`, `amount` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Behavior Rules

- Only the amount changes.
- A rejected amend changes no stored record.
- Money is integer cents at every layer.
