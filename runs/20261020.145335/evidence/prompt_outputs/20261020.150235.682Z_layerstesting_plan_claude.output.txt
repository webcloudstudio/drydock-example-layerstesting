# FEATURE: Load Transactions

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Load transactions from a CSV file atomically, keeping each txn_id from the file. |
| Depends On  | DATABASE.md, FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, FEATURE-NonNegativeBalance.md, FEATURE-ValidateText.md, FEATURE-ValidateAmount.md, FEATURE-ValidateDate.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md |
| Provides    | ledger load transactions |
| Consumes    | accounts.get, categories.get, transactions.create |

## Questions

- None.

## Purpose

Loads `transactions` from a CSV file. The file either stores every row or stores none. Each row
keeps the `txn_id` written in the file, so a loaded transaction is never renumbered.

## Command

`ledger load transactions <csv>`

## Contract

- The header must match exactly `txn_id,date,account,category,amount,memo`, in that order. A file
  whose header differs, reorders, or omits a column is rejected with exit 3 and stores no rows.
- `txn_id` is an integer and must be unique among existing transactions and within the file. A
  duplicate is rejected with exit 3.
- `date` is validated by FEATURE-ValidateDate. `memo` is validated by FEATURE-ValidateText.
- `amount` is parsed to integer cents by FEATURE-ValidateAmount. No floating point is used.
- `account` must name an existing account and `category` an existing category. An unknown value
  is rejected with exit 3.
- After every row is staged, and before commit, FEATURE-NonNegativeBalance checks each account.
  Any negative balance rejects the file with exit 3.
- A file that cannot be read exits 1 and writes nothing to standard output.
- Any rejected row rejects the whole file. The command runs as one transaction through
  FEATURE-CommandTransaction.
- On success, standard output is `table,loaded` then `transactions,<rows>`.

## Database Interface

- `FEATURE-LEDGER-002` — read: look up each row's account - supplies: `account` - returns: `account`
- `FEATURE-LEDGER-007` — read: look up each row's category - supplies: `category` - returns: `category`
- `FEATURE-LEDGER-011` — write: insert each accepted row - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`

## Programmatic Acceptance

=== AC load-txn-round-trip ===
Intent: A valid file stores every row with its own txn_id and amount in integer cents, and reports the loaded count.

import csv
import io
import os
import tempfile

from cli.testing import cli_runner
from persistence.testing import db_session

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn
assert cli_runner("init")[0] == 0

with db_session(dsn) as db:
    db.accounts.create(account="DRAWER1", name="Front Drawer")
    db.categories.create(category="SALES", description="Sales receipts")

csv_path = os.path.join(os.path.dirname(dsn), "txns.csv")
with open(csv_path, "w") as handle:
    handle.write("txn_id,date,account,category,amount,memo\n")
    handle.write("7,2026-01-02,DRAWER1,SALES,155.26,sales day 1\n")
    handle.write("8,2026-01-02,DRAWER1,SALES,-12.50,refund\n")

exit_code, out, err = cli_runner("load", "transactions", csv_path)
print(out)
print(err)
assert exit_code == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows[0] == ["table", "loaded"]
assert rows[1] == ["transactions", "2"]

with db_session(dsn) as db:
    stored = sorted((row.txn_id, row.amount) for row in db.transactions.list())
assert stored == [(7, 15526), (8, -1250)]
=== END AC load-txn-round-trip ===

# FEATURE: Account Add

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Add an account with ledger account add, rejecting duplicates and invalid fields. |
| Depends On  | DATABASE.md, FEATURE-CommandTransaction.md, FEATURE-ValidateText.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md, FEATURE-InitSchema.md |
| Provides    | ledger account add |
| Consumes    | accounts.get, accounts.create |

## Questions

- None.

## Purpose

Adds one account row. The new account starts with no transactions and a balance of `0.00`.

## Command

`ledger account add <code> <name>`

## Contract

- `code` is 1 to 12 characters from `A-Z` and `0-9`. Any other value is rejected with exit 3.
- `name` is 1 to 40 characters with no comma or newline. Any other value is rejected with exit 3.
- A code that already exists is rejected with exit 3 and changes nothing.
- On success, standard output is the header `account,name,transactions,balance` followed by the
  row `<code>,<name>,0,0.00`.
- Any failure writes nothing to standard output and one diagnostic line to standard error.
- The command runs as one transaction through FEATURE-CommandTransaction.

## Database Interface

- `FEATURE-LEDGER-002` — read: check whether the code already exists - supplies: `account` - returns: `account`
- `FEATURE-LEDGER-003` — write: create the account row - supplies: `account`, `name` - returns: `account`, `name`

## Programmatic Acceptance

# FEATURE: Account Get

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Get one account with its transaction count and balance computed from the database. |
| Depends On  | DATABASE.md, FEATURE-AccountAdd.md, FEATURE-ValidateText.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md, FEATURE-InitSchema.md |
| Provides    | ledger account get |
| Consumes    | accounts.get, transactions.list |

## Questions

- None.

## Purpose

Writes the account row for one code. The transaction count and balance are computed by query from
the stored transactions, never stored on the account.

## Command

`ledger account get <code>`

## Contract

- On success, standard output is the header `account,name,transactions,balance` followed by one row
  `<code>,<name>,<count>,<balance>`. `balance` is the signed sum of the account's transaction
  amounts in integer cents, written with exactly two decimals.
- A code that is well formed but absent exits 4 and writes nothing to standard output.
- A code that is malformed under FEATURE-ValidateText exits 3 and writes nothing to standard output.
  Validation precedes the lookup.
- The command is read-only. It changes no table.

## Database Interface

- `FEATURE-LEDGER-002` — read: read the account row - supplies: `account` - returns: `account`, `name`

## Programmatic Acceptance

# FEATURE: Account Delete

| Field       | Value |
|-------------|-------|

## Purpose

Deletes one account row when no transaction refers to it.

## Command

`ledger account delete <code>`

## Contract

- An absent code exits 4 and changes nothing.
- An account with one or more transactions is refused with exit 3 and changes nothing.
- On success, standard output is the header `deleted` followed by the row `<code>`.
- Any failure writes nothing to standard output and one diagnostic line to standard error.
- The transaction check runs before the delete operation. The command runs as one transaction
  through FEATURE-CommandTransaction.

## Database Interface

- `FEATURE-LEDGER-002` — read: confirm the account exists - supplies: `account` - returns: `account`
- `FEATURE-LEDGER-005` — write: delete the account row - supplies: `account` - returns: `account`

## Programmatic Acceptance

=== AC acct-delete-empty ===
Intent: Deleting an account with no transactions writes the deleted header and code, and the account is then absent.

import csv
import io
import os
import tempfile

from cli.testing import cli_runner

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn
assert cli_runner("init")[0] == 0

code = "CASH9"
assert cli_runner("account", "add", code, "Event Float")[0] == 0

exit_code, out, err = cli_runner("account", "delete", code)
print(out)
print(err)
assert exit_code == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows == [["deleted"], [code]]

exit_code, out, err = cli_runner("account", "get", code)
assert exit_code == 4
assert out == ""
=== END AC acct-delete-empty ===

=== AC acct-delete-refused-with-transactions ===
Intent: An account with a stored transaction is refused with exit 3, prints nothing, and remains present with its transaction count unchanged.

import csv
import io
import os
import tempfile

from cli.testing import cli_runner
from persistence.testing import db_session

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn
assert cli_runner("init")[0] == 0

code, name = "DRAWER1", "Front Drawer"
assert cli_runner("account", "add", code, name)[0] == 0
with db_session(dsn) as db:
    db.categories.create(category="SALES", description="Sales receipts")
    db.transactions.create(txn_id=1, date="2026-01-02", account=code, category="SALES", amount=50000, memo="")

exit_code, out, err = cli_runner("account", "delete", code)
print(err)
assert exit_code == 3
assert out == ""

exit_code, out, err = cli_runner("account", "get", code)
assert exit_code == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows[1] == [code, name, "1", "500.00"]
