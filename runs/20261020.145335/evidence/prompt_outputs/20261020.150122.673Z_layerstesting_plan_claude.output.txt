# FEATURE: Non-Negative Balance

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Reject any command whose changes would leave an account balance below zero. |
| Depends On  | FEATURE-CommandTransaction.md, DATABASE.md |
| Provides    | balance.ensure_non_negative(db, accounts) |
| Consumes    | db.accounts.list, db.transactions.list |

## Questions

- None.

## Purpose

Guards every mutating command. After a command's writes and before its transaction commits, the
command passes the accounts it touched to `balance.ensure_non_negative`. The function computes each
named account's balance as the sum of its transaction amounts, in integer cents, from the database.
If any balance is below zero it raises `RejectedError` with `exit_code` set to `3`. The caller then
rolls back the command's transaction, so no table changes.

## Interface

- `balance.ensure_non_negative(db, accounts)`: `accounts` is an iterable of account codes. Returns
  `None` when every named balance is zero or positive. Raises `balance.RejectedError` otherwise.
- `balance.RejectedError`: carries `exit_code`, which is `3`.
- Reads: `db.accounts.list` to confirm each named account exists, and `db.transactions.list` to sum
  amounts per account. Writes nothing.

## Behavior

1. Sum the `amount` integer-cent values of every transaction whose `account` equals each named code.
2. An account with no transactions has balance `0`.
3. A balance below `0` raises `RejectedError` for the first offending account in code order.
4. Amounts are never converted to floating point at any step.

## Programmatic Acceptance

=== AC nonneg-rejects-negative-balance ===
Intent: A balance below zero raises RejectedError with exit code 3.
import tempfile
import os

from persistence import open_database
from balance import RejectedError, ensure_non_negative

work = tempfile.mkdtemp()
db = open_database(os.path.join(work, "ledger.db"))
db.categories.create(category="OPENING", description="Opening balance")
db.accounts.create(account="CASH1", name="Till")
db.transactions.create(txn_id=1, date="2026-01-01", account="CASH1", category="OPENING", amount=-500, memo="")

expected_exit = 3
raised = None
try:
    ensure_non_negative(db, ["CASH1"])
except RejectedError as error:
    raised = error
print("raised:", raised)
assert raised is not None
assert raised.exit_code == expected_exit

# FEATURE: Initialize Schema

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provide `ledger init`, which drops and recreates the three ledger tables empty. |
| Depends On  | FEATURE-DatabaseTarget.md, FEATURE-CommandTransaction.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md, DATABASE.md |
| Provides    | ledger init |
| Consumes    | open_database, db.accounts.list, db.categories.list, db.transactions.list |

## Questions

- None.

## Purpose

`ledger init` resets the store. It drops `accounts`, `categories`, and `transactions` if they exist,
recreates all three from the declared schema, and leaves them empty. It writes nothing to standard
output and exits `0`. It runs inside the command transaction, so a failure leaves the prior tables
as they were.

A missing SQLite file is created empty by the first command that opens it. If a command then finds
no ledger tables, it exits `1` and writes nothing to standard output. The no-tables failure is
exercised by the commands that read the tables; this feature verifies `init` itself.

## Trigger

`ledger init` with no further arguments. Usage errors (extra arguments) exit `2` under
FEATURE-CliDispatch.md.

## Sequence

1. Resolve the database target through FEATURE-DatabaseTarget.md.
2. Open the store with `open_database`.
3. Drop each declared table if present.
4. Create each declared table empty, using the generated schema.
5. Commit. Write nothing.

## Routes and Interfaces

- `ledger init`: exit `0` on success, `1` when the database is unreachable.

## Reads and Writes

- Writes: drops and recreates `accounts`, `categories`, and `transactions`.
- Reads: none beyond the table existence check.

# FEATURE: Count Rows

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provide `ledger count`, which reports the row count of each ledger table. |
| Depends On  | FEATURE-InitSchema.md, FEATURE-CliOutput.md, DATABASE.md |
| Provides    | ledger count |
| Consumes    | db.accounts.list, db.categories.list, db.transactions.list |

## Questions

- None.

## Purpose

`ledger count` writes the row count of each ledger table as CSV. Each count is a query against the
store. No count is stored, cached, or hardcoded.

## Trigger

`ledger count` with no further arguments.

## Sequence

1. Resolve the database target and open the store.
2. Count rows in `accounts`, then `categories`, then `transactions`, each by a query.
3. Write the header and three rows, then exit `0`.

## Routes and Interfaces

- `ledger count`: writes `table,rows`, then `accounts,<n>`, `categories,<n>`, `transactions,<n>`.
- Exit `1` when the tables are missing, with nothing on standard output.

## Reads and Writes

- Reads: all rows of `accounts`, `categories`, and `transactions`, counted by query.
- Writes: none.

# FEATURE: Load Accounts

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provide `ledger load accounts <csv>`, which loads every account row from a file or none. |
| Depends On  | FEATURE-CommandTransaction.md, FEATURE-ValidateText.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md, FEATURE-InitSchema.md, DATABASE.md |
| Provides    | ledger load accounts |
| Consumes    | db.accounts.create, db.accounts.get, db.accounts.list |

## Questions

- None.

## Purpose

`ledger load accounts <csv>` reads an accounts file and inserts every row into the `accounts` table.
The whole load runs in one command transaction: if any row is rejected, no row is stored.

## Trigger

`ledger load accounts <path>`.

## Sequence

1. Open the file. If it cannot be read, exit `1`.
2. Check the header is exactly `account,name`. If it is not, exit `3`.
3. Validate each row's code and name with the validators of FEATURE-ValidateText.md. An invalid row,
   or a code repeated within the file or already present in the table, exits `3`.
4. Insert every row with `db.accounts.create`, inside the command transaction.
5. Write `table,loaded` then `accounts,<rows>` and exit `0`.

## Routes and Interfaces

- `ledger load accounts <csv>`: exit `0` on success; `1` unreadable file; `2` wrong argument count;
  `3` rejected header or row, with nothing stored.

## Reads and Writes

- Writes: inserts the file's rows into `accounts`, all or none.
- Reads: `accounts` for duplicate detection.

## Programmatic Acceptance
