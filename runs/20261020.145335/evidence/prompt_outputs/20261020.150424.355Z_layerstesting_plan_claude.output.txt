# FEATURE: Post Transaction

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Post one cash transaction to an existing account and category, assigning the next transaction id. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-AccountAdd.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md, FEATURE-CommandTransaction.md, FEATURE-NonNegativeBalance.md, FEATURE-ValidateText.md, FEATURE-ValidateAmount.md, FEATURE-ValidateDate.md |
| Provides    | ledger txn post |
| Consumes    | db.accounts.get, db.categories.get, db.transactions.list, db.transactions.create |

## Questions

- None.

## Purpose

Adds one transaction to the ledger. The command is the only way a new cash movement enters the
store outside `ledger load` and `ledger transfer`.

## Command

`ledger txn post <account> <category> <amount> <date> [<memo>]`

## Behavior

- Validate the account and category codes with FEATURE-ValidateText, the amount with
  FEATURE-ValidateAmount, and the date with FEATURE-ValidateDate. Any violation exits 3.
- An account or category that is not present exits 3 and stores nothing.
- Assign `txn_id` one more than the largest id present, or `1` when the table is empty. The largest
  id is computed from the stored rows, never assumed.
- Store the amount as integer cents. Store the memo as given; when the memo argument is omitted,
  store an empty memo.
- Run the command inside the transaction wrapper of FEATURE-CommandTransaction. The stored row is
  rejected with exit 3 when it would leave the account balance below zero, per
  FEATURE-NonNegativeBalance.
- On success, write the new row as the transaction CSV row defined by FEATURE-CliOutput.

## Database Interface

- `FEATURE-LEDGER-002` — read: get an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-LEDGER-007` — read: get a category by code - supplies: `category` - returns: `category`, `description`
- `FEATURE-LEDGER-009` — read: list transactions - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-011` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

=== AC txn-post-round-trip ===
Intent: A posted transaction is stored with the supplied fields and is read back unchanged, with id 1 in an empty table.

# Exercises ledger txn post, then reads the stored row back through the persistence library.
import os
import tempfile

from cli.testing import cli_runner
from persistence import open_database
from persistence.schema import AccountRow, CategoryRow, TransactionKey
from persistence.testing import db_session

account = "DRAWER1"
category = "SALES"
date = "2026-04-01"
amount_in = "45.50"
memo = "walk in sale"

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn
with db_session(dsn) as db:
    db.accounts.create(AccountRow(account=account, name="Front Drawer"))
    db.categories.create(CategoryRow(category=category, description="Sales receipts"))

code, out, err = cli_runner("txn", "post", account, category, amount_in, date, memo)
print(out)
print(err)
assert code == 0

row = open_database(dsn).transactions.get(TransactionKey(txn_id=1))
assert row is not None
assert row.account == account
assert row.category == category
assert row.date == date
assert row.amount == 4550
assert row.memo == memo

# FEATURE: Transfer Between Accounts

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Move a positive amount between two accounts as two linked TRANSFER transactions, or store neither. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-AccountAdd.md, FEATURE-CliDispatch.md, FEATURE-CliOutput.md, FEATURE-CommandTransaction.md, FEATURE-NonNegativeBalance.md, FEATURE-ValidateAmount.md, FEATURE-ValidateDate.md, FEATURE-ValidateText.md |
| Provides    | ledger transfer |
| Consumes    | db.accounts.get, db.transactions.list, db.transactions.create |

## Questions

- None.

## Purpose

Records a movement of cash between two places, such as drawer to safe, as a matched pair of rows.

## Command

`ledger transfer <from> <to> <amount> <date>`

## Behavior

- Validate both account codes with FEATURE-ValidateText, the amount with FEATURE-ValidateAmount, and
  the date with FEATURE-ValidateDate. A violation exits 3.
- The amount must be positive. The two accounts must differ. Either rule failing exits 3.
- An account that is not present exits 3.
- Write two rows in category `TRANSFER`, both in one transaction. The outgoing row takes the next
  id after the largest present; the incoming row takes the id after that.
  - Outgoing: the source account, a negative amount, memo `transfer to <to>`.
  - Incoming: the destination account, a positive amount, memo `transfer from <from>`.
- If either account balance would be below zero after both rows, per FEATURE-NonNegativeBalance,
  the command exits 3 and neither row is stored.
- On success, write the two rows as CSV per FEATURE-CliOutput, outgoing first.

## Database Interface

- `FEATURE-LEDGER-002` — read: get an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-LEDGER-009` — read: list transactions - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-011` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

=== AC xfer-round-trip ===
Intent: A transfer stores two TRANSFER rows, outgoing first with the next two ids, with the linked memos and opposite signed amounts.
