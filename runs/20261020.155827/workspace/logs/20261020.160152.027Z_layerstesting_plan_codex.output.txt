## Configuration

The database DSN is resolved in this order:

1. `DATABASE_URL`
2. `DATABASE_PATH`
3. `data/app.db`

A `postgres://` or `postgresql://` URL selects PostgreSQL. Other values select SQLite, with an optional `sqlite://` prefix.

## Schema

## `accounts`

| Field | Type | Notes |
|---|---|---|
| `account` | TEXT [PK] [NOT NULL] | Account code. |
| `name` | TEXT NOT NULL | Account name. |

## `categories`

| Field | Type | Notes |
|---|---|---|
| `category` | TEXT [PK] [NOT NULL] | Category code. |
| `description` | TEXT NOT NULL | Category description. |

## `transactions`

| Field | Type | Notes |
|---|---|---|
| `txn_id` | INTEGER [PK] [NOT NULL] | Transaction identifier. |
| `date` | TEXT NOT NULL | Calendar date in `YYYY-MM-DD` form. |
| `account` | TEXT NOT NULL REFERENCES accounts(account) | Account code. |
| `category` | TEXT NOT NULL REFERENCES categories(category) | Category code. |
| `amount` | INTEGER NOT NULL | Signed amount in cents. |
| `memo` | TEXT NOT NULL | Optional memo, empty when omitted. |

## Persistence Interface

Application callers use `open_database(dsn)` and declared operations on `db.accounts`, `db.categories`, and `db.transactions`. SQL, driver connections, and table access remain inside the shipped persistence package.

## Programmatic Acceptance

- None. Drydock owns generated schema construction and persistence connectivity invariants deterministically.

## User Acceptance

- None.

## Guardrails

- All database access must go through the shipped persistence library.
- Amounts must remain integer cents; floating point is forbidden.
- Foreign keys must enforce valid account and category references.
- Schema creation must be idempotent.
- Every command must execute as one transaction.
