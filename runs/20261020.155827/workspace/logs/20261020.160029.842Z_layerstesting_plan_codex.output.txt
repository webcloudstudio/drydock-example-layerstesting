# FEATURE: Transaction CSV Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Loads validated transaction CSV batches atomically into the ledger. |
| Depends On  | FEATURE-ACCOUNT-CATEGORY-LOAD.md, DATABASE.md |
| Provides    | ledger load transactions |
| Consumes    | ./ledger executable, ledger persistence operations |

## Questions

- None.

## Purpose

Load transaction rows while preserving supplied identifiers and enforcing all transaction, reference, date, amount, duplicate, balance, and atomicity rules.

## Workflow

1. Validate the exact transaction header and every row.
2. Parse amounts into integer cents and validate real calendar dates.
3. Validate account and category references and duplicate identifiers.
4. Insert the complete batch in one transaction.
5. Recompute affected balances before commit.
6. Emit the loaded-row result only after commit.

## Database Interface

- `FEATURE-LEDGER-008` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-013` — read: inspect transactions for balance validation - supplies: none - returns: `txn_id`, `account`, `amount`

## Programmatic Acceptance

# FEATURE: Account Operations

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Creates, reads, renames, and deletes ledger accounts with lifecycle validation. |
| Depends On  | FEATURE-TRANSACTION-LOAD.md, DATABASE.md |
| Provides    | ledger account add, ledger account get, ledger account rename, ledger account delete |
| Consumes    | ./ledger executable, ledger persistence operations |

## Questions

- None.

## Purpose

Manage account records while enforcing code and name validation, uniqueness, not-found behavior, transaction references, and computed account balances.

## Database Interface

- `FEATURE-LEDGER-003` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-LEDGER-004` — read-write: read and rename an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-LEDGER-005` — write: delete an account - supplies: `account` - returns: `account`
- `FEATURE-LEDGER-011` — read: query account balances - supplies: none - returns: `account`, `name`, `transactions`, `balance`

## Workflow

- Add validates the account code and name, rejects duplicates, and returns the computed account row.
- Get returns the account row with transaction count and balance.
- Rename changes only the name.
- Delete succeeds only when the account has no transactions.
- Missing accounts return exit code 4; rejected mutations return exit code 3.

# FEATURE: Transaction Operations

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Posts, reads, amends, and deletes individual cash transactions atomically. |
| Depends On  | FEATURE-TRANSACTION-LOAD.md, DATABASE.md |
| Provides    | ledger txn post, ledger txn get, ledger txn amend, ledger txn delete |
| Consumes    | ./ledger executable, ledger persistence operations |

## Questions

- None.

## Purpose

Provide individual transaction mutations and reads with generated identifiers, validation, preservation of immutable fields, and non-negative balance enforcement.

## Database Interface

- `FEATURE-LEDGER-008` — read-write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-009` — read-write: amend a transaction amount - supplies: `txn_id`, `amount` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-010` — write: delete a transaction - supplies: `txn_id` - returns: `txn_id`

## Workflow

- Post validates references, amount, date, and memo, then assigns one more than the maximum identifier.
- Get returns the complete transaction row.
- Amend changes only the amount and rechecks the affected balance.
- Delete removes an existing transaction only when the resulting balance remains non-negative.
- Missing identifiers return exit code 4; rejected mutations return exit code 3.

# FEATURE: Transfers

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Executes atomic two-entry transfers between distinct ledger accounts. |
| Depends On  | FEATURE-TRANSACTION-OPERATIONS.md, DATABASE.md |
| Provides    | ledger transfer |
| Consumes    | ./ledger executable, ledger persistence operations |

## Questions

- None.

## Purpose

Move a positive amount between two distinct accounts by creating consecutive outgoing and incoming transaction rows in one database transaction.

## Database Interface

- `FEATURE-LEDGER-008` — write: create outgoing and incoming transfer transactions - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Workflow

1. Validate both accounts, the positive amount, and the real date.
2. Allocate consecutive identifiers.
3. Create the outgoing `TRANSFER` row with a negative amount.
4. Create the incoming `TRANSFER` row with a positive amount.
5. Validate all resulting balances before commit.
6. Emit both rows in identifier order.

| Provides    | ledger report balances |
| Consumes    | ./ledger executable, ledger persistence operations |

## Questions

- None.

## Purpose

Compute the balances report directly from account and transaction data, including accounts with no transactions and a computed total row.

## Database Interface

- `FEATURE-LEDGER-011` — read: query balances by account - supplies: none - returns: `account`, `name`, `transactions`, `balance`

The report emits:
