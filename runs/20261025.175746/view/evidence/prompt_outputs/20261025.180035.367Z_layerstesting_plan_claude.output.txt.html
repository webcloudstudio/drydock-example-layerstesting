# ARCHITECTURE: LayersTesting

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Modules, boundaries, and technical decisions for the LayersTesting cash ledger CLI. |
| Depends On | None |
| Provides | bin/test.sh, pyproject.toml, tests/conftest.py |

## Questions

- None.

## Purpose

`ledger` is a single-executable command-line cash ledger. It keeps accounts, categories, and cash
transactions in a relational database reached only through the shipped persistence library, rejects
a failing command before it writes, enforces non-negative balances, and reports balances, category
totals, and monthly totals. All values come from queries; no report row, count, or total is embedded.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Python 3.11 or newer | Implementation language for every module. |
| SQLite | The database, reached only through the shipped persistence package. |
| CLI | The `ledger` executable at the application root and the `cli` package behind it. |
| pytest | The test runner behind `bin/test.sh`. |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh`. |

## Project Layout

| Path | Role |
|---|---|
| `ledger` | Executable at the application root; calls `cli.main` and exits with its return value. |
| `cli/` | Command-line package: dispatch, errors, validators, money, output, commands. |
| `cli/commands/` | One module per command; each registers a handler with the command registry. |
| `persistence/` | Generated and shipped by Drydock from `DATABASE.md`; never hand-written. |
| `tests/` | The project's own pytest suite, with `conftest.py` exposing `db_session` and `cli_runner`. |
| `bin/test.sh` | POSIX sh launcher: activates `.venv`, runs `pytest -q` from the root, exits zero only when all tests pass. |
| `pyproject.toml`, `uv.lock` | Dependency manifest and committed lock; environment created by `uv venv`. |
| `sources/` | Read-only scoring assets staged by Drydock; application code never reads them. |

## Module Ownership

| Boundary | Owning module | Allowed low-level access |
|---|---|---|
| Persistence | `persistence/` (generated) | The only package that imports a database driver. |
| Configuration | `persistence.open_database` via `cli.database` | Resolves `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| File stores | None | Command modules read only the CSV path named on the command line. |
| External services | None | No network access. |

Callers use `db.<table>.<operation>(...)` as declared in `DATABASE.md`. SQL, sessions, table names,
and column names never cross that boundary, and no command issues DDL.

## Technical Decisions

- Money is integer cents at every layer; floating point is never used. Parsing and formatting use
  integer arithmetic only.
- Every command validates its full input and every business rule before its first write.
- Sums, counts, balances, and the next transaction id are computed by services from listed rows.
- Standard output carries only CSV (`\n` endings, no quoting); diagnostics go to standard error.
- Exit codes: 0 success, 1 operational, 2 usage, 3 rejected, 4 not found.
- Commands register themselves in a registry; the dispatcher checks arity before opening the database.

# FEATURE: CLI Foundation

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | The ledger executable, command dispatch, exit-code mapping, CSV output, and shared input validators. |
| Depends On | DATABASE.md, ARCHITECTURE.md |
| Provides | ledger, cli.main, cli.testing.cli_runner, cli.errors, cli.validate, cli.money, cli.output, cli.registry |

## Questions

- None.

## Purpose

Provide the executable and the shared machinery every command uses, so command stories write only
their own behavior.

## Interface

| Module | Contract |
|---|---|
| `ledger` | Executable at the application root; runs `cli.main(sys.argv[1:])` and exits with the result. |
| `cli/__init__.py` | `main(argv: list[str] \| None = None) -> int`. |
| `cli/testing.py` | `cli_runner(*args) -> (exit_code, stdout, stderr)` without spawning a process. |
| `cli/errors.py` | `LedgerError` with an `exit_code` attribute; subclasses `Operational` (1), `Usage` (2), `Rejected` (3), `NotFound` (4). |
| `cli/registry.py` | `register(path, min_args, max_args, handler)` and `COMMANDS`. A handler is `run(db, args) -> list[list[str]]` returning the header and data rows. |
| `cli/commands/` | Every module is imported at startup; each registers its handlers. |
| `cli/database.py` | `open_ledger()` opens the store with `open_database`, using `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| `cli/validate.py` | `validate_code`, `validate_name`, `validate_memo`, `validate_date`; each returns the value or raises `Rejected`. |
| `cli/money.py` | `parse_amount(text) -> int` cents and `format_amount(cents) -> str`, integer arithmetic only. |
| `cli/output.py` | `write_rows(rows)` writes comma-separated rows with `\n` endings and no quoting; `TRANSACTION_HEADER`, `format_transaction(row)`. |

## Behavior

- The dispatcher resolves the command path and checks the argument count before opening the
  database. An unknown command, unknown table or report, or wrong argument count exits 2.
- A `LedgerError` is mapped to its exit code; the message goes to standard error as one line and
  nothing is written to standard output. Any other database failure exits 1.
- Output is written only after the handler returns, so a failing command writes nothing to
  standard output.
- Codes are 1 to 12 characters from `A-Z` and `0-9`. Names are 1 to 40 characters. Memos are 0 to
  60 characters. None contains a comma or newline. Dates are real calendar dates `YYYY-MM-DD`.
- Amounts match `-?DIGITS[.D[D]]`, never zero. Output amounts have exactly two decimals, a leading
  `-` when negative, and no thousands separator.
- A non-integer transaction id is rejected with exit 3 (disclosed decision Q-003).

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Balance Rules

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Account summaries and the non-negative balance check used by every mutating command. |
| Depends On | FEATURE-CliFoundation.md, DATABASE.md |
| Provides | cli.balance.account_summary, cli.balance.balances, cli.balance.check_balances, cli.balance.next_txn_id |
| Consumes | transactions.list, accounts.get |

## Questions

- None.

## Purpose

An account's balance is the sum of its transaction amounts. No command may leave a balance below
zero. This module computes balances from stored rows in integer cents and applies the rule before a
command writes, so a violation changes nothing.

## Interface

| Function | Contract |
|---|---|
| `account_summary(db, code) -> tuple[int, int]` | Transaction count and balance in cents for the account, computed from its stored transactions; `(0, 0)` when it has none. |
| `balances(db) -> dict[str, int]` | Balance in cents per account that has transactions. |
| `check_balances(db, deltas)` | `deltas` maps account code to the net change in cents the command would make. Raises `Rejected` (exit 3) when any stored balance plus its delta is below zero; returns `None` otherwise. Writes nothing. |
| `next_txn_id(db) -> int` | One more than the largest stored `txn_id`, or `1` when the table is empty. |

Commands express a post as `{account: amount}`, an amend as `{account: new - old}`, a delete as
`{account: -amount}`, a transfer as both sides, and a load as the per-account sum of the file.
A balance of exactly zero is allowed. Computation is service-side from listed rows (decision Q-002).

## Database Interface

- `FEATURE-TRANSACTIONS-003` — read: list transactions for balances and the largest id - supplies: `account` - returns: `txn_id`, `account`, `amount`
- `FEATURE-ACCOUNTS-002` — read: confirm an account exists - supplies: `account` - returns: `account`, `name`

# FEATURE: Init

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | The ledger init command resets the ledger to empty and writes nothing to standard output. |
| Depends On | FEATURE-CliFoundation.md, DATABASE.md |
| Provides | ledger init |
| Consumes | transactions.list, transactions.delete, categories.list, categories.delete, accounts.list, accounts.delete |

## Questions

- None.

## Purpose

`ledger init` prepares an empty ledger for loading and use and removes existing ledger records when
rerun. The schema is provisioned by the DATABASE step, so init issues no DDL (decision Q-001).

## Behavior

- Takes no arguments; any argument is a usage error (exit 2).
- Deletes all transactions first, then all categories, then all accounts, through the declared
  repository operations, so foreign keys are never violated.
- Writes nothing to standard output and exits 0. Rerunning leaves an empty ledger.

## Database Interface

- `FEATURE-TRANSACTIONS-003` — read: list transactions to remove - supplies: `account` - returns: `txn_id`
- `FEATURE-TRANSACTIONS-005` — write: delete each transaction - supplies: `txn_id` - returns: `txn_id`
- `FEATURE-CATEGORIES-003` — read: list categories to remove - supplies: `category` - returns: `category`
- `FEATURE-CATEGORIES-004` — write: delete each category - supplies: `category` - returns: `category`
- `FEATURE-ACCOUNTS-003` — read: list accounts to remove - supplies: `account` - returns: `account`
- `FEATURE-ACCOUNTS-005` — write: delete each account - supplies: `account` - returns: `account`

# FEATURE: Count

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | The ledger count command reports the number of rows in each table. |
| Depends On | FEATURE-CliFoundation.md, DATABASE.md |
| Provides | ledger count |
| Consumes | accounts.list, categories.list, transactions.list |

## Questions

- None.

## Purpose

`ledger count` prints a CSV of row counts per table, read from the database at run time.

## Behavior

- Takes no arguments; any argument is a usage error (exit 2).
- Prints the header `table,rows`, then the rows `accounts`, `categories`, `transactions` in that
  order, each with its stored row count, and exits 0.

## Database Interface

- `FEATURE-ACCOUNTS-003` — read: count accounts from the listed rows - supplies: `account` - returns: `account`
- `FEATURE-CATEGORIES-003` — read: count categories from the listed rows - supplies: `category` - returns: `category`
- `FEATURE-TRANSACTIONS-003` — read: count transactions from the listed rows - supplies: `account` - returns: `txn_id`

## Programmatic Acceptance
