# FEATURE: Txn Post

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `ledger txn post` command validates and stores one new transaction and prints its row. |
| Depends On  | FEATURE-BalanceRules.md, FEATURE-CliFoundation.md, DATABASE.md |
| Provides    | ledger txn post |
| Consumes    | transactions.create, transactions.list, accounts.get, categories.get, check_balances |

## Questions

- None.

## Purpose

`ledger txn post <account> <category> <amount> <date> [<memo>]` records one receipt or payment
against an account. The command checks every input and the resulting balance before its first
write, so a rejected post changes nothing.

## Trigger

An operator runs `./ledger txn post` with four or five arguments.

## Sequence

1. Reject a wrong argument count with exit 2 (fewer than four or more than five arguments after `post`).
2. Validate the account code, category code, amount, date, and memo with the shared validators. Any invalid value exits 3.
3. Look up the account with `accounts.get` and the category with `categories.get`. An unknown account or category exits 3.
4. Convert the amount to integer cents. Zero and amounts with more than two decimal places exit 3.
5. List the account's transactions with `transactions.list` and run `check_balances` with the proposed added row. A balance below zero exits 3.
6. List all transactions with `transactions.list`, take the largest `txn_id` plus one (or `1` when none exist) as the new id.
7. Store the row with `transactions.create`, then print the header row and the stored row as CSV. Exit 0.

## Output

```text
txn_id,date,account,category,amount,memo
<id>,<date>,<account>,<category>,<amount with two decimals>,<memo>
```

An omitted memo is stored and printed as an empty field. Failures write one diagnostic line to standard error and nothing to standard output.

## Reads

- `accounts.get`, `categories.get`, `transactions.list`

## Writes

- `transactions.create`, only after every check has passed

## Database Interface

- `FEATURE-TRANSACTIONS-001` — write: create the new transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TRANSACTIONS-003` — read: list transactions to find the largest id and the account balance - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-ACCOUNTS-002` — read: confirm the account exists - supplies: `account` - returns: `account`, `name`
- `FEATURE-CATEGORIES-002` — read: confirm the category exists - supplies: `category` - returns: `category`, `description`

import csv
import io
from cli.testing import cli_runner
from persistence.testing import db_session

acct = "TPOST1"
cat = "TPCAT1"
amount_text = "45.50"
cents = 4550
when = "2026-04-01"
memo = "walk in sale"
with db_session() as db:
    db.accounts.create(account=acct, name="Post Account")
    if db.categories.get(category=cat) is None:
        db.categories.create(category=cat, description="Post Category")
    before_max = max([r.txn_id for r in db.transactions.list()] or [0])

    assert int(data[0]) == before_max + 1
    assert data[1] == when
    assert data[2] == acct
    assert data[3] == cat
    assert data[4] == amount_text
    assert data[5] == memo

    assert stored is not None
    assert stored.amount == cents

# FEATURE: Txn Amend

|-------------|-------|
| Version     | 20261025 V1 |

## Questions

- None.

## Purpose

`ledger txn amend <id> <amount>` corrects the amount of a recorded transaction. Date, account, category, and memo never change.

## Trigger

An operator runs `./ledger txn amend <id> <amount>`.

## Sequence

```text
txn_id,date,account,category,amount,memo
<id>,<date>,<account>,<category>,<new amount with two decimals>,<memo>
```

## Reads

- `transactions.get`, `transactions.list`

## Writes

- `transactions.update` setting only `amount`, after every check has passed

- `FEATURE-TRANSACTIONS-002` — read: retrieve the transaction to amend - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TRANSACTIONS-003` — read: list the account's transactions for the balance check - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TRANSACTIONS-004` — write: change the amount - supplies: `txn_id`, `amount` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

# FEATURE: Transfer

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `ledger transfer` command moves cash between two distinct accounts by storing two matching TRANSFER rows, both or neither. |
| Depends On  | FEATURE-BalanceRules.md, FEATURE-CliFoundation.md, DATABASE.md |
| Provides    | ledger transfer |
| Consumes    | transactions.create, transactions.list, accounts.get, check_balances |

## Questions

- None.

## Purpose

`ledger transfer <from> <to> <amount> <date>` records an equal debit on the source account and credit on the destination account in category `TRANSFER`, so total cash held is unchanged.

## Trigger

An operator runs `./ledger transfer` with four arguments.

## Sequence

1. Reject a wrong argument count with exit 2.
2. Validate both account codes, the amount, and the date. The accounts must differ, the amount must be positive with at most two decimals, and the date must be a real calendar date. Any violation exits 3.
3. Look up both accounts with `accounts.get`. An unknown account exits 3.
4. List the source account's transactions and run `check_balances` with the proposed debit and credit. A balance below zero exits 3.
5. Compute `n` as the largest stored `txn_id` plus one (or `1` when none exist).
6. Store the outgoing row (`-amount`, source account, id `n`, memo `transfer to <to>`) and the incoming row (`+amount`, destination account, id `n+1`, memo `transfer from <from>`), both in category `TRANSFER`, both as one unit of work: both are stored or neither.
7. Print the header row and both rows, outgoing first. Exit 0.

## Output

```text
txn_id,date,account,category,amount,memo
<n>,<date>,<from>,TRANSFER,-<amount>,transfer to <to>
<n+1>,<date>,<to>,TRANSFER,<amount>,transfer from <from>
```

## Reads

- `accounts.get`, `transactions.list`

## Writes

- `transactions.create` twice, only after every check has passed

## Database Interface

- `FEATURE-TRANSACTIONS-001` — write: create the outgoing and incoming rows - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TRANSACTIONS-003` — read: list transactions to find the largest id and the source balance - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-ACCOUNTS-002` — read: confirm each account exists - supplies: `account` - returns: `account`, `name`

    assert balance(dst) == dst_before + 10000
