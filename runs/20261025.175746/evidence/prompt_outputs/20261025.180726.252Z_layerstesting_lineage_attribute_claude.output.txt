<requirement name="cli-executable-contract" stories="cli-foundation">
The product is an executable named `ledger` at the application root.
</requirement>
<requirement name="python-sqlite-stack" stories="python-foundation">
Implement in Python 3.11 or newer over SQLite, through the shipped Python persistence
library. Tests run under pytest.
</requirement>
<requirement name="database-schema" stories="database">
Three tables. Amounts are stored as integer cents and never as floating point.
</requirement>
<requirement name="persistence-library-access" stories="database">
All database access goes through the shipped persistence library and the relational layer
generated from `DATABASE.md`. Application code never opens a database driver directly.
</requirement>
<requirement name="atomic-commands" stories="load-accounts,load-categories,load-transactions,transfer-command,balance-rules">
**A rejected command changes nothing.** A command checks every input and rule before its
first write. A load that rejects row 11 stores none of rows 1 to 10. A transfer stores both of
its rows or neither.
</requirement>
<requirement name="non-negative-balance" stories="balance-rules,load-transactions,txn-post,txn-amend,txn-delete,transfer-command">
**No command leaves an account balance below zero.** An account's balance is the sum of its
transaction amounts. Posting, amending, deleting, transferring, and loading are all subject to
this rule, checked before the command writes anything.
</requirement>
<requirement name="input-validation" stories="cli-foundation">
**Codes** (`account`, `category`) are 1 to 12 characters from `A-Z` and `0-9`.
</requirement>
<requirement name="amount-and-date-format" stories="cli-foundation">
**Amounts** on input match `-?DIGITS[.D[D]]`: at most two decimal places, never zero. On output
an amount is written with exactly two decimal places, a leading `-` when negative, and no
thousands separator: `-12.50`, `0.00`, `5000.00`.
</requirement>
<requirement name="valid-dates" stories="cli-foundation">
**Dates** are real calendar dates written `YYYY-MM-DD`. `2026-02-30` is rejected.
</requirement>
<requirement name="txn-id-assignment" stories="load-transactions,txn-post,transfer-command">
**Transaction ids.** A loaded transaction keeps the `txn_id` from its file. A posted
transaction receives one more than the largest `txn_id` present, or `1` in an empty table. A
transfer's outgoing row takes that id and its incoming row the next.
</requirement>
<requirement name="csv-output-and-exit-codes" stories="cli-foundation">
Every successful command except `init` writes CSV to standard output: one header row, then data
rows, comma-separated, no quoting, no trailing spaces, `\n` line endings. `init` writes nothing.
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="init-command" stories="init-command">
`ledger init` | Prepares an empty ledger for loading and use; removes existing ledger records when rerun. Nothing written.
</requirement>
<requirement name="count-command" stories="count-command">
`ledger count` | `table,rows`, then `accounts`, `categories`, `transactions` rows in that order.
</requirement>
<requirement name="load-command" stories="load-accounts,load-categories,load-transactions">
`ledger load <table> <csv>` | Loads `accounts`, `categories`, or `transactions` from a file whose header matches the table's columns in the order above. Writes `table,loaded` and `<table>,<rows>`.
</requirement>
<requirement name="account-add" stories="account-add">
`ledger account add <code> <name>` | The new account row.
</requirement>
<requirement name="account-get" stories="account-get">
`ledger account get <code>` | The account row.
</requirement>
<requirement name="account-rename" stories="account-rename">
`ledger account rename <code> <name>` | The updated account row.
</requirement>
<requirement name="account-delete" stories="account-delete">
`ledger account delete <code>` | `deleted` and the code. Refused while the account has transactions.
</requirement>
<requirement name="txn-post" stories="txn-post">
`ledger txn post <account> <category> <amount> <date> [<memo>]` | The new transaction row.
</requirement>
<requirement name="txn-get" stories="txn-get">
`ledger txn get <id>` | The transaction row.
</requirement>
<requirement name="txn-amend" stories="txn-amend">
`ledger txn amend <id> <amount>` | The updated transaction row. Only the amount changes.
</requirement>
<requirement name="txn-delete" stories="txn-delete">
`ledger txn delete <id>` | `deleted` and the id.
</requirement>
<requirement name="transfer" stories="transfer-command">
`ledger transfer <from> <to> <amount> <date>` | Two transaction rows in category `TRANSFER`: `-amount` on `<from>` with memo `transfer to <to>`, then `+amount` on `<to>` with memo `transfer from <from>`. The amount is positive and the accounts differ.
</requirement>
<requirement name="report-balances" stories="report-balances,balance-rules">
`ledger report balances` | `account,name,transactions,balance` per account ordered by code, then `TOTAL,,<count>,<sum>`.
</requirement>
<requirement name="report-categories" stories="report-categories">
`ledger report categories` | `category,description,transactions,inflow,outflow,net` per category ordered by code, including categories with no transactions, then `TOTAL,,<count>,<inflow>,<outflow>,<net>`.
</requirement>
<requirement name="report-monthly" stories="report-monthly">
`ledger report monthly` | `month,transactions,inflow,outflow,net` per `YYYY-MM` that has transactions, ascending, then `TOTAL,<count>,<inflow>,<outflow>,<net>`.
</requirement>
<requirement name="exit-codes" stories="cli-foundation">
| `0` | Success. |
| `1` | Operational failure: database unreachable, tables missing, file unreadable. |
| `2` | Usage error: unknown command, unknown table or report, wrong argument count. |
| `3` | Rejected: invalid code, name, amount, date, or file row; duplicate key; unknown account or category; account in use; any change that would leave a negative balance. |
| `4` | Not found: `account get/rename/delete` of an absent account, `txn get/amend/delete` of an absent id. |
</requirement>
<requirement name="automated-test-suite" stories="python-foundation">
The completed application provides a POSIX-compatible `bin/test.sh` that runs its own automated
test suite from the application root and exits zero only when every test passes.
</requirement>
<requirement name="scoring-harness" stories="release-verification">
The harness creates a fresh database, runs `./ledger init`, loads the seed files, and then runs a
fixed sequence of 43 checks.
</requirement>
