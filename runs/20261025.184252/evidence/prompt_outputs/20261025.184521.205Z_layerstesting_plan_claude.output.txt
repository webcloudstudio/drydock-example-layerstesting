  uv.lock, a .venv created by uv venv, and a POSIX sh bin/test.sh that activates the environment,

provides:     accounts.*, categories.*, transactions.*
depends:      foundation
acceptance:   yes
instructions: |
  Author DATABASE.md and let Drydock generate the persistence package. Write no persistence code.

  Tables: accounts(account PK, name), categories(category PK, description), transactions(txn_id
  INTEGER PK, date, account REFERENCES accounts, category REFERENCES categories, amount INTEGER
  cents, memo). Declare one access pattern per repository operation any story needs: create, get,
  update, delete, list for each table; per-account transaction count and balance sums; the maximum
  txn_id; per-account list of transactions; and delete-all operations for each table so init can
  empty the ledger.

## story ledger-rules
summary:      Provide shared validation and money helpers for codes, names, memos, amounts, dates, and balance projection.
type:         service
kind:         capability
phase:        1
implements:   FEATURE-LedgerRules.md
stack:        python.md
provides:     ledger_rules.parse_amount, ledger_rules.format_amount, ledger_rules.validate_date, ledger_rules.validate_code, ledger_rules.validate_text, ledger_rules.check_balances
depends:      cli-foundation
acceptance:   yes
instructions: |
  Implement pure, driver-free helpers. Codes are 1-12 chars of A-Z0-9. Names and descriptions are
  1-40 chars; memos 0-60 chars; none contain a comma or newline. Amounts on input match
  -?DIGITS[.D[D]], never zero, parsed with integer arithmetic into cents. Output amounts have
  exactly two decimals, a leading - when negative, no thousands separator. Dates are real calendar
  dates YYYY-MM-DD. Violations raise the rejected error (exit 3).

  Provide a balance projection helper that applies a proposed set of added, changed, and removed
  transactions to current per-account balances and rejects when any resulting balance is below zero.
