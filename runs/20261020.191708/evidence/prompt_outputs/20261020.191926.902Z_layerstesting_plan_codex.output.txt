# FEATURE: Account Transfers

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Execute atomic two-row transfers between ledger accounts. |
| Depends On  | FEATURE-Balance-Invariant.md, FEATURE-Transaction-Management.md |
| Provides    | transfer |
| Consumes    | command dispatch, transactions.create, accounts.get, categories.get, prospective balance validation |

## Questions

- None.

## Purpose

A transfer moves a positive amount from one existing account to another by creating two consecutive transactions in category `TRANSFER`.

## Workflow

1. Validate both account codes, account existence, distinctness, positive amount, date, and the `TRANSFER` category.
2. Calculate both prospective balances before writing.
3. Create the outgoing row, then the incoming row, in one transaction.
4. Emit both transaction rows in identifier order.
5. Roll back completely on any rejection.

The outgoing memo is `transfer to <destination>` and the incoming memo is `transfer from <source>`.

## Programmatic Acceptance

=== AC transfers-success ===
Intent: A valid transfer creates two persisted transaction rows and succeeds.
from cli.testing import cli_runner
from persistence.testing import db_session
import csv
import io
import os
import tempfile

with tempfile.TemporaryDirectory() as directory:
    dsn = os.path.join(directory, "ledger.db")
    os.environ["DATABASE_URL"] = dsn

    assert cli_runner("init")[0] == 0
    assert cli_runner("account", "add", "FROM", "Source")[0] == 0
    assert cli_runner("account", "add", "TO", "Destination")[0] == 0
    assert cli_runner("category", "add", "TRANSFER", "Internal transfer")[0] == 0
    assert cli_runner("txn", "post", "FROM", "TRANSFER", "100.00", "2026-04-01")[0] == 0

    code, output, _ = cli_runner("transfer", "FROM", "TO", "25.00", "2026-04-02")
    assert code == 0
    rows = list(csv.reader(io.StringIO(output)))
    assert len(rows) == 3

    with db_session(dsn) as db:
        transactions = db.transactions.list()
        assert len(transactions) == 3
        assert transactions[-2].amount == -2500
        assert transactions[-1].amount == 2500
        assert transactions[-2].account == "FROM"
        assert transactions[-1].account == "TO"

# FEATURE: Balance Report

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Report account balances and transaction counts from persisted ledger data. |
| Depends On  | FEATURE-Transaction-Management.md |
| Provides    | report balances |
| Consumes    | accounts.list, transactions.list |

## Questions

- None.

## Purpose

The balances report lists every account ordered by account code, with its transaction count and integer-cent balance, followed by a computed total row.

# FEATURE: Project Test Suite

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provide the automated project test runner and comprehensive ledger test suite. |
| Depends On  | FEATURE-CLI-Validation.md, FEATURE-Account-Management.md, FEATURE-Transaction-Management.md, FEATURE-Transfers.md, FEATURE-Report-Balances.md, FEATURE-Report-Categories.md, FEATURE-Report-Monthly.md |
| Provides    | bin/test.sh, pytest suite |
| Consumes    | ledger command surface |

## Questions

- None.

## Purpose

Provide a POSIX-compatible `bin/test.sh` that runs the complete pytest suite from the application root and returns success only when every project test passes.

## Test Scope

The suite covers:

- command dispatch and usage errors;
- database initialization and configuration;
- account and category loading;
- transaction loading and atomic rejection;
- account and transaction CRUD;
- balance invariants and atomic transfers;
- balance, category, and monthly reports;
- validation boundaries and all documented exit codes.

The suite uses temporary databases and does not modify supplied sources.
