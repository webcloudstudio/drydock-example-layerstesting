# FEATURE: Account and Category Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Atomically validate and load account and category CSV files. |
| Depends On  | ARCHITECTURE.md, FEATURE-CLI-Dispatcher.md, FEATURE-CLI-Validation.md, FEATURE-Database-Configuration.md |
| Provides    | load accounts, load categories |
| Consumes    | command dispatch, database configuration, accounts.create, categories.create |

## Questions

- None.

## Purpose

`ledger load accounts <csv>` and `ledger load categories <csv>` import validated master data. Files must be readable, have the exact table header, contain valid codes and text, and contain no duplicate keys. Validation completes before any row is written.

## Workflow

1. Resolve the configured database.
2. Read and validate the complete file.
3. Reject malformed rows, duplicate keys, or conflicts with existing rows without changing state.
4. Insert all rows atomically.
5. Emit the loaded table and count.

## Database Interface

- `FEATURE-DB-002` — read-write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-DB-003` — read-write: create a category - supplies: `category`, `description` - returns: `category`, `description`

## Programmatic Acceptance

=== AC account-category-load-roundtrip ===
Intent: Valid account and category files are loaded and their persisted rows are readable.
import csv
import os
import tempfile
from pathlib import Path
from cli.testing import cli_runner

with tempfile.TemporaryDirectory() as d:
    os.environ["DATABASE_PATH"] = str(Path(d) / "ledger.db")
    assert cli_runner("init")[0] == 0
    accounts = Path(d) / "accounts.csv"
    categories = Path(d) / "categories.csv"
    account_rows = [["account", "name"], ["A1", "Drawer"]]
    category_rows = [["category", "description"], ["C1", "Sales"]]
    accounts.write_text("\n".join(",".join(r) for r in account_rows) + "\n")
    categories.write_text("\n".join(",".join(r) for r in category_rows) + "\n")
    assert cli_runner("load", "accounts", str(accounts))[0] == 0
    assert cli_runner("load", "categories", str(categories))[0] == 0
    code, out, _ = cli_runner("account", "get", "A1")
    assert code == 0
    assert list(csv.reader(out.splitlines()))[1][0:2] == account_rows[1]
=== END AC account-category-load-roundtrip ===

# FEATURE: Transaction Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Atomically validate and load transaction CSV files. |
| Depends On  | FEATURE-Account-Category-Loading.md, FEATURE-Database-Configuration.md |
| Provides    | load transactions |
| Consumes    | command dispatch, database configuration, transactions.create, accounts.get, categories.get |

## Questions

- None.

## Purpose

`ledger load transactions <csv>` validates every transaction before writing any row, including headers, fields, references, duplicate identifiers, dates, amounts, and prospective account balances.

## Workflow

The complete file is parsed into integer-cent transactions, validated against existing accounts and categories and against duplicate IDs, then checked for non-negative balances. Only a fully valid batch is inserted in one transaction.

## Database Interface

- `FEATURE-DB-004` — read-write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-DB-005` — read: retrieve account balance - supplies: `account` - returns: `account`, `transactions`, `balance`
- `FEATURE-DB-006` — read: retrieve transaction - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

# FEATURE: Transaction Management

| Field       | Value |

- None.

## Purpose

Manage transaction rows with generated identifiers, exact cent formatting, validated dates and amounts, and atomic balance checks.

## Operations

- `txn post` assigns one greater than the largest existing identifier.

# FEATURE: Balance Invariant

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Enforce non-negative account balances before every transaction mutation. |
| Depends On  | FEATURE-Transaction-Management.md, FEATURE-Transaction-Loading.md |
| Provides    | prospective balance validation |
| Consumes    | transactions.create, transactions.update, transactions.delete |

## Questions

- None.

## Purpose

Every posting, amendment, deletion, transfer, and transaction load computes the affected account balances before writing. Any negative result rejects the complete command with no table changes.

## Invariant

For each account, the sum of all persisted transaction amounts must be greater than or equal to zero after every successful command.

## Database Interface

- `FEATURE-DB-005` — read: retrieve account balance - supplies: `account` - returns: `account`, `balance`
- `FEATURE-DB-006` — read-write: create, update, or delete transactions - supplies: `txn_id`, `amount` - returns: transaction fields
