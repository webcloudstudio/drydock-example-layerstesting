# FEATURE: Account Add

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger account add` and the shared account row builder used by every account command. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliFoundation.md, FEATURE-CsvOutput.md, FEATURE-TextValidation.md, FEATURE-BalanceGuard.md, FEATURE-Init.md, FEATURE-StoreAccess.md |
| Provides | ledger account add, ledger_app.accounts.account_row |
| Consumes | ledger_app.validation.code, ledger_app.validation.name, ledger_app.balances.balance_cents, ledger_app.store.open_store, cli.output.write_table, cli.errors |

## Questions

- None.

## Purpose

`ledger account add <code> <name>` stores a new account and writes its row. It also owns
`ledger_app.accounts.account_row(db, code)`, which the get, rename, and delete commands reuse.

## Interface

| Command | Arguments | Exit codes |
|---------|-----------|------------|
| `ledger account add` | `<code> <name>` (exactly two) | 0 stored; 2 wrong argument count; 3 invalid code or name, or duplicate code; 1 operational failure |

- Registered through `cli.registry.register` with a usage line and exact arity of two arguments.
- The command validates code (`validation.code`) and name (`validation.name`) first, then checks the
  code is not already stored, then creates the account. Nothing is written when any check fails.
- Standard output on success is CSV: header `account,name,transactions,balance`, then one row. A new
  account has `0` transactions and balance `0.00`.
- The stdout write is the handler's final act, through `cli.output.write_table`.
- Failures write nothing to stdout and one diagnostic line to stderr.

## Shared row builder

`account_row(db, code)` reads the stored account and its stored transactions through the database and
returns a list of four strings `[account, name, transactions, balance]`, or `None` when the account is
absent. `transactions` is the count of the account's stored transactions. `balance` is the sum of their
integer-cent amounts formatted with `cli.output.format_cents`. No floating point is used.

## Database Interface

- `FEATURE-ACCOUNTS-001` — read: check whether the account code is already stored - supplies: `account` - returns: `account`, `name`
- `FEATURE-ACCOUNTS-003` — write: create the account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-TRANSACTIONS-002` — read: list the account's transactions for count and balance - supplies: `account` - returns: `txn_id`, `amount`

# FEATURE: Transaction Post

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger txn post` plus the shared transaction row formatter and next-id rule. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliFoundation.md, FEATURE-CsvOutput.md, FEATURE-TextValidation.md, FEATURE-AmountValidation.md, FEATURE-DateValidation.md, FEATURE-BalanceGuard.md, FEATURE-Init.md, FEATURE-StoreAccess.md |
| Provides | ledger txn post, ledger_app.transactions.txn_row, ledger_app.transactions.next_txn_id |
| Consumes | ledger_app.validation.code, ledger_app.validation.amount_cents, ledger_app.validation.date, ledger_app.validation.memo, ledger_app.balances.ensure_non_negative, ledger_app.store.open_store, cli.output.write_table, cli.output.format_cents, cli.errors |

## Questions

- None.

## Purpose

`ledger txn post <account> <category> <amount> <date> [<memo>]` validates and stores one transaction
and writes the stored row. The story also owns `txn_row` and `next_txn_id`, which get, amend, delete,
and transfer reuse.

## Interface

| Command | Arguments | Exit codes |
|---------|-----------|------------|
| `ledger txn post` | `<account> <category> <amount> <date>` and an optional `<memo>` (four or five) | 0 stored; 2 wrong argument count; 3 rejected; 1 operational failure |

Checks, all before the first write:

1. Account and category codes are valid (`validation.code`); the amount parses to non-zero integer
   cents (`validation.amount_cents`); the date is a real `YYYY-MM-DD` date (`validation.date`); the
   memo (empty when omitted) is valid (`validation.memo`).
2. The account and the category exist, otherwise exit 3.
3. `ensure_non_negative` accepts the account's net change, otherwise exit 3.

The new id is one more than the largest stored `txn_id`, or `1` when none is stored. On success the
output is header `txn_id,date,account,category,amount,memo` and the stored row. Failures write nothing
to stdout, store nothing, and write one diagnostic line to stderr.

## Shared helpers

- `next_txn_id(db)` returns the largest stored `txn_id` plus one, or `1` in an empty table, computed
  from `transactions.list`.
- `txn_row(t)` takes a stored transaction (mapping or attribute row) and returns a list of six strings
  `[txn_id, date, account, category, amount, memo]`, with the amount formatted by `format_cents`.

## Database Interface

- `FEATURE-ACCOUNTS-001` — read: confirm the account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORIES-001` — read: confirm the category exists - supplies: `category` - returns: `category`
- `FEATURE-TRANSACTIONS-002` — read: list transactions for the next id and the balance - supplies: `account` - returns: `txn_id`, `amount`
- `FEATURE-TRANSACTIONS-003` — write: store the transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
