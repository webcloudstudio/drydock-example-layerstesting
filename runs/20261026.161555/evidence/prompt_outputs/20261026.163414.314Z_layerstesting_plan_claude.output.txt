# FEATURE: Report Balances

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The `ledger report balances` command lists each account with its transaction count and balance, then a TOTAL row. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-BalanceGuard.md, FEATURE-Init.md, FEATURE-CsvOutput.md |
| Provides | ledger report balances |
| Consumes | ledger_app.balances.balance_cents, cli.output.write_table, ledger_app.store.open_store |

## Questions

- None.

## Purpose

`ledger report balances` computes, from stored transactions, one row per account ordered by account
code, followed by a TOTAL row. Every value is aggregated in integer cents in the service layer from list
results; no value is hardcoded.

## Trigger

`./ledger report balances` takes no further arguments. A wrong argument count is a usage error (exit 2).

## Sequence

1. Open the store through `open_store`.
2. List accounts (ordered by code) and list transactions.
3. For each account, count its transactions and sum their amounts in integer cents.
4. Write the header `account,name,transactions,balance`, one row per account, then
   `TOTAL,,<count>,<sum>` where count is the number of transactions across all accounts and sum is
   the sum of all balances. Amounts are formatted with two decimals.
5. With no accounts the output is the header and `TOTAL,,0,0.00`.

## Database Interface

- `FEATURE-ACCOUNTS-002` — read: list accounts by code - supplies: none - returns: `account`, `name`
- `FEATURE-TRANSACTIONS-002` — read: list transactions - supplies: `account` - returns: `txn_id`, `account`, `amount`

## Reads

Accounts and transactions. Writes: none.

## Programmatic Acceptance

a1, a2, cat = "ZZRB1", "ZZRB2", "ZZRBC"

    for acct, amts in plan.items():
        for c in amts:
            tid += 1
            db.transactions.create(

    by = {r[0]: r for r in rows[1:-1]}
    for acct, amts in plan.items():
        assert by[acct][2] == str(len(amts))
        assert by[acct][3] == fmt(sum(amts))

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The `ledger report categories` command lists every category with transaction count, inflow, outflow, and net, then a TOTAL row. |

| Provides | ledger report categories |
| Consumes | cli.output.write_table, ledger_app.store.open_store |

## Questions

- None.

## Purpose

`ledger report categories` totals stored transactions by category, including categories that have no
transactions, and ends with a TOTAL row. Aggregation is done in integer cents from list results.

## Trigger

`./ledger report categories` takes no further arguments; a wrong argument count exits 2.

## Sequence

1. Open the store through `open_store`.
2. List categories (ordered by code) and list transactions.
3. For each category count its transactions; `inflow` sums positive amounts; `outflow` sums the

   `inflow - outflow`.
4. Write the header `category,description,transactions,inflow,outflow,net`, a row for every category,
   then `TOTAL,,<count>,<inflow>,<outflow>,<net>`.
5. With no transactions, every category shows 0 transactions and 0.00 for inflow, outflow, and net,
   followed by the zero TOTAL row.

- `FEATURE-CATEGORIES-002` — read: list categories by code - supplies: none - returns: `category`, `description`

Categories and transactions. Writes: none.

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |

| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-Init.md, FEATURE-CsvOutput.md, FEATURE-StoreAccess.md |
| Provides | ledger report monthly |
| Consumes | cli.output.write_table, ledger_app.store.open_store |

## Questions

- None.

## Purpose

`ledger report monthly` groups stored transactions by the `YYYY-MM` prefix of their date and reports
each month in ascending order with a TOTAL row. Aggregation is in integer cents.

## Trigger

`./ledger report monthly` takes no further arguments; a wrong argument count exits 2.

## Sequence

1. Open the store through `open_store`.
2. List transactions and group by the first seven characters of `date`.
3. For each month count transactions, sum positive amounts as `inflow`, sum absolute values of
   negative amounts as `outflow`, and compute `net = inflow - outflow`.
4. Write the header `month,transactions,inflow,outflow,net`, one row per month that has
   transactions in ascending order, then `TOTAL,<count>,<inflow>,<outflow>,<net>`.
5. With no transactions, write only the header and the zero TOTAL row.

## Database Interface

- `FEATURE-TRANSACTIONS-002` — read: list transactions - supplies: `account` - returns: `txn_id`, `date`, `amount`

## Reads

Transactions. Writes: none.

# FEATURE: Atomic Commands

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Assembly of the member write commands proving that every rejected command checks everything first and changes nothing. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, FEATURE-LoadTransactions.md, FEATURE-AccountAdd.md, FEATURE-AccountRename.md, FEATURE-AccountDelete.md, FEATURE-TxnPost.md, FEATURE-TxnAmend.md, FEATURE-TxnDelete.md, FEATURE-TransferRules.md, FEATURE-BalanceGuard.md |
| Provides | ledger atomic-command guarantee |
| Consumes | ledger load, ledger account add, ledger account rename, ledger account delete, ledger txn post, ledger txn amend, ledger txn delete, ledger transfer |

## Questions

- None.

## Purpose

Every write command validates all inputs and rules before its first write. This assembly story drives
rejected invocations of each write command through the built CLI and compares a full snapshot of
accounts, categories, and transactions before and after. Gaps found are fixed in the member stories'
code. Writes within one command share the persistence library's transaction scope where it offers
one, so two concurrent commands each complete in full or change nothing; the concurrent case is
verified by the project's own pytest suite against a temporary database.

## Database Interface

- `FEATURE-ACCOUNTS-002` — read: list accounts - supplies: none - returns: `account`, `name`
- `FEATURE-CATEGORIES-002` — read: list categories - supplies: none - returns: `category`, `description`
- `FEATURE-TRANSACTIONS-002` — read: list transactions - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

=== AC atomic-load-transactions ===

import csv
import dataclasses
import os
import tempfile

from cli.testing import cli_runner
from persistence.testing import db_session

def tup(r):
    if isinstance(r, dict):
        return tuple(sorted(r.items()))
    return dataclasses.astuple(r)

def snap(db):
    return (
        [tup(r) for r in db.accounts.list()],
        [tup(r) for r in db.categories.list()],
        [tup(r) for r in db.transactions.list()],
    )

def write(path, rows):
    with open(path, "w", newline="") as fh:
        w = csv.writer(fh, lineterminator="\n")
        w.writerow(["txn_id", "date", "account", "category", "amount", "memo"])
        w.writerows(rows)

acct, cat = "ZZAT1", "ZZATC"
with db_session() as db:

=== AC atomic-transfer ===
Intent: Rejected transfers store neither leg, while a valid transfer stores both.

import dataclasses

from cli.testing import cli_runner
from persistence.testing import db_session

def tup(r):
    if isinstance(r, dict):
        return tuple(sorted(r.items()))
    return dataclasses.astuple(r)

def snap(db):
    return (
        [tup(r) for r in db.accounts.list()],
        [tup(r) for r in db.categories.list()],
        [tup(r) for r in db.transactions.list()],
    )

src, dst, cat = "ZZAT4", "ZZAT5", "ZZATC4"
with db_session() as db:
    db.accounts.create(account=src, name="Transfer Source")
    db.accounts.create(account=dst, name="Transfer Dest")
    db.categories.create(category=cat, description="Atomic category four")
    if db.categories.get(category="TRANSFER") is None:
        db.categories.create(category="TRANSFER", description="Internal transfer")
    db.transactions.create(
        txn_id=900004301, date="2026-06-08", account=src, category=cat, amount=5000, memo=""
    )
    before = snap(db)
    cases = [
        ("transfer", src, dst, "500.00", "2026-06-09"),
        ("transfer", src, src, "1.00", "2026-06-09"),
        ("transfer", src, dst, "0.00", "2026-06-09"),
        ("transfer", src, dst, "-1.00", "2026-06-09"),
        ("transfer", src, "ZZNONE", "1.00", "2026-06-09"),
    ]
    for args in cases:
        code, out, err = cli_runner(*args)

        assert code == 3

unknown report, or wrong argument count exits 2 with exactly one stderr line showing the expected

command and sub-verb has a usage line and arity limits. Successful output is one header and
comma-separated unquoted rows with `\n` endings and two-decimal amounts. Failures write nothing to
stdout.
