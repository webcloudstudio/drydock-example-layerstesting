# FEATURE: Init

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The `ledger init` command prepares the store and removes every existing ledger row. |
| Depends On | DATABASE.md, FEATURE-StoreAccess.md, FEATURE-CsvOutput.md, FEATURE-CliFoundation.md |
| Provides | ledger init |
| Consumes | ledger_app.store.open_store |

## Questions

- None.

## Purpose

`ledger init` is the only command that prepares storage. It leaves an empty, usable ledger so a load can follow, and it is how the grader returns to a known state.

## Behavior

- Takes no arguments. Any argument is a usage error, exit 2.
- When the database location is the default `data/app.db`, creates its parent directory if missing.
- Opens the store through `ledger_app.store.open_store`, which provisions the declared tables idempotently.
- Deletes all transactions first, then categories, then accounts, so references never dangle.
- Writes nothing to standard output and exits 0. A rerun on an empty or populated ledger behaves the same.
- If the store cannot be opened, exits 1 with one stderr line and no stdout.

## Database Interface

- `FEATURE-TRANSACTIONS-006` — write: remove every transaction - supplies: `floor_id`
- `FEATURE-CATEGORIES-004` — write: remove every category - supplies: `floor_code`
- `FEATURE-ACCOUNTS-006` — write: remove every account - supplies: `floor_code`

- None.

## Purpose

Lets the operator and the grader confirm what the ledger holds across separate invocations.

## Behavior

# FEATURE: Load Accounts

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The `ledger load accounts` command stores accounts from a CSV file all-or-nothing and defines the shared strict CSV reader. |
| Depends On | DATABASE.md, FEATURE-Init.md, FEATURE-TextValidation.md, FEATURE-CsvOutput.md, FEATURE-StoreAccess.md |
| Provides | ledger load accounts, ledger_app.csv_input.read_rows |
| Consumes | ledger_app.validation.code, ledger_app.validation.name, cli.output.write_table |

## Questions

- None.

## Purpose

Bulk-loads accounts from a file whose header is `account,name`. It also delivers `read_rows`, the strict reader every load command uses.

## Behavior

- Arguments: `<csv>`. A wrong argument count is a usage error, exit 2.
- `read_rows(path, header)` parses with the `csv` module. The header must equal the expected columns exactly. A header mismatch, an empty file, a blank line, or a row whose field count differs from the header is Rejected, exit 3. An unreadable or missing file is an operational failure, exit 1.
- Every row's code and name are validated with the shared text validators. A name containing a comma (only possible through quoting) is rejected.
- Duplicate codes inside the file, and codes already stored, are Rejected, exit 3.
- Only after every check passes are all rows stored. A rejected load stores none of its rows.
- Writes `table,loaded` then `accounts,<N>`, where N is the number of rows stored.

## Database Interface

- `FEATURE-ACCOUNTS-001` — read: look up a code to detect an existing account - supplies: `account` - returns: `account`
- `FEATURE-ACCOUNTS-003` — write: store one account per file row - supplies: `account`, `name` - returns: `account`, `name`

## Programmatic Acceptance

# FEATURE: Load Transactions

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The `ledger load transactions` command validates a whole CSV file and stores every transaction or none. |
| Depends On | DATABASE.md, FEATURE-LoadCategories.md, FEATURE-AmountValidation.md, FEATURE-DateValidation.md, FEATURE-TextValidation.md, FEATURE-BalanceGuard.md |
| Provides | ledger load transactions |
| Consumes | ledger_app.csv_input.read_rows, ledger_app.validation.amount_cents, ledger_app.validation.date, ledger_app.balances.ensure_non_negative |

## Questions

- None.

## Purpose

Bulk-loads transactions from a file whose header is `txn_id,date,account,category,amount,memo`, keeping each `txn_id` from the file.

## Behavior

- Arguments: `<csv>`; a wrong argument count is a usage error, exit 2. Malformed files follow `read_rows` (exit 3 for header, blank line, field count; exit 1 unreadable).
- Each `txn_id` must be a positive integer, unique within the file and absent from storage; otherwise Rejected, exit 3.
- Each amount is parsed to integer cents (never zero, at most two decimals), each date must be a real `YYYY-MM-DD` date, and each memo is validated (0 to 60 characters, no comma or newline).
- Each account and category must already be stored (exit 3 otherwise).
- The command computes each account's net change over the whole file, adds its stored balance, and Rejects (exit 3) if any final balance is below zero. The check is on the final balance, not per row.
- Only after every check passes are all rows stored. A rejected load stores none of its rows.
- Writes `table,loaded` then `transactions,<N>`.

## Database Interface

- `FEATURE-TRANSACTIONS-001` — read: detect an id already stored - supplies: `txn_id` - returns: `txn_id`
- `FEATURE-TRANSACTIONS-002` — read: list stored transactions to compute balances - returns: `account`, `amount`
- `FEATURE-TRANSACTIONS-003` — write: store one transaction per file row - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`
- `FEATURE-ACCOUNTS-001` — read: confirm each account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORIES-001` — read: confirm each category exists - supplies: `category` - returns: `category`
