## story cli-foundation
summary:      Provide the cli package, command registry, exit-code mapping, and the ledger executable.
type:         foundational
kind:         capability
phase:        1
implements:   FEATURE-CliFoundation.md
stack:        python.md, cli.md
provides:     cli.main, cli.testing.cli_runner, cli.errors, cli.registry.register
acceptance:   yes
depends:      foundation, database
instructions: |
  Implement `cli.main(argv) -> int`, `cli/__main__.py`, `cli/testing.py` (cli_runner), and an
  executable POSIX-sh file `ledger` at the application root that runs the project interpreter
  with `-m cli`.
  `cli.errors` defines UsageError (exit 2), Rejected (exit 3), NotFound (exit 4) and
  OperationalError (exit 1). main maps each to its exit code and writes exactly one diagnostic
  line to stderr and nothing to stdout; any other unexpected exception maps to exit 1.
  `cli.registry.register(path, handler, usage, min_args, max_args)` records a command; main
  matches the longest registered path prefix, checks arity, and raises UsageError whose message is
  the usage line of the failing command (for an unknown command, a one-line list of commands).
  Command modules are auto-discovered from the `cli.commands` package with pkgutil, so a command
  story only adds a module there.
