## Planning Instructions

### Delivery Shape

This is a command-line ledger. Inputs are `ledger` command arguments, CSV files named on the
`load` command, and the `DATABASE_URL` or `DATABASE_PATH` setting. Outputs are CSV on standard
output for successful commands, one diagnostic line on standard error for failures, and exit codes
0 through 4.

Execution flow: `init`, then `load accounts`, `load categories`, and `load transactions`, then any
mix of account, transaction, transfer, count, and report commands. Every write command validates all
of its inputs and balance rules before its first write.

Persistence is three relational tables (accounts, categories, transactions) accessed only through the
shipped persistence library. SQLite is the implemented and verified engine. All persisting commands are
CLI consumers, so their repository-call contracts use consumer sensitivity `data`. Plan records these
contracts in DATABASE.md with ids under the domains ACCOUNTS, CATEGORIES, TRANSACTIONS, and REPORTS.

implementation story, and runs `sh sources/run.sh` unfiltered. Its exit status is the complete-suite proof.

Sea Trials are separate from story tests. st-001 is the grader proof. st-004 through st-011 are
deterministic proofs. st-012 through st-015 are guardrails verified by reviewed evidence.
