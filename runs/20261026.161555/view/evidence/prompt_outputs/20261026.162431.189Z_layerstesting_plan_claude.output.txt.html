# ARCHITECTURE: LayersTesting

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Modules, boundaries, and technical decisions for the LayersTesting command-line cash ledger. |
| Provides | cli, ledger_app |

## Questions

- None.

## Purpose

`ledger` is a command-line cash ledger for a small shop. It keeps accounts, categories, and cash
transactions in a relational database reached only through the shipped persistence library. Every
command either completes in full or changes nothing, no command leaves an account balance below
zero, and three reports (balances, category totals, monthly totals) are computed from stored rows.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|---|---|
| Python 3.11 or newer | Implementation language for the `cli` and `ledger_app` packages. |
| SQLite | The database, reached through the generated `persistence` package. The DSN selects the engine. |
| CLI | The `ledger` executable at the application root and the `cli` package behind it. |
| pytest | Test runner behind `bin/test.sh`. |
| POSIX sh | `ledger` launcher, `bin/test.sh`, and the supplied grader. |

## Project Layout

| Path | Owner | Content |
|---|---|---|
| `pyproject.toml`, `uv.lock` | foundation | Dependency manifest (`requires-python >= 3.11`, pytest, psycopg[binary]) and committed lock. |
| `.venv/`, `bin/` | foundation | Environment created by `uv venv` and the launchers that activate it. |
| `ledger` | cli-foundation | Executable POSIX sh launcher at the application root. |
| `cli/` | cli-foundation | Entry point, registry, errors, output, and `cli/commands/` modules. |
| `ledger_app/` | foundation and services | Configuration, store access, validation, balances, and services. |
| `persistence/` | Drydock | Copied and generated; never written by hand. |
| `tests/` | every story | pytest suite with `conftest.py`. |

The service package is `ledger_app` because a directory named `ledger` cannot coexist with the
executable `ledger` at the application root.

## Modules

| Module | Responsibility |
|---|---|
| `cli.main` | Parse argv, dispatch through the registry, map errors to exit codes, write one stderr line on failure. |
| `cli.registry` | Command table: path, handler, usage line, argument arity. |
| `cli.errors` | `UsageError` (2), `Rejected` (3), `NotFound` (4), `OperationalError` (1). |
| `cli.output` | CSV writing and integer-cent formatting. |
| `cli.commands.*` | One module per command family; each registers its commands on import. |
| `ledger_app.config` | Database location resolution. |
| `ledger_app.store` | Opens the store through `persistence.open_database`; maps failures to exit 1. |
| `ledger_app.validation` | Pure validators for codes, names, memos, amounts, and dates. |
| `ledger_app.csv_input` | Strict CSV reader for `load`. |
| `ledger_app.balances` | Balance computation and the non-negative guard. |
| `ledger_app.accounts`, `ledger_app.transactions`, `ledger_app.transfers` | Row builders and write services. |

## Module Ownership

| Boundary | Owning module | Allowed low-level access |
|---|---|---|
| Persistence | `persistence/` (generated) | The only code that imports a database driver. |
| Store access | `ledger_app.store` | Calls `persistence.open_database`; nothing else opens a database. |
| Configuration | `ledger_app.config` | Reads `DATABASE_URL`, `DATABASE_PATH`, and the default `data/app.db`. |
| File store | none | The only files read are CSV files named on the `load` command. |
| External services | none | No network access. |

## Technical Decisions

- Services call `db.<table>.<operation>(...)`; SQL, sessions, and table names never cross that boundary.
- Money is integer cents at every layer; floating point is never used for money.
- Repository operations have no aggregates, so reports are aggregated in services from list results.
- Every command validates all inputs and rules before its first write.
- A handler writes standard output only as its final act, so a failing command never leaks stdout.
- Failures write one diagnostic line to standard error; standard error is never compared.
- SQLite is the implemented and verified engine; PostgreSQL DSNs are classified and routed to the persistence library.

# FEATURE: CLI Foundation

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The cli package, command registry, exit-code mapping, and the ledger executable. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | cli.main, cli.testing.cli_runner, cli.errors, cli.registry.register |

## Questions

- None.

## Purpose

Every command story adds a module under `cli.commands` and registers its commands. This story
fixes the shared contract they all build on: dispatch, usage errors, and exit codes.

## Interface

- `cli.main(argv: list[str] | None = None) -> int` uses `sys.argv[1:]` when `argv` is `None`, never calls `sys.exit`, and returns the exit code.
- `cli/__main__.py` runs `sys.exit(main())`, so `python -m cli` is the process entry point.
- `cli.testing.cli_runner(*args) -> (exit_code, stdout, stderr)` runs `main` in-process with captured streams.
- `ledger` at the application root is an executable POSIX sh launcher. It resolves its own directory, selects `.venv/bin/python` when present and `python3` otherwise, sets `PYTHONPATH` to that directory, does not change the working directory (relative CSV paths belong to the caller), and runs `-m cli "$@"`.

## Errors

`cli.errors` defines a base `LedgerError(Exception)` taking a message, and four subclasses each carrying an integer class attribute `exit_code`:

| Class | exit_code |
|---|---|
| `UsageError` | 2 |
| `Rejected` | 3 |
| `NotFound` | 4 |
| `OperationalError` | 1 |

`main` maps each to its exit code, writes exactly one diagnostic line to standard error and nothing to standard output. Any other unexpected exception maps to exit 1 with one stderr line.

## Registry

`cli.registry.register(path, handler, usage, min_args, max_args)` records a command.

- `path` is a tuple of words, such as `("account", "add")`.
- `handler(args: list[str]) -> None` receives the arguments after the command path and writes any stdout itself as its final act.
- `usage` is the one-line expected form of the command.
- `min_args` and `max_args` bound the argument count.

`main` matches the longest registered path prefix and checks arity. An unknown command, or an incomplete group such as a missing sub-verb, raises `UsageError` with a one-line list of commands. A wrong argument count raises `UsageError` whose message is the usage line of the failing command. Command modules are auto-discovered once per process from the `cli.commands` package with `pkgutil`; discovery never clears commands already registered.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: CSV Output

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | CSV table writing and integer-cent formatting shared by every reporting command. |
| Depends On | FEATURE-CliFoundation.md |
| Provides | cli.output.write_table, cli.output.format_cents |
| Consumes | cli.errors |

## Questions

- None.

## Purpose

Every successful command except `init` writes CSV to standard output: one header row, then data
rows, comma-separated, no quoting, no trailing spaces, `\n` line endings. Amounts are written with
exactly two decimal places, a leading `-` when negative, and no thousands separator.

## Interface

- `format_cents(cents: int) -> str` uses integer arithmetic only. It writes an optional leading minus, the whole digits, a point, and exactly two decimals, with no separators. Zero is written with two decimals and no sign.
- `write_table(header: list[str], rows: Iterable[Sequence[str]]) -> None` writes the header row then each row to `sys.stdout`, resolved at call time so redirection works. Fields are joined with commas, never quoted, each line ends in `\n`, and no line has trailing spaces. Values are already strings.
- Handlers call `write_table` as their last statement, after every check and write has succeeded, so a failing command never leaks stdout.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Text Validation

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Pure validators for codes, names, descriptions, and memos. |
| Depends On | FEATURE-CliFoundation.md |
| Provides | ledger_app.validation.code, ledger_app.validation.name, ledger_app.validation.memo |
| Consumes | cli.errors |

## Questions

- None.

## Purpose

Rules 3 and 4 of the ledger contract: codes (`account`, `category`) are 1 to 12 characters from
`A-Z` and `0-9`. Names and descriptions are 1 to 40 characters. Memos are 0 to 60 characters. None
of them contains a comma or a newline.

## Interface

Each function takes a string, returns it unchanged when valid, and raises `cli.errors.Rejected` (exit 3) otherwise.

| Function | Rule |
|---|---|
| `code(value)` | Full match of 1 to 12 characters from `A-Z` and `0-9`; a trailing newline is not tolerated. |
| `name(value)` | 1 to 40 characters with no comma, carriage return, or newline. Also validates descriptions. |
| `memo(value)` | 0 to 60 characters with no comma, carriage return, or newline. |

Values are never stripped or altered.

## Database Interface

- None — persistence is owned by DATABASE.md.
