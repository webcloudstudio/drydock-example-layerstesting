# FEATURE: Amount Validation

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Parse input amounts into signed integer cents, rejecting zero and malformed values. |
| Depends On | FEATURE-CliFoundation.md, ARCHITECTURE.md |
| Provides | ledger_app.validation.amount_cents |
| Consumes | cli.errors |

## Questions

- None.

## Purpose

Every command that accepts a money amount (`txn post`, `txn amend`, `transfer`, `load transactions`) converts the text to integer cents through one function. Money is never a float at any layer.

## Interface

`ledger_app.validation.amount_cents(text: str) -> int`

- Returns signed integer cents, a plain `int`.
- Raises `cli.errors.Rejected` (exit 3) for any value that is not accepted.

## Rules

1. The text must match `-?DIGITS[.D[D]]` over the whole string: an optional minus, one or more ASCII digits, then optionally a period followed by one or two ASCII digits. Use a full match, so a trailing newline is not tolerated.
2. Conversion uses string splitting and integer arithmetic only. A one-digit fraction is tens of cents (`5.5` is 550 cents); no fraction means whole units.
3. A value equal to zero (`0`, `0.0`, `0.00`, `-0`, `-0.00`) is rejected.
4. Rejected shapes include three or more decimals (even `1.000`), a leading `+`, an empty string, surrounding whitespace, a bare `.`, a missing integer part (`.5`), a trailing period (`1.`), thousands separators, exponents, and non-numeric text.
5. No `float`, `Decimal` of a float, or `round` appears in the implementation.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Questions

## Purpose

Transactions, transfers, and loaded files carry dates. One function decides whether text is an acceptable date, and the stored value is the text exactly as validated.

## Interface

`ledger_app.validation.date(text: str) -> str`

- Returns the input text unchanged when it is valid.
- Raises `cli.errors.Rejected` (exit 3) otherwise.

## Rules

1. The text must be exactly a four-digit year, a hyphen, a two-digit month, a hyphen, and a two-digit day, all ASCII digits. No other layout is accepted (`2026-2-3`, `2026/02/03`, `20260203`, surrounding whitespace, and trailing newline are rejected).

3. The reported date is not normalized, so storage and output show the same text.

# FEATURE: Database Location

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Resolve the database location from DATABASE_URL, DATABASE_PATH, or data/app.db. |
| Depends On | ARCHITECTURE.md |
| Provides | ledger_app.config.resolve_dsn |
| Consumes | None |

## Questions

- None.

## Purpose

Every command locates its database the same way. Resolution is a pure function of an explicit environment mapping and the application root, so it is testable without changing the process environment.

## Interface

`ledger_app.config.resolve_dsn(env, root) -> str`

- `env` is a mapping of environment variable names to values; the function never reads `os.environ` itself.
- `root` is the application root directory as a string or path.
- Returns a string DSN for the persistence library.

## Rules

1. Order of precedence: `DATABASE_URL`, then `DATABASE_PATH`, then the default `data/app.db`.
2. A variable that is empty counts as unset, so resolution falls through to the next source.
3. A value beginning `postgres://` or `postgresql://` is a PostgreSQL DSN and is returned unchanged.
4. Any other value is a SQLite file path. A leading `sqlite://` prefix is stripped first (`sqlite:///tmp/x.db` yields `/tmp/x.db`).
5. A relative SQLite path, including the default, is resolved against `root` and returned as an absolute path. An absolute path is returned as given.
6. Resolution never touches the filesystem: it creates no directory and opens nothing.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

# FEATURE: Store Access

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Open the store through the persistence library and map operational failures to exit 1. |
| Depends On | FEATURE-DatabaseLocation.md, FEATURE-CliFoundation.md, DATABASE.md, ARCHITECTURE.md |
| Provides | ledger_app.store.open_store |
| Consumes | ledger_app.config.resolve_dsn, persistence.open_database, cli.errors |

## Questions

- None.

## Purpose

All commands reach the database through one function. It resolves the location, opens the store with the shipped persistence library, and turns any operational failure into the one error the CLI maps to exit 1.

## Interface

`ledger_app.store.open_store(dsn: str | None = None, *, prepare: bool = False)`

- With no `dsn`, resolves one using `resolve_dsn(os.environ, application_root)`.
- Returns the persistence `Database` (`db.accounts`, `db.categories`, `db.transactions`).
- `prepare=True` is used only by `init`: the declared tables are created idempotently through the persistence library's provisioning. With `prepare=False` the function verifies each declared table can be read and raises when one cannot.

## Rules

1. Any persistence error, OS error, or failed connection (unreachable server, unreadable file, a path that is a directory, missing tables) is raised as `cli.errors.OperationalError`, exit 1, one stderr line, no stdout.
2. Nothing is written to standard output by this function.
3. Application code imports no database driver (`sqlite3`, `psycopg`); only the generated `persistence` package does.
4. SQLite is the verified engine; PostgreSQL DSNs are routed to the persistence library unchanged.

## Database Interface

- `FEATURE-ACCOUNTS-001` — read: probe the accounts table - supplies: `account` - returns: `account`
- `FEATURE-CATEGORIES-001` — read: probe the categories table - supplies: `category` - returns: `category`
- `FEATURE-TRANSACTIONS-001` — read: probe the transactions table - supplies: `txn_id` - returns: `txn_id`

import ast
import pathlib

banned = {"sqlite3", "psycopg", "psycopg2"}
found = []

# FEATURE: Balance Guard

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Compute account balances and reject any change that would leave one below zero. |
| Depends On | FEATURE-StoreAccess.md, FEATURE-CliFoundation.md, DATABASE.md, ARCHITECTURE.md |
| Provides | ledger_app.balances.balance_cents, ledger_app.balances.ensure_non_negative |
| Consumes | ledger_app.store.open_store, cli.errors |

## Questions

- None.

## Purpose

An account's balance is the sum of its transaction amounts in integer cents. No command may leave any account below zero. Every write command computes the net change it would make and asks the guard before its first write.

## Interface

- `ledger_app.balances.balance_cents(db, account: str) -> int` sums the stored amounts of the account's transactions; 0 when it has none.
- `ledger_app.balances.ensure_non_negative(db, deltas: Mapping[str, int]) -> None` takes the net change in cents per account, adds each to the stored balance, and raises `cli.errors.Rejected` (exit 3) if any final balance is below zero.

## Rules

1. The check is on the final balance a command would leave, not per row: callers combine every row of a command (a whole load file, both transfer legs, an amend's new minus old) into one net delta per account.
2. A final balance of exactly zero is allowed.
3. An account with no stored transactions has balance 0; a negative delta on it is rejected, a positive one is accepted.
4. Every named account is checked before anything is reported; the guard itself writes nothing.
5. Integer arithmetic only.

## Database Interface

- `FEATURE-TRANSACTIONS-002` — read: list the transactions of one account - supplies: `account` - returns: `amount`

## Programmatic Acceptance
