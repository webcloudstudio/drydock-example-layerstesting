## Purpose

`ledger` is a single-operator command-line cash ledger. Each invocation resolves the database, runs exactly one command, writes CSV to standard output on success or one diagnostic line to standard error on failure, and exits with a code from the exit-code table. Every command checks all inputs and rules before its first write.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file remains the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python 3.11+ | All application code, with the project tree, `.venv` (created by `uv venv`), `pyproject.toml` and committed `uv.lock`. |
| SQLite | The store, reached only through the generated `persistence` package. A `postgres://` or `postgresql://` DSN selects PostgreSQL through the same package. |
| CLI | The `ledger` executable at the application root, dispatching to `cli.main`. |
| pytest | The test runner behind `bin/test.sh`. |
| POSIX sh | `bin/test.sh`, the `ledger` launcher and the supplied grader. |

## Modules

| Module | Responsibility |
|--------|----------------|
| `ledger` (executable, POSIX sh) | Launcher: picks `.venv/bin/python` when present, else `python3`, sets `PYTHONPATH` to the application root and runs `python -m cli`. |
| `cli/__init__.py` | `main(argv) -> int`, the command registry `register_command(name, handler)`, dispatch. |
| `cli/__main__.py` | Calls `sys.exit(main())`. |
| `cli/testing.py` | `cli_runner(*args) -> (exit_code, stdout, stderr)`. |
| `ledger_config.py` | `database_dsn(env=None)` and `open_db()`. |
| `ledger_errors.py` | Error types, exit codes and the single-line stderr handler. |
| `csv_output.py` | `format_cents` and `write_rows`. |
| `validation.py` | Code, text, amount and date validation. |
| `balance_rules.py` | Final-balance check shared by every writing command. |
| `commands/` | One module per command family, each registering its handlers. |
| `persistence/` | Generated by Drydock from `DATABASE.md`; never hand-written. |

## Module Ownership

| Boundary | Owning module | Low-level APIs it may access |
|----------|---------------|------------------------------|
| Persistence | `persistence/` (generated) | The database driver, SQL, sessions. |
| Configuration | `ledger_config.py` | `os.environ`, `persistence.open_database`. |
| CLI | `cli/` | `sys.argv`, `sys.stdout`, `sys.stderr`. |
| Diagnostics | `ledger_errors.py` | `sys.stderr`. |
| File reading | `commands/load*.py` | Opening the CSV path given on the command line. |

No other module imports `sqlite3`, `psycopg` or any other database driver.

## Command Handler Contract

A handler is `handler(args: list[str]) -> None`, where `args` are the arguments after the command name. A handler validates everything, computes its result, and only then writes to the database and to standard output. It signals failure by raising a `ledger_errors` exception and never writes to standard output before it can no longer fail.

## Commands

`init`, `count`, `load accounts|categories|transactions`, `account add|get|rename|delete`, `txn post|get|amend|delete`, `transfer`, `report balances|categories|monthly`.

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success. |
| 1 | Operational failure: database unreachable, tables missing, file unreadable, unexpected error. |
| 2 | Usage error: unknown command, table or report, wrong argument count. |
| 3 | Rejected: invalid input, duplicate key, unknown reference, account in use, negative balance. |
| 4 | Not found. |

## Technical Decisions

- Money is integer cents at every layer; no floating point anywhere.
- Report values are always computed from stored rows; none is embedded.
- A rejected command changes nothing: validation and the balance rule run before the first write, and writes for one command share one database transaction.
- No application-level authentication; diagnostics never echo a DSN or credential.

=== AC foundation-no-direct-drivers ===
Intent: No application module outside the persistence package imports a database driver.

import ast
from pathlib import Path

skip = {".venv", "persistence", "tests", "sources", "__pycache__", ".git"}
drivers = {"sqlite3", "psycopg", "psycopg2", "sqlalchemy"}
offenders = []
for path in Path(".").rglob("*.py"):
    if skip & set(path.parts):
        continue
    tree = ast.parse(path.read_text(encoding="utf-8"))
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            names = {a.name.split(".")[0] for a in node.names}
        elif isinstance(node, ast.ImportFrom):
            names = {(node.module or "").split(".")[0]}
        else:
            continue
        if names & drivers:
            offenders.append(str(path))
print(offenders)
assert offenders == []
=== END AC foundation-no-direct-drivers ===

## Guardrails

- Application code never opens a database driver; all access goes through the generated persistence package.
- No floating point for money at any layer.
- Do not modify anything under `sources/`, and never read `sources/run.sh` or a seed file from application code.
- No report row, count or total is hardcoded.
