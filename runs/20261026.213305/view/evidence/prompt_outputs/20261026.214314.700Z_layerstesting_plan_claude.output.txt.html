# FEATURE: Load Categories

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |

| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-LedgerInit.md, FEATURE-Validation.md, FEATURE-CsvOutput.md, FEATURE-ErrorContract.md |

## Questions

- None.

## Purpose

`ledger load categories <csv>` loads category records from a CSV file whose header is exactly `category,description`. The whole file is parsed and every row, every duplicate key and every rule is checked before the first write, so a rejected file stores nothing.

## Behavior

- Header: must equal `category,description` in names and order; otherwise exit 3 before any row is stored.
- Each row: `category` is a code (1 to 12 characters of `A-Z0-9`); `description` is 1 to 40 characters with no comma or newline. A bad row rejects the file with exit 3.
- Duplicate `category` values inside the file, or equal to a stored category, reject the file with exit 3.
- An unreadable or missing file exits 1.
- Success writes CSV `table,loaded` then `categories,<rows>` where `<rows>` is the number of rows loaded. Exit 0.
- All inserts happen in one database transaction.

## Database Interface

- `FEATURE-CATEGORY-001` — write: create a category - supplies: `category`, `description` - returns: `category`, `description`
- `FEATURE-CATEGORY-002` — read: get a category to detect a stored duplicate - supplies: `category` - returns: `category`, `description`

# FEATURE: Load Transactions

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger load transactions <csv>` with row validation and the final-balance rule, all or nothing. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, FEATURE-Validation.md, FEATURE-BalanceRules.md, FEATURE-CsvOutput.md |
| Provides | ledger load transactions |
| Consumes | ledger.register_command, persistence.open_database, validation.parse_amount, validation.parse_date, validation.check_code, validation.check_text, balance_rules.check_final_balances, csv_output.write_rows, ledger_errors.Rejected |

## Questions

- None.

## Purpose

`ledger load transactions <csv>` loads transaction records from a file whose header is exactly `txn_id,date,account,category,amount,memo`. Each loaded transaction keeps the `txn_id` from its file. The whole file is validated before the first write.

## Behavior

- Header must match exactly in names and order; otherwise exit 3 with no write.
- Each row is validated: `txn_id` is an integer, `date` a real calendar date `YYYY-MM-DD`, `account` and `category` valid codes that exist (stored rows), `amount` matching `-?DIGITS[.D[D]]` with at most two decimals and never zero (parsed to integer cents, no floating point), `memo` 0 to 60 characters without comma or newline.
- A `txn_id` repeated in the file or already stored rejects the file.
- The negative-balance rule is judged on each account's final balance after the whole file (stored balance plus all file amounts). An intermediate dip restored by a later row of the same file is accepted.
- Any failure exits 3 (unknown account or category, bad row, duplicate id, negative final balance), writes nothing to standard output and stores nothing.
- A header-only file loads zero rows and writes `table,loaded` then `transactions,0`.
- Success writes `table,loaded` then `transactions,<rows>`. Validation, the balance check and all inserts run in one database transaction.

## Database Interface

- `FEATURE-TXN-001` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-002` — read: get a transaction to detect a stored duplicate id - supplies: `txn_id` - returns: `txn_id`
- `FEATURE-TXN-003` — read: list an account's transactions for its stored balance - supplies: `account` - returns: `txn_id`, `account`, `amount`
- `FEATURE-ACCOUNT-002` — read: confirm an account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORY-002` — read: confirm a category exists - supplies: `category` - returns: `category`

# FEATURE: Account Get

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger account get <code>` printing an account with its transaction count and balance. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-AccountAdd.md, FEATURE-CsvOutput.md, FEATURE-ErrorContract.md |
| Provides | ledger account get |
| Consumes | ledger.register_command, persistence.open_database, csv_output.write_rows, ledger_errors.NotFound |

## Questions

- None.

## Purpose

`ledger account get <code>` prints the current account row, with the transaction count and balance computed from stored transactions at the time of the call.

## Behavior

- Argument: exactly one code; any other count is a usage error (exit 2).
- Writes `account,name,transactions,balance` then the row. `transactions` is the number of the account's transactions; `balance` is the sum of their amounts in integer cents, written with exactly two decimals, a leading `-` when negative, and `0.00` for zero.
- An absent code exits 4 with nothing on standard output.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: get an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-003` — read: list the account's transactions to count and sum them - supplies: `account` - returns: `txn_id`, `account`, `amount`

## Programmatic Acceptance

=== AC account-get-with-activity ===

        db.transactions.create(
            txn_id=920001 + i, date="2026-05-01", account=acct, category=cat, amount=cents, memo=""
        )

    assert list(csv.reader(io.StringIO(out))) == [
        ["account", "name", "transactions", "balance"],
