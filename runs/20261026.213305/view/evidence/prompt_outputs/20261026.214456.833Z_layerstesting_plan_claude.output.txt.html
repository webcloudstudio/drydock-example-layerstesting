# FEATURE: Account Delete

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger account delete <code>`, which removes an account that has no transactions. |
| Depends On | FEATURE-AccountGet.md, FEATURE-TxnPost.md, FEATURE-CliFoundation.md, FEATURE-ErrorContract.md, FEATURE-CsvOutput.md, DATABASE.md |
| Provides | ledger account delete |
| Consumes | ledger.register_command, persistence.open_database, csv_output.write_rows, ledger_errors.NotFound, ledger_errors.Rejected, ledger txn post |

## Questions

- None.

## Purpose

Delete one account by code. An account that still has transactions is refused so that no transaction is orphaned. Source Rule 1 applies: the command checks everything before its single write.

## Behavior

- Invocation: `ledger account delete <code>` with exactly one argument.
- The account is looked up through `db.accounts.get`. An absent code exits 4 with nothing on stdout.
- Transactions of the account are listed through `db.transactions.list(account=<code>)`. If any exist, the command exits 3 and changes nothing.
- Otherwise the account is removed with `db.accounts.delete` and the command writes two CSV lines to stdout: `deleted`, then the code. No header row beyond that pair.
- Failures write nothing to stdout and one diagnostic line to stderr.
- The existence check, the transaction check and the delete run in one database transaction.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: look up the account - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-003` — read: list the account's transactions - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-ACCOUNT-005` — write: delete the account - supplies: `account` - returns: `account`

# FEATURE: Txn Post

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger txn post`, which validates and stores one transaction with an assigned id under the non-negative balance rule. |
| Depends On | FEATURE-AccountAdd.md, FEATURE-LoadCategories.md, FEATURE-Validation.md, FEATURE-BalanceRules.md, FEATURE-CsvOutput.md, FEATURE-CliFoundation.md, FEATURE-ErrorContract.md, DATABASE.md |
| Provides | ledger txn post |
| Consumes | ledger.register_command, persistence.open_database, validation.parse_amount, validation.parse_date, validation.check_code, validation.check_text, balance_rules.check_final_balances, csv_output.write_rows, ledger_errors.Rejected |

## Questions

- None.

## Purpose

Record one receipt or payment against an account and category. Source Rules 1 to 7 apply: every input is checked before the first write, the balance never goes below zero, amounts are integer cents, dates are real calendar dates.

## Behavior

- Invocation: `ledger txn post <account> <category> <amount> <date> [<memo>]`; four or five arguments.
- Validation, all before any write, each failure exiting 3: account and category codes (1 to 12 of `A-Z0-9`); amount matching `-?DIGITS[.D[D]]` (no leading dot, `+`, spaces or separators, at most two decimals, never zero in any form) converted to integer cents with integer arithmetic; date a real `YYYY-MM-DD` date (`2028-02-29` valid, `2026-02-29` and `2026-02-30` invalid); memo 0 to 60 characters with no comma or newline.
- The account must exist (`db.accounts.get`) and the category must exist (`db.categories.get`); otherwise exit 3.
- Balance: the resulting balance of the account (sum of its stored amounts plus the new amount) is checked with `balance_rules.check_final_balances`; a negative result exits 3.
- The new `txn_id` is the largest stored id plus one, or 1 for an empty table, computed from `db.transactions.list`. The id computation, the balance check and the insert run in one database transaction so two concurrent posts never share an id.
- A missing memo stores the empty string.
- Success writes the header `txn_id,date,account,category,amount,memo` and the new row, amount with exactly two decimals.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`, `name`
- `FEATURE-CATEGORY-002` — read: confirm the category exists - supplies: `category` - returns: `category`, `description`
- `FEATURE-TXN-003` — read: list stored transactions for id and balance computation - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-001` — write: create the transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

# FEATURE: Txn Amend

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger txn amend <id> <amount>`, which changes only a transaction's amount under the non-negative balance rule. |
| Depends On | FEATURE-TxnPost.md, FEATURE-Validation.md, FEATURE-BalanceRules.md, FEATURE-CsvOutput.md, FEATURE-CliFoundation.md, FEATURE-ErrorContract.md, DATABASE.md |

## Questions

- None.

## Purpose

Correct the amount of an existing transaction. Date, account, category and memo never change.

## Behavior

- Invocation: `ledger txn amend <id> <amount>` with exactly two arguments.
- A non-integer id exits 3. An integer id with no stored row exits 4.
- The amount follows the source amount rules (`-?DIGITS[.D[D]]`, at most two decimals, never zero) and is converted to integer cents with integer arithmetic; violations exit 3.
- The account's resulting balance (stored amounts with this row's amount replaced) is checked with `balance_rules.check_final_balances`; a negative result exits 3 and changes nothing.
- Success updates only the amount and writes the header `txn_id,date,account,category,amount,memo` and the updated row.
- Read, check and update run in one database transaction.

## Database Interface

- `FEATURE-TXN-002` — read: get the transaction - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-003` — read: list the account's transactions for the balance check - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-004` — write: change the amount - supplies: `txn_id`, `amount` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

# FEATURE: Txn Delete

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Implements `ledger txn delete <id>`, which removes a transaction only when no balance would go negative. |
| Depends On | FEATURE-TxnPost.md, FEATURE-BalanceRules.md, FEATURE-CsvOutput.md, FEATURE-CliFoundation.md, FEATURE-ErrorContract.md, DATABASE.md |
| Provides | ledger txn delete |
| Consumes | ledger.register_command, persistence.open_database, balance_rules.check_final_balances, csv_output.write_rows, ledger_errors.NotFound, ledger_errors.Rejected |

## Questions

- None.

## Purpose

Remove one transaction by id. Deleting a receipt can push an account negative, so the balance rule is applied to the state after the deletion.

## Behavior

- Invocation: `ledger txn delete <id>` with exactly one argument.
- A non-integer id exits 3. An integer id with no stored row exits 4.
- The account's balance without this row is checked with `balance_rules.check_final_balances`; a negative result exits 3 and changes nothing.
- Success deletes the row and writes two lines: `deleted`, then the id.
- Read, check and delete run in one database transaction.

## Database Interface

- `FEATURE-TXN-002` — read: get the transaction - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-003` — read: list the account's transactions for the balance check - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-005` — write: delete the transaction - supplies: `txn_id` - returns: `txn_id`
