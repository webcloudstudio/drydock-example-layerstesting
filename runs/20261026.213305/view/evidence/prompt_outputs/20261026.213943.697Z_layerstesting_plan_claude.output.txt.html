# ARCHITECTURE: LayersTesting

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Module layout, boundaries and technical decisions for the LayersTesting command-line cash ledger. |
| Provides | python project tree |

## Questions

- None.

## Purpose

`ledger` is a single-operator command-line cash ledger. Each invocation resolves the database, runs exactly one command, writes CSV to standard output on success or one diagnostic line to standard error on failure, and exits with a code from the exit-code table. Every command checks all inputs and rules before its first write.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file remains the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python 3.11+ | All application code, with the project tree, `.venv` (created by `uv venv`), `pyproject.toml` and committed `uv.lock`. |
| SQLite | The store, reached only through the generated `persistence` package. A `postgres://` or `postgresql://` DSN selects PostgreSQL through the same package. |
| CLI | The `ledger` executable at the application root, dispatching to `cli.main`. |
| pytest | The test runner behind `bin/test.sh`. |
| POSIX sh | `bin/test.sh`, the `ledger` launcher and the supplied grader. |

## Modules

| Module | Responsibility |
|--------|----------------|
| `ledger` (executable, POSIX sh) | Launcher: picks `.venv/bin/python` when present, else `python3`, sets `PYTHONPATH` to the application root and runs `python -m cli`. |
| `cli/__init__.py` | `main(argv) -> int`, the command registry `register_command(name, handler)`, dispatch. |
| `cli/__main__.py` | Calls `sys.exit(main())`. |
| `cli/testing.py` | `cli_runner(*args) -> (exit_code, stdout, stderr)`. |
| `ledger_config.py` | `database_dsn(env=None)` and `open_db()`. |
| `ledger_errors.py` | Error types, exit codes and the single-line stderr handler. |
| `csv_output.py` | `format_cents` and `write_rows`. |
| `validation.py` | Code, text, amount and date validation. |
| `balance_rules.py` | Final-balance check shared by every writing command. |
| `commands/` | One module per command family, each registering its handlers. |
| `persistence/` | Generated by Drydock from `DATABASE.md`; never hand-written. |

## Module Ownership

| Boundary | Owning module | Low-level APIs it may access |
|----------|---------------|------------------------------|
| Persistence | `persistence/` (generated) | The database driver, SQL, sessions. |
| Configuration | `ledger_config.py` | `os.environ`, `persistence.open_database`. |
| CLI | `cli/` | `sys.argv`, `sys.stdout`, `sys.stderr`. |
| Diagnostics | `ledger_errors.py` | `sys.stderr`. |
| File reading | `commands/load*.py` | Opening the CSV path given on the command line. |

No other module imports `sqlite3`, `psycopg` or any other database driver.

## Command Handler Contract

A handler is `handler(args: list[str]) -> None`, where `args` are the arguments after the command name. A handler validates everything, computes its result, and only then writes to the database and to standard output. It signals failure by raising a `ledger_errors` exception and never writes to standard output before it can no longer fail.

## Commands

`init`, `count`, `load accounts|categories|transactions`, `account add|get|rename|delete`, `txn post|get|amend|delete`, `transfer`, `report balances|categories|monthly`.

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success. |
| 1 | Operational failure: database unreachable, tables missing, file unreadable, unexpected error. |
| 2 | Usage error: unknown command, table or report, wrong argument count. |
| 3 | Rejected: invalid input, duplicate key, unknown reference, account in use, negative balance. |
| 4 | Not found. |

## Technical Decisions

- Money is integer cents at every layer; no floating point anywhere.
- Report values are always computed from stored rows; none is embedded.
- A rejected command changes nothing: validation and the balance rule run before the first write, and writes for one command share one database transaction.
- No application-level authentication; diagnostics never echo a DSN or credential.

offenders = []
for path in Path(".").rglob("*.py"):
    if skip & set(path.parts):
        continue
    tree = ast.parse(path.read_text(encoding="utf-8"))
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            names = {a.name.split(".")[0] for a in node.names}
        elif isinstance(node, ast.ImportFrom):
            names = {(node.module or "").split(".")[0]}
        else:
            continue
        if names & drivers:
            offenders.append(str(path))
print(offenders)
assert offenders == []

# FEATURE: Cli Foundation

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | The executable `ledger`, its command registry and dispatcher, and database location resolution. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | ledger, ledger.register_command, ledger_config.database_dsn |
| Consumes | persistence.open_database |

## Questions

- None.

## Purpose

Give every later command a place to register and a single way to resolve and open the database.

## Executable

`ledger` sits at the application root with its executable bit set. It is a POSIX sh script that resolves its own directory, chooses `.venv/bin/python` when present and `python3` otherwise, and runs `PYTHONPATH=<root> exec <python> -m cli "$@"`. It does not change the working directory, so `data/app.db` is relative to the caller.

## Interface

- `cli.main(argv: list[str] | None = None) -> int` uses `sys.argv[1:]` when `argv` is `None`.
- `cli.register_command(name: str, handler)` registers a handler under `name`, either one word (`init`) or two words (`account add`).
- Dispatch: when at least two arguments are given and `args[0] + " " + args[1]` is registered, that handler receives `args[2:]`; otherwise when `args[0]` is registered its handler receives `args[1:]`. An empty argument list or an unregistered command writes one line to standard error and returns `2`, with nothing on standard output.
- A handler that returns normally yields exit `0`. Before the error-contract story lands, any exception from a handler writes one generic line to standard error and returns `1`.
- `cli/testing.py` provides `cli_runner(*args) -> (exit_code, stdout, stderr)` as in the CLI foundation contract.

## Database Location

`ledger_config.database_dsn(env=None) -> str` reads `env` (default `os.environ`): `DATABASE_URL` when set and non-empty, else `DATABASE_PATH` when set and non-empty, else `data/app.db`. The value is returned unchanged. `ledger_config.open_db()` returns `persistence.open_database(database_dsn())`. The DSN is never printed.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Csv Output

| Field | Value |

| Depends On | FEATURE-CliFoundation.md |
| Provides | csv_output.format_cents, csv_output.write_rows |
| Consumes | ledger.register_command |

## Questions

- None.

## Purpose

Every successful command writes its result through this module so that formatting is identical everywhere.

## Interface

- `csv_output.format_cents(cents: int) -> str` returns the amount with exactly two decimals, a leading `-` when negative, no thousands separator, and `0.00` for zero (never `-0.00`). Computed with integer arithmetic (`divmod` on the absolute value). A non-`int` argument (including `float` and `bool`) raises `TypeError`.
- `csv_output.write_rows(rows) -> None` writes each row to the current `sys.stdout` (looked up at call time) as its cells joined by `,`, with no quoting, no trailing spaces and a `\n` line ending. Cells that are `int` are rendered with `str`; a `float` cell raises `TypeError`. Nothing is written when a row is invalid.

# FEATURE: Error Contract

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Error types, exit codes and the one-line standard error diagnostic for failed commands. |
| Depends On | FEATURE-CliFoundation.md |
| Provides | ledger_errors.Rejected, ledger_errors.NotFound, ledger_errors.OperationalFailure, ledger_errors.UsageError |
| Consumes | ledger.register_command |

## Questions

- None.

## Purpose

Failures map to a fixed exit code and exactly one diagnostic line on standard error; standard output stays empty.

## Interface

- `ledger_errors.LedgerError(Exception)` is the base, with class attribute `exit_code`.
- `Rejected` has `exit_code` 3, `NotFound` 4, `OperationalFailure` 1, `UsageError` 2.
- `ledger_errors.handle(exc: BaseException) -> int` writes one line to standard error and returns the exit code: the `exit_code` of a `LedgerError`, otherwise `1` (unexpected errors, including database errors). The message has newlines collapsed to spaces and every `scheme://...` token replaced by `<redacted>`, so a DSN or password never reaches a diagnostic.
- `cli.main` calls `handle` for any exception raised by a handler. An unknown command or empty argument list is a `UsageError` and exits 2.

# FEATURE: Validation

| Field | Value |
|-------|-------|
| Version | 20261026 V1 |
| Description | Validation of codes, names, memos, amounts and dates, with amounts converted to integer cents. |
| Depends On | FEATURE-ErrorContract.md |
| Provides | validation.parse_amount, validation.parse_date, validation.check_code, validation.check_text |
| Consumes | ledger_errors.Rejected |

## Questions

- None.

## Purpose

Every command validates its inputs through this module before it writes. Every violation raises `ledger_errors.Rejected` (exit 3).

## Interface

- `check_code(value: str) -> str`: 1 to 12 characters, each in `A-Z` or `0-9` (ASCII only). Returns the value.
- `check_text(value: str, max_len: int = 40, min_len: int = 1) -> str`: length within `min_len..max_len`, no comma, no newline or carriage return. Names and descriptions use the defaults; memos use `max_len=60, min_len=0`. Returns the value.
- `parse_amount(text: str) -> int`: the whole string matches `-?[0-9]+(\.[0-9]{1,2})?` (ASCII digits). No leading dot, plus sign, spaces, thousands separator, trailing dot or more than two decimals. The result is integer cents computed with integer arithmetic only, and a zero amount in any form (`0`, `0.00`, `-0`) is rejected.
- `parse_date(text: str) -> str`: matches `YYYY-MM-DD` with ASCII digits and is a real calendar date, with leap years honored (`2028-02-29` valid, `2026-02-29` invalid). Returns the text unchanged.
