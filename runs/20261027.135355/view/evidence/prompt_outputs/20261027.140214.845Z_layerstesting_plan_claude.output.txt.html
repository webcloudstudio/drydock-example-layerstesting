# FEATURE: Account Get

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger account get <code>`, printing the current account row with live transaction count and balance. |
| Depends On | FEATURE-AccountAdd.md, FEATURE-CliEntry.md, DATABASE.md |
| Provides | ledger account get |
| Consumes | ledger_core.accounts, cli.registry |

## Questions

- None.

## Purpose

`ledger account get <code>` prints the account's header row and data row `account,name,transactions,balance`. The transaction count and balance are computed from the account's stored transactions using the `account_row` helper exported by `ledger_core.accounts`. The balance is the sum of integer cents, formatted with exactly two decimals.

## Behavior

- Exactly one argument is required; any other count is a usage error, exit 2.
- An absent code exits 4 with one stderr line and nothing on stdout.
- Success exits 0 and writes the CSV with `\n` line endings.
- The command never writes to the database.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: get an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-005` — read: list an account's transactions - supplies: `account` - returns: `amount`

## Programmatic Acceptance

=== AC account-get-existing ===
Intent: An account with two stored transactions is printed with its live count and its balance, both derived from the fixture amounts.
Requires: executable=python3; scope=test

import csv
import io
from persistence.testing import db_session
from cli.testing import cli_runner

def money(c):
    sign = "-" if c < 0 else ""
    q, r = divmod(abs(c), 100)
    return f"{sign}{q}.{r:02d}"

code, label, cat = "ZZAG1", "Get Probe", "ZZAGC1"
amounts = [1000, -250]
with db_session() as db:
    db.accounts.create(account=code, name=label)
    db.categories.create(category=cat, description="Get Category")
    base = 900001001
    for i, cents in enumerate(amounts):
        db.transactions.create(txn_id=base + i, date="2026-04-01", account=code, category=cat, amount=cents, memo="")
    rc, out, err = cli_runner("account", "get", code)
    print(out)
    print(err)
    assert rc == 0
    rows = list(csv.reader(io.StringIO(out)))
    assert rows[0] == ["account", "name", "transactions", "balance"]
    assert rows[1] == [code, label, str(len(amounts)), money(sum(amounts))]
    assert len(rows) == 2

# FEATURE: Transaction Post

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger txn post`, validating every input and the balance rule before inserting one transaction. |
| Depends On | FEATURE-CliEntry.md, FEATURE-Validation.md, FEATURE-BalanceRule.md, DATABASE.md |
| Provides | ledger txn post, ledger_core.transactions |
| Consumes | ledger_core.validation, ledger_core.money, ledger_core.balances, cli.registry |

## Questions

- None.

## Purpose

`ledger txn post <account> <category> <amount> <date> [<memo>]` records one transaction and prints the header row `txn_id,date,account,category,amount,memo` followed by the new row. `ledger_core.transactions` exports `txn_row` (formats a stored transaction as an output row) and `next_txn_id` (largest stored `txn_id` plus one, or 1 in an empty table), used by the other transaction commands and by transfer.

## Behavior

- Four or five arguments are required; otherwise exit 2. An omitted memo is stored as the empty string.
- Everything is checked before the write, in this order: amount, date, and memo validation; account exists; category exists; no resulting balance below zero. Any violation exits 3 and writes nothing.
- The amount is parsed to integer cents with no floating point and printed with exactly two decimals.
- The new `txn_id` is the largest present plus one, or 1 when none exist.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: check the account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORY-002` — read: check the category exists - supplies: `category` - returns: `category`
- `FEATURE-TXN-005` — read: list transactions for balance and next id - supplies: `account` - returns: `txn_id`, `amount`
- `FEATURE-TXN-001` — write: create the transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance
