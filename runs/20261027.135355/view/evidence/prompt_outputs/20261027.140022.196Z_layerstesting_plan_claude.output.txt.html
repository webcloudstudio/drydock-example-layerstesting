# FEATURE: Load CSV Reader

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Shared reader that opens a CSV file named on the command line, checks its header, and returns numbered rows. |
| Depends On | ARCHITECTURE.md, FEATURE-CliEntry.md |
| Provides | ledger_core.csvio |
| Consumes | ledger, cli.registry |

## Questions

- None.

## Purpose

The three `ledger load <table> <csv>` commands share one reader so that file handling, header
checking, and the exit codes for unreadable files and malformed rows are identical. The reader
only reads: it never touches the database and never writes.

## Interface

`ledger_core.csvio.read_rows(path, header)`

- `path` is the file path named on the command line; `header` is the sequence of column names the
  table requires, in order.
- Returns a list of `(line_number, fields)` tuples, one per data row, in file order. `line_number`
  is the 1-based line of the file (the header is line 1, so the first data row is line 2). `fields`
  is a list of strings exactly as parsed by the `csv` module.
- A file that is missing or cannot be read or decoded raises `Operational` (exit 1).
- A header that differs from `header` in names or order, an empty file, or a data row whose field
  count differs from `len(header)` raises `Rejected` (exit 3), with a diagnostic naming the line.
- A file with a valid header and no data rows returns an empty list.
- Blank lines are not data rows and are skipped.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

import csv
import os
import tempfile
from ledger_core.csvio import read_rows

header = ["account", "name"]
rows = [["ZZR1", "First Row"], ["ZZR2", "Second Row"], ["ZZR3", "Third Row"]]

    path = os.path.join(d, "in.csv")
    with open(path, "w", newline="") as fh:
        w = csv.writer(fh, lineterminator="\n")
        w.writerow(header)
        w.writerows(rows)
    got = read_rows(path, header)
    assert len(got) == len(rows)
    for i, (line_no, fields) in enumerate(got):
        assert line_no == i + 2
        assert list(fields) == rows[i]

# FEATURE: Load Accounts

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger load accounts <csv>` as an all-or-nothing bulk load. |
| Depends On | FEATURE-LoadCsvReader.md, FEATURE-Validation.md, DATABASE.md |
| Provides | ledger load accounts |
| Consumes | ledger_core.csvio, ledger_core.validation, cli.registry |

## Questions

- None.

## Purpose

Load accounts from a CSV file whose header is `account,name`. Every row is validated before the
first write; the rows are then written together or not at all.

## Behavior

1. `ledger load accounts <csv>` takes exactly one file argument; other counts exit 2.
2. Read the file with `ledger_core.csvio.read_rows(path, ("account", "name"))`. An unreadable file
   exits 1; a wrong header or wrong field count exits 3.
3. Validate every row before any write: the code is 1 to 12 characters of `A-Z0-9`, the name is 1
   to 40 characters with no comma or newline, the code does not repeat within the file, and the code
   is not already stored.
4. Insert every row in one atomic unit. A failure at any row leaves every earlier row unstored.
5. Print `table,loaded` then `accounts,<rows>`, where `<rows>` is the number of rows inserted.
6. Any rejection exits 3 with nothing on standard output and one diagnostic line on standard error.
   A header-only file loads zero rows and prints `accounts,0`.

## Database Interface

- `FEATURE-ACCOUNT-005` — read: list stored accounts to detect duplicate keys - supplies: — - returns: `account`, `name`
- `FEATURE-ACCOUNT-001` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`

# FEATURE: Load Transactions

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger load transactions <csv>` with full validation and the balance rule checked before any write. |
| Depends On | FEATURE-LoadCsvReader.md, FEATURE-Validation.md, FEATURE-BalanceRule.md, FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, DATABASE.md |
| Provides | ledger load transactions |
| Consumes | ledger_core.csvio, ledger_core.validation, ledger_core.balances, cli.registry |

## Questions

- None.

## Purpose

Load transactions from a CSV file whose header is `txn_id,date,account,category,amount,memo`.
Each row keeps the `txn_id` from the file. The file is accepted entirely or not at all.

## Behavior

1. `ledger load transactions <csv>` takes exactly one file argument; other counts exit 2.
2. Read the file with `ledger_core.csvio.read_rows(path, ("txn_id", "date", "account", "category", "amount", "memo"))`.
   An unreadable file exits 1; a wrong header or wrong field count exits 3.
3. Validate every row before any write: `txn_id` is an integer, not repeated in the file and not
   already stored; the date is a real calendar date `YYYY-MM-DD`; the account and category exist in
   the store; the amount matches `-?DIGITS[.D[D]]`, has at most two decimals, and is not zero; the
   memo is 0 to 60 characters with no comma or newline. Amounts are converted to integer cents
   without floating point.
4. Apply `ledger_core.balances.check_no_negative` to all rows together as inserts. The effect of
   the whole file is considered at once, so a withdrawal that precedes its funding deposit in the
   file is accepted when the final balance is not below zero. A resulting negative balance for any
   account rejects the file.
5. Insert every row in one atomic unit, then print `table,loaded` and `transactions,<rows>`.
6. Any rejection exits 3, writes nothing to standard output, and stores none of the rows.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm each referenced account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORY-002` — read: confirm each referenced category exists - supplies: `category` - returns: `category`
- `FEATURE-TXN-002` — read: detect an already stored txn_id - supplies: `txn_id` - returns: `txn_id`
- `FEATURE-TXN-001` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

# FEATURE: Account Add

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger account add <code> <name>` and the shared `account_row` helper. |
| Depends On | FEATURE-CliEntry.md, FEATURE-Validation.md, DATABASE.md |
| Provides | ledger account add, ledger_core.accounts |
| Consumes | ledger_core.validation, ledger_core.money, cli.registry |

## Questions

- None.

## Purpose

Create one account and print its row. The module `ledger_core.accounts` also exports the helper the
other account commands use to build an account row from live data.

## Behavior

1. `ledger account add <code> <name>` takes exactly two arguments; other counts exit 2.
2. Validate the code (1 to 12 characters of `A-Z0-9`) and the name (1 to 40 characters, no comma or
   newline). A violation exits 3.
3. A code that is already stored exits 3 and leaves the stored account unchanged.
4. Insert the account, then print CSV: the header `account,name,transactions,balance` and one row
   with the new account, its name, `0` transactions, and balance `0.00`.
5. A failing command writes nothing to standard output.

## Interface

`ledger_core.accounts.account_row(db, code)` returns `None` when the account is absent, otherwise
the tuple `(account, name, transactions, balance_cents)` where `transactions` is the number of that
account's stored transactions and `balance_cents` is the integer sum of their amounts. Both are
computed from the database on every call. Formatting the balance as text is done by
`ledger_core.money.format_cents` in the command, not in the helper.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: get an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-ACCOUNT-001` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-TXN-005` — read: list an account's transactions to count and sum them - supplies: `account` - returns: `amount`
