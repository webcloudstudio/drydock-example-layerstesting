## Planning Instructions

### Delivery Shape

The system is a Python 3.11+ command-line executable named `ledger` at the application root. Inputs are command-line arguments and CSV files named on the command line. Outputs are CSV on standard output and diagnostics on standard error. All persistence goes through the shipped persistence library over SQLite, with `DATABASE_URL` or `DATABASE_PATH` selecting the database file. Each writing command validates all inputs and rules before its first write, so it either completes fully or changes nothing.

## Compass
A command-line cash ledger for a small shop that tracks cash across drawers, a safe, and petty cash. Every receipt and payment is recorded against an account, and three reports summarize balances, category totals, and monthly totals. ## Constraints

- SQLite database; `DATABASE_URL` (optionally `sqlite://`-prefixed) takes precedence over `DATABASE_PATH`, which defaults to `data/app.db`.
- Amounts stored as integer cents; never floating point.
- Application code never opens a database driver directly; all access goes through the shipped persistence library.
- Output is CSV with `\n` line endings, no quoting, no trailing spaces, two-decimal amounts.
- `sources/run.sh`, `sources/seed_*.csv`, and `sources/seed_transactions_bad.csv` are read-only scoring assets.

## Guardrails
- Application code never reads `sources/run.sh` and never embeds a report answer.
- Every report is computed from the database.
- A rejected command changes nothing; validation completes before the first write.
- No command leaves an account balance below zero.
- Standard error is never compared by the grader; failures write nothing to standard output.
