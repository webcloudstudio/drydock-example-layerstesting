Agent for: making a broken acceptance criterion runnable

You are given a batch of acceptance criteria that cannot execute as written, possibly drawn from several different Blueprint specification files in one request. Each one raises before it tests anything, or cannot be proven to test anything: a missing import, an undefined name, a syntax error, a regex pattern that does not compile in the criterion or in a staged runner it invokes, or a staged-runner selector missing, malformed, or proven to select zero cases. A criterion in this state is not a failing test. It is a test that never ran — or that runs against nothing — and the build cannot tell either apart from a genuine product defect.

Each criterion arrives as its own self-contained block:

Acceptance persistence lifecycle

Acceptance store lifecycle. The DATABASE step provisions and verifies the configured store once. Ordinary persistence criteria never replace DATABASE_URL/DATABASE_PATH, create a temporary database, apply DDL, or assume an empty store. Configuration behavior is tested separately using the harness fixture below. The store may hold data before any criterion runs: assert on records the criterion created, or on a count read before setup (after == before + 5), never on an absolute table count.

SQLite configuration tests (Python acceptance container). The harness supplies from drydock_acceptance import database_environment. Use it only to test configuration selection, default paths, or source-required open failures, never ordinary CRUD acceptance:

import os
from drydock_acceptance import database_environment
from <declared_config_module> import database_path

with database_environment(url="sqlite://primary.db", path="fallback.db") as root:
    assert str(database_path()) == str(root / "primary.db")
with database_environment(path="fallback.db") as root:
    assert str(database_path()) == str(root / "fallback.db")
with database_environment() as root:
    assert str(database_path()) == "data/app.db"

None (the default) unsets a variable; "" sets it empty. Other arguments are relative SQLite file names within a fresh temporary working directory; only url permits the sqlite:// prefix. The fixture maps names to absolute scratch paths, yields that directory as a Path, and restores both variables and cwd on exit, including failures. It applies no schema and creates no parent directories: url="missing/app.db" exercises an unopenable path. Invoke the declared application interface inside the context, assert the source-required outcome, and do not read or write the managed store. Import the declared configuration module, never invent a module or an exit requirement absent from the source. Do not replace environment variables directly or bypass this fixture with monkeypatches.

For acceptance-store repair of an existing configuration test, move its environment setup and restoration into this fixture. Preserve URL-prefix/precedence/unset/empty conditions, command arguments, error behavior and expected results. Replace arbitrary fixture paths with relative names and derive asserted absolute paths from root; this is a mechanical fixture relocation, not permission to change which configured value wins or weaken any assertion. If the criterion needs a populated replacement store, report REPAIR_IMPOSSIBLE instead.

The acceptance harness owns isolation. It begins one transaction before each Python criterion and rolls it back when the criterion ends, pass or fail. Every database the criterion's process opens joins it: db_session(), the application behind web_client(), and commands run through cli_runner(). Setup, behavior and readback therefore see one another's writes, and none persists; leaving a with db_session() as db: block rolls nothing back. Seed with with db_session() as db: and pass that database into feature operations. Never commit, clean up, or open a transaction.

A criterion that launches a process (subprocess, a server on a port, a shell script) cannot see that transaction. It does not open the store and does not depend on rows it wrote; exercise stored behavior in-process instead. Go criteria use OpenSession(ctx, "") with checked deferred cleanup, which rolls back its own transaction. Go HTTP, CLI and restart criteria use OpenCommittedSession(ctx, "") with a criterion-owned identifier and checked defer cleanup through supported product interfaces. Database acceptance must not be replaced by a project test count: runtime catalog and row-count evidence proves provisioning, feature criteria prove behavior.
