Planning Instructions

Delivery Shape

The system is a Python 3.11+ command-line executable named ledger at the application root. Inputs are command-line arguments and CSV files named on the command line. Outputs are CSV on standard output and diagnostics on standard error. All persistence goes through the shipped persistence library over SQLite, with DATABASE_URL or DATABASE_PATH selecting the database file. Each writing command validates all inputs and rules before its first write, so it either completes fully or changes nothing.

Story Realization Map

  • LEDGER-SCHEMA-001: sources/INSTRUCTIONS.md Commands table (init, count); sources/run.sh A1–A2, Z1–Z2. Requires persistence library schema setup and a count command.
  • LEDGER-LOAD-001: sources/INSTRUCTIONS.md Database and Commands (load accounts); sources/seed_accounts.csv; sources/run.sh B1, D2. Requires the accounts table and atomic load.
  • LEDGER-LOAD-002: sources/seed_categories.csv; sources/run.sh B2. Requires the categories table and atomic load.
  • LEDGER-LOAD-003: sources/seed_transactions.csv, sources/seed_transactions_bad.csv; sources/run.sh B3, D1. Requires foreign-key validation before any write.
  • LEDGER-LOAD-004: sources/INSTRUCTIONS.md Exit codes (1); sources/run.sh (no direct check; covered by the exit-code contract).
  • LEDGER-ACCT-001 through LEDGER-ACCT-004: sources/INSTRUCTIONS.md account commands and rules 3–4; sources/run.sh E1–E8.
  • LEDGER-TXN-001 through LEDGER-TXN-004: sources/INSTRUCTIONS.md transaction commands and rules 5–7; sources/run.sh F1–F10, G3–G5.
  • LEDGER-XFER-001: sources/INSTRUCTIONS.md transfer command and rule 1; sources/run.sh G1–G2.
  • LEDGER-RPT-001 through LEDGER-RPT-003: sources/INSTRUCTIONS.md report commands; sources/run.sh C1–C3, H1–H3.
  • LEDGER-CLI-001: sources/INSTRUCTIONS.md Output and Exit codes; sources/run.sh U1–U2.
  • LEDGER-CLI-002: sources/INSTRUCTIONS.md Rule 2; sources/run.sh G3–G5.

Test and Acceptance Strategy

Focused story tests run the story's own slice of the Python test suite in bin/test.sh, scoped per story. The terminal verification story runs the grader sh sources/run.sh and the unfiltered suite. Sea Trials are verified by the SEA_TRIALS.md criteria, and the grader is the authoritative proof for report and workflow correctness.

Sequencing and Dependencies

  1. LEDGER-SCHEMA-001 (init and count) first.
  2. LEDGER-LOAD-001, LEDGER-LOAD-002 in parallel after LEDGER-SCHEMA-001.
  3. LEDGER-LOAD-003 after LEDGER-LOAD-001 and LEDGER-LOAD-002.
  4. Account, transaction, and transfer stories after the loads.
  5. Report stories after all write stories are in place.
  6. LEDGER-CLI-001 and LEDGER-CLI-002 cross-cut and are verified during each story they touch.
  7. Terminal verification story runs the full grader after all others.

Source Conflicts and Gaps

  • Source conflict: none. INSTRUCTIONS.md and run.sh agree on every output format, exit code, and rule checked by the grader.
  • Gap: INSTRUCTIONS.md does not state the exit code for a missing or invalid DATABASE_URL value. Resolved by choosing the narrowest behavior: exit 1 as an operational failure, with no writes.
  • Gap: The behavior when ledger init is run with no prior database file is not stated. Resolved by creating the file and schema.
