Choices I made for you to review:

  1. SQLite location pre-check. The shipped SQLite driver creates a missing parent directory on connect, and open_database is lazy. So missing/app.db would open and exit 0, which breaks the cli-unopenable-database criterion. I added a check in cli/__init__.py that refuses a SQLite location whose directory does not exist (exit 1). PostgreSQL DSNs skip the check. This also stops a typo from creating an empty store. If you'd rather the library create directories, this check should change on replan.
  2. Launcher changes to the project root. This makes the default data/app.db root-relative, which matches the project layout. A relative DATABASE_PATH is therefore resolved against the project root, not the caller's directory.
  3. No argparse parser. Dispatch is by command-word prefix, because argparse subcommands don't fit multi-word commands like account add.
