FEATURE: Balance Rule

FieldValue
Version20261027 V1
DescriptionChecks that a proposed set of transaction changes leaves no account balance below zero before anything is written.
Depends OnARCHITECTURE.md, DATABASE.md
Providesledger_core.balances
Consumespersistence.transactions

Purpose

An account's balance is the sum of its transaction amounts in integer cents. Load, post, amend, delete, and transfer call this module before their first write. It only reads and never writes.

Interface

ledger_core.balances:

NameMeaning
Insert(account, amount)A transaction to be added to account with amount cents.
Edit(txn_id, amount)A stored transaction whose amount becomes amount.
Delete(txn_id)A stored transaction to be removed.
current_balance(db, account) -> intSum of the stored amounts of account; 0 when it has none.
check_no_negative(db, changes)Raises Rejected (exit 3) if any affected account's resulting balance is below zero; returns None otherwise.

check_no_negative groups all changes by account, takes each account's stored balance, applies the combined net delta (an Edit contributes new minus stored amount, a Delete contributes minus the stored amount), and rejects when any result is below zero. Changes are judged together, not one after another, so the order of changes does not matter. A resulting balance of exactly zero is allowed.

Database Interface

  • FEATURE-TXN-002 — read: get a stored transaction for an edit or delete - supplies: txn_id - returns: account, amount
  • FEATURE-TXN-005 — read: list an account's transactions to sum its balance - supplies: — - returns: amount

=== AC balance-current ===
Intent: current_balance sums an account's stored amounts and is zero for an account with no transactions.

from persistence.testing import db_session from ledger_core.balances import current_balance

acct, empty, cat = "ZZBR1", "ZZBR2", "ZZBRC1" with db_session() as db: db.accounts.create(account=acct, name="Balance Probe") db.accounts.create(account=empty, name="Empty Probe") db.categories.create(category=cat, description="Balance Cat") amounts = [1000, -300] for offset, cents in enumerate(amounts): db.transactions.create(txn_id=900100001 + offset, date="2026-05-01", account=acct, category=cat, amount=cents, memo="") assert current_balance(db, acct) == sum(amounts) assert current_balance(db, empty) == 0 === END AC balance-current ===

=== AC balance-insert ===
Intent: An insert that lands the balance at zero passes, one cent below zero is rejected with exit 3, and nothing is written either way.

from persistence.testing import db_session from ledger_core.balances import check_no_negative, Insert from ledger_core.errors import Rejected

acct, cat = "ZZBR3", "ZZBRC3" with db_session() as db: db.accounts.create(account=acct, name="Insert Probe") db.categories.create(category=cat, description="Balance Cat") db.transactions.create(txn_id=900100011, date="2026-05-01", account=acct, category=cat, amount=700, memo="") before = len(db.transactions.list(account=acct)) assert check_no_negative(db, [Insert(acct, -700)]) is None raised = None try: check_no_negative(db, [Insert(acct, -701)]) except Rejected as err: raised = err assert raised is not None assert raised.exit_code == 3 assert len(db.transactions.list(account=acct)) == before === END AC balance-insert ===

User Acceptance

  • None.

Guardrails

  • The check writes nothing; it only reads through the declared repository operations.
  • Amounts are integer cents; no floating point is used.
  • Only accounts touched by the proposed changes are judged; other accounts' balances do not affect the result.
  • Balances are computed from stored rows, never cached or hardcoded.
