FEATURE: Transfer

FieldValue
Version20261027 V1
DescriptionImplements ledger transfer <from> <to> <amount> <date>, an atomic two-row move of cash between distinct accounts in category TRANSFER.
Depends OnFEATURE-TxnPost.md, FEATURE-Validation.md, FEATURE-BalanceRule.md, FEATURE-CliEntry.md, DATABASE.md
Providesledger transfer
Consumesledger_core.transactions, ledger_core.validation, ledger_core.balances, cli.registry

Purpose

Move cash between two accounts as two transaction rows that are stored together or not at all. Persistence is reached only through ledger_core.transactions, which calls the generated persistence package.

Behavior

  1. Argument count other than four after transfer exits 2.
  2. Validate before any write: the amount is positive with at most two decimals, the date is a real YYYY-MM-DD date, both accounts exist, they differ, and category TRANSFER exists. Any violation exits 3.
  3. The source balance after the debit must not be below zero, checked through ledger_core.balances; otherwise exit 3.
  4. The outgoing row takes id max(txn_id)+1 (or 1 when empty): amount -amount, account <from>, category TRANSFER, memo transfer to <to>. The incoming row takes the next id: amount +amount, account <to>, memo transfer from <from>.
  5. Both rows are inserted atomically and printed under the header txn_id,date,account,category,amount,memo.
  6. A failing command writes nothing to standard output and stores neither row.

Database Interface

  • None — persistence is owned by DATABASE.md and reached through ledger_core.transactions.

=== AC transfer-success ===
Intent: A valid transfer exits 0 and prints two rows with consecutive ids starting at the previous maximum plus one, category TRANSFER, the signed amounts, and the specified memos; a separate read shows both stored.

from cli.testing import cli_runner from persistence.testing import db_session import csv import io

def f(row, name): return row[name] if isinstance(row, dict) else getattr(row, name)

src, dst, cat = "ZZTF1", "ZZTF2", "TRANSFER" day = "2026-05-10" amount_text = "250.00" cents = int(amount_text.replace(".", "")) with db_session() as db: db.accounts.create(account=src, name="Source Account") db.accounts.create(account=dst, name="Dest Account") if db.categories.get(category=cat) is None: db.categories.create(category=cat, description="Internal transfer") db.transactions.create(txn_id=900300001, date="2026-05-01", account=src, category=cat, amount=100000, memo="funding") before_max = max(f(r, "txn_id") for r in db.transactions.list()) code, out, err = cli_runner("transfer", src, dst, amount_text, day) print(out) print(err) assert code == 0 rows = list(csv.reader(io.StringIO(out))) assert len(rows) == 3 out_row, in_row = rows[1], rows[2] assert int(out_row[0]) == before_max + 1 assert int(in_row[0]) == int(out_row[0]) + 1 assert out_row[1] == day and in_row[1] == day assert out_row[2] == src and in_row[2] == dst assert out_row[3] == cat and in_row[3] == cat assert out_row[4] == "-" + amount_text assert in_row[4] == amount_text assert out_row[5] == "transfer to " + dst assert in_row[5] == "transfer from " + src assert f(db.transactions.get(txn_id=int(out_row[0])), "amount") == -cents assert f(db.transactions.get(txn_id=int(in_row[0])), "amount") == cents === END AC transfer-success ===

User Acceptance

  • None.

Guardrails

  • Both rows are written together or neither is; every check runs before the first write.
  • Amounts are integer cents; floating point is never used for money.
  • Standard output stays empty on any failure; the diagnostic goes to standard error.
  • Ids are never hardcoded; they derive from the largest stored txn_id.
