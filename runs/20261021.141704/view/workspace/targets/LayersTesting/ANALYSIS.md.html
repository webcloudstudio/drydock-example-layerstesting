Planning Instructions

Delivery Shape

The product is a single-process Python command-line program, the ledger executable at the application root, invoked once per command. Inputs are argv and CSV files named by load. State lives in a relational store: SQLite by default, PostgreSQL when DATABASE_URL is a PostgreSQL DSN. Outputs are CSV on stdout, one diagnostic line on stderr for failures, and an exit code from 0 to 4. Each command validates all inputs and the balance guard, then performs its writes in one database transaction. The supplied sh sources/run.sh drives acceptance from the application root.

Test and Acceptance Strategy

Each story other than ACC-001 proves itself with a focused pytest slice it owns and declares Suite: scoped. The supplied sources/run.sh accepts no scope selector, so no non-terminal story runs it. ACC-001 is the single terminal verification story. It depends on every other story and declares Suite: full in its heading block. It runs sh sources/run.sh unfiltered and passes only when every supplied check passes. Sea Trial st-001 proves the same verdict.

Sequencing and Dependencies

Build order: CLI-001, then DB-001 and DB-002, then SCHEMA-001 and SCHEMA-002. Next come the validation stories VAL-001 through VAL-005, then the accounts stories ACCT-001 through ACCT-004. LOAD-001 and LOAD-002 follow the accounts and categories work. Then TXN-001 through TXN-004, LOAD-003, and XFER-001. Reports (RPT-001 to RPT-003) come after the write stories. CLI-002 through CLI-005 and DB-003 and DB-004 are built with the foundation. TEST-001 follows the feature stories, TEST-002 follows TEST-001, and ACC-001 is last. The seed files and sources/run.sh are staged before ACC-001 runs. External dependencies are Python 3.11 or newer, SQLite, pytest, and POSIX sh.

Source Conflicts and Gaps

  • No cross-source conflicts were found. sources/INSTRUCTIONS.md and sources/run.sh agree on every command, output row, and exit code.
  • The shipped persistence library is not among the sources. It is treated as the layer generated from DATABASE.md under the persistence catalog entry, and DB-002 covers it.
  • PostgreSQL is named by the DSN rule while this build is SQLite. DB-001 requires recognition and routing of a PostgreSQL DSN; the grader verifies only SQLite.
  • No help-text format is stated. CLI-003 synthesizes it.
  • The sources state no authentication model. The product is a local command-line tool with no protected resource, so none is specified.
  • Each command's concurrency is bounded by one database transaction, per DB-002 and AC-002.
