# FEATURE: Rules Amount

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Parses and formats cash amounts as integer cents. |
| Depends On  | ARCHITECTURE.md |
| Provides    | rules.amount.parse_amount, rules.amount.format_amount |
| Consumes    | — |

## Questions

- None.

## Behavior

- `parse_amount(text: str) -> int` lives in `rules/amount.py`. It accepts text matching `-?DIGITS[.D[D]]`: an optional leading minus, one or more digits, and an optional decimal point followed by one or two digits. It returns the value in integer cents.
- Zero in any spelling (`0`, `0.00`, `-0.00`) is rejected. Every other non-matching text is rejected.
- A rejected text raises `ValueError`. Callers map `ValueError` to exit code 3.
- `format_amount(cents: int) -> str` writes exactly two decimal places, a leading `-` when negative, and no thousands separator. Zero formats as `0.00`.
- No floating-point value is used at any step.

## Programmatic Acceptance

=== AC amount-round-trip ===
Intent: Parsing a canonical amount text and formatting the cents returns the original text.

from rules.amount import parse_amount, format_amount

for text in ["-12.50", "5000.00", "0.05", "-0.05", "1234.56"]:
    cents = parse_amount(text)
    assert isinstance(cents, int)
    assert format_amount(cents) == text
=== END AC amount-round-trip ===

=== AC amount-whole-and-tenths ===
Intent: Whole, one-decimal, and negative inputs parse to the expected integer cents.

from rules.amount import parse_amount

assert parse_amount("5000") == 500000
assert parse_amount("1.5") == 150
assert parse_amount("-0.5") == -50
=== END AC amount-whole-and-tenths ===

=== AC amount-rejects-invalid ===
Intent: Zero, excess precision, malformed, and empty amounts raise ValueError.

from rules.amount import parse_amount

def rejected(text):
    try:
        parse_amount(text)
    except ValueError:
        return True
    return False

for text in ["0", "0.00", "-0.00", "1.234", "1,00", ".5", "5.", "", "abc"]:
    assert rejected(text)
=== END AC amount-rejects-invalid ===

=== AC amount-format-no-separator ===
Intent: Formatted amounts have exactly two decimal places and no thousands separator.

from rules.amount import parse_amount, format_amount

text = format_amount(parse_amount("1234.56"))
assert "," not in text
assert len(text.split(".")[1]) == 2
=== END AC amount-format-no-separator ===

## User Acceptance

- None.

## Guardrails

- Amount parsing and formatting perform no I/O and open no database driver.
- Money is never represented as a floating-point value at any layer.

# FEATURE: Rules Text

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Validates account and category codes, names, descriptions, and memos. |
| Depends On  | ARCHITECTURE.md |
| Provides    | rules.text.validate_code, rules.text.validate_name, rules.text.validate_memo |
| Consumes    | — |

## Questions

- None.

## Behavior

- Module: `rules/text.py`. Each validator returns its input unchanged when valid and raises `ValueError` when invalid. Callers map `ValueError` to exit code 3.
- `validate_code(value: str)` accepts 1 to 12 characters, each from `A-Z` or `0-9`. Lowercase letters, spaces, and any other character are rejected.
- `validate_name(value: str)` accepts 1 to 40 characters. The same rule applies to category descriptions.
- `validate_memo(value: str)` accepts 0 to 60 characters. An empty memo is valid.
- `validate_name` and `validate_memo` reject any value containing a comma or a newline.

# FEATURE: Rules Balance

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Refuses any command whose resulting account balance would be negative. |
| Depends On  | FEATURE-Database-Location.md, FEATURE-Rules-Amount.md, DATABASE.md |
| Provides    | rules.balance.check_non_negative |
| Consumes    | db.transactions.list |

## Questions

- None.

## Behavior

- Module: `rules/balance.py`. `check_non_negative(db, deltas: dict[str, int]) -> None` takes the signed integer-cent change per account code that the calling command is about to apply. The caller aggregates a batch's changes per account before calling.
- For each account in `deltas`, the current balance is the sum of the `amount` values of that account's transactions, read through `FEATURE-BALANCE-001`. An account with no transactions has a current balance of zero.
- If any current balance plus its delta is below zero, the function raises `ValueError` naming the account. Otherwise it returns `None`.
- The function performs no writes. Callers invoke it before their first write and map `ValueError` to exit code 3.

## Database Interface

- `FEATURE-BALANCE-001` — read: list the transactions of one account - supplies: `account` - returns: `account`, `amount`

## Programmatic Acceptance

=== AC balance-allows-and-refuses ===
Intent: A delta that leaves a balance at zero or above is allowed; a delta that goes below zero is refused, and a refusal writes nothing.

from persistence.testing import db_session
from rules.balance import check_non_negative

def rejected(db, deltas):
    try:
        check_non_negative(db, deltas)
    except ValueError:
        return True
    return False

with db_session() as db:
    db.accounts.create(account="PETTY", name="Petty Cash")
    db.categories.create(category="SUPPLY", description="Supplies")
    row = db.transactions.create(txn_id=1, date="2026-04-01", account="PETTY", category="SUPPLY", amount=1000, memo="opening")
    assert row.amount == 1000
    assert check_non_negative(db, {"PETTY": -1000}) is None
    assert check_non_negative(db, {"PETTY": 500}) is None
    assert rejected(db, {"PETTY": -1001})
    assert len(db.transactions.list()) == 1
=== END AC balance-allows-and-refuses ===

=== AC balance-no-transactions-is-zero ===

# FEATURE: Load Core

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Shared CSV load path for the accounts, categories, and transactions tables with all-or-nothing writes. |
| Depends On  | FEATURE-Database-Location.md, FEATURE-Rules-Amount.md, FEATURE-Rules-Text.md, FEATURE-Rules-Date.md, FEATURE-Rules-Balance.md, DATABASE.md |
| Provides    | ledger load <table> <csv>, load.core.load_file |
| Consumes    | db.accounts.create, db.categories.create, db.transactions.create, db.accounts.list, db.categories.list, db.transactions.list, rules.balance.check_non_negative |

## Questions

- None.

## Behavior

- Module: `load/core.py`. `load_file(db, table: str, path: str) -> int` is the shared path for `ledger load <table> <csv>`. It returns the number of rows stored.
- `table` must be `accounts`, `categories`, or `transactions`. Any other name raises `KeyError`, which the dispatcher maps to exit code 2.
- The header line must equal exactly: `account,name` for accounts; `category,description` for categories; `txn_id,date,account,category,amount,memo` for transactions. Any other header raises `ValueError`.
- Each data row is split on commas. A row whose field count differs from the header raises `ValueError`. A header-only file has zero rows and is valid.
- Row rules: accounts use `validate_code` and `validate_name`; categories use `validate_code` and `validate_name` on the description; transactions use `txn_id` (digits, at least 1), `validate_date`, `parse_amount`, and `validate_memo`. A transaction's account and category must already exist in the store.
- A key duplicated within the file or already present in the store raises `ValueError`.
- For transactions, the per-account sum of the file's amounts is passed to `check_non_negative`. A refusal raises `ValueError`.
- Every row is validated and every balance is checked before the first write. Only then are rows written with `db.<table>.create` in file order, and the count is returned.
- The `ledger load` handler prints `table,loaded` and `<table>,<count>` on success. An unreadable file raises `OSError`, which maps to exit code 1. Any `ValueError` maps to exit code 3. Diagnostics go to standard error.

## Database Interface

- `FEATURE-LOAD-001` — write: insert validated account rows - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-LOAD-002` — write: insert validated category rows - supplies: `category`, `description` - returns: `category`, `description`
- `FEATURE-LOAD-003` — write: insert validated transaction rows - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `amount`
- `FEATURE-LOAD-004` — read: list existing accounts for key and reference checks - returns: `account`
- `FEATURE-LOAD-005` — read: list existing categories for key and reference checks - returns: `category`
- `FEATURE-LOAD-006` — read: list existing transactions for key checks - returns: `txn_id`
