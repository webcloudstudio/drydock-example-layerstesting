# FEATURE: Load Accounts

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Bulk-load the accounts table from a CSV file with header account,name. |
| Depends On  | ARCHITECTURE.md, FEATURE-Load-Core.md, FEATURE-Schema-Init.md |
| Provides    | ledger load accounts |
| Consumes    | |

## Questions

- None.

## Purpose

`ledger load accounts <csv>` reads an accounts file and inserts every row into the `accounts`
table. The file's header must be exactly `account,name`. On success the command prints
`table,loaded` then `accounts,N`, where N is the number of rows loaded. A header-only file loads
zero rows and exits 0. An unreadable file exits 1. Any rejected row exits 3 and the store is left
unchanged.

## Behavior

- Argument form: `ledger load accounts <csv>`.
- Header must match `account,name` in that order; otherwise the file is rejected with exit 3.
- Each data row is validated with the code rule (1 to 12 characters from `A-Z` and `0-9`) and the
  name rule (1 to 40 characters, no comma, no newline). A duplicate code, whether within the file
  or already present in `accounts`, is a rejected row.
- All rows are validated before the first write; any rejected row writes nothing (see
  FEATURE-Load-Core.md).
- Success output is CSV on stdout: `table,loaded` then `accounts,N`.
- An unreadable file exits 1; diagnostics go to stderr.

## Routes

- Command: `ledger load accounts <csv>`

## Reads

- `accounts` (duplicate-code check)

## Writes

- `accounts` (insert validated rows)

## Database Interface

- `FEATURE-ACCOUNT-001` — write: insert a validated account row - supplies: `account`, `name` - returns: `account`, `name`

## Programmatic Acceptance

=== AC load-accounts-round-trip ===
Intent: Loading a valid accounts file stores every row and reading the count back returns the loaded rows.
Suite: scoped

from persistence.testing import db_session
from cli.testing import cli_runner

import os
import tempfile

with db_session() as db:
    os.environ["DATABASE_URL"] = db.dsn if hasattr(db, "dsn") else os.environ.get("DATABASE_URL", "")
    code, out, err = cli_runner("init")
    assert code == 0

    path = os.path.join(tempfile.mkdtemp(), "accounts.csv")
    with open(path, "w", encoding="ascii") as f:
        f.write("account,name\nDRAWER1,Front Drawer\nPETTY,Petty Cash\n")

    code, out, err = cli_runner("load", "accounts", path)
    print(out)
    print(err)
    assert code == 0

    rows = db.accounts.list()
    assert len(rows) == 2
    assert {r.account for r in rows} == {"DRAWER1", "PETTY"}

# FEATURE: Load Transactions

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Bulk-load the transactions table from a CSV file, keeping each txn_id from the file. |
| Depends On  | ARCHITECTURE.md, FEATURE-Load-Core.md, FEATURE-Load-Accounts.md, FEATURE-Load-Categories.md, FEATURE-Rules-Balance.md |
| Provides    | ledger load transactions |
| Consumes    | |

## Questions

- None.

## Purpose

`ledger load transactions <csv>` reads a transactions file and inserts every row into the
`transactions` table, keeping the `txn_id` each row carries. The file's header must be exactly
`txn_id,date,account,category,amount,memo`. On success the command prints `table,loaded` then
`transactions,N`. An unknown account or category, or any invalid row, exits 3. Nothing is written
unless every row passes.

## Behavior

- Argument form: `ledger load transactions <csv>`.
- Header must match `txn_id,date,account,category,amount,memo` in that order; otherwise exit 3.
- Each row is validated: `txn_id` is a positive integer not already present; `date` passes the
  calendar rule (`YYYY-MM-DD`); `account` and `category` must exist in their tables; `amount`
  passes the amount rule; `memo` is 0 to 60 characters with no comma or newline.
- The balance rule is checked over the whole batch before the first write: no account balance may
  fall below zero after the load.
- Any rejected row, or a balance violation, writes nothing and exits 3.
- Success output is CSV on stdout: `table,loaded` then `transactions,N`.
- An unreadable file exits 1; diagnostics go to stderr.

## Routes

- Command: `ledger load transactions <csv>`

## Reads

- `accounts`, `categories`, `transactions` (validation and balance check)

## Writes

- `transactions` (insert validated rows)

## Database Interface

- `FEATURE-TRANSACTION-001` — write: insert a validated transaction row with its file txn_id - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

# FEATURE: Load Atomic

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Prove that any rejected load, across all three load commands, stores none of its rows and leaves every table unchanged. |
| Depends On  | ARCHITECTURE.md, FEATURE-Load-Accounts.md, FEATURE-Load-Categories.md, FEATURE-Load-Transactions.md |
| Provides    | |
| Consumes    | ledger load accounts, ledger load categories, ledger load transactions |

## Questions

- None.

## Purpose

This feature is the assembly check for atomic loading. A rejected load must exit 3 and leave the
`accounts`, `categories`, and `transactions` tables exactly as they were before the command ran.
It owns no new behavior; it verifies the all-or-nothing rule across the three load commands.

## Behavior

- A load that contains any rejected row exits 3 and writes no rows.
- A rejected accounts reload (duplicate codes against existing rows) leaves every table unchanged.
- A rejected transactions batch (unknown account) leaves every table unchanged.

## Routes

- None. This feature is assembly and verification only.

## Reads

- `accounts`, `categories`, `transactions` (before and after snapshots)

## Writes

- None.

## Database Interface

- None — persistence is owned by FEATURE-Load-Transactions.md and FEATURE-Load-Accounts.md.

## Programmatic Acceptance

Suite: scoped
Requires: executable=python3; scope=test

from persistence.testing import db_session
from cli.testing import cli_runner

import os
import tempfile

with db_session() as db:
    code, out, err = cli_runner("init")
    assert code == 0

    d = tempfile.mkdtemp()
    acc = os.path.join(d, "accounts.csv")
    with open(acc, "w", encoding="ascii") as f:
        f.write("account,name\nSAFE,Store Safe\n")
    cat = os.path.join(d, "categories.csv")
    with open(cat, "w", encoding="ascii") as f:
        f.write("category,description\nSALES,Sales receipts\n")
    assert cli_runner("load", "accounts", acc)[0] == 0
    assert cli_runner("load", "categories", cat)[0] == 0

    before_accounts = db.accounts.list()
    before_categories = db.categories.list()
    before_transactions = db.transactions.list()

    bad = os.path.join(d, "transactions.csv")
    with open(bad, "w", encoding="ascii") as f:
        f.write("txn_id,date,account,category,amount,memo\n1,2026-01-01,SAFE,SALES,10.00,ok\n2,2026-01-01,NOSUCH,SALES,10.00,bad\n")

    code, out, err = cli_runner("load", "transactions", bad)
    print(out)
    print(err)
    assert code == 3

    assert db.accounts.list() == before_accounts
    assert db.categories.list() == before_categories
    assert db.transactions.list() == before_transactions
=== END AC load-atomic-transactions ===

- None.

## Purpose

`ledger account add <code> <name>` inserts one account row and prints it. The code and name are
validated before the write. A new account has zero transactions and a balance of `0.00`. A

  name rule (1 to 40 characters, no comma, no newline). Either failing exits 3.
- A code already present in `accounts` exits 3 and writes nothing.
- Success output is CSV on stdout: header `account,name,transactions,balance`, then the row
  `<code>,<name>,0,0.00`.

- Command: `ledger account add <code> <name>`
