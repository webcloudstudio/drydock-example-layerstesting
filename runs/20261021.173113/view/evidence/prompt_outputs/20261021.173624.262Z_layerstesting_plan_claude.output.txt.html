# ARCHITECTURE: Cash Ledger

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Module layout, boundaries, and technical decisions for the LayersTesting cash ledger CLI. |
| Depends On  | |
| Provides    | |
| Consumes    | |

## Questions

- None.

## Purpose

A single-user command-line cash ledger named `ledger`, implemented in Python 3.11 or newer over
SQLite. Every command validates all input and rules before its first write, and a rejected command
changes nothing.

## Technology Stack

- Python 3.11+ — implementation language.
- SQLite — database, reached through the shipped persistence library (`persistence.db`,
  `open_database(dsn)`).
- CLI — the `ledger` executable at the application root, calling `cli.main`.
- pytest — test runner behind `bin/test.sh`.
- POSIX sh — `bin/test.sh` and the supplied grader.

## Foundation Layout

- `pyproject.toml` declares Python 3.11 or newer and `pytest`. `uv.lock` is committed.
- `.venv` is created by `uv venv`.
- `bin/test.sh` is a POSIX wrapper that runs `pytest -q` from the application root.
- `ledger` at the application root calls `cli.main`.

## Modules

| Module | Responsibility |
|--------|----------------|
| `cli` | Command-line entry point, dispatch table, usage errors, help text, CSV output. |
| `persistence` | Generated and shipped database package. Application code reaches the store only through it. |
| `rules` | Amount codec, code/name/memo validation, date validation, non-negative balance check. |
| `load` | Shared CSV load path: header check, row validation, all-or-nothing write. |
| `commands` | Account, transaction, transfer, schema, and report command handlers. |

## Boundaries

| Boundary | Owner | Allowed access |
|----------|-------|----------------|
| Database location | `cli` (resolves `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`) | Passes the DSN to `persistence.open_database`. |
| Store access | `persistence` | Only `persistence.db.<table>.<verb>(...)` callers. No driver import outside the library. |
| Business rules | `rules` | Pure functions; no storage access. |
| Command handlers | `commands` | Call `rules` and `persistence`; never a driver. |

## Module Ownership

| Boundary | Module that owns it | Low-level APIs that module may access |
|----------|---------------------|----------------------------------------|
| Persistence | `persistence` (generated from `DATABASE.md`) | `sqlite3` via the shipped library only |
| Configuration | `cli` | `os.environ` for the three location variables |
| File stores | None | Not used |
| External services | None | Not used |

## Technical Decisions

- Amounts are stored and computed as integer cents. No floating point at any layer.
- Each command checks every rule before its first write, so a rejected command writes nothing.
- The database DSN selects the engine: `postgres://` and `postgresql://` are PostgreSQL DSNs; any
  other value is a SQLite file path, optionally prefixed `sqlite://`.
- Exit codes follow the source contract: 0 success, 1 operational, 2 usage, 3 rejected, 4 not found.

## Programmatic Acceptance

- None. Architecture is verified through the feature and story acceptance that implements it.

## User Acceptance

- None.

## Guardrails

- Do not open a database driver outside the shipped persistence library.
- Do not hardcode report rows, counts, or totals.
- Do not read `sources/run.sh` or any seed file from application code.

# FEATURE: Database Location

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Resolve the database location and open the store through the persistence library. |
| Depends On  | ARCHITECTURE.md |
| Provides    | open_database configuration |
| Consumes    | |

## Questions

- None.

## Purpose

Select the store named by `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`, and open it
through `persistence.open_database`. A `postgres://` or `postgresql://` value is a PostgreSQL DSN
and is never treated as a file path.

## Database Interface

- None — persistence is owned by FEATURE-Schema-Init.md.

## Programmatic Acceptance

Intent: DATABASE_URL takes precedence over DATABASE_PATH when both are set.

import os
from cli.config import database_dsn

os.environ["DATABASE_URL"] = "/tmp/url-wins.db"
os.environ["DATABASE_PATH"] = "/tmp/path-loses.db"
dsn = database_dsn()
assert dsn == "/tmp/url-wins.db"
=== END AC database-location-precedence ===

os.environ.pop("DATABASE_PATH", None)

## User Acceptance

- None.

## Guardrails

- Never treat a `postgres://` or `postgresql://` DSN as a file path.
- Never open a database driver directly; reach the store only through `persistence.open_database`.

# FEATURE: Schema Init

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |

| Depends On  | ARCHITECTURE.md, FEATURE-Database-Location.md, FEATURE-CLI-Entry.md |

## Questions

- None.

## Purpose

`ledger init` drops `accounts`, `categories`, and `transactions` if present, recreates them empty,
writes nothing to standard output, and exits 0.

## Database Interface

- `FEATURE-SCHEMA-001` — write: drop and recreate all declared tables - returns: none

## Programmatic Acceptance

Intent: After init, count reports zero rows in each of the three tables.
Requires: executable=python3; scope=test

import subprocess
import sys

result = subprocess.run(
    [sys.executable, "ledger", "init"],
    capture_output=True, text=True,
    env={**__import__("os").environ, "DATABASE_URL": "/tmp/schema-init.db"},
)
print(result.stderr, file=sys.stderr)
assert result.returncode == 0
assert result.stdout == ""
=== END AC schema-init-empty ===

=== AC schema-init-recreates ===

import subprocess

assert second.stdout == ""

- None.

## Guardrails

- `init` writes nothing to standard output.
- Init drops and recreates all three tables; it never migrates existing tables.
