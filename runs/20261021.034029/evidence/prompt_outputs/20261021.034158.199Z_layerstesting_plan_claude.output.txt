# ARCHITECTURE: LayersTesting

## Questions

## Overview

The product is a command-line cash ledger named `ledger`, located at the application root and invoked as `./ledger <command>`. The application is a Python 3.11+ package tree with a `.venv` environment created by `uv venv`, a `pyproject.toml`, and a committed `uv.lock`. Commands read arguments from the command line and CSV files; results are written as CSV on standard output and diagnostics on standard error.

## Modules and Boundaries

| Module | Owns | May access |
|---|---|---|
| `ledger` (POSIX sh launcher) | Process entry at the application root; runs the `cli` package under `.venv/bin/python`. | `.venv` interpreter only |
| `cli` | Argument parsing, command dispatch, usage errors (exit 2), CSV output formatting. | `persistence` public interface only |
| `persistence` (generated, shipped library) | Store access, transactions, schema application, DSN engine selection. | Declared table operations only |
| `services` (per-feature modules) | Validation rules (codes, names, amounts, dates, memos), balance checks, atomic write composition. | `persistence` public interface |

No module outside `persistence` opens a database driver. Application code never reads `sources/run.sh` or any seed file; seed data reaches the store only through `ledger load`.

## Module Ownership for Persistence, Configuration, and File Boundaries

| Boundary | Owner | Notes |
|---|---|---|
| Store access | `persistence` | Selected by `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| Configuration | `cli` | Resolves the DSN and passes it to `persistence.open_database`. |
| Seed files | `cli` (load command) | Read as CSV input only; never referenced by application code otherwise. |
| Output | `cli` | CSV to standard output; diagnostics to standard error. |

## Routes, Commands, and Interfaces

- Commands: `init`, `count`, `load`, `account`, `txn`, `transfer`, `report`.
- Exit codes: `0` success, `1` operational failure, `2` usage error, `3` rejected, `4` not found.
- Integer cents are the only money representation; floating point is not used at any layer.

## Technical Decisions

- Launcher: a POSIX sh `ledger` script at the application root executes the `cli` package under `.venv/bin/python` (see DECISIONS.json Q-001).
- Engine: SQLite through the shipped persistence library; a PostgreSQL DSN selects the PostgreSQL engine at runtime (see DECISIONS.json Q-003).
- Every command validates all inputs and rules before its first write; a failing command changes nothing.

## Technology Stack

- Python 3.11+ (language, `python.md`).
- SQLite (database, `sqlite.md`, reached through the shipped persistence library).
- CLI (`cli.md`, the `ledger` executable).
- pytest (test runner behind `bin/test.sh`).
- POSIX sh (`bin/test.sh`, the `ledger` launcher, and the supplied grader).

## Programmatic Acceptance

- None. Architecture is realized and verified by the stories that implement the features it names; the executable surface is asserted in the `foundation` story and the feature specifications.

## User Acceptance

- None.

## Guardrails

- Do not modify, rewrite, regenerate, or substitute any file under `sources/`.
- Do not read `sources/run.sh` or any seed file from application code.
- Do not hardcode a report row, a count, or a total; every value comes from a query.
- Do not open a database driver outside the shipped persistence library.
- Do not use floating point for money at any layer.
