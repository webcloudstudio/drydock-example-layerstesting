# FEATURE: Load Accounts

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Load accounts from a CSV file with `ledger load accounts`. |
| Depends On  | FEATURE-Schema-Init.md |
| Provides    | ledger load accounts |

## Questions

- None.

## Purpose

Populate the `accounts` table from a CSV file whose header is `account,name`.

## Interface

`ledger load accounts <csv>`

## Behavior

- The file header must be `account,name`. A header that does not match is a rejected file and exits 3.
- Every row is validated before the first write. A code is 1 to 12 characters from `A-Z` and `0-9`. A name is 1 to 40 characters and contains no comma or newline.
- A code that repeats within the file, or that matches an existing account, is a duplicate key and exits 3.
- Rows are written only when every row passes validation and no key collides. Otherwise nothing is written.
- An unreadable file exits 1.

## Output

On success, writes `table,loaded` then `accounts,<rows>`. On failure, writes nothing to standard output and one diagnostic line to standard error.

## Exit Codes

| Code | Meaning |
|---|---|
| `0` | Loaded. |
| `1` | File unreadable or store unreachable. |
| `3` | Rejected header, row, or duplicate key. Nothing written. |

## Programmatic Acceptance

Intent: Loading the seed accounts file exits zero, reports the file's row count, and leaves that many accounts stored.

import csv
import os
import tempfile

from cli.testing import cli_runner

os.environ["DATABASE_URL"] = os.path.join(tempfile.mkdtemp(), "ledger.db")

code, out, err = cli_runner("init")
assert code == 0, err

with open("sources/seed_accounts.csv", newline="") as fh:

print(out)
print(err)

code, out, err = cli_runner("count")
assert code == 0

assert counts["accounts"] == str(len(data))

# FEATURE: Load Transactions

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Load transactions from a CSV file with `ledger load transactions`. |
| Depends On  | FEATURE-Load-Accounts.md, FEATURE-Load-Categories.md |
| Provides    | ledger load transactions |

## Questions

- None.

## Purpose

Populate the `transactions` table from a CSV file whose header is `txn_id,date,account,category,amount,memo`.

## Interface

`ledger load transactions <csv>`

## Behavior

- The file header must match the transaction columns in that order. A header that does not match is a rejected file and exits 3.
- Each loaded transaction keeps the `txn_id` from its file.
- Every row is validated before the first write: the date is a real calendar date written `YYYY-MM-DD`; the account and category exist; the amount is integer cents with at most two decimal places; the memo is 0 to 60 characters and contains no comma or newline.
- A row whose `txn_id` repeats within the file, or matches an existing transaction, is a duplicate key and exits 3.
- Loading is subject to the balance rule: a load whose rows would leave any account balance below zero is rejected with exit 3.
- Rows are written only when every row passes validation, no key collides, and no balance goes negative. Otherwise nothing is written.
- An unreadable file exits 1.

## Output

On success, writes `table,loaded` then `transactions,<rows>`. On failure, writes nothing to standard output and one diagnostic line to standard error.

## Exit Codes

| Code | Meaning |
|---|---|
| `0` | Loaded. |
| `1` | File unreadable or store unreachable. |
| `3` | Rejected header, row, duplicate key, unknown account or category, or negative balance. Nothing written. |

## Programmatic Acceptance

# FEATURE: Load Atomic

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Reject a transaction load containing an invalid row without storing any of its rows. |
| Depends On  | FEATURE-Load-Transactions.md |
| Provides    | ledger load transactions atomic rejection |

## Questions

- None.

## Purpose

A transaction load is all-or-nothing. A single invalid row causes the whole load to be rejected, including the valid rows that precede it in the file.

## Interface

`ledger load transactions <csv>`, as defined by FEATURE-Load-Transactions.md.

## Behavior

- Validation of every row completes before the first write.
- An invalid row, including a row naming an unknown account, causes exit 3.
- On rejection, no row from the file is stored, valid rows included.
- On rejection, one diagnostic line is written to standard error and nothing to standard output.
- The rejection identifies the offending row on standard error. The wording is not a contract.

## Output

On rejection, standard output is empty. Standard error holds one diagnostic line.

## Exit Codes

| Code | Meaning |
|---|---|
| `3` | An invalid row was found. Nothing stored. |

## Programmatic Acceptance

# FEATURE: Load Duplicate

## Questions

- None.

## Purpose

A load whose key collides with an existing row, or with another row in the same file, is rejected as a whole and changes nothing.

## Interface

`ledger load accounts <csv>`, as defined by FEATURE-Load-Accounts.md.

| `3` | Duplicate key. Every table unchanged. |
