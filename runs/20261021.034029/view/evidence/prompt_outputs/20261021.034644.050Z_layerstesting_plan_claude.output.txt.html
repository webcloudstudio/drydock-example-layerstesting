# FEATURE: Account Get

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Retrieve one account by code with `ledger account get`, writing its row or exiting 4 when absent. |
| Depends On  | FEATURE-Acct-Add.md, ARCHITECTURE.md, DATABASE.md |
| Provides    | ledger account get |
| Consumes    | accounts.get |

## Questions

- None.

## Purpose

Read one account so an operator can check its name and current balance before posting or amending.

## Command

`ledger account get <code>`

## Reads

- `accounts.get` (FEATURE-LEDGER-002) with the account code as input.
- The `transactions` count and `balance` are computed from the database at query time: the count of the account's transactions, and the sum of its transaction amounts in integer cents.

## Output

On success, standard output is a header row and one data row, CSV, no quoting:

```text
account,name,transactions,balance
<code>,<name>,<transactions>,<balance>
```

`balance` is written with exactly two decimal places and a leading `-` when negative.

## Exit Codes

- `0` on success.
- `4` when no account has the given code. Nothing is written to standard output; one diagnostic line goes to standard error.

## Programmatic Acceptance

# FEATURE: Account Rename

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Rename an existing account with `ledger account rename`, writing the updated row or exiting 4 when absent. |
| Depends On  | FEATURE-Acct-Add.md, FEATURE-Acct-Get.md, ARCHITECTURE.md, DATABASE.md |
| Provides    | ledger account rename |
| Consumes    | accounts.get, accounts.update |

## Questions

- None.

## Purpose

Change the display name of an account. The code, the transactions, and the balance are not affected.

## Command

`ledger account rename <code> <name>`

## Reads and Writes

- Reads the account with `accounts.get` (FEATURE-LEDGER-002) to decide whether it exists.
- Writes only the name with `accounts.update` (FEATURE-LEDGER-004).
- The name is validated before any write: 1 to 40 characters, with no comma and no newline.

## Output

On success, standard output is the header row and the updated account row, in the form of `account,name,transactions,balance`.

## Exit Codes

- `0` on success.
- `3` when the name fails validation. Nothing is written.
- `4` when no account has the given code. Nothing is written; one diagnostic line goes to standard error.

# FEATURE: Account Delete

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Delete an account with `ledger account delete`, refused while the account has transactions and exiting 4 when absent. |
| Depends On  | FEATURE-Acct-Add.md, FEATURE-Txn-Post.md, ARCHITECTURE.md, DATABASE.md |
| Provides    | ledger account delete |
| Consumes    | accounts.get, transactions.list, accounts.delete |

## Questions

- None.

## Purpose

Remove an account that is no longer used. An account that still owns transactions is never removed, so no transaction is left pointing at a missing account.

## Command

`ledger account delete <code>`

## Reads and Writes

- Reads the account with `accounts.get` (FEATURE-LEDGER-002). If absent, the command exits 4.
- Reads the account's transactions with `transactions.list` (FEATURE-LEDGER-011). If any exist, the command exits 3 and changes nothing.
- Otherwise removes the account with `accounts.delete` (FEATURE-LEDGER-005).

## Output

On success, standard output is two lines: `deleted`, then the code.

## Exit Codes

- `0` on success.
- `3` when the account has one or more transactions. The account is left in place and nothing is written.
- `4` when no account has the given code. Nothing is written; one diagnostic line goes to standard error.

# FEATURE: Transaction Post

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Post one cash transaction with `ledger txn post`, validating every input and balance rule before the single write. |
| Depends On  | FEATURE-Acct-Add.md, FEATURE-Load-Categories.md, ARCHITECTURE.md, DATABASE.md |
| Provides    | ledger txn post |
| Consumes    | accounts.get, categories.get, transactions.list, transactions.create |

## Questions

- None.

## Purpose

Record one receipt or payment against an account and category. This is the only way a new transaction enters the ledger outside loading and transfers.

## Command

`ledger txn post <account> <category> <amount> <date> [<memo>]`

## Validation

All of the following are checked before the first write. Any failure exits 3 and writes nothing.

- `account` exists (`accounts.get`); an unknown account is rejected.
- `category` exists (`categories.get`); an unknown category is rejected.
- `amount` matches `-?DIGITS[.D[D]]`: at most two decimal places, never zero. It is stored as integer cents.
- `date` is a real calendar date written `YYYY-MM-DD`.
- `memo` is 0 to 60 characters, with no comma and no newline. An absent memo is stored as empty.
- The account balance after the post is not below zero. The balance is the sum of the account's transaction amounts, computed from `transactions.list`.

## Transaction Id

The new row receives one more than the largest `txn_id` present (`transactions.list`), or `1` when the table is empty. Ids are never reused.

## Output

On success, standard output is the header row and the new row:

```text
txn_id,date,account,category,amount,memo
<id>,<date>,<account>,<category>,<amount>,<memo>
```

`amount` is written with exactly two decimal places.

## Exit Codes

- `0` on success.
- `3` for any validation or balance failure above. Nothing is written.

# FEATURE: Transaction Get

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Retrieve one transaction by id with `ledger txn get`, writing its row or exiting 4 when absent. |
| Depends On  | FEATURE-Txn-Post.md, ARCHITECTURE.md, DATABASE.md |
| Provides    | ledger txn get |
| Consumes    | transactions.get |

## Questions

- None.

## Purpose

Read one transaction so an operator can confirm what was recorded.

## Command

`ledger txn get <id>`

## Reads

- `transactions.get` (FEATURE-LEDGER-010) with the id as input.
- No writes.

## Output

On success, standard output is the header row and the transaction row:

```text
txn_id,date,account,category,amount,memo
<id>,<date>,<account>,<category>,<amount>,<memo>
```

`amount` is written with exactly two decimal places and a leading `-` when negative.

## Exit Codes

- `0` on success.
- `4` when no transaction has the given id. Nothing is written to standard output; one diagnostic line goes to standard error.

## Programmatic Acceptance
