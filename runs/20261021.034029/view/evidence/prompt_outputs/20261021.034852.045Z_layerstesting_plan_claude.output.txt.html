# FEATURE: Txn Amend

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Amend the amount of a posted transaction with `ledger txn amend`, rejecting negative balances and absent ids. |
| Depends On  | DATABASE.md, FEATURE-Txn-Post.md |
| Provides    | ledger txn amend |
| Consumes    | None. |

## Questions

- None.

## Purpose

`ledger txn amend <id> <amount>` changes the amount of one existing transaction. Only the amount
changes. The command validates the amount and the resulting account balance before its first write.
On success it writes the updated transaction row as CSV.

## Behavior

- An absent id exits 4 and changes nothing.
- An amount with more than two decimal places exits 3 and changes nothing.
- An amount that would leave the account balance below zero exits 3 and changes nothing.
- On success the row is written with header `txn_id,date,account,category,amount,memo`.

## Programmatic Acceptance

=== AC txn-amend-roundtrip ===
Intent: `ledger txn amend` changes only the amount of a posted transaction, and a read-back returns the new amount with every other field unchanged.

# FEATURE: Transfer

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Move cash between two accounts with `ledger transfer`, writing two linked rows atomically or changing nothing. |
| Depends On  | DATABASE.md, FEATURE-Txn-Post.md |
| Provides    | ledger transfer |
| Consumes    | None. |

## Questions

- None.

## Purpose

`ledger transfer <from> <to> <amount> <date>` records a movement of cash between two accounts as
two rows in category `TRANSFER`. The outgoing row carries `-amount` on `<from>` and the incoming row
carries `+amount` on `<to>`. Both rows are written together or neither is written.

## Behavior

- The amount must be positive. The two accounts must differ. Either violation exits 3 and changes nothing.
- A transfer that would leave either account balance below zero exits 3 and changes nothing.
- On success the two rows take ids N and N+1, where N is one more than the largest id present.
- On success the output header is `txn_id,date,account,category,amount,memo`, followed by the outgoing row and then the incoming row.

## Programmatic Acceptance

=== AC transfer-roundtrip ===
Intent: `ledger transfer` writes two TRANSFER rows with ids N and N+1, with opposite signed amounts on the two accounts, and both rows read back correctly.
