# FEATURE: Re-initialization Drops Every Row

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | A second `ledger init` leaves the accounts, categories, and transactions tables at zero rows. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-Schema-Init.md |
| Provides    | ledger init (re-run) |
| Consumes    | accounts.list, categories.list, transactions.list |

## Questions

- None.

## Purpose

Running `ledger init` a second time, after data has been loaded, must discard every row and leave all three tables empty. This is the reinitialization guarantee for CLI-002.

## Behavior

1. `ledger init` drops and recreates `accounts`, `categories`, and `transactions` empty.
2. A second run of `ledger init` on a populated store leaves every table at zero rows.
3. `ledger init` writes nothing to standard output and exits 0.

| Provides    | ledger load transactions |
| Consumes    | transactions.create, accounts.get, categories.get |

## Questions

- None.

## Purpose

Populate the `transactions` table from a CSV file, so that reports can be computed from the database.

## Behavior

1. `ledger load transactions <csv>` reads a CSV with header `txn_id,date,account,category,amount,memo`.
2. Each loaded transaction keeps the `txn_id` from its file.
3. Every row is validated (account and category exist, amount in cents, date is a real calendar date) before any write.
4. On success, writes `table,loaded` then `transactions,<rows>`.
5. A load into a non-empty table adds rows only when every row validates and no key collides; otherwise it exits 3 and changes nothing (Q-002).

# FEATURE: Atomic Load Rejection

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | A transactions load containing an invalid row, including an unknown account, exits 3 and stores none of its rows. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-Load-Transactions.md |
| Provides    | ledger load transactions (rejection path) |
| Consumes    | transactions.create |

## Questions

- None.

## Purpose

A load is all-or-nothing. If any row fails validation, none of the file's rows may be stored, including rows that were individually valid.

## Behavior

1. A transactions load whose file contains an invalid row exits 3.
2. The command writes nothing to standard output and one diagnostic line to standard error.
3. No row from the file, including rows before the invalid one, is stored.
4. Row 11 of `seed_transactions_bad.csv` names unknown account `NOSUCH` and is the rejecting row.
