# FEATURE: Account Delete

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Delete an account that has no transactions through `ledger account delete <code>`. |
| Depends On  | DATABASE.md, FEATURE-ACCOUNT-RENAME.md, FEATURE-NONNEGATIVE-BALANCE.md |
| Provides    | ledger account delete |
| Consumes    | accounts.get, transactions.list, accounts.delete |

## Questions

- None.

## Purpose

`ledger account delete <code>` removes an account that no transaction references. An account that
still has transactions is never removed, and no transaction is changed or removed to make room.

## Behavior

- Validate `<code>` with the code rule: 1 to 12 characters from `A-Z` and `0-9`. An invalid code
  exits 3.
- Read the account. An absent code exits 4 and writes nothing.
- Read the transactions. If any transaction names the account, exit 3 and change nothing.
- Otherwise delete the account row inside the command's transaction, commit, then write the header
  `deleted` and the code.
- On any failure, write nothing to standard output and one diagnostic line to standard error.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-003` — read: list transactions to refuse deletion while the account is in use - supplies: none - returns: `account`
- `FEATURE-ACCOUNT-005` — write: delete the account row - supplies: `account` - returns: `deleted`

## Programmatic Acceptance

=== AC account-delete-removes ===
Intent: Deleting an account with no transactions exits 0, writes deleted then the code, and removes the account row.

import os
import tempfile

from cli.testing import cli_runner
from persistence.testing import db_session

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn
account_code = "CASH9"
with db_session(dsn) as db:
    db.accounts.create(account=account_code, name="Event Float")

exit_code, out, err = cli_runner("account", "delete", account_code)
print(out)
print(err)
assert exit_code == 0
assert out.splitlines() == ["deleted", account_code]
with db_session(dsn) as db:
    assert account_code not in [row.account for row in db.accounts.list()]
=== END AC account-delete-removes ===

# FEATURE: Transaction Post

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Post a new cash transaction through `ledger txn post`, assigning the next transaction id. |
| Depends On  | DATABASE.md, FEATURE-ACCOUNT-ADD.md, FEATURE-LOAD-CATEGORIES.md, FEATURE-NONNEGATIVE-BALANCE.md, FEATURE-VALIDATE-CODE.md, FEATURE-VALIDATE-TEXT.md, FEATURE-VALIDATE-AMOUNT.md, FEATURE-VALIDATE-DATE.md |
| Provides    | ledger txn post |
| Consumes    | accounts.get, categories.get, transactions.list, transactions.create |

## Questions

- None.

## Purpose

`ledger txn post <account> <category> <amount> <date> [<memo>]` records one receipt or payment
against an existing account and category. The command assigns the transaction id; the caller
never supplies it.

## Behavior

- Validate the account and category codes, the amount, the date, and the memo. The memo is optional
  and holds 0 to 60 characters with no comma or newline. Any violation exits 3.
- Read the account and the category. An unknown account or category exits 3.
- Read the largest existing `txn_id`. The new id is one more than that, or `1` when the table is
  empty.
- Insert the row, check that no account balance is below zero, then commit.
- On success, write the header `txn_id,date,account,category,amount,memo` and the new row. Amounts
  are written with exactly two decimal places.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`, `name`
- `FEATURE-CATEGORY-002` — read: confirm the category exists - supplies: `category` - returns: `category`, `description`
- `FEATURE-TXN-003` — read: list transactions to find the largest `txn_id` and check balances - supplies: none - returns: `txn_id`, `account`, `amount`
- `FEATURE-TXN-001` — write: insert the new transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

| Field       | Value |

# FEATURE: Transaction Amend

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Change the amount of one transaction through `ledger txn amend <id> <amount>`. |
| Depends On  | DATABASE.md, FEATURE-TXN-GET.md, FEATURE-NONNEGATIVE-BALANCE.md, FEATURE-VALIDATE-AMOUNT.md |
| Provides    | ledger txn amend |
| Consumes    | transactions.get, transactions.list, transactions.update |

## Questions

- None.

## Purpose

`ledger txn amend <id> <amount>` replaces the amount of one transaction. No other field changes.

## Behavior

- Validate the amount with the amount rule. A violation exits 3.
- Read the transaction. An absent id exits 4 and writes nothing.
- Update only the `amount` field inside the command's transaction.
- Check that no account balance is below zero after the change. A violation exits 3 and rolls back.

  row.

- `FEATURE-TXN-002` — read: confirm the transaction exists - supplies: `txn_id` - returns: `txn_id`, `account`, `amount`
- `FEATURE-TXN-003` — read: list transactions to check balances after the change - supplies: none - returns: `account`, `amount`
- `FEATURE-TXN-004` — write: update the amount - supplies: `txn_id`, `amount` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

# FEATURE: Transaction Delete

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Delete one transaction through `ledger txn delete <id>`. |
| Depends On  | DATABASE.md, FEATURE-TXN-GET.md, FEATURE-TXN-POST.md, FEATURE-NONNEGATIVE-BALANCE.md |
| Provides    | ledger txn delete |
| Consumes    | transactions.get, transactions.list, transactions.delete |

## Questions

- None.

## Purpose

`ledger txn delete <id>` removes one transaction. A deleted id becomes available again: the next
post takes the largest remaining id plus one.

## Behavior

- Read the transaction. An absent id exits 4 and writes nothing.
- Delete the row inside the command's transaction.
- Check that no account balance is below zero after the deletion. A violation exits 3 and rolls back.
- On success, commit and write the header `deleted` and the id.

## Database Interface

- `FEATURE-TXN-002` — read: confirm the transaction exists - supplies: `txn_id` - returns: `txn_id`
- `FEATURE-TXN-003` — read: list transactions to check balances after the deletion - supplies: none - returns: `account`, `amount`
- `FEATURE-TXN-005` — write: delete the transaction row - supplies: `txn_id` - returns: `deleted`

## Programmatic Acceptance

import os

import os
import tempfile

from cli.testing import cli_runner
from persistence.testing import db_session

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn
account_code = "CASH1"
category_code = "SALES"
date_value = "2026-04-01"
with db_session(dsn) as db:
    db.accounts.create(account=account_code, name="Cash One")
    db.categories.create(category=category_code, description="Sales receipts")
    db.transactions.create(
        txn_id=1, date=date_value, account=account_code, category=category_code,
        amount=4550, memo="sale",
    )
    db.transactions.create(
        txn_id=2, date=date_value, account=account_code, category=category_code,
        amount=100, memo="sale",
    )
largest_remaining_id = 1
delete_exit, delete_out, delete_err = cli_runner("txn", "delete", "2")
print(delete_err)
assert delete_exit == 0

post_exit, post_out, post_err = cli_runner(
    "txn", "post", account_code, category_code, "1.00", date_value
)
print(post_err)
assert post_exit == 0
assert int(post_out.splitlines()[1].split(",")[0]) == largest_remaining_id + 1
=== END AC txn-delete-id-reused ===

## Guardrails

- `txn delete` never deletes a row for an absent id.
- A deletion that leaves any account balance below zero is never committed.
