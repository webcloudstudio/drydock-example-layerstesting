## Overview

The cash ledger is a local, single-user command-line program. Its executable is `ledger` at the
application root. Every command reaches the database only through the generated persistence package,
runs as one transaction, and writes CSV to standard output with diagnostics on standard error.

## Layout

| Path | Owner | Purpose |
|------|-------|---------|
| `ledger` | cli | Executable at the application root that dispatches each command. |
| `cli/` | cli | Command dispatch, CSV output, exit codes, and usage errors. |
| `amounts.py` | amounts | Conversion between integer cents and two-decimal amount text. |
| `config.py` | config | Resolution of `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |

| `schema.sql` | generated | Idempotent DDL generated from `DATABASE.md`. |
| `bin/test.sh` | test runner | POSIX runner for the project suite with a slice selector. |
| `tests/` | project suite | pytest tests written beside the code. |
| `pyproject.toml`, `uv.lock`, `.venv/` | language foundation | Dependency manifest, lockfile, and environment. |

## Module Ownership

| Boundary | Owner | Low-level access permitted |
|----------|-------|----------------------------|
| Persistence | `persistence/` package | `sqlite3` and `psycopg` are reached only inside `persistence/`. |
| Configuration | `config.py` | Reads `DATABASE_URL` and `DATABASE_PATH` from the environment. |
| File store | None | The product has no file store beyond the database. |
| External service | None | Network access only to the PostgreSQL server named by `DATABASE_URL`. |

## Technology Stack

- Python 3.11 or newer: implementation language and pytest test runner (`python.md`).
- SQLite: default database engine, reached through the persistence library (`sqlite.md`).
- PostgreSQL: engine selected when `DATABASE_URL` is a `postgres://` or `postgresql://` DSN,
  with `psycopg[binary]` as the driver (`postgres.md`). Variance: `TECHNOLOGY_STACK.md` does not list
  PostgreSQL, but `sources/INSTRUCTIONS.md` requires it. The sources govern, per decision Q-001.
- CLI: the `ledger` executable (`cli.md`).
- Shell: POSIX `sh` for `bin/test.sh` and the supplied grader (`common.md`).

## Technical Decisions

- Amounts are stored as integer cents. No layer uses floating point for money.
- Every command runs as one database transaction through `open_database(dsn)`.
- `pyproject.toml` declares Python 3.11 or newer, `pytest`, and `psycopg[binary]`. `uv.lock` is
  committed. `.venv` is created by `uv venv`.

## Questions

- None.

## Purpose

`bin/test.sh` is the single entry point for the project's automated tests. Story-level builds run
a slice of the suite. The terminal story runs the whole suite.

## Behavior

- `sh bin/test.sh` runs `pytest -q` from the application root with no selector.
- `sh bin/test.sh SLICE` passes `SLICE` to pytest as a `-k` expression, narrowing the run to the
  matching tests.
- Before running pytest, the script exports `DATABASE_URL` pointing at a fresh temporary SQLite
  file, so tests never touch the user's database.
- The script exits `0` only when every selected test passes, and a nonzero status otherwise.
- The script uses the interpreter in `.venv` when it exists.
- The script is POSIX `sh`.

=== AC test-runner-selector ===
Intent: The slice selector runs only the matching tests and reports their result in the exit status.

import os
import subprocess

probes = {
    "tests/test_ac_probe_pass.py": "def test_probe_pass():\n    assert True\n",
    "tests/test_ac_probe_fail.py": "def test_probe_fail():\n    assert False\n",
}
os.makedirs("tests", exist_ok=True)
try:
    for path, source in probes.items():
        with open(path, "w", encoding="utf-8") as handle:
            handle.write(source)
    passing = subprocess.run(["sh", "bin/test.sh", "probe_pass"], capture_output=True, text=True)
    failing = subprocess.run(["sh", "bin/test.sh", "probe_fail"], capture_output=True, text=True)
finally:
    for path in probes:
        if os.path.exists(path):
            os.remove(path)
print(passing.stdout)
print(passing.stderr)
print(failing.stdout)
print(failing.stderr)
assert passing.returncode == 0
assert failing.returncode != 0
=== END AC test-runner-selector ===

# FEATURE: Database Selection

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Resolves the database location from the environment and reports connection failures as persistence errors. |
| Depends On  | DATABASE.md, FEATURE-TEST-RUNNER.md |
| Provides    | resolve_dsn(environ) -> str |
| Consumes    | open_database(dsn) |

## Questions

- None.

## Purpose

Every command opens the database at the location the environment names. Resolution lives in
`config.py`, and the persistence library then selects the engine from the DSN.

## Behavior

- `resolve_dsn(environ)` returns the value of `DATABASE_URL` when it is set and non-empty.
- Otherwise it returns the value of `DATABASE_PATH` when that is set and non-empty.
- Otherwise it returns `data/app.db`.
- The returned value is the configured string unchanged. No normalization is applied.
- A `postgres://` or `postgresql://` DSN selects PostgreSQL. Any other value selects SQLite, with an
  optional `sqlite://` prefix. The persistence library makes that choice.
- Connection failures and expired connect attempts surface as `PersistenceError`, so the command
  layer can exit `1`.

## Programmatic Acceptance

# FEATURE: Amount Cents

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Converts between validated amount text and integer cents using integer arithmetic only. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-TEST-RUNNER.md |
| Provides    | parse_amount(text) -> int; format_cents(cents) -> str |

## Questions

- None.

## Purpose

Amounts are stored as integer cents and shown with two decimal places. This module is the only place
that converts between the two forms.

## Behavior

- `parse_amount(text)` accepts text matching `-?DIGITS[.D[D]]`, with at most two decimal places, and
  returns the signed integer cent value. `12.5` is `1250` cents.
- `parse_amount` raises `ValueError` for any other text, including text with more than two decimal
  places and text containing a comma.
- `format_cents(cents)` returns text with exactly two decimal places, a leading `-` when negative,
  and no thousands separator.
- All arithmetic is integer arithmetic. No float or `Decimal` conversion is used at any point.

## Programmatic Acceptance
