# FEATURE: Account Add

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | `account add` stores a new account with zero transactions and a zero balance; a duplicate code exits 3. |
| Depends On  | FEATURE-ATOMIC-COMMANDS.md, FEATURE-VALIDATE-CODE.md, FEATURE-VALIDATE-TEXT.md, DATABASE.md |
| Provides    | ledger account add <code> <name> |
| Consumes    | accounts.create, accounts.get |

## Purpose

`ledger account add <code> <name>` creates one account. The command is one transaction. The output
is the new account row in the `account,name,transactions,balance` format.

## Behavior

- The code and name are validated before any database access.
- A new account has zero transactions and a balance of `0.00`.
- A code that already exists is rejected with exit 3 and changes nothing.

## Database Interface

- `FEATURE-ACCOUNT-001` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-ACCOUNT-002` — read: retrieve an account by code - supplies: `account` - returns: `account`, `name`

## Programmatic Acceptance

=== AC account-add-round-trip ===
# Intent: `account add` stores the account, reports zero transactions and a zero balance, and is readable back through the database.

import csv
import io
import os
import sys
import tempfile
from decimal import Decimal
from pathlib import Path

from cli.testing import cli_runner
from persistence.testing import db_session

dsn = str(Path(tempfile.mkdtemp()) / "ledger.db")
os.environ["DATABASE_URL"] = dsn

account_code = "CASH9"
account_name = "Event Float"

exit_code, out, err = cli_runner("init")
assert exit_code == 0

exit_code, out, err = cli_runner("account", "add", account_code, account_name)
print(out)
print(err, file=sys.stderr)
assert exit_code == 0

rows = list(csv.DictReader(io.StringIO(out)))
assert len(rows) == 1
assert rows[0]["account"] == account_code
assert rows[0]["name"] == account_name
assert int(rows[0]["transactions"]) == 0
assert Decimal(rows[0]["balance"]) == Decimal(0)

with db_session(dsn) as db:
    stored = db.accounts.get(account=account_code)
assert stored is not None
assert stored.name == account_name
=== END AC account-add-round-trip ===

# FEATURE: Atomic Transaction Load Rejection

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | A transaction load with any invalid or duplicate row exits 3 and stores none of its rows. |
| Depends On  | FEATURE-LOAD-TRANSACTIONS.md, FEATURE-ATOMIC-COMMANDS.md, FEATURE-NONNEGATIVE-BALANCE.md, DATABASE.md |
| Provides    | ledger load transactions <csv> (atomic rejection) |
| Consumes    | ledger load transactions <csv>, transactions.create, accounts.get, categories.get |

## Purpose

A load of transactions is one command. If any row fails validation, references an unknown account
or category, or repeats a `txn_id`, the whole command is rejected. No row from the file persists,
including rows that were valid on their own. The rejection exits 3 and writes one diagnostic line
to standard error.

## Behavior

- Every row is validated before commit. The first failing row ends the command.
- The transaction is rolled back. Rows 1 to 10 of `sources/seed_transactions_bad.csv` do not persist
  when row 11 names the unknown account `NOSUCH`.
- A file containing two rows with the same `txn_id` is rejected in full.
- A rejected load leaves `transactions` exactly as it was.

## Database Interface

- `FEATURE-TXN-001` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-ACCOUNT-002` — read: retrieve an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-CATEGORY-002` — read: retrieve a category by code - supplies: `category` - returns: `category`, `description`

## Programmatic Acceptance

=== AC load-atomic-bad-file ===

# FEATURE: Load Header Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | A load whose header does not match the table's columns in order exits 3; an unreadable file exits 1. |
| Depends On  | FEATURE-LOAD-TRANSACTIONS.md, FEATURE-ACCOUNT-001.md, DATABASE.md |
| Provides    | header validation for ledger load <table> <csv> |
| Consumes    | ledger load <table> <csv>, accounts.create, transactions.list |

## Purpose

Before any row is read, the loader compares the file's header with the table's declared columns.
The comparison is exact and ordered. A mismatch is a rejected file and exits 3. A file that cannot
be opened or read is an operational failure and exits 1.

## Behavior

- Column names must match the table's columns in the order given in `sources/INSTRUCTIONS.md`.
- A reordered, renamed, missing, or extra column is a mismatch.
- A mismatch stores no rows and changes no table.
- An unreadable or nonexistent file exits 1 and changes no table.

## Database Interface

- `FEATURE-ACCOUNT-001` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-TXN-003` — read: list transactions - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance
