# FEATURE: Transfer Between Accounts

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Moves an amount between two accounts as two linked rows in category TRANSFER. |
| Depends On  | FEATURE-TXN-POST.md, FEATURE-NONNEGATIVE-BALANCE.md, FEATURE-VALIDATE-AMOUNT.md, FEATURE-VALIDATE-DATE.md |
| Provides    | ledger transfer |

## Questions

- None.

## Purpose

`ledger transfer <from> <to> <amount> <date>` records an internal movement of cash. It stores two rows in category `TRANSFER`: a negative row on `<from>` and a positive row on `<to>`, with the memos and ids the Commands table specifies.

## Behavior

1. Validate `<from>`, `<to>`, `<amount>`, and `<date>` with the shared validators.
2. Open one database transaction.
3. Assign the outgoing row the next `txn_id` (one more than the largest present, or `1` in an empty table) and the incoming row the id after it.
4. Insert both rows, check that no account balance is below zero, then commit.
5. Write the header row and the two transaction rows to standard output, outgoing row first.

Identical accounts, non-positive amounts, and unknown accounts are rejected before any row is written. Those cases are specified in FEATURE-TRANSFER-REJECTION.md.

## Programmatic Acceptance

=== AC transfer-stores-two-linked-rows ===
Intent: A successful transfer stores a negative row on the source and a positive row on the destination, with consecutive ids and the TRANSFER category.

import csv
import io
import os
import tempfile
from decimal import Decimal

from cli.testing import cli_runner
from persistence import open_database

os.environ["DATABASE_URL"] = os.path.join(tempfile.mkdtemp(), "ledger.db")
for args in (
    ("init",),
    ("load", "accounts", "sources/seed_accounts.csv"),
    ("load", "categories", "sources/seed_categories.csv"),
    ("load", "transactions", "sources/seed_transactions.csv"),
):
    code, out, err = cli_runner(*args)
    assert code == 0, err

db = open_database(os.environ["DATABASE_URL"])
previous_max = max(row.txn_id for row in db.transactions.list())

from_account = "DRAWER1"
to_account = "SAFE"
amount_text = "500.00"
amount_cents = 50000
date = "2026-04-03"

code, out, err = cli_runner("transfer", from_account, to_account, amount_text, date)
assert code == 0, err
rows = list(csv.reader(io.StringIO(out)))
assert len(rows) == 3, rows
header, outgoing_fields, incoming_fields = rows
assert header == ["txn_id", "date", "account", "category", "amount", "memo"]

outgoing = dict(zip(header, outgoing_fields))
incoming = dict(zip(header, incoming_fields))
assert int(outgoing["txn_id"]) == previous_max + 1
assert int(incoming["txn_id"]) == previous_max + 2
assert outgoing["account"] == from_account
assert incoming["account"] == to_account
assert outgoing["category"] == incoming["category"] == "TRANSFER"
assert outgoing["date"] == incoming["date"] == date
assert int(Decimal(outgoing["amount"]).scaleb(2)) == -amount_cents
assert int(Decimal(incoming["amount"]).scaleb(2)) == amount_cents
assert outgoing["memo"].split() == ["transfer", "to", to_account]
assert incoming["memo"].split() == ["transfer", "from", from_account]

for fields in (outgoing, incoming):
    code, out, err = cli_runner("txn", "get", fields["txn_id"])
    assert code == 0, err
    stored = list(csv.reader(io.StringIO(out)))
    assert stored[1] == [fields[name] for name in header]

# FEATURE: Transfer Rejection

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Rejects invalid transfers with exit 3 and no change to any table. |
| Depends On  | FEATURE-TRANSFER.md, FEATURE-VALIDATE-AMOUNT.md |

## Questions

- None.

## Purpose

A transfer is rejected when its two accounts are identical, its amount is not positive, its amount is zero, or either account is unknown. Each rejection exits 3, writes nothing to standard output, and leaves every table exactly as it was.

## Behavior

1. Check that `<from>` and `<to>` differ.
2. Check that `<amount>` is positive and passes the amount rules.
3. Check that both accounts exist.
4. On any failure, roll back and exit 3 with one diagnostic line on standard error.

## Programmatic Acceptance

# FEATURE: Balances Report

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Reports each account's transaction count and balance, then a TOTAL row, computed from the database. |
| Depends On  | FEATURE-LOAD-TRANSACTIONS.md, FEATURE-TRANSFER.md, FEATURE-TXN-DELETE.md, FEATURE-CSV-OUTPUT.md |
| Provides    | ledger report balances |

## Questions

- None.

## Purpose

`ledger report balances` writes `account,name,transactions,balance` for every account ordered by code, followed by `TOTAL,,<count>,<sum>`. The balance of an account is the sum of its transaction amounts.

## Behavior

1. Read every account and every transaction from the database.
2. For each account, count its transactions and sum their amounts in integer cents.
3. Write one row per account ordered by code, then the TOTAL row over all transactions.
4. Write amounts with exactly two decimal places.

When no accounts exist, only the header and the TOTAL row are written, with count `0` and sum `0.00`.

## Programmatic Acceptance

=== AC report-balances-match-database ===
Intent: Each balances row and the TOTAL row equal values computed from the accounts and transactions read back from the database.

# FEATURE: Categories Report

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Reports inflow, outflow, and net per category, including categories with no transactions, then a TOTAL row, computed from the database. |
| Depends On  | FEATURE-LOAD-TRANSACTIONS.md, FEATURE-TRANSFER.md, FEATURE-TXN-DELETE.md, FEATURE-CSV-OUTPUT.md |
| Provides    | ledger report categories |

## Questions

- None.

## Purpose

`ledger report categories` writes `category,description,transactions,inflow,outflow,net` for every category ordered by code, followed by `TOTAL,,<count>,<inflow>,<outflow>,<net>`.

## Behavior

1. Read every category and every transaction from the database.
2. For each category, count its transactions, sum positive amounts as `inflow`, and sum the absolute values of negative amounts as `outflow`.
3. Compute `net` as `inflow - outflow`.
4. Write one row per category ordered by code, including categories with no transactions, then the TOTAL row.

When no categories exist, only the header and the TOTAL row are written, with zeros in every numeric column.

## Programmatic Acceptance

# FEATURE: Monthly Report

## Questions

- None.

## Purpose

`ledger report monthly` writes `month,transactions,inflow,outflow,net` for every `YYYY-MM` that has transactions, in ascending order, followed by `TOTAL,<count>,<inflow>,<outflow>,<net>`.
