# FEATURE: Validate Text

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Validates free-text names, descriptions, and memos against their length limits and forbidden characters. |
| Depends On  | ARCHITECTURE.md, FEATURE-EXIT-CODES.md, FEATURE-TEST-RUNNER.md |
| Provides    | validation.text.validate_text |

## Questions

- None.

## Purpose

Names and descriptions must be 1 to 40 characters. Memos must be 0 to 60 characters. None may contain a comma or a newline. This module enforces those rules before any command writes to the database.

## Behavior

- `validate_text(value, min_length, max_length)` returns `value` unchanged when `min_length <= len(value) <= max_length` and `value` contains neither `,` nor a newline.
- Any other input raises `ValueError` with a one-line message. The CLI layer maps `ValueError` from validators to exit code 3.
- Callers pass the limits: names and descriptions use `1, 40`; memos use `0, 60`.
- The module lives at `validation/text.py` as part of a namespace package. It creates no `__init__.py`.

## Programmatic Acceptance

=== AC text-accepts-bounds ===
Intent: Text at each inclusive limit, including an empty memo, is returned unchanged.

from validation.text import validate_text

name_min = "x"
name_max = "A" * 40
memo_max = "m" * 60
empty_memo = ""

assert validate_text(name_min, 1, 40) == name_min
assert validate_text(name_max, 1, 40) == name_max
assert validate_text(empty_memo, 0, 60) == empty_memo
assert validate_text(memo_max, 0, 60) == memo_max
=== END AC text-accepts-bounds ===

=== AC text-rejects-length ===
Intent: Text shorter than the minimum or longer than the maximum raises ValueError.

from validation.text import validate_text

cases = [
    ("", 1, 40),
    ("B" * 41, 1, 40),
    ("C" * 61, 0, 60),
]

    try:
        validate_text(value, low, high)
    except ValueError:
        rejected += 1
assert rejected == len(cases)
=== END AC text-rejects-length ===

Intent: A comma or a newline anywhere in the text raises ValueError regardless of length.

# FEATURE: Validate Amount

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Validates input amount text against the signed, nonzero, at-most-two-decimal rule. |
| Depends On  | ARCHITECTURE.md, FEATURE-AMOUNT-CENTS.md, FEATURE-EXIT-CODES.md, FEATURE-TEST-RUNNER.md |
| Provides    | validation.amount.validate_amount |

## Questions

- None.

## Purpose

Input amounts must match `-?DIGITS[.D[D]]`, must never be zero, and must have at most two decimal places. Invalid amounts are rejected before any conversion to integer cents.

## Behavior

- `validate_amount(text)` returns `text` unchanged when it matches `-?DIGITS[.D[D]]`, has at most two decimal places, and its numeric value is not zero.
- Any other input raises `ValueError` with a one-line message. The CLI layer maps it to exit code 3.
- Examples of rejected input include `0`, `0.00`, `-0`, `1.234`, `1.`, `.50`, `+5`, `1,000.00`, and the empty string.
- The module lives at `validation/amount.py` as part of a namespace package. It creates no `__init__.py`.

## Programmatic Acceptance

# FEATURE: Schema Init

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Implements `ledger init`, which drops and recreates the accounts, categories, and transactions tables empty. |
| Depends On  | DATABASE.md, FEATURE-EXIT-CODES.md, FEATURE-TEST-RUNNER.md |
| Provides    | ledger init |
| Consumes    | open_database(dsn) |

## Questions

- None.

## Purpose

`ledger init` gives the ledger an empty three-table schema. It is the first command the shop runs, and it is the only command that removes all rows.

## Behavior

- `ledger init` drops the `accounts`, `categories`, and `transactions` tables if present, then recreates them empty from the generated `schema.sql`.
- The command writes nothing to standard output and exits 0 on success.
- The command runs inside one database transaction, as required by FEATURE-ATOMIC-COMMANDS.
- Drop and recreate uses the generated schema lifecycle only. It adds no repository operation to `DATABASE.md`.
- An unreachable database exits 1 through the exit-code mapping in FEATURE-EXIT-CODES.

## Programmatic Acceptance

=== AC init-creates-empty-schema ===
Intent: Running init on a fresh store exits 0, writes nothing to standard output, and leaves every table empty.

import os
import sys
import tempfile

from cli.testing import cli_runner
from persistence import open_database

# FEATURE: Schema Count

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Implements `ledger count`, which reports the number of rows in each of the three tables. |
| Depends On  | FEATURE-SCHEMA-INIT.md, FEATURE-CSV-OUTPUT.md, DATABASE.md |
| Provides    | ledger count |
| Consumes    | accounts.list, categories.list, transactions.list |

## Questions

- None.

## Purpose

`ledger count` lets the shop confirm how many rows each table holds. Every count is computed from the database at the moment the command runs.

## Behavior

- `ledger count` writes the header `table,rows`, then one row each for `accounts`, `categories`, and `transactions`, in that order.
- Each count is the number of rows returned by the table's `list` operation.
- The output follows the CSV conventions in FEATURE-CSV-OUTPUT.
- The command exits 0 on success.

## Programmatic Acceptance

=== AC count-reports-each-table ===
Intent: After rows are created through the persistence layer, count reports the header and one row per table with counts read back from the database.

import csv
import io
import os
import sys
import tempfile

from cli.testing import cli_runner
from persistence import open_database

with tempfile.TemporaryDirectory() as work:
    dsn = os.path.join(work, "ledger.db")
    os.environ["DATABASE_URL"] = dsn
    code, out, err = cli_runner("init")
    assert code == 0
    db = open_database(dsn)
    db.accounts.create(account="CASH1", name="Till")
    db.accounts.create(account="CASH2", name="Safe")
    db.categories.create(category="SALES", description="Sales receipts")
    code, out, err = cli_runner("count")
    print(out)
    print(err, file=sys.stderr)
    assert code == 0
    rows = list(csv.reader(io.StringIO(out)))
    expected = [
        ["table", "rows"],
        ["accounts", str(len(db.accounts.list()))],
        ["categories", str(len(db.categories.list()))],
        ["transactions", str(len(db.transactions.list()))],
    ]
    assert rows == expected
=== END AC count-reports-each-table ===
