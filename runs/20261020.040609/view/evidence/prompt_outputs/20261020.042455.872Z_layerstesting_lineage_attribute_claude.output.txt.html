<requirement name="ledger-cli-dispatch" stories="foundation-001,cli-003,cli-004">
Build a command-line cash ledger for a small shop. The product is an executable named `ledger` at the application root.
</requirement>
<requirement name="database-selection" stories="foundation-002">
`DATABASE_URL` names the database. When `DATABASE_URL` is unset, `DATABASE_PATH` is used, then `data/app.db`.
</requirement>
<requirement name="amount-cents-format" stories="foundation-004,valid-003">
Amounts are stored as integer cents and never as floating point.
</requirement>
<requirement name="persistence-contract" stories="foundation-003,scaffold-python">
All database access goes through the shipped persistence library and the relational layer generated from `DATABASE.md`. Application code never opens a database driver directly.
</requirement>
<requirement name="schema-init" stories="schema-001">
`ledger init` drops all three tables if present and creates them empty. Nothing written.
</requirement>
<requirement name="schema-count" stories="schema-002">
`ledger count` writes `table,rows`, then `accounts`, `categories`, `transactions` rows in that order.
</requirement>
<requirement name="csv-output" stories="cli-001">
Every successful command except `init` writes CSV to standard output: one header row, then data rows, comma-separated, no quoting, no trailing spaces, `\n` line endings.
</requirement>
<requirement name="exit-codes" stories="cli-002">
| Code | Meaning |
|---|---|
| `0` | Success. |
| `1` | Operational failure: database unreachable, tables missing, file unreadable. |
| `2` | Usage error: unknown command, unknown table or report, wrong argument count. |
| `3` | Rejected: invalid code, name, amount, date, or file row; duplicate key; unknown account or category; account in use; any change that would leave a negative balance. |
| `4` | Not found: `account get/rename/delete` of an absent account, `txn get/amend/delete` of an absent id. |
</requirement>
<requirement name="validate-code" stories="valid-001">
Codes (`account`, `category`) are 1 to 12 characters from `A-Z` and `0-9`.
</requirement>
<requirement name="validate-text" stories="valid-002">
Names and descriptions are 1 to 40 characters. Memos are 0 to 60 characters. None of them contains a comma or a newline.
</requirement>
<requirement name="validate-amount" stories="valid-003">
Amounts on input match `-?DIGITS[.D[D]]`: at most two decimal places, never zero. On output an amount is written with exactly two decimal places, a leading `-` when negative, and no thousands separator: `-12.50`, `0.00`, `5000.00`.
</requirement>
<requirement name="validate-date" stories="valid-004">
Dates are real calendar dates written `YYYY-MM-DD`. `2026-02-30` is rejected.
</requirement>
<requirement name="atomic-commands" stories="integ-001">
Every command is one database transaction. A command that fails for any reason leaves every table exactly as it was. A load that rejects row 11 stores none of rows 1 to 10. A transfer stores both of its rows or neither.
</requirement>
<requirement name="nonnegative-balance" stories="integ-002,xfer-002,txn-003,txn-004,txn-001,load-003">
No command leaves an account balance below zero. An account's balance is the sum of its transaction amounts. Posting, amending, deleting, transferring, and loading are all subject to this rule, checked after the command's changes and before it commits.
</requirement>
<requirement name="load-accounts" stories="load-001,load-004,load-005">
`ledger load accounts <csv>` loads `accounts` from a file whose header matches the table's columns in the order above. Writes `table,loaded` and `accounts,<rows>`.
</requirement>
<requirement name="load-categories" stories="load-002,load-004,load-005">
`ledger load categories <csv>` loads `categories` from a file whose header matches the table's columns in the order above. Writes `table,loaded` and `categories,<rows>`.
</requirement>
<requirement name="load-transactions" stories="load-003,load-004,load-005">
`ledger load transactions <csv>` loads `transactions` from a file whose header matches the table's columns in the order above. A loaded transaction keeps the `txn_id` from its file. Writes `table,loaded` and `transactions,<rows>`.
</requirement>
<requirement name="reject-invalid-load" stories="load-004">
A load that rejects row 11 stores none of rows 1 to 10.
</requirement>
<requirement name="account-add" stories="acct-001,valid-001,valid-002,schema-001">
`ledger account add <code> <name>` writes the new account row.
</requirement>
<requirement name="account-get" stories="acct-002">
`ledger account get <code>` writes the account row.
</requirement>
<requirement name="account-rename" stories="acct-003">
`ledger account rename <code> <name>` writes the updated account row.
</requirement>
<requirement name="account-delete" stories="acct-004">
`ledger account delete <code>` writes `deleted` and the code. Refused while the account has transactions.
</requirement>
<requirement name="txn-post" stories="txn-001,valid-003,valid-004">
`ledger txn post <account> <category> <amount> <date> [<memo>]` writes the new transaction row. A posted transaction receives one more than the largest `txn_id` present, or `1` in an empty table.
</requirement>
<requirement name="txn-get" stories="txn-002">
`ledger txn get <id>` writes the transaction row.
</requirement>
<requirement name="txn-amend" stories="txn-003">
`ledger txn amend <id> <amount>` writes the updated transaction row. Only the amount changes.
</requirement>
<requirement name="txn-delete" stories="txn-004">
`ledger txn delete <id>` writes `deleted` and the id.
</requirement>
<requirement name="transfer" stories="xfer-001,xfer-002">
`ledger transfer <from> <to> <amount> <date>` writes two transaction rows in category `TRANSFER`: `-amount` on `<from>` with memo `transfer to <to>`, then `+amount` on `<to>` with memo `transfer from <from>`. The amount is positive and the accounts differ. A transfer's outgoing row takes that id and its incoming row the next.
</requirement>
<requirement name="report-balances" stories="rpt-001">
`ledger report balances` writes `account,name,transactions,balance` per account ordered by code, then `TOTAL,,<count>,<sum>`.
</requirement>
<requirement name="report-categories" stories="rpt-002">
`ledger report categories` writes `category,description,transactions,inflow,outflow,net` per category ordered by code, including categories with no transactions, then `TOTAL,,<count>,<inflow>,<outflow>,<net>`. `inflow` is the sum of positive amounts. `outflow` is the sum of the absolute values of negative amounts, written as a positive number. `net` is `inflow - outflow`.
</requirement>
<requirement name="report-monthly" stories="rpt-003">
`ledger report monthly` writes `month,transactions,inflow,outflow,net` per `YYYY-MM` that has transactions, ascending, then `TOTAL,<count>,<inflow>,<outflow>,<net>`.
</requirement>

The completed application provides a POSIX-compatible `bin/test.sh` that runs its own automated test suite from the application root and exits zero only when every test passes.
