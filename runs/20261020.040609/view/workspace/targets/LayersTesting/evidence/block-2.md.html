foundation-005: bin/test.sh

  • POSIX sh script. It runs pytest -q from the application root, or pytest -q -k SLICE when given one argument.
  • It exports DATABASE_URL as a fresh temporary SQLite path in a mktemp -d directory that is removed on exit. It never uses the caller's database.
  • It uses .venv/bin/python when present and falls back to python3.
  • It exits with pytest's status, so it is 0 only when every selected test passes.

It checks integer-cent amounts, the 60-character memo boundary, the empty-memo default, foreign-key rejection, undeclared verbs raising UnknownOperation, and per-test fresh stores.

Choices I made

  • The runner tests re-invoke bin/test.sh against a sentinel module with a selector token that appears in no other test name. This keeps the outer suite from recursing into itself.
  • The runner exports a plain path for DATABASE_URL, matching the run.sh grader, rather than a sqlite:// URL.
  • I did not add the data/logs tee logging from common.md. It would mask pytest's exit status under POSIX sh, which has no pipefail.
