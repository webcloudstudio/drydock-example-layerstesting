# Feature: Transaction Delete

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Delete one transaction by id, applying the non-negative balance rule after the delete. |
| Depends On  | DATABASE.md, FEATURE-Balance-Rule.md, FEATURE-Command-Transaction.md, FEATURE-CLI-Output.md, FEATURE-CLI-Dispatch.md |
| Provides    | ledger txn delete <id> |
| Consumes    | transactions.get, transactions.delete |

## Questions

- None.

## Purpose

`ledger txn delete <id>` removes one transaction. On success it prints `deleted` and the id. An
absent id exits 4. A delete that leaves any account below zero exits 3. Every rejected delete
changes nothing.

## Trigger

The user runs `ledger txn delete <id>`.

## Behavior

1. Parse `<id>` as an integer. A non-integer id exits 3 before any lookup.
2. Within the command transaction, fetch the row by `txn_id` through `transactions.get`. An absent
   id exits 4.
3. Remove the row through `transactions.delete`.
4. Apply the balance rule to the account the removed row touched (FEATURE-Balance-Rule.md). A
   negative balance exits 3 and rolls back the delete.
5. Commit and print:

```text
deleted
<id>
```

## Routes and Interfaces

| Interface | Kind | Notes |
|---|---|---|
| `ledger txn delete <id>` | CLI command | Exit 0 on success, 3 on rejection, 4 when absent. |

## Reads and Writes

| Operation | Access | Repository operation | Notes |
|---|---|---|---|
| Fetch transaction | read | `transactions.get` | Absent id maps to exit 4. |
| Delete transaction | write | `transactions.delete` | Runs inside the command transaction. |

# Feature: Transfer

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Store a transfer as two TRANSFER rows, or neither, under the non-negative balance rule. |
| Depends On  | DATABASE.md, FEATURE-Transaction-Post.md, FEATURE-Balance-Rule.md, FEATURE-Amount-Format.md, FEATURE-Date-Validation.md, FEATURE-Code-Validation.md, FEATURE-CLI-Output.md, FEATURE-CLI-Dispatch.md |
| Provides    | ledger transfer <from> <to> <amount> <date> |
| Consumes    | accounts.get, transactions.create, transactions.list |

## Questions

- None.

## Purpose

`ledger transfer <from> <to> <amount> <date>` moves cash between two accounts. It stores two rows
in category `TRANSFER`: `-amount` on `<from>` and `+amount` on `<to>`. Both rows are stored or
neither is.

## Trigger

The user runs `ledger transfer <from> <to> <amount> <date>`.

## Behavior

1. Validate syntax before any lookup: `<amount>` parses as a positive amount, and `<date>` is a
   real `YYYY-MM-DD` date. Either failure exits 3.
2. Require `<from>` and `<to>` to differ. Equal accounts exit 3.
3. Within the command transaction, confirm both accounts exist through `accounts.get`. A missing
   account exits 3, not 4.
4. Take the next two ids: `n` and `n+1`, where `n` is one more than the largest `txn_id` present
   (1 in an empty table), using the shared next-id function from FEATURE-Transaction-Post.md.
5. Create the row `n` on `<from>` with amount `-amount` and memo `transfer to <to>`, and the row
   `n+1` on `<to>` with amount `+amount` and memo `transfer from <from>`. Both use category
   `TRANSFER`.
6. Apply the balance rule to both touched accounts (FEATURE-Balance-Rule.md). A negative balance
   exits 3 and rolls back both rows.
7. Commit and print the two rows in CSV with the header:

```text
txn_id,date,account,category,amount,memo
<n>,<date>,<from>,TRANSFER,-<amount>,transfer to <to>
<n+1>,<date>,<to>,TRANSFER,<amount>,transfer from <from>
```

Amounts are written with exactly two decimal places (FEATURE-Amount-Format.md).

## Routes and Interfaces

| Interface | Kind | Notes |
|---|---|---|
| `ledger transfer <from> <to> <amount> <date>` | CLI command | Exit 0 on success, 3 on rejection. |

## Reads and Writes

| Operation | Access | Repository operation | Notes |
|---|---|---|---|
| Confirm accounts | read | `accounts.get` | Missing account exits 3. |
| Read largest id | read | `transactions.list` | Next id is derived from the rows, never stored. |
| Insert the two rows | write | `transactions.create` | Both inserts run inside one command transaction. |

# Feature: Report Balances

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Print one balance row per account, ordered by code, then a TOTAL row, all computed from the database. |
| Depends On  | DATABASE.md, FEATURE-Amount-Format.md, FEATURE-Command-Transaction.md, FEATURE-CLI-Output.md, FEATURE-CLI-Dispatch.md |
| Provides    | ledger report balances |
| Consumes    | accounts.list, transactions.list |

## Questions

- None.

## Purpose

`ledger report balances` reports each account's transaction count and balance, followed by a
TOTAL row across all accounts.

## Trigger

The user runs `ledger report balances`.

## Behavior

1. Within the command transaction, read every account through `accounts.list`, ordered by
   `account` ascending.
2. For each account, compute its transaction count and balance by query. The balance is the sum
   of its transaction amounts in integer cents, formatted per FEATURE-Amount-Format.md.
3. Print the header and one row per account:

```text
account,name,transactions,balance
```

4. Print the TOTAL row. Its count is the total number of transactions, and its balance is the sum
   of every transaction amount:

```text
TOTAL,,<count>,<sum>
```

5. With no accounts, print only `TOTAL,,0,0.00` after the header.

No value is embedded as a constant. Every count and sum is derived from a query.

## Routes and Interfaces

| Interface | Kind | Notes |
|---|---|---|
| `ledger report balances` | CLI command | Exit 0 on success. |

## Reads and Writes

| Operation | Access | Repository operation | Notes |
|---|---|---|---|
| List accounts | read | `accounts.list` | Ordered by code. |
| List transactions | read | `transactions.list` | Aggregated per account and in total. |

# Feature: Report Categories

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Print one row per category, including categories with no transactions, ordered by code, then a TOTAL row, all computed from the database. |
| Depends On  | DATABASE.md, FEATURE-Amount-Format.md, FEATURE-Command-Transaction.md, FEATURE-CLI-Output.md, FEATURE-CLI-Dispatch.md |
| Provides    | ledger report categories |
| Consumes    | categories.list, transactions.list |

## Questions

- None.

## Purpose

`ledger report categories` reports, for every category, its description, transaction count,
inflow, outflow, and net, followed by a TOTAL row.

## Trigger

The user runs `ledger report categories`.

## Behavior

1. Within the command transaction, read every category through `categories.list`, ordered by
   `category` ascending.
2. For each category, compute by query over `transactions.list`:
   - `transactions`: the number of rows in that category.
   - `inflow`: the sum of positive amounts, in integer cents.
   - `outflow`: the sum of the absolute values of negative amounts, in integer cents, printed as a
     positive number.
   - `net`: `inflow - outflow`.
   A category with no transactions reports `0`, `0.00`, `0.00`, `0.00`.
3. Print the header and one row per category:

```text
category,description,transactions,inflow,outflow,net
```

4. Print the TOTAL row, whose count, inflow, outflow, and net are summed over every transaction:

```text
TOTAL,,<count>,<inflow>,<outflow>,<net>
```

Amounts are formatted per FEATURE-Amount-Format.md. No value is embedded as a constant.

| Interface | Kind | Notes |
|---|---|---|
| `ledger report categories` | CLI command | Exit 0 on success. |

| Operation | Access | Repository operation | Notes |
|---|---|---|---|

| List transactions | read | `transactions.list` | Aggregated per category and in total. |

     positive number.
   - `net`: `inflow - outflow`.
4. Print the header, then one row per month in ascending `YYYY-MM` order:

```text
month,transactions,inflow,outflow,net
```

5. Print the TOTAL row, whose count, inflow, outflow, and net are summed over every transaction:

```text
TOTAL,<count>,<inflow>,<outflow>,<net>
```

6. With no transactions, print only `TOTAL,0,0.00,0.00,0.00` after the header.

Amounts are formatted per FEATURE-Amount-Format.md. No value is embedded as a constant.
