# FEATURE: Account Rename

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Rename an existing account by code and print the updated account row. |
| Depends On  | DATABASE.md, FEATURE-CLI-Dispatch.md, FEATURE-CLI-Output.md, FEATURE-Code-Validation.md, FEATURE-Command-Transaction.md |
| Provides    | ledger account rename <code> <name> |
| Consumes    | accounts.get, accounts.update |

## Questions

- None.

## Purpose

`ledger account rename <code> <name>` changes the name of an existing account. It validates the
code and the new name, looks up the account, updates its name, and prints the updated row.

## Behavior

- The command runs inside one command transaction (FEATURE-Command-Transaction.md).
- The `<code>` argument is validated as an account code (FEATURE-Code-Validation.md) before any lookup.
- The `<name>` argument is validated as an account name: 1 to 40 characters, no comma, no newline.
  An invalid name exits 3 with no change.
- The account is looked up with `accounts.get`. An absent code exits 4 with no change.
- On success the name is written with `accounts.update` and the updated row is printed through the
  CSV output contract (FEATURE-CLI-Output.md) as:

  ```text
  account,name,transactions,balance
  <code>,<new name>,<transaction count>,<balance>
  ```

- The transaction count and balance are computed from the account's transactions by query, never
  embedded.

## Routes and Interfaces

| Command | Exit 0 | Exit 3 | Exit 4 |
|---|---|---|---|
| `ledger account rename <code> <name>` | updated row | invalid code or name | absent code |

## Database Interface

- `FEATURE-ACCOUNT-002` — read: retrieve an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-ACCOUNT-004` — write: update account name - supplies: `account`, `name` - returns: `account`, `name`

# FEATURE: Account Delete

| Field       | Value |
|-------------|-------|

| Provides    | ledger account delete <code> |
| Consumes    | accounts.get, accounts.delete, transactions.list |

## Questions

- None.

## Purpose

`ledger account delete <code>` removes an account. The delete is refused while any transaction
references the account.

## Behavior

- The command runs inside one command transaction (FEATURE-Command-Transaction.md).
- The `<code>` argument is validated as an account code (FEATURE-Code-Validation.md) before any lookup.

- If any transaction references the account, the command exits 3 with no change.
- Otherwise the account is removed with `accounts.delete` and the output is:

  ```text
  deleted
  <code>
  ```

- `FEATURE-ACCOUNT-005` — write: delete an account - supplies: `account` - returns: `rows`
- `FEATURE-TXN-003` — read: list transactions to detect references - supplies: none - returns: `account`

# FEATURE: Transaction Post

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Post a transaction with the next id after validating every field and applying the balance rule. |
| Depends On  | DATABASE.md, FEATURE-CLI-Dispatch.md, FEATURE-CLI-Output.md, FEATURE-Code-Validation.md, FEATURE-Amount-Format.md, FEATURE-Date-Validation.md, FEATURE-Balance-Rule.md, FEATURE-Command-Transaction.md |
| Provides    | ledger txn post <account> <category> <amount> <date> [<memo>], next_txn_id() |
| Consumes    | accounts.get, categories.get, transactions.list, transactions.create |

## Questions

- None.

## Purpose

`ledger txn post` records one transaction against an account and category. It assigns the next
transaction id, validates every field, applies the non-negative balance rule, and prints the new row.

## Behavior

- The command runs inside one command transaction (FEATURE-Command-Transaction.md).
- Argument syntax is validated before any lookup. A malformed amount, date, code, or memo exits 3
  even when the account is absent (AC-010).
- The amount is parsed as integer cents (FEATURE-Amount-Format.md). Zero in any form exits 3.
- The date is validated as a real `YYYY-MM-DD` calendar date (FEATURE-Date-Validation.md).
- The memo is optional, 0 to 60 characters, with no comma or newline. An omitted memo is stored as
  the empty string.
- The account and category are looked up with `accounts.get` and `categories.get`. A missing account
  or category exits 3, not 4 (AC-011).
- `next_txn_id()` returns the largest `txn_id` from `transactions.list` plus one, or `1` when the
  table is empty. Ids are computed by query.
- The balance rule (FEATURE-Balance-Rule.md) is checked after the insert and before commit. A
  resulting negative balance exits 3 with no change.
- On success the row is written with `transactions.create` and printed as:

  ```text
  txn_id,date,account,category,amount,memo
  <id>,<date>,<account>,<category>,<amount>,<memo>
  ```

  The amount uses the two-decimal output format.

## Routes and Interfaces

| Command | Exit 0 | Exit 3 | Exit 4 |
|---|---|---|---|
| `ledger txn post <account> <category> <amount> <date> [<memo>]` | new row | malformed argument, missing account or category, negative balance | not used |

## Database Interface

- `FEATURE-ACCOUNT-002` — read: retrieve an account by code - supplies: `account` - returns: `account`
- `FEATURE-CATEGORY-002` — read: retrieve a category by code - supplies: `category` - returns: `category`
- `FEATURE-TXN-003` — read: list transactions to compute the next id and balances - supplies: none - returns: `txn_id`, `account`, `amount`
- `FEATURE-TXN-001` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
