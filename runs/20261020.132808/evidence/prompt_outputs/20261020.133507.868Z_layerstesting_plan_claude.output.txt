# FEATURE: Command Transaction

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Runs every ledger command inside exactly one database transaction that commits on success and rolls back on failure. |
| Depends On  | FEATURE-Database-Location.md, DATABASE.md |
| Provides    | run_command(db, command) |
| Consumes    | open_database, db.accounts.create, db.accounts.list |

## Questions

- None.

## Purpose

Every command that reads or writes the store runs inside one transaction. A command either completes in full or changes nothing.

## Behavior

- `run_command(db, command)` opens one transaction on `db`, calls `command(db)` once, commits when the call returns, and returns the value the command returned.
- If `command` raises, every write made through `db` during that call is rolled back, and the exception propagates unchanged.
- A persistence error raised while the transaction is open, including a write lock held by another connection, rolls back the same way and propagates. The CLI maps it to exit 1 through FEATURE-Operational-Errors.md.
- The wrapper does not commit or roll back inside a command body. Commands never open their own transaction.

## Programmatic Acceptance

=== AC command-transaction-commits ===
Intent: A command that returns normally has its write persisted and its return value passed back to the caller.

from persistence.testing import db_session
from transaction import run_command

account_code = "TXNA1"
account_name = "Commit Test"

with db_session() as db:
    result = run_command(db, lambda d: d.accounts.create(account=account_code, name=account_name))
    assert result.account == account_code
    matches = [row for row in db.accounts.list() if row.account == account_code]
    assert len(matches) == 1
    assert matches[0].name == account_name
=== END AC command-transaction-commits ===

=== AC command-transaction-rolls-back-all-writes ===
Intent: When a command raises after two writes, neither write persists and the exception reaches the caller.

from persistence.testing import db_session
from transaction import run_command

first_code = "TXNB1"
second_code = "TXNB2"

class Abort(Exception):
    pass

def write_then_fail(d):
    d.accounts.create(account=first_code, name="Rollback First")
    d.accounts.create(account=second_code, name="Rollback Second")
    raise Abort("forced after two writes")

with db_session() as db:
    before = len(db.accounts.list())
    raised = False
    try:
        run_command(db, write_then_fail)
    except Abort:
        raised = True
    assert raised
    after = db.accounts.list()
    assert len(after) == before
    assert all(row.account not in (first_code, second_code) for row in after)
=== END AC command-transaction-rolls-back-all-writes ===

=== AC command-transaction-propagates-exception ===
Intent: The exception raised by a failing command is the same object the caller receives, not a wrapped or swallowed error.

from persistence.testing import db_session
from transaction import run_command

raised_error = RuntimeError("forced by criterion")

def fail(d):
    raise raised_error

with db_session() as db:
    try:
        run_command(db, fail)
    except RuntimeError as caught:
        assert caught is raised_error
    else:
        raise AssertionError("run_command swallowed the command's exception")
=== END AC command-transaction-propagates-exception ===

## User Acceptance

- None.

## Guardrails

- No module begins or commits a transaction outside `run_command`.
- A failed command never leaves a partial write in any table.
- No command body commits its own work.
- Application code reaches the store only through the `persistence` package, never through a database driver.

# FEATURE: Schema Init

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Implements `ledger init`, which drops and recreates the three ledger tables empty. |
| Depends On  | FEATURE-Command-Transaction.md, FEATURE-CLI-Dispatch.md, DATABASE.md |
| Provides    | ledger init |
| Consumes    | open_database, run_command |

## Questions

- None.

## Purpose

`ledger init` resets the store to three empty tables, so a later load or report starts from a known state.

## Behavior

- `ledger init` drops `accounts`, `categories`, and `transactions` if they exist, then recreates them empty from the generated schema through the `persistence` package.
- The drop and recreate run inside one command transaction (FEATURE-Command-Transaction.md).
- `init` writes nothing to standard output and exits 0.
- Argument-count errors are rejected by FEATURE-CLI-Dispatch.md before this handler runs.

## Programmatic Acceptance

=== AC schema-init-exit-and-silent ===
Intent: `ledger init` exits 0 and writes nothing to standard output on a fresh database.

import os
import tempfile

from cli.testing import cli_runner

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn

code, out, err = cli_runner("init")
assert code == 0
assert out == ""
=== END AC schema-init-exit-and-silent ===

=== AC schema-init-drops-existing-rows ===
Intent: Running `ledger init` against a store holding a row leaves all three tables empty.

import tempfile

seeded.accounts.create(account="INITA", name="Before Init")
assert len(seeded.accounts.list()) == 1

code, out, err = cli_runner("init")
assert code == 0
assert out == ""

after = open_database(dsn)
assert len(after.accounts.list()) == 0
assert len(after.categories.list()) == 0
assert len(after.transactions.list()) == 0
=== END AC schema-init-drops-existing-rows ===

=== AC schema-init-recreates-usable-schema ===
Intent: After `ledger init` runs a second time, the recreated tables accept a new row.

import os
import tempfile

from cli.testing import cli_runner
from persistence import open_database

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn

first_code, first_out, first_err = cli_runner("init")
assert first_code == 0
second_code, second_out, second_err = cli_runner("init")
assert second_code == 0
assert second_out == ""

db = open_database(dsn)
db.accounts.create(account="INITB", name="After Init")
assert len(db.accounts.list()) == 1
=== END AC schema-init-recreates-usable-schema ===

## User Acceptance

- None.

## Guardrails

- `init` does not read any file under `sources/`.
- `init` never writes to standard output.
- Schema objects are created only through the generated `schema.sql`, never by inline SQL in this handler.

# FEATURE: Schema Count

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Implements `ledger count`, which prints the row count of each ledger table. |
| Depends On  | FEATURE-Schema-Init.md, FEATURE-CLI-Output.md, DATABASE.md |
| Provides    | ledger count |
| Consumes    | open_database, write_csv |

## Questions

- None.

## Purpose

`ledger count` tells an operator how many rows each table holds, which is how the seed loads are checked.

## Behavior

- Prints `table,rows`, then one line each for `accounts`, `categories`, and `transactions`, in that order.
- Each count is the number of rows returned by that table's list operation in `DATABASE.md`. No count is stored or hardcoded.
- The output is written through `write_csv`, so the contract in FEATURE-CLI-Output.md applies.
- Exits 0 on success.

## Programmatic Acceptance

=== AC schema-count-header-and-order ===
Intent: `ledger count` writes a `table,rows` header followed by the three table lines in the fixed order.

import os
import tempfile

from cli.testing import cli_runner

os.environ["DATABASE_URL"] = dsn

assert init_code == 0

code, out, err = cli_runner("count")
assert code == 0
lines = out.splitlines()
assert len(lines) == 4
assert lines[0].split(",") == ["table", "rows"]
assert [line.split(",")[0] for line in lines[1:]] == ["accounts", "categories", "transactions"]
=== END AC schema-count-header-and-order ===

=== AC schema-count-matches-stored-rows ===

# FEATURE: CLI Dispatch

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Routes `ledger` command words to their handlers and rejects usage errors with exit 2 before any database access. |
| Depends On  | FEATURE-CLI-Platform.md |
| Provides    | ledger <command> routing, usage error exit 2 |
| Consumes    | cli.main, cli_runner |

## Questions

- None.

## Purpose

Every `ledger` invocation is either handed to the handler its story owns or rejected as a usage error. Nothing else happens first.

## Behavior

- The command word, sub-verb, and argument count are checked against the Commands table before any handler or database access runs.
- An unknown command, unknown sub-verb, unknown table, unknown report, or wrong argument count exits 2 with exactly one line on standard error and nothing on standard output.
- A correctly shaped command is passed to its handler, and the handler's exit code is returned unchanged.

## Programmatic Acceptance

=== AC cli-dispatch-usage-errors-exit-two ===
Intent: Each unknown command, sub-verb, table, report, or wrong argument count exits 2 with empty stdout and one stderr line.

from cli.testing import cli_runner

usage_errors = [
    ("frobnicate",),
    ("report", "nosuch"),
    ("load", "nosuch", "missing.csv"),
    ("account", "nosuch"),
    ("count", "extra"),
    ("account", "add", "ONLY"),
]

for args in usage_errors:
    code, out, err = cli_runner(*args)
    print(args, err)
    assert code == 2
    assert out == ""
    assert len(err.splitlines()) == 1
=== END AC cli-dispatch-usage-errors-exit-two ===

=== AC cli-dispatch-usage-touches-no-database ===
Intent: A usage error exits 2 without creating or opening the database file named by DATABASE_URL.

import os
import tempfile

from cli.testing import cli_runner

dsn = os.path.join(tempfile.mkdtemp(), "ledger.db")
os.environ["DATABASE_URL"] = dsn

code, out, err = cli_runner("frobnicate")
assert code == 2
assert not os.path.exists(dsn)
=== END AC cli-dispatch-usage-touches-no-database ===

=== AC cli-dispatch-main-returns-usage-code ===
Intent: The published `main` entry point returns the integer 2 for an unknown command.

from cli import main

result = main(["frobnicate"])
assert isinstance(result, int)
assert result == 2
=== END AC cli-dispatch-main-returns-usage-code ===

## User Acceptance

- None.

## Guardrails

- Argument validation completes before any database connection is opened.
- Usage diagnostics go to standard error only and are never written to standard output.
- Dispatch never reads a file named on the command line before validating the command.

# FEATURE: CLI Output

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provides the CSV writer every successful ledger command uses for standard output. |
| Depends On  | FEATURE-CLI-Platform.md |
| Provides    | cli.output.write_csv(header, rows) |
| Consumes    | none |

## Questions

- None.

## Purpose

Every successful command except `init` reports its result as CSV on standard output, in one shared format.

## Behavior

- `write_csv(header, rows)` writes the header row, then one row per entry in `rows`, to standard output.
- Fields are joined with commas, are never quoted, and each line ends with a single `\n`.
- No line carries a trailing space, and no line contains a carriage return.
- With an empty `rows`, only the header row is written.
- Nothing is written to standard error.

## Programmatic Acceptance

=== AC cli-output-header-then-rows ===
Intent: `write_csv` writes the header row followed by one comma-separated line per data row, in order.

import contextlib
import io

from cli.output import write_csv

header = ["account", "name"]
rows = [["ALPHA", "Alpha Drawer"], ["BETA", "Beta Safe"]]

buf = io.StringIO()
with contextlib.redirect_stdout(buf):
    write_csv(header, rows)

lines = buf.getvalue().splitlines()
assert len(lines) == len(rows) + 1
assert lines[0].split(",") == header
assert [line.split(",") for line in lines[1:]] == rows
=== END AC cli-output-header-then-rows ===

=== AC cli-output-no-quoting-or-trailing-space ===
Intent: Output contains no quote characters, no carriage returns, no trailing spaces, and one line ending per written line.

import contextlib
import io

from cli.output import write_csv

header = ["category", "description"]
rows = [["SALES", "Sales receipts"], ["RENT", "Rent"]]

buf = io.StringIO()
with contextlib.redirect_stdout(buf):
    write_csv(header, rows)

text = buf.getvalue()
assert '"' not in text
assert chr(13) not in text
assert text.count(chr(10)) == len(rows) + 1
assert all(line == line.rstrip() for line in text.splitlines())
=== END AC cli-output-no-quoting-or-trailing-space ===

=== AC cli-output-header-only-and-silent-stderr ===
Intent: With no data rows, only the header is written to standard output, and nothing is written to standard error.

import contextlib
import io

from cli.output import write_csv

header = ["table", "loaded"]

out_buf = io.StringIO()
err_buf = io.StringIO()
with contextlib.redirect_stdout(out_buf), contextlib.redirect_stderr(err_buf):
    write_csv(header, [])

lines = out_buf.getvalue().splitlines()
assert len(lines) == 1
assert lines[0].split(",") == header
assert err_buf.getvalue() == ""
=== END AC cli-output-header-only-and-silent-stderr ===

## User Acceptance

- None.

## Guardrails

- No field is quoted or escaped; values containing a comma or newline are rejected upstream by validation, never encoded here.
- The writer formats only the values it is given and never formats money or dates itself.
