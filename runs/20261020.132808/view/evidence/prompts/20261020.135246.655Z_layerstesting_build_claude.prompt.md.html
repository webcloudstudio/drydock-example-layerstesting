## Compass

Build a command-line cash ledger, an executable named `ledger` at the application root, as
described in `sources/INSTRUCTIONS.md`. It keeps accounts, categories, and cash transactions in a
relational database reached only through the shipped persistence library, enforces atomic commands
and non-negative balances, and reports balances, category totals, and monthly totals.

Correctness is measured by `sources/run.sh`: 43 checks of exit code and standard output against
known answers computed from the seed files. The goal is every check passing.

## Constraints

- Store amounts as integer cents.
- Run every command as one database transaction.
- Run without network access other than to a PostgreSQL server named by `DATABASE_URL`.

### How do we execute and measure Acceptance Criteria in this language?

An Acceptance Criterion (AC) is an executable check of Blueprint-required behavior. Use the
existing Programmatic Acceptance format: a Python script with assertions against the built
product. Drydock executes each criterion through `languages/python/acceptance/runner.py`; `pytest -q`

an assertion failure fails the check. The harness reports failure operands and available case

available observations as key/value data associated with the criterion. Missing observations
are unknown, not proof that code or an interaction was unused.

### How does this language provide the shared persistence contract?

Use `stack/persistence.md`. Drydock copies `Rigging/languages/python/persistence/{db,sqlite,postgres}.py` and generates

# FEATURE: Database Location

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Resolve the database location from DATABASE_URL, then DATABASE_PATH, then data/app.db, and reject PostgreSQL DSNs in this build. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-CLI-Platform.md |
| Provides    | resolve_database_location() |
| Consumes    | open_database(dsn) |

## Purpose

Every command finds its database through this resolution. The resolved value is passed to
`open_database(dsn)`. This feature does not open a connection.

## Interface

- `database_location.resolve_database_location() -> str` returns the location string.
- `database_location.DatabaseLocationError` is raised for an unsupported DSN.

## Resolution Rules

1. If `DATABASE_URL` is set, it is used.
2. Else, if `DATABASE_PATH` is set, it is used.
3. Else, the value is `data/app.db`, which is relative to the working directory.
4. A `sqlite://` prefix is removed. The remainder is the location.
5. A value beginning `postgres://` or `postgresql://` raises `DatabaseLocationError`. The CLI
   boundary maps that error to exit 1.

## Programmatic Acceptance

=== AC dbloc-default ===
Intent: With neither DATABASE_URL nor DATABASE_PATH set, the location is data/app.db.

import os

from database_location import resolve_database_location

keys = ("DATABASE_URL", "DATABASE_PATH")
saved = {key: os.environ.pop(key, None) for key in keys}
try:
    location = resolve_database_location()
finally:
    for key, value in saved.items():
        if value is not None:
            os.environ[key] = value
print(location)
assert location == "data/app.db"
=== END AC dbloc-default ===
