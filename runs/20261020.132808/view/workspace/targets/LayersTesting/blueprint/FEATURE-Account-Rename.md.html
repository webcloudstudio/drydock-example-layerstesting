FEATURE: Account Rename

FieldValue
Version20261020 V1
DescriptionRename an existing account by code and print the updated account row.
Depends OnDATABASE.md, FEATURE-CLI-Dispatch.md, FEATURE-CLI-Output.md, FEATURE-Code-Validation.md, FEATURE-Command-Transaction.md
Providesledger account rename <code> <name>
Consumesaccounts.get, accounts.update

Purpose

ledger account rename <code> <name> changes the name of an existing account. It validates the code and the new name, looks up the account, updates its name, and prints the updated row.

Behavior

  • The command runs inside one command transaction (FEATURE-Command-Transaction.md).
  • The <code> argument is validated as an account code (FEATURE-Code-Validation.md) before any lookup.
  • The <name> argument is validated as an account name: 1 to 40 characters, no comma, no newline.

An invalid name exits 3 with no change.

  • The account is looked up with accounts.get. An absent code exits 4 with no change.
  • On success the name is written with accounts.update and the updated row is printed through the

CSV output contract (FEATURE-CLI-Output.md) as:

  account,name,transactions,balance
  <code>,<new name>,<transaction count>,<balance>
  • The transaction count and balance are computed from the account's transactions by query, never

embedded.

Programmatic Acceptance

=== AC account-rename-updates-name ===
Intent: Renaming an existing account stores the new name and the read-back row shows it.
Suite: scoped

from cli.testing import cli_runner from persistence.testing import db_session

code, out, _ = None, None, None with db_session() as db: db.accounts.create(account="CASH9", name="Event Float") code, out, _ = cli_runner("account", "rename", "CASH9", "Event Cash Box") row = db.accounts.get(account="CASH9")

assert code == 0 assert out == "account,name,transactions,balance\nCASH9,Event Cash Box,0,0.00\n" assert row.name == "Event Cash Box" === END AC account-rename-updates-name ===

=== AC account-rename-absent-exits-4 ===
