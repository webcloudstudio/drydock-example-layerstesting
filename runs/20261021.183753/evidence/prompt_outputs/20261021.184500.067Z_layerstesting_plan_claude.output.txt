# FEATURE: Count

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Report row counts for the accounts, categories, and transactions tables. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | ledger count |
| Consumes    | accounts.list, categories.list, transactions.list |

## Questions

- None.

## Purpose

`ledger count` reports how many rows each of the three tables holds, so the operator can confirm the state of the ledger after `init` and each bulk load.

## Trigger

The operator runs `./ledger count` with no further arguments.

## Behavior

- Output is CSV on standard output: header `table,rows`, then one row each for `accounts`, `categories`, and `transactions`, in that order.
- Each count is computed by the database from the persistence library, using the list operations declared in `DATABASE.md` (`FEATURE-COUNT-001` to `FEATURE-COUNT-003`). No count is stored or hardcoded.
- The command changes nothing.
- Exit code `0` on success.
- A database that is unreachable or lacks the declared tables exits `1` with one diagnostic line on standard error and nothing on standard output.
- Extra arguments exit `2` with nothing on standard output (usage error, per dispatch).

## Access

| Pattern | Owner | Access | Operation |
|---------|-------|--------|-----------|
| FEATURE-COUNT-001 | FEATURE-Count.md | read | `accounts.list` |
| FEATURE-COUNT-002 | FEATURE-Count.md | read | `categories.list` |
| FEATURE-COUNT-003 | FEATURE-Count.md | read | `transactions.list` |

## Database Interface

- `FEATURE-COUNT-001` — read: list accounts - returns: `account`
- `FEATURE-COUNT-002` — read: list categories - returns: `category`
- `FEATURE-COUNT-003` — read: list transactions - returns: `txn_id`

# FEATURE: Field Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Validate account and category codes, names, descriptions, and memos before any write. |
| Depends On  | ARCHITECTURE.md |
| Provides    | validate_code, validate_name, validate_memo |
| Consumes    | |

## Questions

- None.

## Purpose

Every command that accepts a code, name, description, or memo validates it before reading the database or writing. Shared validators keep the rule identical across account add, rename, load, and post.

## Trigger

Invoked by every command story that accepts a code, name, description, or memo, before any write.

## Behavior

- `validate_code(value)`: accepts 1 to 12 characters, each from `A-Z` or `0-9`. Lowercase, punctuation, whitespace, and any other character is rejected.
- `validate_name(value)`: accepts 1 to 40 characters for names and descriptions. Used for account names, category descriptions, and any other 1-to-40 text field.
- `validate_memo(value)`: accepts 0 to 60 characters. An empty string is valid and is stored as an empty memo.
- All three reject any value containing a comma (`,`) or a newline (`\n` or `\r`).
- A rejected value raises a validation error that the calling command maps to exit `3` with one diagnostic line on standard error and nothing on standard output.
- Validators are pure: they read no database and write nothing.

## Programmatic Acceptance

# FEATURE: Amount Parsing

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Parse input amounts to integer cents and format output amounts with exactly two decimals. |
| Depends On  | ARCHITECTURE.md |
| Provides    | parse_amount_cents, format_cents |
| Consumes    | |

## Questions

- None.

## Purpose

Every amount-bearing command parses its input into integer cents and formats stored cents back to decimal text. Money never passes through floating point at any layer.

## Trigger

Invoked by every command that accepts an amount: `txn post`, `txn amend`, `transfer`, and `load transactions`.

## Behavior

- `parse_amount_cents(text)` accepts input matching `-?DIGITS[.D[D]]`: an optional leading minus, one or more digits, and an optional decimal point followed by one or two digits.
- The parsed value is non-zero. `0`, `0.00`, and `-0.00` are rejected.
- Accepted input returns a Python `int` of cents, computed by integer arithmetic on the digit strings (for example `"-12.5"` returns `-1250`, `"45"` returns `4500`).
- Any other input (a third decimal place, a `+` sign, a thousands separator, whitespace, exponent notation, a non-numeric string) is rejected.
- A rejected amount raises a validation error that the calling command maps to exit `3`.
- `format_cents(cents)` returns the decimal text with exactly two decimal places, a leading `-` when negative, and no thousands separator (for example `-1250` returns `-12.50`, `0` returns `0.00`, `500000` returns `5000.00`).
- No function in this feature uses floating point.

# FEATURE: Date Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Accept only YYYY-MM-DD dates that name a real calendar day, including leap days. |
| Depends On  | ARCHITECTURE.md |
| Provides    | validate_date |
| Consumes    | |

## Questions

- None.

## Purpose

Every command that accepts a date validates it before writing, so no transaction is stored with a date that is malformed or does not exist.

## Trigger

Invoked by every command that accepts a date: `txn post`, `transfer`, and `load transactions`.

## Behavior

- `validate_date(text)` accepts only the exact form `YYYY-MM-DD` (four digits, hyphen, two digits, hyphen, two digits) that names a real calendar day.
- Leap days are accepted only in leap years: `2024-02-29` is valid; `2026-02-29` is not.
- Impossible days are rejected, including `2026-02-30`, `2026-04-31`, and month `00` or `13`.
- Any other form (missing zero padding such as `2026-1-05`, a time component, a slash separator, whitespace) is rejected.
- Returns the input unchanged when valid. A rejected date raises a validation error that the calling command maps to exit `3`.
- The validator reads no database and writes nothing.

# FEATURE: Non-Negative Balance

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Reject any change that would leave an account balance below zero, checked against the database before the first write. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-Init.md |
| Provides    | check_balances_after(changes) |
| Consumes    | transactions.list |

## Questions

- None.

## Purpose

No command may leave any account with a negative balance. The balance is the sum of that account's transaction amounts. The check runs against the database for every account a command would change, before that command writes anything.

## Trigger

Invoked by every command that changes transactions: `txn post`, `txn amend`, `txn delete`, `transfer`, and `load transactions`.

## Behavior

- `check_balances_after(changes)` takes a list of `(account, delta_cents)` pairs describing the proposed change. A delta is the signed cents a command would add to that account.
- For each distinct affected account, it computes the current balance as the sum of the account's transaction amounts read from the database, then adds the summed deltas for that account.
- If any resulting balance is below zero, it raises a rule-breach error that the calling command maps to exit `3`, and nothing is written.
- If every resulting balance is zero or greater, it returns normally and the calling command proceeds to write.
- An account with no transactions has a current balance of zero.
- The check is read-only.
- Several changes to one account in the same command are summed before the comparison, so a transfer that drives one account negative is rejected even if each leg alone would not be.

## Access

| Pattern | Owner | Access | Operation |
|---------|-------|--------|-----------|
| FEATURE-COUNT-003 | FEATURE-Count.md | read | `transactions.list` |

The balance check reads the transaction list through the same declared read operation used by Count, and it cites that pattern rather than adding one. Account-scoped reads are computed in the persistence layer's query, not by a new repository operation.

## Database Interface

- `FEATURE-COUNT-003` — read: list transactions - returns: `account`, `amount`
