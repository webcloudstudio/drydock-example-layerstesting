# ARCHITECTURE: LayersTesting

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Architecture of a command-line cash ledger: one executable, a cli package, a generated persistence package over SQLite and PostgreSQL. |
| Depends On  | — |
| Provides    | — |

## Questions

- None.

## Overview

The product is a single executable, `ledger`, at the application root. It dispatches each command to
a module in the `cli` package. Every module reaches the database only through the generated
`persistence` package. Each command completes in full or changes nothing.

## Modules

| Module | Responsibility |
|--------|----------------|
| `ledger` (root executable) | Imports `cli` and exits with the code `cli.main` returns. |
| `cli` | Entry point `main(argv)`, command routing, shared diagnostic and exit helpers, and command modules. |
| `cli.config` | Resolves the database location from the environment. |
| `persistence` | Generated from `DATABASE.md`: `open_database(dsn)`, declared table operations, `reset_schema(dsn)`, and `db_session()` for criteria. |
| `schema.sql` | Generated from `DATABASE.md`: `CREATE ... IF NOT EXISTS` for the three tables. |

## Module Ownership

| Boundary | Owner | Allowed low-level access |
|----------|-------|--------------------------|
| Persistence | `persistence` package, which includes the shipped engines | Only the shipped persistence library. Application code never imports a driver. |
| Configuration | `cli.config` | Environment variable reads only. |
| File store | None. Load files are read by the load modules. | Standard file reads of the file named on the command line. |
| External service | None. PostgreSQL is reached only through the DSN passed to `open_database`. | None beyond the persistence library. |

## Interfaces

- `cli.main(argv: list[str] | None = None) -> int` returns the exit code.
- `cli.dispatch.run(argv)` routes a command and converts a `LedgerError(code, message)` into one
  stderr line and its exit code.
- `cli.config.resolve_database_dsn(environ)` returns the DSN.
- `persistence.open_database(dsn)` returns the `Database` handle.
- `persistence.reset_schema(dsn)` drops every declared table and applies `schema.sql`.

## Data Flow

`route → command module → db.<table>.<operation>(...)`. Amounts are integer cents throughout.
Floating point is not used for money at any layer.

## Technology Stack

- Python 3.11 or newer: implementation language, with `.venv` created by `uv venv`.
- SQLite through the standard-library engine: default database, selected by the DSN.
- PostgreSQL through the shipped engine: selected only when `DATABASE_URL` begins `postgres://` or `postgresql://`.
- CLI: the `ledger` executable at the application root.
- pytest: test runner behind `bin/test.sh`.
- POSIX sh: `bin/test.sh` and the supplied grader.

## Technical Decisions

- Each command validates every input and rule before its first write.
- Each command relies on the database's own transactions. No application-level locking is added.
- Diagnostics go to standard error. Successful output is CSV on standard output.
- Exit codes: 0 success, 1 operational failure, 2 usage error, 3 rejected, 4 not found.

## Programmatic Acceptance

- None. Architecture is verified through the feature specifications that implement each module.

## User Acceptance

- None.

## Guardrails

- Application code never opens a database driver outside the shipped persistence library.
- Money is never stored or computed as floating point.
- No network access other than to a PostgreSQL server named by `DATABASE_URL`.

# FEATURE: Command Dispatch

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Route each ledger command to its module and reject unknown commands, tables, reports, and argument counts with exit code 2. |
| Depends On  | FEATURE-Executable.md, DATABASE.md |
| Provides    | cli.dispatch.run(argv), LedgerError(code, message), ledger help routing table |

## Questions

- None.

## Purpose

Dispatch maps the first argument to a command module, checks the argument count against the command's
declared arity, and runs it. Any usage problem is rejected before a command module or the database is touched.

## Trigger

Every `ledger` invocation.

## Routes and Interface Points

- `cli.dispatch.run(argv)` returns an exit code.
- `LedgerError(code, message)` is raised by any command module to fail. `run` writes `message` as
  one line to standard error and returns `code`.
- Usage errors use code 2 and write nothing to standard output.

## Reads and Writes

None. Dispatch reads only its arguments.

## Operational Behavior

- Unknown commands, unknown table names for `load`, unknown report names, and wrong argument counts
  exit 2 with one stderr line and nothing on standard output.
- Each command module declares its accepted argument count, which dispatch checks.

## Database Interface

- None — persistence is owned by DATABASE.md; this feature reaches no repository.

# FEATURE: Database Configuration

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Resolve the database location from DATABASE_URL, then DATABASE_PATH, then data/app.db under the application root. |
| Depends On  | FEATURE-Dispatch.md, DATABASE.md |
| Provides    | cli.config.resolve_database_dsn(environ), cli.config.open_configured_database() |

## Questions

- None.

## Purpose

Every command opens the same store. This feature chooses it from the environment in a fixed order, so
the grader and operators select a store without changing code.

## Trigger

Every command that touches the database calls `open_configured_database()`.

## Routes and Interface Points

- `resolve_database_dsn(environ)` takes a mapping and returns a DSN string.
- `open_configured_database()` calls `persistence.open_database` with the resolved DSN.

## Resolution Rules

1. If `DATABASE_URL` is set, use it.
   - A value beginning `postgres://` or `postgresql://` is returned unchanged.
   - Otherwise the value is a SQLite path. Remove any leading `sqlite://` and return the rest.
2. Otherwise, if `DATABASE_PATH` is set, return it.
3. Otherwise return `data/app.db` resolved against the application root, as an absolute path.

## Reads and Writes

Reads the environment only. Writes nothing. Creating the file is the job of the persistence library.

## Operational Behavior

- Resolution happens at call time, so changes to the environment take effect on the next command.
- An empty `DATABASE_URL` is treated as unset.

## Database Interface

- None — persistence is owned by DATABASE.md; this feature reaches no repository.

## Programmatic Acceptance

# FEATURE: Schema Initialization

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Drop and recreate the accounts, categories, and transactions tables empty, writing nothing to standard output. |
| Depends On  | FEATURE-Configuration.md, DATABASE.md |
| Provides    | ledger init |
| Consumes    | cli.config.open_configured_database, persistence.reset_schema |

## Questions

- None.

## Purpose

`init` brings the store to the declared empty schema. It is the first command the grader runs, and it
is also how an operator clears the ledger.

## Trigger

`ledger init` with no further arguments.

## Routes and Interface Points

- `ledger init` takes no arguments and exits with 0 on success.

## Reads and Writes

- Calls `persistence.reset_schema(dsn)` with the DSN from `cli.config`. The reset drops every table
  named in `DATABASE.md` and applies `schema.sql`, so all three tables exist and hold no rows.
- Writes nothing to standard output on success.

## Operational Behavior

- A store that cannot be opened or reset is an operational failure: write one diagnostic line to
  standard error and exit 1. The store is left as it was.
- Running `init` on an existing, populated store clears it.

## Database Interface

- None — persistence is owned by DATABASE.md; schema reset is a persistence-package entry point.

## Programmatic Acceptance

=== AC init-clears-rows ===
Intent: init exits 0, writes nothing to standard output, and leaves every table empty, including after a row was written.

import os
import tempfile
from pathlib import Path

from cli.testing import cli_runner
from persistence import open_database

with tempfile.TemporaryDirectory() as tmp:
    path = str(Path(tmp) / "ledger.db")
    os.environ["DATABASE_URL"] = path
    try:
        setup_code, setup_out, setup_err = cli_runner("init")
        print(setup_err)
        assert setup_code == 0
        assert setup_out == ""
        db = open_database(path)
        db.accounts.create(account="CASH1", name="Till One")
        assert len(db.accounts.list()) == 1
        code, out, err = cli_runner("init")
        print(err)
        assert code == 0
        assert out == ""
        db = open_database(path)
        assert len(db.accounts.list()) == 0
        assert len(db.categories.list()) == 0
        assert len(db.transactions.list()) == 0
    finally:
        os.environ.pop("DATABASE_URL", None)
=== END AC init-clears-rows ===
