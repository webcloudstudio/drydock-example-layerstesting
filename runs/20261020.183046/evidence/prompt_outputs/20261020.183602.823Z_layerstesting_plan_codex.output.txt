# FEATURE: Account Balance Reports

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Generate account balance reports from persisted accounts and transactions. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-BULK-LOADING.md |
| Provides    | `ledger report balances` |
| Consumes    | accounts repository, transactions repository |

## Questions

- None.

## Purpose

The balance report presents every account in code order, including accounts with no transactions. It reports transaction counts and integer-cent balances formatted with exactly two decimal places, followed by an aggregate total row.

## Workflow

1. Read accounts and their transaction aggregates through the persistence boundary.
2. Order accounts by account code.
3. Format each account row as `account,name,transactions,balance`.
4. Emit the total transaction count and sum as `TOTAL,,<count>,<sum>`.

All values are calculated from persisted database state.

# FEATURE: Category and Monthly Reports

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Generate category and monthly transaction aggregation reports. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-BULK-LOADING.md |
| Provides    | `ledger report categories`, `ledger report monthly` |
| Consumes    | categories repository, transactions repository |

## Questions

- None.

## Purpose

Category reports aggregate every declared category, including categories without transactions. Monthly reports aggregate only months represented by transactions. Both reports calculate inflow, outflow, net, transaction counts, deterministic ordering, and a total row.

## Workflow

### Category report

Read categories and transaction aggregates, order categories by code, and emit:

`category,description,transactions,inflow,outflow,net`

The total row is:

`TOTAL,,<count>,<inflow>,<outflow>,<net>`.

### Monthly report

Group transactions by the first seven characters of their ISO date, order months ascending, and emit:

`month,transactions,inflow,outflow,net`

The total row is:

`TOTAL,<count>,<inflow>,<outflow>,<net>`.

Outflow is the positive absolute sum of negative amounts. Net equals inflow minus outflow.

# FEATURE: Account Lifecycle

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provide account creation, retrieval, renaming, and deletion operations. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-CLI-FOUNDATION.md |
| Provides    | `ledger account add`, `ledger account get`, `ledger account rename`, `ledger account delete` |
| Consumes    | accounts repository, transactions repository |

## Questions

- None.

## Purpose

Manage account records through the CLI while preserving validation, uniqueness, transaction references, and the declared exit-code contract.

## Behavior

- `account add` validates the code and name, rejects duplicates, persists the account, and returns the account row.
- `account get` returns the requested account row or exits `4` when absent.
- `account rename` validates and persists the replacement name or exits `4` when absent.
- `account delete` removes an account with no transactions and returns `deleted` plus the code.
- Deletion of an account with transactions is rejected with exit `3`.
- Rejected operations produce no standard output and do not modify state.

## Programmatic Acceptance

=== AC account-create-read-update-delete ===
Intent: Account creation, retrieval, renaming, and deletion round-trip through the public CLI.

import io

assert cli_runner("init")[0] == 0

assert code == 0

assert rows[0]["account"] == account
assert rows[0]["name"] == name

assert cli_runner("account", "rename", account, renamed)[0] == 0
code, stdout, stderr = cli_runner("account", "get", account)
assert code == 0
assert list(csv.DictReader(io.StringIO(stdout)))[0]["name"] == renamed

assert cli_runner("account", "delete", account)[0] == 0
assert cli_runner("account", "get", account)[0] == 4
=== END AC account-create-read-update-delete ===

- Account deletion must preserve transaction referential integrity.
- Missing account operations return exit code `4` without standard output.

# FEATURE: Transaction Lifecycle

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provide transaction posting, retrieval, amendment, and deletion operations. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-CLI-FOUNDATION.md |
| Provides    | `ledger txn post`, `ledger txn get`, `ledger txn amend`, `ledger txn delete` |
| Consumes    | accounts repository, categories repository, transactions repository |

## Questions

- None.

## Behavior

- `txn post` validates references, amount, date, memo, and balance before allocating the next transaction id.
- `txn get` returns the transaction or exits `4` when absent.
- `txn amend` changes only the amount and preserves all other fields.
- `txn delete` removes the transaction and returns `deleted` plus its id.
- Invalid, absent, duplicate, or balance-violating operations produce no standard output and preserve state.

## Programmatic Acceptance

=== AC transaction-validation ===
Intent: Invalid transaction references, amounts, and dates are rejected without output.

=== END AC transaction-validation ===

## User Acceptance

- None.

## Guardrails

- Amounts are integer cents internally and formatted with exactly two decimal places.
- Transaction ids are allocated from the current maximum, not reused from deleted rows unless they are the next permitted id.
- Failed mutations must not partially write.

# FEATURE: Transfers

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Execute atomic paired transfers between ledger accounts. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-TRANSACTION-LIFECYCLE.md |
| Provides    | `ledger transfer` |
| Consumes    | accounts repository, categories repository, transactions repository |

## Questions

- None.

## Purpose

Transfer a positive amount between two distinct existing accounts as one atomic operation. The outgoing transaction is written first with a negative amount, followed by the incoming transaction with a positive amount.

## Behavior

The command validates both accounts, the positive amount, date, available source balance, consecutive ids, the `TRANSFER` category, and generated memos before writing either transaction. It emits both rows in order:

- outgoing: `-amount`, memo `transfer to <to>`
- incoming: `+amount`, memo `transfer from <from>`

A rejected transfer returns exit code `3`, emits no standard output, and creates neither row.
