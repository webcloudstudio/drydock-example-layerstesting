<requirement name="relational-storage" stories="database">
It stores everything in a relational database through the shipped persistence library, and every command either completes in full or changes nothing.

All database access goes through the shipped persistence library and the relational layer generated from `DATABASE.md`. Application code never opens a database driver directly.
</requirement>
<requirement name="command-interface" stories="cli-foundation">
The product is an executable named `ledger` at the application root.

The contract below is the same for every language and database: the same commands, the same output, and the same exit codes.
</requirement>
<requirement name="schema-lifecycle" stories="schema-lifecycle">
`ledger init` | Drops all three tables if present and creates them empty. Nothing written.

`ledger count` | `table,rows`, then `accounts`, `categories`, `transactions` rows in that order.
</requirement>
<requirement name="bulk-load" stories="bulk-loading">
`ledger load <table> <csv>` | Loads `accounts`, `categories`, or `transactions` from a file whose header matches the table's columns in the order above. Writes `table,loaded` and `<table>,<rows>`.
</requirement>
<requirement name="account-management" stories="account-lifecycle">
`ledger account add <code> <name>` | The new account row.

`ledger account get <code>` | The account row.

`ledger account rename <code> <name>` | The updated account row.

`ledger account delete <code>` | `deleted` and the code. Refused while the account has transactions.
</requirement>
<requirement name="transaction-management" stories="transaction-lifecycle">
`ledger txn post <account> <category> <amount> <date> [<memo>]` | The new transaction row.

`ledger txn get <id>` | The transaction row.

`ledger txn amend <id> <amount>` | The updated transaction row. Only the amount changes.

`ledger txn delete <id>` | `deleted` and the id.
</requirement>
<requirement name="paired-transfers" stories="transfers">
`ledger transfer <from> <to> <amount> <date>` | Two transaction rows in category `TRANSFER`: `-amount` on `<from>` with memo `transfer to <to>`, then `+amount` on `<to>` with memo `transfer from <from>`. The amount is positive and the accounts differ.
</requirement>
<requirement name="balance-reports" stories="balance-reports">
`ledger report balances` | `account,name,transactions,balance` per account ordered by code, then `TOTAL,,<count>,<sum>`.
</requirement>
<requirement name="aggregate-reports" stories="aggregate-reports">
`ledger report categories` | `category,description,transactions,inflow,outflow,net` per category ordered by code, including categories with no transactions, then `TOTAL,,<count>,<inflow>,<outflow>,<net>`.

`ledger report monthly` | `month,transactions,inflow,outflow,net` per `YYYY-MM` that has transactions, ascending, then `TOTAL,<count>,<inflow>,<outflow>,<net>`.
</requirement>
<requirement name="non-negative-balances" stories="financial-invariants">
No command leaves an account balance below zero. An account's balance is the sum of its transaction amounts. Posting, amending, deleting, transferring, and loading are all subject to this rule, checked before the command writes anything.
</requirement>
<requirement name="conformance-suite" stories="conformance">
The completed application provides a POSIX-compatible `bin/test.sh` that runs its own automated test suite from the application root and exits zero only when every test passes. The suite covers each command, each exit code, and each rule above against a real temporary database.
</requirement>
