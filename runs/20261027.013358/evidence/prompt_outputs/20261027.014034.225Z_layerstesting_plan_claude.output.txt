# ARCHITECTURE: LayersTesting Cash Ledger

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Modules, boundaries and technical decisions for the `ledger` command-line cash ledger. |
| Provides | python-project |

## Questions

- None.

## Overview

`ledger` is a single-process command-line application. An executable named `ledger` at the
application root dispatches `./ledger <command>` to Python command modules. Each command resolves the
database, validates every input, checks every rule against stored data, and then performs all of its
writes in one database transaction or none. Reports read stored data only.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python 3.11 or newer | All application code, tests and acceptance criteria. |
| SQLite | The ledger store, reached only through the generated `persistence` package. |
| CLI | The `ledger` executable and the `cli` package. |
| pytest | The project test suite behind `bin/test.sh`. |
| POSIX sh | `bin/test.sh` and the `ledger` launcher. |

## Module Layout

```text
ledger                  executable launcher (POSIX sh) at the application root
cli/                    entry package: main(), errors, commands/, testing
  __init__.py           main(argv) -> int
  errors.py             CliError and its four subclasses
  testing.py            cli_runner(*args) -> (exit_code, stdout, stderr)
  commands/             one module per command, each exposing run(args) -> list[str]
ledgerlib/              domain code shared by commands
  config.py             database location resolution and open_ledger()
  csvout.py             cents formatting and CSV row helpers
  validation.py         codes, names, memos, amounts, dates, ids
  rules.py              balances, non-negative rule, transaction id allocation
persistence/            generated by Drydock from DATABASE.md; never edited by hand
tests/                  project pytest suite
bin/test.sh             application test runner
pyproject.toml, uv.lock project manifest and committed lockfile
```

The domain package is named `ledgerlib` because the executable `ledger` occupies that name at the
application root.

## Module Ownership

| Boundary | Owning module | Low-level APIs it may access |
|----------|---------------|------------------------------|
| Persistence | `persistence` (generated) | The `sqlite3` driver. No other module imports a database driver. |
| Configuration | `ledgerlib.config` | `os.environ`, filesystem path creation for the database file's parent. |
| Output formatting | `ledgerlib.csvout` | Integer arithmetic and string joining only. |
| Input validation | `ledgerlib.validation` | `re`, `datetime.date` for calendar checks. |
| Business rules | `ledgerlib.rules` | `db.<table>.<operation>(...)` only. |
| Process boundary | `cli` | `sys.stdout`, `sys.stderr`, exit codes. |
| File stores | none | Load commands read the CSV path the user names; no other file store. |
| External services | none | No network access. |

## Technical Decisions

- Money is integer cents at every layer. Floating point is never used for money. Output formatting
  and parsing use integer arithmetic.
- Commands return output lines; `cli.main` writes them to standard output only after the command
  succeeds, so a failing command writes nothing to standard output and one diagnostic line to
  standard error.
- Exit codes: 0 success, 1 operational failure, 2 usage error, 3 rejected, 4 not found. They are
  carried by `CliError` subclasses.
- Every command checks all input and all balance rules before its first write. Reads that feed a
  write, such as the next transaction id, occur in the same database transaction as the write.
- Reports and balances are computed in Python from list rows; no aggregate is stored.
- Application code never reads `sources/run.sh` or any seed file, and never embeds a report answer.
- Only SQLite is supported; a PostgreSQL DSN is refused with exit 1 and nothing is written.
- There is no authentication; access is governed by file permissions on the database.

# FEATURE: CLI Entry

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | The `ledger` executable, the `cli` dispatcher and the exit-code error mapping. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | ledger, cli.main |
| Consumes | python-project, persistence |

## Questions

- None.

## Purpose

Give every command one entry point with one failure contract: output is buffered and written only on
success, and any failure produces one line on standard error, nothing on standard output, and a
conventional exit code.

## Interface

- `ledger` at the application root is an executable POSIX sh launcher. It runs
  `cli.main(sys.argv[1:])` with `.venv/bin/python` when present, otherwise `python3`, and exits with
  the returned value.
- `cli.main(argv: list[str] | None = None) -> int`.
- `cli/testing.py` provides `cli_runner(*args) -> (exit_code, stdout, stderr)`.
- `cli/errors.py` defines `CliError` with an `exit_code` attribute and the subclasses
  `OperationalError` (1), `UsageError` (2), `RejectedError` (3) and `NotFoundError` (4).
- `cli/commands/` is a package. `argv[0]` names the module `cli.commands.<command>`, imported
  lazily; each module exposes `run(args: list[str]) -> list[str]` returning output lines and
  printing nothing.

## Behavior

- With no arguments, or when the command module does not exist, `main` raises a usage error:
  exit 2, nothing on standard output, one diagnostic line on standard error.
- On success `main` writes the returned lines to standard output, each ended by `\n`, and returns 0.
- A `CliError` raised by a command produces one diagnostic line on standard error, nothing on
  standard output, and the error's `exit_code`.
- Any other exception is an operational failure: exit 1, one diagnostic line, nothing on standard
  output.
- The remaining arguments after the command name are passed to `run` unchanged.
- No command logic lives in this feature.

## Database Interface

- None — persistence is declared by DATABASE.md and reached through ledgerlib by later features.

import sys
import types

from cli.errors import NotFoundError, OperationalError, RejectedError, UsageError
from cli.testing import cli_runner

expected = {OperationalError: 1, UsageError: 2, RejectedError: 3, NotFoundError: 4}

    def run(args, error_class=error_class):
        raise error_class("probe failure")

    module = types.ModuleType("cli.commands.zzprobe")
    module.run = run
    sys.modules["cli.commands.zzprobe"] = module
    code, out, err = cli_runner("zzprobe")
    print(code, repr(out), repr(err))
    assert code == status
    assert error_class("x").exit_code == status
    assert out == ""
    assert len(err.strip().splitlines()) == 1
sys.modules.pop("cli.commands.zzprobe", None)

project test exists under `tests/` so the runner has something to run.

# FEATURE: Database Selection

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Resolve the ledger database location from configuration and open it through the persistence library. |
| Depends On | FEATURE-CliEntry.md, DATABASE.md |
| Provides | ledgerlib.config |
| Consumes | cli.main, persistence |

## Questions

- None.

## Purpose

Decide which database a command uses and refuse unsupported engines before anything is written.

## Interface

`ledgerlib/config.py`:

- `resolve_database(environ: Mapping[str, str] | None = None) -> str` returns the SQLite location
  using `DATABASE_URL`, else `DATABASE_PATH`, else `data/app.db`. A leading `sqlite://` is removed.
  `environ` defaults to `os.environ`; an unset or empty value counts as absent.
- A value beginning `postgres://` or `postgresql://` raises `OperationalError` (exit 1) before any
  file or directory is created or written.
- `open_ledger(environ: Mapping[str, str] | None = None)` returns an open persistence `Database` for
  the resolved location via `open_database`. An unreachable location, or an existing file that is
  not a valid database, raises `OperationalError`. Nothing is written to standard output.

## Database Interface

- None — persistence is declared by DATABASE.md and reached through `open_database`.

## Programmatic Acceptance

=== AC config-postgres-refused ===
Intent: A PostgreSQL DSN is refused with exit code 1 and no database file is created.

import os
import tempfile

from cli.errors import OperationalError
from ledgerlib.config import resolve_database

with tempfile.TemporaryDirectory() as tmp:
    would_create = os.path.join(tmp, "nested", "ledger.db")
    for dsn in ("postgres://localhost/ledger", "postgresql://localhost/ledger"):

        assert raised.exit_code == 1

    assert not os.path.exists(os.path.dirname(would_create))

=== AC config-invalid-database-file ===
Intent: An existing file that is not a valid database makes open_ledger fail with exit code 1 and print nothing.

import contextlib
import io
import os
import tempfile

from cli.errors import OperationalError
from ledgerlib.config import open_ledger

with tempfile.TemporaryDirectory() as tmp:
    bogus = os.path.join(tmp, "not_a_database.db")
    with open(bogus, "wb") as handle:
        handle.write(b"x" * 4096)
    out = io.StringIO()
    raised = None
    with contextlib.redirect_stdout(out):
        try:
            db = open_ledger({"DATABASE_URL": bogus})
            db.accounts.list()
        except OperationalError as exc:
            raised = exc
    assert raised is not None
    assert raised.exit_code == 1
    assert out.getvalue() == ""
=== END AC config-invalid-database-file ===

- Nothing is written to standard output on failure.

# FEATURE: CSV Output

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Format integer cents and CSV rows exactly as the output contract requires. |
| Depends On | FEATURE-CliEntry.md |
| Provides | ledgerlib.csvout |
| Consumes | cli.main |

## Questions

- None.

## Purpose

One place formats money and rows, so every command prints amounts with exactly two decimal places and
rows with no quoting, no trailing spaces and no thousands separators.

## Interface

`ledgerlib/csvout.py`:

- `format_cents(cents: int) -> str` writes integer cents with exactly two decimals, a leading `-`
  when negative, and no thousands separator. It uses integer arithmetic only, so zero is `0.00`
  and never `-0.00`. A non-integer (including `float` and `bool`) raises `TypeError`.
- `csv_line(fields) -> str` joins fields with commas, with no quoting and no trailing newline;
  `cli.main` adds the `\n` ending.
- `ACCOUNT_HEADER` is `account,name,transactions,balance`.
- `TRANSACTION_HEADER` is `txn_id,date,account,category,amount,memo`.
- `account_row(account, name, transactions, balance_cents) -> str`.
- `transaction_row(txn_id, date, account, category, amount_cents, memo) -> str`.

## Database Interface

- None — this feature formats values and reaches no repository.

## Programmatic Acceptance
