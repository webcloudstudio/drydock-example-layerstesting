# FEATURE: Transfer

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Move cash between two accounts as a pair of TRANSFER transactions written atomically. |
| Depends On | FEATURE-LedgerRules.md, FEATURE-Validation.md, FEATURE-CsvOutput.md, FEATURE-LoadCategories.md |
| Provides | ledger transfer |
| Consumes | ledgerlib.rules, ledgerlib.validation, ledgerlib.csvout |

## Questions

- None.

## Purpose

`ledger transfer <from> <to> <amount> <date>` moves cash from one account to another. It stores
two rows in category `TRANSFER` with consecutive ids, or stores neither.

## Trigger

Command line: `./ledger transfer <from> <to> <amount> <date>`. Implemented in
`cli/commands/transfer.py` as `run(args) -> list[str]`.

## Sequence

1. Require exactly four arguments, else `UsageError` (exit 2) before any database access.
2. Validate both account codes, the amount and the date through `ledgerlib.validation`
   (exit 3 on violation). The amount must be strictly positive; zero and negative amounts are rejected.
3. Reject `<from>` equal to `<to>` (exit 3).
4. Open the ledger. Require both accounts and the category `TRANSFER` to exist (exit 3).
5. Project the source balance after the outgoing row with `ledgerlib.rules`; a negative result is
   rejected (exit 3). The destination balance only grows.
6. In one database transaction, read `next_txn_id`, write the outgoing row with that id, then the
   incoming row with the next id.
7. Return the header `txn_id,date,account,category,amount,memo` and both rows read back from storage.

## Rows Written

| Row | Account | Amount (cents) | Memo |
|-----|---------|----------------|------|
| Outgoing, id N | `<from>` | `-amount` | `transfer to <to>` |
| Incoming, id N+1 | `<to>` | `+amount` | `transfer from <from>` |

Both rows use category `TRANSFER` and the given date. Amounts are integer cents.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

=== AC transfer-success ===
Intent: A valid transfer exits 0, prints header plus two rows with consecutive ids, stores both rows, and conserves total cash.

import csv
import io
from decimal import Decimal
from persistence.testing import db_session
from cli.testing import cli_runner

src = "ZZXFA1"
dst = "ZZXFB1"
seed_cat = "ZZXFSEED"
date = "2026-06-01"
amount = "50.00"
cents = int(Decimal(amount) * 100)
with db_session() as db:
    if db.categories.get(category="TRANSFER") is None:
        db.categories.create(category="TRANSFER", description="Internal transfer")
    db.categories.create(category=seed_cat, description="Xfer seed")
    db.accounts.create(account=src, name="Xfer Source")
    db.accounts.create(account=dst, name="Xfer Dest")
    seed_id = max([r.txn_id for r in db.transactions.list()], default=0) + 1
    db.transactions.create(txn_id=seed_id, date=date, account=src, category=seed_cat, amount=10000, memo="seed")
    total_before = sum(r.amount for r in db.transactions.list())
    code, out, err = cli_runner("transfer", src, dst, amount, date)
    print(out)
    print(err)
    assert code == 0
    rows = list(csv.reader(io.StringIO(out)))
    assert rows[0] == ["txn_id", "date", "account", "category", "amount", "memo"]
    assert len(rows) == 3
    out_row, in_row = rows[1], rows[2]
    assert int(in_row[0]) == int(out_row[0]) + 1
    assert out_row[1] == date and in_row[1] == date
    assert out_row[2] == src and in_row[2] == dst
    assert out_row[3] == "TRANSFER" and in_row[3] == "TRANSFER"
    assert Decimal(out_row[4]) == Decimal(-cents) / 100
    assert Decimal(in_row[4]) == Decimal(cents) / 100
    first = db.transactions.get(txn_id=int(out_row[0]))
    second = db.transactions.get(txn_id=int(in_row[0]))
    assert first is not None and second is not None
    assert first.account == src and first.amount == -cents
    assert second.account == dst and second.amount == cents
    assert first.category == "TRANSFER" and second.category == "TRANSFER"
    assert sum(r.amount for r in db.transactions.list(account=src)) == 10000 - cents
    assert sum(r.amount for r in db.transactions.list(account=dst)) == cents
    assert sum(r.amount for r in db.transactions.list()) == total_before

# FEATURE: Report Balances

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Report each account's transaction count and balance, plus a total row, computed from stored data. |
| Depends On | FEATURE-LedgerRules.md, FEATURE-LoadTransactions.md, FEATURE-CsvOutput.md |
| Provides | ledger report balances |
| Consumes | ledgerlib.rules, ledgerlib.csvout |

## Questions

- None.

## Purpose

`ledger report balances` prints one row per account ordered by code, then a `TOTAL` row. It also
creates the report dispatcher used by the other reports.

## Trigger

Command line: `./ledger report balances`. Implemented in `cli/commands/report.py`, which holds a
report-name table. An unknown report name, a missing name, or extra arguments is a `UsageError`
(exit 2) raised before any database access.

## Output

Header `account,name,transactions,balance`, then per account (ordered by code) the account code,
name, the count of its transactions, and its balance. Final row `TOTAL,,<count>,<sum>` where
`<count>` is the total number of stored transactions and `<sum>` the total of all balances.
Money is formatted from integer cents with exactly two decimals and never prints as `-0.00`.
On an empty ledger the output is the header and `TOTAL,,0,0.00`.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

=== AC balances-report ===
Intent: Balances rows follow stored accounts in code order with counts and two-decimal balances derived from stored transactions, and a zero balance prints as 0.00.

import csv
import io
import re
from decimal import Decimal
from persistence.testing import db_session
from cli.testing import cli_runner

money = re.compile(r"^-?\d+\.\d\d$")

    db.categories.create(category="ZZRBCAT", description="Rpt Bal")
    db.accounts.create(account="ZZRB1", name="Rpt One")
    db.accounts.create(account="ZZRB2", name="Rpt Two")
    db.accounts.create(account="ZZRB3", name="Rpt Zero")
    base = max([r.txn_id for r in db.transactions.list()], default=0) + 1
    specs = [("ZZRB1", 12345), ("ZZRB1", -2000), ("ZZRB2", 50), ("ZZRB3", 700), ("ZZRB3", -700)]
    for i, (acct, cents) in enumerate(specs):
        db.transactions.create(txn_id=base + i, date="2099-01-15", account=acct, category="ZZRBCAT", amount=cents, memo="rb")
    code, out, err = cli_runner("report", "balances")
    print(out)
    print(err)
    assert code == 0
    assert out.endswith("\n")
    assert '"' not in out and "\r" not in out
    rows = list(csv.reader(io.StringIO(out)))
    assert rows[0] == ["account", "name", "transactions", "balance"]
    accounts = db.accounts.list()
    txns = db.transactions.list()

        assert r[1] == a.name

    assert len(total) == 4
    assert total[0] == "TOTAL" and total[1] == ""
    assert int(total[2]) == len(txns)
    assert money.match(total[3])
    assert Decimal(total[3]) == Decimal(sum(t.amount for t in txns)) / 100
    zero = [r for r in data if r[0] == "ZZRB3"][0]
    assert zero[3] == "0.00"
    assert all(r[3] != "-0.00" for r in data)

import csv
import io
from decimal import Decimal

# FEATURE: Report Categories

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Report transaction count, inflow, outflow and net per category, including unused categories. |
| Depends On | FEATURE-ReportBalances.md |
| Provides | ledger report categories |
| Consumes | ledger report balances |

## Questions

- None.

## Purpose

`ledger report categories` summarizes stored transactions per category and in total.

## Trigger

Command line: `./ledger report categories`, added to the report-name table in
`cli/commands/report.py`. Extra arguments are a `UsageError` (exit 2).

## Output

Header `category,description,transactions,inflow,outflow,net`, one row per stored category ordered
by code (categories with no transactions included with count 0 and zero amounts), then
`TOTAL,,<count>,<inflow>,<outflow>,<net>`. `inflow` is the sum of positive amounts, `outflow` the
sum of absolute values of negative amounts written as a positive number, and `net` is
`inflow - outflow`. All money uses exactly two decimals computed from integer cents.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

import csv
import io
import re
from decimal import Decimal
from persistence.testing import db_session
from cli.testing import cli_runner

money = re.compile(r"^-?\d+\.\d\d$")
with db_session() as db:
    db.accounts.create(account="ZZRC1", name="Rpt Cat Acct")
    db.categories.create(category="ZZRCMIX", description="Rpt Mixed")
    db.categories.create(category="ZZRCOUT", description="Rpt Outflow")
    db.categories.create(category="ZZRCNONE", description="Rpt Unused")
    base = max([r.txn_id for r in db.transactions.list()], default=0) + 1
    specs = [("ZZRCMIX", 10000), ("ZZRCMIX", 550), ("ZZRCMIX", -2525), ("ZZRCOUT", -799)]
    for i, (cat, cents) in enumerate(specs):
        db.transactions.create(txn_id=base + i, date="2099-03-10", account="ZZRC1", category=cat, amount=cents, memo="rc")
    code, out, err = cli_runner("report", "categories")
    print(out)
    print(err)
    assert code == 0
    assert out.endswith("\n")
    rows = list(csv.reader(io.StringIO(out)))
    assert rows[0] == ["category", "description", "transactions", "inflow", "outflow", "net"]
    cats = db.categories.list()
    txns = db.transactions.list()
    data, total = rows[1:-1], rows[-1]
    assert [r[0] for r in data] == [c.category for c in cats]
    for r, c in zip(data, cats):
        amounts = [t.amount for t in txns if t.category == c.category]
        inflow = sum(a for a in amounts if a > 0)
        outflow = -sum(a for a in amounts if a < 0)
        assert len(r) == 6
        assert r[1] == c.description
        assert int(r[2]) == len(amounts)
        for field in r[3:]:
            assert money.match(field)
        assert Decimal(r[3]) == Decimal(inflow) / 100
        assert Decimal(r[4]) == Decimal(outflow) / 100
        assert Decimal(r[5]) == Decimal(inflow - outflow) / 100
    unused = [r for r in data if r[0] == "ZZRCNONE"][0]
    assert int(unused[2]) == 0
    assert Decimal(unused[3]) == 0 and Decimal(unused[4]) == 0 and Decimal(unused[5]) == 0
    all_amounts = [t.amount for t in txns]
    t_in = sum(a for a in all_amounts if a > 0)
    t_out = -sum(a for a in all_amounts if a < 0)
    assert len(total) == 6
    assert total[0] == "TOTAL" and total[1] == ""
    assert int(total[2]) == len(txns)
    assert Decimal(total[3]) == Decimal(t_in) / 100
    assert Decimal(total[4]) == Decimal(t_out) / 100
    assert Decimal(total[5]) == Decimal(t_in - t_out) / 100

# FEATURE: Usage Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Guarantee every unknown command, table, report, verb or wrong argument count exits 2 with a usage line on standard error only. |
| Depends On | FEATURE-Init.md, FEATURE-Count.md, FEATURE-LoadTransactions.md, FEATURE-AccountDelete.md, FEATURE-TxnAmend.md, FEATURE-TxnDelete.md, FEATURE-Transfer.md, FEATURE-ReportCategories.md, FEATURE-ReportMonthly.md |
| Provides | cli.usage |
| Consumes | ledger, ledger init, ledger count, ledger load accounts, ledger load categories, ledger load transactions, ledger account add, ledger account get, ledger account rename, ledger account delete, ledger txn post, ledger txn get, ledger txn amend, ledger txn delete, ledger transfer, ledger report balances, ledger report categories, ledger report monthly |

## Questions

- None.

## Purpose

Integration story proving the usage-error contract across the whole command table.

## Usage Table

One shared usage table covers every command and sub-verb; a usage error prints that command's
one-line usage text to standard error.

| Command | Usage |
|---------|-------|
| `init` | `ledger init` |
| `count` | `ledger count` |
| `load` | `ledger load <accounts\|categories\|transactions> <csv>` |
| `account add` / `get` / `rename` / `delete` | `ledger account add <code> <name>`, `get <code>`, `rename <code> <name>`, `delete <code>` |
| `txn post` / `get` / `amend` / `delete` | `ledger txn post <account> <category> <amount> <date> [<memo>]`, `get <id>`, `amend <id> <amount>`, `delete <id>` |
| `transfer` | `ledger transfer <from> <to> <amount> <date>` |
| `report` | `ledger report <balances\|categories\|monthly>` |

## Behavior

- `ledger` with no arguments, an unknown command, unknown table, unknown report, unknown verb, or
  wrong argument count exits 2.
- Standard output is empty; standard error carries the usage text.
- Argument-count checks happen before any database access, so a usage error never reads or writes
  the database.
- Invalid values of correct arity (for example a non-digit transaction id) are rejections (exit 3),
  and absent records are not found (exit 4); neither is a usage error.

## Database Interface

- None — persistence is owned by DATABASE.md.
