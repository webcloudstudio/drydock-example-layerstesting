Planning Instructions

Delivery Shape

The system is a single-process command-line ledger. The ledger executable at the application root reads command arguments, the database location from DATABASE_URL or DATABASE_PATH, and CSV files for loads. It writes CSV to standard output, diagnostics to standard error, and exits with codes 0 to 4.

Each command resolves the database, validates every input, checks every balance rule against stored data, and then either performs all of its writes in one database transaction or performs none. Reports read stored data only.

Repository-call contracts for DATABASE.md, all with consumer sensitivity data (CLI consumer):

Source Conflicts and Gaps

The unattended policy applies, so no blocker or questionnaire is raised. Each item below is a selected behavior, recorded here as the decision of record.

  1. Authentication. No auth model is stated. Selected: no authentication. This is a local command-line tool whose access is governed by the operator's file permissions on the database.
  2. PostgreSQL DSN. The Database section recognizes postgres:// and postgresql:// values, but the Stack and the job specify SQLite only. Selected: this build supports SQLite only. A PostgreSQL DSN is refused with exit 1 and nothing is written (AC-001).
  3. Shipped persistence library. It is not among the imported sources. Selected: the relational layer generated from DATABASE.md under persistence.md is the library. Plan authors DATABASE.md.
  4. Transaction id arguments. Rule 3 through Rule 6 do not name ids. Selected: a non-digit id is rejected with exit 3, and an absent id exits 4 (AC-007). The same rule applies to amend and delete.
  5. Help text. No help output is stated. Selected: usage text goes to standard error on usage errors (AC-011). Help does not write to standard output.
  6. Transfer legs. Single legs can be amended or deleted. Selected: permitted under the balance rule (AC-008).
  7. Concurrency. Sources require each command to be all-or-nothing and do not state a locking model. Selected: atomicity comes from the database transaction (AC-003).
  8. Database directory. Selected: init creates a missing parent directory (AC-002).
  9. Load balance check. Selected: evaluated on each account's final balance after the whole file (AC-006).
  10. Deployment target. None stated. Selected: a local executable run from the application root.
