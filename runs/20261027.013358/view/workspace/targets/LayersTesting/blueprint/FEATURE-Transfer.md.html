FEATURE: Transfer

FieldValue
Version20261027 V1
DescriptionMove cash between two accounts as a pair of TRANSFER transactions written atomically.
Depends OnFEATURE-LedgerRules.md, FEATURE-Validation.md, FEATURE-CsvOutput.md, FEATURE-LoadCategories.md
Providesledger transfer
Consumesledgerlib.rules, ledgerlib.validation, ledgerlib.csvout

Purpose

ledger transfer <from> <to> <amount> <date> moves cash from one account to another. It stores two rows in category TRANSFER with consecutive ids, or stores neither.

Trigger

Command line: ./ledger transfer <from> <to> <amount> <date>. Implemented in cli/commands/transfer.py as run(args) -> list[str].

Sequence

  1. Require exactly four arguments, else UsageError (exit 2) before any database access.
  2. Validate both account codes, the amount and the date through ledgerlib.validation

(exit 3 on violation). The amount must be strictly positive; zero and negative amounts are rejected.

  1. Reject <from> equal to <to> (exit 3).
  2. Open the ledger. Require both accounts and the category TRANSFER to exist (exit 3).
  3. Project the source balance after the outgoing row with ledgerlib.rules; a negative result is

rejected (exit 3). The destination balance only grows.

  1. In one database transaction, read next_txn_id, write the outgoing row with that id, then the

incoming row with the next id.

  1. Return the header txn_id,date,account,category,amount,memo and both rows read back from storage.

Rows Written

RowAccountAmount (cents)Memo
Outgoing, id N<from>-amounttransfer to <to>
Incoming, id N+1<to>+amounttransfer from <from>

Both rows use category TRANSFER and the given date. Amounts are integer cents.

Database Interface

  • None — persistence is owned by DATABASE.md.

=== AC transfer-success ===
Intent: A valid transfer exits 0, prints header plus two rows with consecutive ids, stores both rows, and conserves total cash.

import csv import io from decimal import Decimal from persistence.testing import db_session from cli.testing import cli_runner

src = "ZZXFA1" dst = "ZZXFB1" seed_cat = "ZZXFSEED" date = "2026-06-01" amount = "50.00" cents = int(Decimal(amount) * 100) with db_session() as db: if db.categories.get(category="TRANSFER") is None: db.categories.create(category="TRANSFER", description="Internal transfer") db.categories.create(category=seed_cat, description="Xfer seed") db.accounts.create(account=src, name="Xfer Source") db.accounts.create(account=dst, name="Xfer Dest") seed_id = max([r.txn_id for r in db.transactions.list()], default=0) + 1 db.transactions.create(txn_id=seed_id, date=date, account=src, category=seed_cat, amount=10000, memo="seed") total_before = sum(r.amount for r in db.transactions.list()) code, out, err = cli_runner("transfer", src, dst, amount, date) print(out) print(err) assert code == 0 rows = list(csv.reader(io.StringIO(out))) assert rows[0] == ["txn_id", "date", "account", "category", "amount", "memo"] assert len(rows) == 3 out_row, in_row = rows[1], rows[2] assert int(in_row[0]) == int(out_row[0]) + 1 assert out_row[1] == date and in_row[1] == date assert out_row[2] == src and in_row[2] == dst assert out_row[3] == "TRANSFER" and in_row[3] == "TRANSFER" assert Decimal(out_row[4]) == Decimal(-cents) / 100 assert Decimal(in_row[4]) == Decimal(cents) / 100 first = db.transactions.get(txn_id=int(out_row[0])) second = db.transactions.get(txn_id=int(in_row[0])) assert first is not None and second is not None assert first.account == src and first.amount == -cents assert second.account == dst and second.amount == cents assert first.category == "TRANSFER" and second.category == "TRANSFER" assert sum(r.amount for r in db.transactions.list(account=src)) == 10000 - cents assert sum(r.amount for r in db.transactions.list(account=dst)) == cents assert sum(r.amount for r in db.transactions.list()) == total_before === END AC transfer-success ===

Guardrails

  • Every check completes before the first write; a rejected transfer stores neither row.
  • Both rows are written in one database transaction.
  • Amounts are integer cents; no floating point at any layer.
  • Diagnostics go to standard error only; a failing transfer writes nothing to standard output.
