FEATURE: Load Categories

FieldValue
Version20261027 V1
DescriptionImplements ledger load categories <csv> as an all-or-nothing bulk load of categories.
Depends OnFEATURE-LoadAccounts.md, FEATURE-Validation.md, DATABASE.md
Providesledger load categories
Consumesledger load accounts, ledgerlib.validation

Purpose

Load category records from a CSV file into the ledger. The whole file is accepted or none of it is stored.

Interface

ledger load categories <csv> adds the categories handler to the per-table registry in cli/commands/load.py created by the accounts load story.

Output on success, as CSV with \n endings:

table,loaded
categories,<rows>

Behavior

  1. The file must be readable. An unreadable or missing file is an operational failure (exit 1, nothing on stdout).
  2. The header row must be exactly category,description. Any other header is rejected (exit 3).
  3. Every data row has the same field count as the header, else the file is rejected (exit 3).
  4. Each category is a code of 1 to 12 characters from A-Z and 0-9. Each description is 1 to 40 characters with no comma or newline.
  5. A code repeated within the file, or already stored, is rejected (exit 3).
  6. Every check completes before the first write. Writes happen in one database transaction, so a rejected file stores nothing.
  7. A file with a valid header and no data rows loads zero rows, prints categories,0 and exits 0.
  8. A missing path argument is a usage error (exit 2).

Database Interface

  • None — persistence is owned by DATABASE.md.

Programmatic Acceptance

=== AC load-categories-success ===
Intent: A valid categories file loads in full, reports the row count, and every row reads back through the public store interface.

import csv import os import tempfile from cli.testing import cli_runner from persistence.testing import db_session

def write_csv(directory, name, rows): path = os.path.join(directory, name) with open(path, "w", newline="") as fh: csv.writer(fh, lineterminator="\n").writerows(rows) return path

data = [["ZZLC1", "Load Cat One"], ["ZZLC2", "Load Cat Two"], ["ZZLC3", "Load Cat Three"]] with db_session() as db: with tempfile.TemporaryDirectory() as tmp: path = write_csv(tmp, "cats.csv", [["category", "description"]] + data) code, out, err = cli_runner("load", "categories", path) print(out, err) assert code == 0 parsed = list(csv.reader(out.splitlines())) assert parsed == [["table", "loaded"], ["categories", str(len(data))]] for cat, desc in data: row = db.categories.get(category=cat) assert row is not None assert row.description == desc === END AC load-categories-success ===

import csv import os import tempfile from cli.testing import cli_runner from persistence.testing import db_session

dup = "ZZLD1" stored = "ZZLD2" stored_desc = "Stored Desc" with db_session() as db: db.categories.create(category=stored, description=stored_desc) with tempfile.TemporaryDirectory() as tmp: p1 = os.path.join(tmp, "dup_in_file.csv") with open(p1, "w", newline="") as fh: w = csv.writer(fh, lineterminator="\n") w.writerow(["category", "description"]) w.writerow([dup, "First"]) w.writerow([dup, "Second"]) code1, out1, err1 = cli_runner("load", "categories", p1) p2 = os.path.join(tmp, "dup_stored.csv") with open(p2, "w", newline="") as fh: w = csv.writer(fh, lineterminator="\n") w.writerow(["category", "description"]) w.writerow(["ZZLD3", "New One"]) w.writerow([stored, "Replacement"]) code2, out2, err2 = cli_runner("load", "categories", p2) print(out1, err1, out2, err2) assert code1 == 3 assert code2 == 3 assert out1 == "" and out2 == "" assert db.categories.get(category=dup) is None assert db.categories.get(category="ZZLD3") is None kept = db.categories.get(category=stored) assert kept is not None assert kept.description == stored_desc === END AC load-categories-duplicates ===

User Acceptance

  • None.

Guardrails

  • A rejected load stores none of the file's rows.
  • Application code does not read sources/seed_categories.csv; seed files reach the database only through ledger load.
  • Only the generated persistence package touches the database; no driver import in load code.
  • Diagnostics go to standard error and never to standard output.
