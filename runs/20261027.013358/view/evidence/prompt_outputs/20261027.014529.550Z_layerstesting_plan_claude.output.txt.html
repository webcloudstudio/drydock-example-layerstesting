# FEATURE: Account Delete

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger account delete <code>`, refusing deletion while the account has transactions. |
| Depends On | FEATURE-AccountRename.md, FEATURE-LoadTransactions.md, DATABASE.md |
| Provides | ledger account delete |
| Consumes | ledger account rename, ledger load transactions |

## Questions

- None.

## Purpose

Remove an account that has no transactions. The command is part of `cli/commands/account.py` and shares its verb table with add, get and rename.

## Behavior

1. `ledger account delete <code>` takes exactly one argument; any other count is a usage error (exit 2).
2. An absent code exits 4 with nothing on standard output.
3. An account referenced by any transaction is refused with exit 3 and nothing changes.
4. Otherwise the account row is deleted and the command prints `deleted` then the code, one per line.
5. The in-use check and the delete happen before any other write and in one database transaction.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Transaction Post

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger txn post` with validation, id allocation and the non-negative balance rule. |
| Depends On | FEATURE-LedgerRules.md, FEATURE-LoadCategories.md, FEATURE-AccountAdd.md, FEATURE-Validation.md, FEATURE-CsvOutput.md, DATABASE.md |
| Provides | ledger txn post |
| Consumes | ledgerlib.rules, ledgerlib.validation, ledgerlib.csvout |

## Questions

- None.

## Purpose

Record one receipt or payment against an account. The command lives in `cli/commands/txn.py`, which owns the verb table for `txn post|get|amend|delete`.

## Behavior

1. Usage: `ledger txn post <account> <category> <amount> <date> [<memo>]`. Fewer than four or more than five arguments is a usage error (exit 2). The memo defaults to the empty string.
2. Every input is validated before any write: codes, amount (integer cents, never zero, at most two decimals), real calendar date, and memo rules. Violations exit 3.
3. The account and the category must exist, else exit 3.
4. The projected balance of the account after the post must not be negative, else exit 3.
5. The new `txn_id` is the largest present plus one, or 1 when empty. The id is read and the row written in one database transaction.
6. Output is the header `txn_id,date,account,category,amount,memo` and the new row, amount with exactly two decimals.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance
