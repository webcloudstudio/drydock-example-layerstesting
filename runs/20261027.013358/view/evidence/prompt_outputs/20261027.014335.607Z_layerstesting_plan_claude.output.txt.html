# FEATURE: Load Categories

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger load categories <csv>` as an all-or-nothing bulk load of categories. |
| Depends On | FEATURE-LoadAccounts.md, FEATURE-Validation.md, DATABASE.md |
| Provides | ledger load categories |
| Consumes | ledger load accounts, ledgerlib.validation |

## Questions

- None.

## Purpose

Load category records from a CSV file into the ledger. The whole file is accepted or none of it is stored.

## Interface

`ledger load categories <csv>` adds the `categories` handler to the per-table registry in `cli/commands/load.py` created by the accounts load story.

Output on success, as CSV with `\n` endings:

```text
table,loaded
categories,<rows>
```

## Behavior

1. The file must be readable. An unreadable or missing file is an operational failure (exit 1, nothing on stdout).
2. The header row must be exactly `category,description`. Any other header is rejected (exit 3).
3. Every data row has the same field count as the header, else the file is rejected (exit 3).
4. Each `category` is a code of 1 to 12 characters from `A-Z` and `0-9`. Each `description` is 1 to 40 characters with no comma or newline.
5. A code repeated within the file, or already stored, is rejected (exit 3).
6. Every check completes before the first write. Writes happen in one database transaction, so a rejected file stores nothing.
7. A file with a valid header and no data rows loads zero rows, prints `categories,0` and exits 0.
8. A missing path argument is a usage error (exit 2).

## Database Interface

- None — persistence is owned by DATABASE.md.

import csv
import os
import tempfile
from cli.testing import cli_runner
from persistence.testing import db_session

def write_csv(directory, name, rows):
    path = os.path.join(directory, name)
    with open(path, "w", newline="") as fh:
        csv.writer(fh, lineterminator="\n").writerows(rows)
    return path

data = [["ZZLC1", "Load Cat One"], ["ZZLC2", "Load Cat Two"], ["ZZLC3", "Load Cat Three"]]
with db_session() as db:
    with tempfile.TemporaryDirectory() as tmp:
        path = write_csv(tmp, "cats.csv", [["category", "description"]] + data)
        code, out, err = cli_runner("load", "categories", path)
    print(out, err)
    assert code == 0
    parsed = list(csv.reader(out.splitlines()))
    assert parsed == [["table", "loaded"], ["categories", str(len(data))]]
    for cat, desc in data:
        row = db.categories.get(category=cat)
        assert row is not None
        assert row.description == desc

# FEATURE: Load Transactions

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implements `ledger load transactions <csv>` with whole-file validation and whole-file balance checking. |
| Depends On | FEATURE-LoadCategories.md, FEATURE-LedgerRules.md, FEATURE-Validation.md, DATABASE.md |
| Provides | ledger load transactions |
| Consumes | ledger load categories, ledgerlib.rules, ledgerlib.validation |

## Questions

- None.

## Purpose

Bulk load transactions, keeping each file's `txn_id`, so that either every row is stored or none is.

## Interface

`ledger load transactions <csv>` adds the `transactions` handler to `cli/commands/load.py`.

Output on success:

```text
table,loaded
transactions,<rows>
```

## Behavior

1. An unreadable file is exit 1 with nothing on stdout.
2. The header must be exactly `txn_id,date,account,category,amount,memo`, else exit 3.
3. Each row has the header's field count, else exit 3.
4. `txn_id` is a string of decimal digits; each row keeps its file `txn_id`. A `txn_id` repeated in the file or already stored is rejected (exit 3).
5. `date` is a real calendar date `YYYY-MM-DD`. `amount` matches `-?DIGITS[.D[D]]`, at most two decimals, never zero, and is converted to integer cents with integer arithmetic. `memo` is 0 to 60 characters with no comma or newline.
6. `account` must be stored and `category` must be stored, else exit 3.
7. The balance rule is evaluated on each affected account's final balance after the whole file is applied on top of the stored transactions, not row by row. Any final balance below zero rejects the whole file (exit 3).
8. Every check precedes the first write; writes happen in one database transaction. A rejected file changes nothing.
9. A header-only file loads zero rows and prints `transactions,0`.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

import csv
import os
import tempfile
from decimal import Decimal
from cli.testing import cli_runner
from persistence.testing import db_session

acct = "ZZLTA1"
cat = "ZZLTC1"
rows = [
    ["880001", "2026-04-01", acct, cat, "100.00", "first"],
    ["880002", "2026-04-02", acct, cat, "-30.25", "second"],
]
with db_session() as db:
    db.accounts.create(account=acct, name="Load Txn A")

        assert row is not None

# FEATURE: Account Add
