## Planning Instructions

### Delivery Shape

The system is a single-executable CLI named `ledger` at the application root. Inputs are CSV files and command-line arguments. Outputs are CSV to standard output on success and one diagnostic line to standard error on failure. Persistence is SQLite through the shipped persistence library, with three tables: `accounts`, `categories`, and `transactions`. Amounts are stored as integer cents.

Required execution flow: every command validates all inputs and business rules (including the non-negative balance rule) before its first write, and every write either completes in full or changes nothing.

### Test and Acceptance Strategy

Story-scoped tests: each story runs the grader slice it owns, or the application's `bin/test.sh` scoped to the relevant cases. No story runs the full grader.

Terminal verification story: the grader `sh sources/run.sh` runs unfiltered and must exit 0. That is the single full-suite gate, and it depends on every implementation story. Its acceptance assertion declares `Suite: full`.

Final Sea Trial verification is recorded in `SEA_TRIALS.md`.

# COMPASS: drydock Layers Testing Uat Case

## Compass
A command-line cash ledger for a small shop that tracks cash held across drawers, a safe, and petty cash. It records every receipt and payment against an account and produces three reports: balances by account, totals by category, and totals by month. It is built as a graded exam: the supplied grader `sources/run.sh` is the acceptance proof, and the scored outcomes are exact CSV output and exit codes.

## Constraints
- Executable named `ledger` at the application root.
- Python 3.11 or newer over SQLite, accessed only through the shipped persistence library.
- Amounts stored as integer cents; never floating point.
- Database path from `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`.
- Output CSV with `\n` endings, no quoting, no trailing spaces.
- Standard error never compared by the grader.

## Guardrails
- Never read `sources/run.sh` from application code and never embed a report answer; every report is computed from the database.
- Never modify, rewrite, regenerate, or substitute the scoring assets in `sources/`.
- A rejected command changes nothing; every check runs before the first write.
- No command may leave an account balance below zero.
- Never open a database driver directly from application code.
