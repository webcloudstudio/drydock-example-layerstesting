# FEATURE: Transfer Overdraw Rejection

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | A transfer larger than the source account balance is rejected with exit 3 and writes neither row. |
| Depends On | FEATURE-Transfer.md, FEATURE-LoadTransactions.md, FEATURE-LedgerCore.md, DATABASE.md |
| Provides | transfer overdraw rejection |

## Questions

- None.

## Purpose

`ledger transfer <from> <to> <amount> <date>` must never leave the source account below zero. This
story proves that the projected balance of the source, computed from its stored transactions minus
the transfer amount, is checked before the first write. A rejected transfer exits `3`, writes nothing
to standard output, and leaves the transactions table exactly as it was. A transfer that brings the
source to exactly zero is allowed.

## Behavior

- The source balance is the sum, in integer cents, of the source account's transactions, read from
  the database at command time.
- If the balance minus the transfer amount is below zero, the command exits `3` before writing either
  the outgoing or the incoming row.
- If the source has no transactions its balance is zero and any positive transfer is rejected.
- A transfer equal to the whole balance succeeds and leaves the source at zero.
- No floating point is used at any step.

## Database Interface

- `FEATURE-TXN-002` — read: list the source account's transactions to compute its balance - supplies: `account` - returns: `account`, `amount`

# FEATURE: Balance Rule

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Assembles and verifies that post, amend, delete, transfer, and load each reject any change that would leave an account balance below zero. |
| Depends On | FEATURE-TxnPost.md, FEATURE-TxnAmend.md, FEATURE-TxnDelete.md, FEATURE-TransferOverdraw.md, FEATURE-LoadRejection.md, FEATURE-LedgerCore.md, DATABASE.md |
| Provides | non-negative balance rule |

## Questions

- None.

## Purpose

An account's balance is the sum of its transaction amounts in integer cents. No command may leave
any account balance below zero. This assembly story confirms that every mutating command applies the
shared projected-balance guard from the ledger core before its first write, and wires the guard into
any command that lacks it. A rejection exits `3`, prints nothing to standard output, and leaves every
table unchanged.

## Behavior

- `txn post` rejects a withdrawal larger than the account balance.
- `txn amend` rejects an amount that makes the resulting balance negative.
- `txn delete` rejects deleting a deposit that the remaining transactions depend on.
- `transfer` rejects an amount larger than the source balance.
- `load transactions` rejects a file whose rows, taken together, leave any balance negative, and
  stores none of its rows.
- Each command also allows a change that brings a balance to exactly zero.

## Database Interface

- `FEATURE-TXN-002` — read: list an account's transactions to compute balances - supplies: `account` - returns: `account`, `amount`

## Questions

## Purpose

`ledger report balances` prints one row per account with its transaction count and balance, ordered
by account code, followed by a TOTAL row. Every value is computed from the database at run time;

## Behavior

- Header row: `account,name,transactions,balance`.
- One data row per account, ordered by account code, including accounts with no transactions

- Final row: `TOTAL,,<count>,<sum>` where count is the total number of transactions and sum is the
  total of all balances.
- Balances are sums of integer cents, written with exactly two decimal places, a leading `-` when
  negative, and no thousands separator.
- Output is unquoted CSV with `\n` line endings; exit `0`.

- `FEATURE-ACCOUNT-002` — read: list every account in code order - supplies: `account` - returns: `account`, `name`

    assert re.fullmatch(r"-?\d+\.\d{2}", text), text

    db.accounts.create(account="ACPTRB1", name="Report One")

    db.transactions.create(txn_id=base + 2, date="2026-06-02", account="ACPTRB1", category=cat, amount=-1250, memo="")
    db.transactions.create(txn_id=base + 3, date="2026-06-03", account="ACPTRB2", category=cat, amount=500000, memo="")
    code, out, err = cli_runner("report", "balances")
    print(out)
    print(err)

    data = rows[1:-1]
    total = rows[-1]

    assert [r[0] for r in data] == [a.account for a in accounts]
    assert [r[0] for r in data] == sorted(r[0] for r in data)
    count_sum = 0
    cents_sum = 0
    for row, acct in zip(data, accounts):
        assert len(row) == 4
        txns = db.transactions.list(account=acct.account)
        assert row[1] == acct.name
        assert int(row[2]) == len(txns)
        assert cents(row[3]) == sum(t.amount for t in txns)
        count_sum += len(txns)
        cents_sum += sum(t.amount for t in txns)
    assert total[0] == "TOTAL"
    assert total[1] == ""
    assert len(total) == 4
    assert int(total[2]) == count_sum
    assert cents(total[3]) == cents_sum

# FEATURE: Report Monthly

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger report monthly`, listing transaction count, inflow, outflow, and net per calendar month plus a TOTAL row. |
| Depends On | FEATURE-LoadTransactions.md, FEATURE-CliEntry.md, FEATURE-LedgerCore.md, DATABASE.md |
| Provides | ledger report monthly |

## Questions

- None.

## Purpose

`ledger report monthly` prints one row per `YYYY-MM` that has at least one transaction, in ascending
order, with that month's transaction count, inflow, outflow, and net, followed by a TOTAL row. Every
value is computed from the database at run time.

## Behavior

- Header row: `month,transactions,inflow,outflow,net`.
- The month of a transaction is the first seven characters of its `YYYY-MM-DD` date.
- Only months with transactions appear, ascending.
- `inflow` is the sum of positive amounts. `outflow` is the sum of the absolute values of negative
  amounts, written as a positive number. `net` is `inflow - outflow`.
- Final row: `TOTAL,<count>,<inflow>,<outflow>,<net>`.
- Amounts are written with exactly two decimal places, a leading `-` when negative, and no
  thousands separator. Output is unquoted CSV with `\n` line endings; exit `0`.

## Database Interface

- `FEATURE-TXN-002` — read: list every transaction to group by month - supplies: `account`, `category` - returns: `date`, `amount`

## Programmatic Acceptance

=== AC report-monthly-rows ===
Intent: Each month row's count, inflow, outflow, and net match the stored transactions grouped by date, ascending, followed by a consistent TOTAL row.

import csv
import io
import re
from decimal import Decimal
from persistence.testing import db_session
from cli.testing import cli_runner

def cents(text):
    assert re.fullmatch(r"-?\d+\.\d{2}", text), text
    return int(Decimal(text) * 100)

with db_session() as db:
    acct = "ACPTMR1"
    cat = "ACPTMRC"
    db.accounts.create(account=acct, name="Monthly Report")
    db.categories.create(category=cat, description="Monthly Category")
    base = max([t.txn_id for t in db.transactions.list()], default=0)
    db.transactions.create(txn_id=base + 1, date="2031-07-01", account=acct, category=cat, amount=50000, memo="")
    db.transactions.create(txn_id=base + 2, date="2031-07-15", account=acct, category=cat, amount=-1999, memo="")
    db.transactions.create(txn_id=base + 3, date="2031-09-02", account=acct, category=cat, amount=-2001, memo="")
    code, out, err = cli_runner("report", "monthly")
    print(out)
    print(err)
    assert code == 0
    rows = list(csv.reader(io.StringIO(out)))
    assert rows[0] == ["month", "transactions", "inflow", "outflow", "net"]
    data = rows[1:-1]
    total = rows[-1]
    txns = db.transactions.list()
    months = sorted({t.date[:7] for t in txns})
    assert [r[0] for r in data] == months
    sums = [0, 0, 0, 0]
    for row, month in zip(data, months):
        assert len(row) == 5
        group = [t for t in txns if t.date[:7] == month]
        inflow = sum(t.amount for t in group if t.amount > 0)
        outflow = sum(-t.amount for t in group if t.amount < 0)
        assert int(row[1]) == len(group)
        assert cents(row[2]) == inflow
        assert cents(row[3]) == outflow
        assert cents(row[4]) == inflow - outflow
        sums[0] += len(group)
        sums[1] += inflow
        sums[2] += outflow
        sums[3] += inflow - outflow
    assert total[0] == "TOTAL"
    assert len(total) == 5
    assert int(total[1]) == sums[0]
    assert cents(total[2]) == sums[1]
    assert cents(total[3]) == sums[2]
    assert cents(total[4]) == sums[3]

=== AC report-monthly-reflects-changes ===
Intent: The report is computed from the database, so a new transaction in a month raises that month's count by one.

import csv
import io
from persistence.testing import db_session
from cli.testing import cli_runner

def count_for(out, month):
    rows = list(csv.reader(io.StringIO(out)))
    mine = [r for r in rows[1:-1] if r[0] == month]
    return int(mine[0][1]) if mine else 0

with db_session() as db:
    acct = "ACPTMC1"
    cat = "ACPTMCC"
    month = "2033-05"
    db.accounts.create(account=acct, name="Changing Monthly")
    db.categories.create(category=cat, description="Changing Monthly Category")
    code, out, err = cli_runner("report", "monthly")
    print(out)
    print(err)
    assert code == 0
    first = count_for(out, month)
    tid = max([t.txn_id for t in db.transactions.list()], default=0) + 1
    db.transactions.create(txn_id=tid, date="2033-05-20", account=acct, category=cat, amount=700, memo="")
    code, out, err = cli_runner("report", "monthly")
    print(out)
    print(err)
    assert code == 0
    assert count_for(out, month) == first + 1
