# FEATURE: Account Get

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |

| Consumes | accounts.get, transactions.list |

## Questions

## Purpose

Read one account by code and print it as CSV. The transaction count and balance are computed from the
database on every call and are never stored.

## Command Contract

| Aspect | Rule |
|--------|------|
| Invocation | `ledger account get <code>` with exactly one argument. |
| Success stdout | Header `account,name,transactions,balance`, then one row: code, name, count of the account's transactions, balance as two-decimal text. |
| Balance | Sum of the account's integer-cent amounts, formatted with exactly two decimals, a leading `-` when negative, no thousands separator. No floating point. |
| Absent account | Exit 4, nothing on stdout, one diagnostic line on stderr. |
| Wrong argument count | Exit 2, nothing on stdout. |
| Writes | None. |

## Database Interface

- `FEATURE-ACCOUNT-001` — read: retrieve an account by code - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-002` — read: list the account's transactions to count and sum them - supplies: `account` - returns: `amount`

Intent: Getting an account computes its transaction count and balance from stored integer cents.

import csv
import io
from persistence.testing import db_session
from cli.testing import cli_runner

with db_session() as db:
    code = "AGETB1"
    cat = "AGETBC1"
    name = "Get Balance"
    db.accounts.create(account=code, name=name)
    db.categories.create(category=cat, description="Get Balance Cat")
    amounts = [5000, -1234]
    base = max([t.txn_id for t in db.transactions.list()], default=0) + 1
    for offset, cents in enumerate(amounts):
        db.transactions.create(
            txn_id=base + offset, date="2026-05-01", account=code,
            category=cat, amount=cents, memo="",
        )
    rc, out, err = cli_runner("account", "get", code)
    print(out)
    print(err)
    assert rc == 0
    rows = list(csv.reader(io.StringIO(out)))
    assert rows[1][0] == code
    assert rows[1][1] == name
    assert int(rows[1][2]) == len(amounts)
    assert int(rows[1][3].replace(".", "")) == sum(amounts)
    assert len(rows[1][3].split(".")[1]) == 2

# FEATURE: Account Duplicate Rejection

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |

| Provides | duplicate account rejection |
| Consumes | accounts.list |

## Questions

- None.

## Purpose

An account code is a primary key. Adding an existing code is a rejected command: it exits 3, writes
nothing to stdout, and neither the existing row nor any other row changes.

| Recovery | A later add of a different code succeeds. |

# FEATURE: Transaction Post

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger txn post`, recording one receipt or payment against an account in integer cents. |
| Depends On | FEATURE-AccountAdd.md, FEATURE-LoadCategories.md, FEATURE-LedgerCore.md, FEATURE-CliEntry.md, DATABASE.md |
| Provides | ledger txn post |
| Consumes | transactions.create, transactions.list, accounts.list, categories.get |

## Questions

- None.

## Purpose

Post a single transaction. Every input and the non-negative balance rule are checked before the first
write, so a rejected post changes nothing.

## Command Contract

| Aspect | Rule |
|--------|------|
| Invocation | `ledger txn post <account> <category> <amount> <date> [<memo>]`: four or five arguments. |
| Amount | Matches `-?DIGITS[.D[D]]`, at most two decimals, never zero. Parsed to integer cents by the shared core; no floating point. |
| Date | A real calendar date written `YYYY-MM-DD`. |
| Memo | Optional, 0 to 60 characters, no comma or newline. Absent means the empty string. |
| Account and category | Both must exist; otherwise exit 3. |
| Transaction id | One more than the largest `txn_id` present, or `1` in an empty table. |
| Balance | If the account balance after the post would be below zero, exit 3 before any write. |
| Success stdout | Header `txn_id,date,account,category,amount,memo`, then the new row with the amount as two-decimal text. |
| Rejection | Exit 3, nothing on stdout, no row stored. |
| Wrong argument count | Exit 2, nothing on stdout. |

## Database Interface

- `FEATURE-TXN-003` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-002` — read: list transactions to find the largest id and the account balance - supplies: `account` - returns: `txn_id`, `amount`
- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`
- `FEATURE-CATEGORY-001` — read: confirm the category exists - supplies: `category` - returns: `category`

## Guardrails

- Amounts are parsed to integer cents by the shared core; no floating point at any layer.
- Every input and the balance rule are checked before the first write; a rejected post stores nothing.
- Nothing is written to stdout on failure.
- The transaction id is never supplied by the caller; it is one more than the largest present, or 1.
