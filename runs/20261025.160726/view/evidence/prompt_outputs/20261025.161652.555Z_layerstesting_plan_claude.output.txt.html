# FEATURE: Txn Get

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger txn get <id>`, printing one transaction row or exiting 4 when absent. |
| Depends On | FEATURE-TxnPost.md, FEATURE-CliEntry.md, FEATURE-LedgerCore.md, DATABASE.md |
| Provides | ledger txn get |
| Consumes | cli.main, format_amount |

## Questions

- None.

## Purpose

Read a single transaction by id and print it in the transaction CSV shape. The command never writes.

## Trigger and Interface

`ledger txn get <id>` takes exactly one argument. The id is a base-10 integer.

| Condition | Exit | Stdout |
|-----------|------|--------|
| Row found | 0 | Header `txn_id,date,account,category,amount,memo`, then the row |
| No row with that id | 4 | Nothing |
| Wrong argument count, or an id that is not an integer | 2 | Nothing |
| Database unreachable or tables missing | 1 | Nothing |

One diagnostic line goes to standard error on every failure.

## Sequence

1. Check the argument count and parse the id; failure is a usage error.
2. Read the row through `transactions.get`.
3. If the result is `None`, fail with the not-found exit code.
4. Print the header and one row. The amount is formatted from integer cents with `format_amount`: exactly two decimals, a leading `-` when negative, no thousands separator. An empty memo prints as an empty trailing field.

## Reads

The `transactions` row for the id. Nothing else.

## Writes

None.

## Database Interface

- `FEATURE-TXN-001` — read: get a transaction by id - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

import csv
import io

# FEATURE: Txn Amend

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger txn amend <id> <amount>`, changing only a transaction's amount while keeping every balance non-negative. |
| Depends On | FEATURE-TxnGet.md, FEATURE-LedgerCore.md, FEATURE-CliEntry.md, DATABASE.md |
| Provides | ledger txn amend |
| Consumes | cli.main, parse_amount, format_amount, balance_guard, ledger txn get |

## Questions

- None.

## Purpose

Correct the amount of an existing transaction. Date, account, category, and memo never change. The change is rejected before any write if it would leave the owning account's balance below zero.

## Trigger and Interface

`ledger txn amend <id> <amount>` takes exactly two arguments.

| Condition | Exit | Stdout |
|-----------|------|--------|
| Amended | 0 | Header `txn_id,date,account,category,amount,memo`, then the updated row |
| Amount fails `-?DIGITS[.D[D]]`, has more than two decimals, or is zero | 3 | Nothing |
| Resulting balance of the owning account would be below zero | 3 | Nothing |
| No transaction with that id | 4 | Nothing |
| Wrong argument count, or an id that is not an integer | 2 | Nothing |
| Database unreachable or tables missing | 1 | Nothing |

One diagnostic line goes to standard error on every failure.

## Sequence

1. Check the argument count and parse the id (usage error otherwise).
2. Parse the amount with `parse_amount` into integer cents (rejection otherwise).
3. Locate the transaction by listing transactions; if absent, fail with not found.
4. List the owning account's transactions and ask `balance_guard` for the balance that results from replacing this row's amount; if any resulting balance is below zero, reject.
5. Only after every check passes, write the new amount through `transactions.update`, then print the returned row.

## Reads

All transactions, to locate the row, and the owning account's transactions, to compute the projected balance.

## Writes

The `amount` column of exactly one `transactions` row.

## Database Interface

- `FEATURE-TXN-004` — write: change a transaction amount - supplies: `txn_id`, `amount` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-TXN-002` — read: list transactions to locate the row and compute the projected balance - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

# FEATURE: Txn Validate

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Specifies the input validation `ledger txn post` applies to category, amount, and date before it writes anything. |
| Depends On | FEATURE-TxnPost.md, FEATURE-LedgerCore.md, DATABASE.md |
| Provides | txn post validation |
| Consumes | ledger txn post, parse_amount, validate_date |

## Questions

- None.

## Purpose

Guarantee that an invalid category, amount, or date given to `ledger txn post` is rejected with exit 3 before the first write, and that valid boundary inputs are accepted. Wiring lives in the post command; this specification owns the rules and their proof.

## Rules

| Input | Valid | Rejected with exit 3 |
|-------|-------|----------------------|
| Category | A code present in `categories` | An unknown category |
| Amount | `-?DIGITS[.D[D]]`, never zero, so `12`, `12.5`, `-12.50` | More than two decimals (`1.234`), `12.`, a leading `+`, non-numeric text, empty text, `0`, `0.00`, `-0.00` |
| Date | A real calendar date written `YYYY-MM-DD`, including a leap day in a leap year | `2026-02-30`, `2026-02-29`, `2026-2-3`, non-date text |

A rejected post writes no row, prints nothing to standard output, writes one diagnostic line to standard error, and consumes no transaction id: the next successful post receives one more than the largest id present.

## Database Interface

- `FEATURE-CATEGORY-001` — read: look up the category named on input - supplies: `category` - returns: `category`, `description`
- `FEATURE-ACCOUNT-002` — read: confirm the account exists - supplies: `account` - returns: `account`, `name`

# FEATURE: Transfer

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger transfer <from> <to> <amount> <date>`, writing two TRANSFER rows atomically. |
| Depends On | FEATURE-TxnPost.md, FEATURE-LedgerCore.md, FEATURE-CliEntry.md, DATABASE.md |
| Provides | ledger transfer |
| Consumes | cli.main, parse_amount, format_amount, validate_date, balance_guard |

## Questions

- None.

## Purpose

Move cash between two accounts as a pair of transactions in category `TRANSFER`. Both rows are stored or neither is.

## Trigger and Interface

`ledger transfer <from> <to> <amount> <date>` takes exactly four arguments.

| Condition | Exit | Stdout |
|-----------|------|--------|
| Transferred | 0 | Header `txn_id,date,account,category,amount,memo`, then the outgoing row, then the incoming row |
| Amount malformed, zero, or negative; date invalid; `from` equals `to`; either account unknown | 3 | Nothing |
| Amount exceeds the balance of `from` | 3 | Nothing |
| Wrong argument count | 2 | Nothing |
| Database unreachable or tables missing | 1 | Nothing |

One diagnostic line goes to standard error on every failure.

## Rows Written

| Row | Id | Account | Amount | Memo |
|-----|----|---------|--------|------|
| Outgoing | one more than the largest `txn_id` present, or 1 in an empty table | `<from>` | `-amount` | `transfer to <to>` |
| Incoming | the outgoing id plus one | `<to>` | `+amount` | `transfer from <from>` |

Both rows use category `TRANSFER` and the given date.

## Sequence

1. Check the argument count (usage error otherwise).
2. Parse the amount into integer cents; it must be positive. Validate the date. Require `from` and `to` to differ.
3. Confirm both accounts exist by listing accounts.
4. List transactions; compute the next id and the balance of `from`. Ask `balance_guard` whether subtracting the amount leaves `from` at or above zero.
5. Only after every check passes, write both rows in one database session, outgoing first. The writes use the transaction insert declared by FEATURE-TxnPost.md. A failure of either write leaves neither row stored.
6. Print the header and the two rows.

## Reads

Both accounts, and all transactions for the next id and the source balance.

## Writes

Two `transactions` rows, or none.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm both accounts exist - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-002` — read: list transactions for the next id and the source balance - supplies: `account` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
