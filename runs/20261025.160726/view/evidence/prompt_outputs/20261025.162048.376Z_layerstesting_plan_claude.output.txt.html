# FEATURE: Usage Errors

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Every unknown command, unknown table or report, and wrong argument count exits 2 with nothing on standard output. |
| Depends On | FEATURE-CliEntry.md, FEATURE-Count.md, FEATURE-LoadAccounts.md, FEATURE-AccountAdd.md, FEATURE-TxnPost.md, FEATURE-Transfer.md, FEATURE-ReportBalances.md |
| Provides | usage error contract |
| Consumes | cli.main, ledger count, ledger load accounts, ledger account add, ledger txn post, ledger transfer, ledger report balances |

## Questions

- None.

## Purpose

`ledger` distinguishes a malformed invocation (exit `2`) from a rejected one (exit `3`). A usage
error is detected from the argument vector alone, before the database is opened and before any
file is read, so it can never touch the store.

## Behavior

| Invocation | Exit |
|---|---|
| no arguments | `2` |
| unknown top-level command | `2` |
| `load` with a table other than `accounts`, `categories`, `transactions` | `2` |
| `report` with a report other than `balances`, `categories`, `monthly` | `2` |
| `account` or `txn` with an unknown subcommand | `2` |
| any command with too few or too many arguments | `2` |

Argument counts: `init` 0, `count` 0, `load` 2, `account add` 2, `account get` 1,
`account rename` 2, `account delete` 1, `txn post` 4 or 5, `txn get` 1, `txn amend` 2,
`txn delete` 1, `transfer` 4, `report` 1.

A usage error writes nothing to standard output and one diagnostic line to standard error.

## Database Interface

- None — persistence is owned by FEATURE-Count.md.

# FEATURE: Output Contract

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Successful commands write unquoted CSV with LF endings, init writes nothing, and failures write nothing to standard output. |
| Depends On | FEATURE-CliEntry.md, FEATURE-AccountAdd.md, FEATURE-AccountGet.md, FEATURE-TxnPost.md, FEATURE-ReportBalances.md |
| Provides | output contract |
| Consumes | cli.main, ledger account add, ledger account get, ledger txn post, ledger report balances |

## Questions

- None.

## Purpose

Fixes what each command may put on each stream so the grader's byte-for-byte comparison of
standard output is stable.

## Behavior

- Every successful command except `init` writes one header row then data rows, comma-separated,
  with no quoting, no trailing spaces, and `\n` line endings, ending with a final `\n`.
- `init` writes nothing to standard output.
- A failing command (exit `1`, `2`, `3`, or `4`) writes nothing to standard output and exactly one
  diagnostic line to standard error.
- Money is written with exactly two decimals, a leading `-` when negative, and no thousands
  separator.
- The account row is `account,name,transactions,balance`; the transaction row is
  `txn_id,date,account,category,amount,memo`.

## Database Interface

- None — persistence is owned by FEATURE-AccountAdd.md.

# FEATURE: Database Resolution

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Resolve the database from DATABASE_URL, then DATABASE_PATH, then data/app.db, selecting PostgreSQL or SQLite by prefix. |
| Depends On | FEATURE-Init.md, FEATURE-Count.md, FEATURE-CliEntry.md, DATABASE.md |
| Provides | database resolution, cli.database.resolve_database_dsn, cli.database.database_engine |
| Consumes | cli.main, ledger count, ledger txn post |

## Questions

- None.

## Purpose

Every command opens the store through the shipped persistence library using one DSN chosen by a
single pure resolver. No driver is opened anywhere else and amounts stay integer cents.

## Interface

Module `cli/database.py`:

- `resolve_database_dsn(environ: Mapping[str, str]) -> str` returns `environ["DATABASE_URL"]` when
  set and non-empty, else `environ["DATABASE_PATH"]` when set and non-empty, else `data/app.db`.
  The value is returned unchanged and handed to `persistence.open_database`.
- `database_engine(dsn: str) -> str` returns `postgres` for a value beginning `postgres://` or
  `postgresql://`, and `sqlite` for anything else, including a `sqlite://` prefixed value.
- The command layer calls `resolve_database_dsn(os.environ)` once per invocation. A missing
  directory, unreachable server, or missing tables is exit `1`.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: list accounts to confirm the resolved store is reachable - supplies: `account` - returns: `account`, `name`

## Programmatic Acceptance

## Purpose

`bin/test.sh` is the project's own regression gate. It runs from the application root, activates
the `.venv` environment, and runs `pytest -q`, propagating pytest's exit status.

## Behavior

- Written in POSIX `sh`; no bashisms.
- Changes to the application root regardless of the caller's working directory.
- Exits zero only when every test passes; any failure or collection error is non-zero.
- The pytest suite lives under `tests/` and covers each command, each exit code (`0` to `4`), and
  each rule in the instructions: rejected commands change nothing, no negative balances, code, name,
  memo, amount, and date validation, transaction id assignment, transfer pairing, and the three
  reports. Each test runs against its own temporary database; none uses `sources/run.sh`.
- No test invokes `bin/test.sh` itself.

## Database Interface

- None — persistence is owned by FEATURE-Init.md.
