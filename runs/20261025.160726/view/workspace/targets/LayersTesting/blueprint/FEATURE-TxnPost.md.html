FEATURE: Transaction Post

FieldValue
Version20261025 V1
DescriptionImplements ledger txn post, recording one receipt or payment against an account in integer cents.
Depends OnFEATURE-AccountAdd.md, FEATURE-LoadCategories.md, FEATURE-LedgerCore.md, FEATURE-CliEntry.md, DATABASE.md
Providesledger txn post
Consumestransactions.create, transactions.list, accounts.list, categories.get

Purpose

Post a single transaction. Every input and the non-negative balance rule are checked before the first write, so a rejected post changes nothing.

Command Contract

AspectRule
Invocationledger txn post <account> <category> <amount> <date> [<memo>]: four or five arguments.
AmountMatches -?DIGITS[.D[D]], at most two decimals, never zero. Parsed to integer cents by the shared core; no floating point.
DateA real calendar date written YYYY-MM-DD.
MemoOptional, 0 to 60 characters, no comma or newline. Absent means the empty string.
Account and categoryBoth must exist; otherwise exit 3.
Transaction idOne more than the largest txn_id present, or 1 in an empty table.
BalanceIf the account balance after the post would be below zero, exit 3 before any write.
Success stdoutHeader txn_id,date,account,category,amount,memo, then the new row with the amount as two-decimal text.
RejectionExit 3, nothing on stdout, no row stored.
Wrong argument countExit 2, nothing on stdout.

Database Interface

  • FEATURE-TXN-003 — write: create a transaction - supplies: txn_id, date, account, category, amount, memo - returns: txn_id, date, account, category, amount, memo
  • FEATURE-TXN-002 — read: list transactions to find the largest id and the account balance - supplies: account - returns: txn_id, amount
  • FEATURE-ACCOUNT-002 — read: confirm the account exists - supplies: account - returns: account
  • FEATURE-CATEGORY-001 — read: confirm the category exists - supplies: category - returns: category

Programmatic Acceptance

=== AC txn-post-success ===
Intent: Posting a transaction prints its row with the next id and stores integer cents that read back.

import csv import io from persistence.testing import db_session from cli.testing import cli_runner

with db_session() as db: acct = "TPOSS1" cat = "TPOSSC1" db.accounts.create(account=acct, name="Post Success") db.categories.create(category=cat, description="Post Success Cat") next_id = max([t.txn_id for t in db.transactions.list()], default=0) + 1 amount_text = "45.50" day = "2026-04-01" memo = "walk in sale" rc, out, err = cli_runner("txn", "post", acct, cat, amount_text, day, memo) print(out) print(err) assert rc == 0 rows = list(csv.reader(io.StringIO(out))) assert rows[0] == ["txn_id", "date", "account", "category", "amount", "memo"] assert len(rows) == 2 assert int(rows[1][0]) == next_id assert rows[1][1] == day assert rows[1][2] == acct assert rows[1][3] == cat assert rows[1][4] == amount_text assert rows[1][5] == memo got = db.transactions.get(txn_id=next_id) assert got is not None assert got.date == day assert got.account == acct assert got.category == cat assert got.amount == int(amount_text.replace(".", "")) assert got.memo == memo === END AC txn-post-success ===

User Acceptance

  • None.

Guardrails

  • Amounts are parsed to integer cents by the shared core; no floating point at any layer.
  • Every input and the balance rule are checked before the first write; a rejected post stores nothing.
  • Nothing is written to stdout on failure.
  • The transaction id is never supplied by the caller; it is one more than the largest present, or 1.
