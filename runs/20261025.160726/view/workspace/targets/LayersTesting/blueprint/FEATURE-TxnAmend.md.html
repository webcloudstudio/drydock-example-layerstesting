FEATURE: Txn Amend

FieldValue
Version20261025 V1
DescriptionImplements ledger txn amend <id> <amount>, changing only a transaction's amount while keeping every balance non-negative.
Depends OnFEATURE-TxnGet.md, FEATURE-LedgerCore.md, FEATURE-CliEntry.md, DATABASE.md
Providesledger txn amend
Consumescli.main, parse_amount, format_amount, balance_guard, ledger txn get

Purpose

Correct the amount of an existing transaction. Date, account, category, and memo never change. The change is rejected before any write if it would leave the owning account's balance below zero.

Trigger and Interface

ledger txn amend <id> <amount> takes exactly two arguments.

ConditionExitStdout
Amended0Header txn_id,date,account,category,amount,memo, then the updated row
Amount fails -?DIGITS[.D[D]], has more than two decimals, or is zero3Nothing
Resulting balance of the owning account would be below zero3Nothing
No transaction with that id4Nothing
Wrong argument count, or an id that is not an integer2Nothing
Database unreachable or tables missing1Nothing

One diagnostic line goes to standard error on every failure.

Sequence

  1. Check the argument count and parse the id (usage error otherwise).
  2. Parse the amount with parse_amount into integer cents (rejection otherwise).
  3. Locate the transaction by listing transactions; if absent, fail with not found.
  4. List the owning account's transactions and ask balance_guard for the balance that results from replacing this row's amount; if any resulting balance is below zero, reject.
  5. Only after every check passes, write the new amount through transactions.update, then print the returned row.

Reads

All transactions, to locate the row, and the owning account's transactions, to compute the projected balance.

Writes

The amount column of exactly one transactions row.

Database Interface

  • FEATURE-TXN-004 — write: change a transaction amount - supplies: txn_id, amount - returns: txn_id, date, account, category, amount, memo
  • FEATURE-TXN-002 — read: list transactions to locate the row and compute the projected balance - supplies: account - returns: txn_id, date, account, category, amount, memo

import csv import io from persistence.testing import db_session from cli.testing import cli_runner

with db_session() as db: acct = "TAACCT1" cat = "TACAT1" day = "2026-04-01" memo = "walk in sale" db.accounts.create(account=acct, name="Amend Account") db.categories.create(category=cat, description="Amend Category") new_id = max([t.txn_id for t in db.transactions.list()], default=0) + 1 db.transactions.create(txn_id=new_id, date=day, account=acct, category=cat, amount=4550, memo=memo) code, out, err = cli_runner("txn", "amend", str(new_id), "54.50") print(out) print(err) assert code == 0 rows = list(csv.reader(io.StringIO(out))) assert rows[0] == ["txn_id", "date", "account", "category", "amount", "memo"] assert rows[1] == [str(new_id), day, acct, cat, "54.50", memo] stored = db.transactions.get(txn_id=new_id) assert stored is not None assert stored.amount == 5450 assert stored.date == day assert stored.account == acct assert stored.category == cat assert stored.memo == memo === END AC txnamend-success ===

User Acceptance

  • None.

Guardrails

  • Only the amount changes; date, account, category, and memo are never written.
  • The balance check runs before the first write; a rejected amendment leaves every table unchanged.
  • Amounts are integer cents at every layer; no floating point.
  • Standard output carries only the documented CSV; failures write one diagnostic line to standard error and nothing to standard output.
  • Only the generated persistence package reaches the database.
