FEATURE: Transfer

FieldValue
Version20261025 V1
DescriptionImplements ledger transfer <from> <to> <amount> <date>, writing two TRANSFER rows atomically.
Depends OnFEATURE-TxnPost.md, FEATURE-LedgerCore.md, FEATURE-CliEntry.md, DATABASE.md
Providesledger transfer
Consumescli.main, parse_amount, format_amount, validate_date, balance_guard

Purpose

Move cash between two accounts as a pair of transactions in category TRANSFER. Both rows are stored or neither is.

Trigger and Interface

ledger transfer <from> <to> <amount> <date> takes exactly four arguments.

ConditionExitStdout
Transferred0Header txn_id,date,account,category,amount,memo, then the outgoing row, then the incoming row
Amount malformed, zero, or negative; date invalid; from equals to; either account unknown3Nothing
Amount exceeds the balance of from3Nothing
Wrong argument count2Nothing
Database unreachable or tables missing1Nothing

One diagnostic line goes to standard error on every failure.

Rows Written

RowIdAccountAmountMemo
Outgoingone more than the largest txn_id present, or 1 in an empty table<from>-amounttransfer to <to>
Incomingthe outgoing id plus one<to>+amounttransfer from <from>

Both rows use category TRANSFER and the given date.

Sequence

  1. Check the argument count (usage error otherwise).
  2. Parse the amount into integer cents; it must be positive. Validate the date. Require from and to to differ.
  3. Confirm both accounts exist by listing accounts.
  4. List transactions; compute the next id and the balance of from. Ask balance_guard whether subtracting the amount leaves from at or above zero.
  5. Only after every check passes, write both rows in one database session, outgoing first. The writes use the transaction insert declared by FEATURE-TxnPost.md. A failure of either write leaves neither row stored.
  6. Print the header and the two rows.

Reads

Both accounts, and all transactions for the next id and the source balance.

Writes

Two transactions rows, or none.

Database Interface

  • FEATURE-ACCOUNT-002 — read: confirm both accounts exist - supplies: account - returns: account, name
  • FEATURE-TXN-002 — read: list transactions for the next id and the source balance - supplies: account - returns: txn_id, date, account, category, amount, memo

import csv import io from persistence.testing import db_session from cli.testing import cli_runner

with db_session() as db: src = "XFSRC1" dst = "XFDST1" day = "2026-04-03" opening = "OPENX1" db.accounts.create(account=src, name="Transfer Source") db.accounts.create(account=dst, name="Transfer Dest") db.categories.create(category=opening, description="Opening") db.categories.create(category="TRANSFER", description="Internal transfer") if db.categories.get(category="TRANSFER") is None else None base = max([t.txn_id for t in db.transactions.list()], default=0) db.transactions.create(txn_id=base + 1, date="2026-04-01", account=src, category=opening, amount=10000, memo="fund") code, out, err = cli_runner("transfer", src, dst, "25.00", day) print(out) print(err) assert code == 0 rows = list(csv.reader(io.StringIO(out))) assert rows[0] == ["txn_id", "date", "account", "category", "amount", "memo"] assert len(rows) == 3 out_row, in_row = rows[1], rows[2] assert out_row[:5] == [str(base + 2), day, src, "TRANSFER", "-25.00"] assert in_row[:5] == [str(base + 3), day, dst, "TRANSFER", "25.00"] assert out_row[5].split(" ") == ["transfer", "to", dst] assert in_row[5].split(" ") == ["transfer", "from", src] stored_out = db.transactions.get(txn_id=base + 2) stored_in = db.transactions.get(txn_id=base + 3) assert stored_out is not None and stored_in is not None assert stored_out.amount == -2500 and stored_out.account == src assert stored_in.amount == 2500 and stored_in.account == dst === END AC transfer-success ===

=== AC transfer-balances ===
Intent: A transfer moves exactly the amount between the two account balances.

from persistence.testing import db_session from cli.testing import cli_runner

def balance(db, account): return sum(t.amount for t in db.transactions.list(account=account))

with db_session() as db: src = "XFSRC2" dst = "XFDST2" opening = "OPENX2" db.accounts.create(account=src, name="Balance Source") db.accounts.create(account=dst, name="Balance Dest") db.categories.create(category=opening, description="Opening") if db.categories.get(category="TRANSFER") is None: db.categories.create(category="TRANSFER", description="Internal transfer") base = max([t.txn_id for t in db.transactions.list()], default=0) db.transactions.create(txn_id=base + 1, date="2026-04-01", account=src, category=opening, amount=10000, memo="fund") src_before = balance(db, src) dst_before = balance(db, dst) code, out, err = cli_runner("transfer", src, dst, "40.00", "2026-04-03") print(out) print(err) assert code == 0 assert balance(db, src) == src_before - 4000 assert balance(db, dst) == dst_before + 4000 === END AC transfer-balances ===

User Acceptance

  • None.

Guardrails

  • Both rows are stored or neither; every check completes before the first write.
  • The outgoing row takes the next id and the incoming row the id after it.
  • Amounts are integer cents at every layer; no floating point.
  • The source account balance never goes below zero.
  • Standard output carries only the documented CSV; failures write one diagnostic line to standard error and nothing to standard output.
  • Only the generated persistence package reaches the database.
