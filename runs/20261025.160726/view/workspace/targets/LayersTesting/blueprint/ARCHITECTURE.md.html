FieldValue

DescriptionModule layout, boundaries, exit-code and output contracts for the ledger command-line cash ledger.
Providesledger executable, bin/test.sh launcher contract

Purpose

ledger is a single command-line executable at the application root. It keeps accounts, categories, and cash transactions in a relational database reached only through the shipped persistence library. Every command either completes in full or changes nothing. Balances never go below zero. Money is stored and computed as integer cents at every layer.

Command Flow

  1. main parses argv, finds the longest registered command prefix, and checks argument count.
  2. The handler checks every input and every rule, computes the full change, and only then writes.
  3. The handler returns rows (a header row and data rows) or None.
  4. main writes the rows to standard output as CSV only after the handler has returned.
  5. A raised LedgerError becomes its exit code and one line on standard error; standard output stays empty.

Exit Codes

CodeMeaning
0Success.
1Operational failure: database unreachable, tables missing, file unreadable, or any unexpected exception.
2Usage error: unknown command, table, or report; wrong argument count.
3Rejected: invalid input, duplicate key, unknown reference, account in use, or a change that would leave a negative balance.
4Not found: an absent account or transaction id.

Output Contract

Successful commands except init write CSV: one header row, then data rows, comma-separated, no quoting, no trailing spaces, \n line endings. Amounts print with exactly two decimals, a leading - when negative, and no thousands separator. Failures write nothing to standard output and one diagnostic line to standard error.

Guardrails on Design

  • Report values, counts, and totals are always computed from database reads, never embedded.
  • No floating point for money at any layer.
  • Application code never reads sources/run.sh or any seed file; seed files reach the database only through ledger load.

=== AC arch-no-driver-imports ===
Intent: No application file outside the persistence package imports a database driver.

import ast import os

forbidden = {"sqlite3", "psycopg", "psycopg2"} skip = {".venv", "persistence", "sources", "tests", "pycache", ".git", "blueprint"} offenders = [] for root, dirs, files in os.walk("."): dirs[:] = [d for d in dirs if d not in skip] for name in files: if not (name.endswith(".py") or name == "ledger"): continue path = os.path.join(root, name) with open(path, "rb") as fh: src = fh.read() try: tree = ast.parse(src) except SyntaxError: continue for node in ast.walk(tree): if isinstance(node, ast.Import): mods = [a.name.split(".")[0] for a in node.names] elif isinstance(node, ast.ImportFrom): mods = [(node.module or "").split(".")[0]] else: continue offenders += [(path, m) for m in mods if m in forbidden] assert offenders == [] === END AC arch-no-driver-imports ===

User Acceptance

Guardrails

  • Do not modify, rewrite, regenerate, or substitute any file under sources/.
  • Do not open a database driver outside the shipped persistence library.
  • Do not use floating point for money at any layer.
  • Do not hardcode a report row, a count, or a total.
