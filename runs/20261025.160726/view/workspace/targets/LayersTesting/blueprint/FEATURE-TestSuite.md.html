Purpose

bin/test.sh is the project's own regression gate. It runs from the application root, activates the .venv environment, and runs pytest -q, propagating pytest's exit status.

Behavior

  • Written in POSIX sh; no bashisms.
  • Changes to the application root regardless of the caller's working directory.
  • Exits zero only when every test passes; any failure or collection error is non-zero.
  • The pytest suite lives under tests/ and covers each command, each exit code (0 to 4), and

each rule in the instructions: rejected commands change nothing, no negative balances, code, name, memo, amount, and date validation, transaction id assignment, transfer pairing, and the three reports. Each test runs against its own temporary database; none uses sources/run.sh.

  • No test invokes bin/test.sh itself.

Database Interface

  • None — persistence is owned by FEATURE-Init.md.

Intent: pytest collects at least one test from the application's suite.

result = subprocess.run( [sys.executable, "-m", "pytest", "--collect-only", "-q"], capture_output=True, text=True, ) print(result.stdout) print(result.stderr) assert result.returncode == 0 === END AC testsh-suite-is-collected ===

Guardrails

  • bin/test.sh never reads or runs sources/run.sh.
  • Tests never use the configured application store; each creates a temporary database.
  • Tests use no network access other than a PostgreSQL server named by DATABASE_URL.
