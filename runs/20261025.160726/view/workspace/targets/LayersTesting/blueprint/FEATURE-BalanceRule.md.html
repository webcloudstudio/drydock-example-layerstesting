FEATURE: Balance Rule

FieldValue
Version20261025 V1
DescriptionAssembles and verifies that post, amend, delete, transfer, and load each reject any change that would leave an account balance below zero.
Depends OnFEATURE-TxnPost.md, FEATURE-TxnAmend.md, FEATURE-TxnDelete.md, FEATURE-TransferOverdraw.md, FEATURE-LoadRejection.md, FEATURE-LedgerCore.md, DATABASE.md
Providesnon-negative balance rule

Purpose

An account's balance is the sum of its transaction amounts in integer cents. No command may leave any account balance below zero. This assembly story confirms that every mutating command applies the shared projected-balance guard from the ledger core before its first write, and wires the guard into any command that lacks it. A rejection exits 3, prints nothing to standard output, and leaves every table unchanged.

Behavior

  • txn post rejects a withdrawal larger than the account balance.
  • txn amend rejects an amount that makes the resulting balance negative.
  • txn delete rejects deleting a deposit that the remaining transactions depend on.
  • transfer rejects an amount larger than the source balance.
  • load transactions rejects a file whose rows, taken together, leave any balance negative, and

stores none of its rows.

  • Each command also allows a change that brings a balance to exactly zero.

Database Interface

  • FEATURE-TXN-002 — read: list an account's transactions to compute balances - supplies: account - returns: account, amount

Programmatic Acceptance

=== AC balance-rule-post ===
Intent: txn post rejects a withdrawal exceeding the balance and accepts one that brings it to zero.

from persistence.testing import db_session from cli.testing import cli_runner

with db_session() as db: acct = "ACPTBP1" cat = "ACPTBPC" db.accounts.create(account=acct, name="Post Rule") db.categories.create(category=cat, description="Post Rule Category") tid = max([t.txn_id for t in db.transactions.list()], default=0) + 1 db.transactions.create(txn_id=tid, date="2026-06-01", account=acct, category=cat, amount=5000, memo="") before = len(db.transactions.list()) code, out, err = cli_runner("txn", "post", acct, cat, "-50.01", "2026-06-02") print(out) print(err) assert code == 3 assert out == "" assert len(db.transactions.list()) == before assert sum(t.amount for t in db.transactions.list(account=acct)) == 5000 code, out, err = cli_runner("txn", "post", acct, cat, "-50.00", "2026-06-02") print(out) print(err) assert code == 0 assert len(db.transactions.list()) == before + 1 assert sum(t.amount for t in db.transactions.list(account=acct)) == 0 === END AC balance-rule-post ===

=== AC balance-rule-load ===
Intent: load transactions rejects a file whose rows leave a balance negative and stores none of its rows.

import csv import os import tempfile from persistence.testing import db_session from cli.testing import cli_runner

with db_session() as db: acct = "ACPTBL1" cat = "ACPTBLC" db.accounts.create(account=acct, name="Load Rule") db.categories.create(category=cat, description="Load Rule Category") base = max([t.txn_id for t in db.transactions.list()], default=0) first_id = base + 1 second_id = base + 2 before = len(db.transactions.list()) with tempfile.TemporaryDirectory() as folder: path = os.path.join(folder, "rows.csv") with open(path, "w", newline="") as handle: writer = csv.writer(handle, lineterminator="\n") writer.writerow(["txn_id", "date", "account", "category", "amount", "memo"]) writer.writerow([first_id, "2026-06-01", acct, cat, "10.00", "deposit"]) writer.writerow([second_id, "2026-06-02", acct, cat, "-10.01", "overdraw"]) code, out, err = cli_runner("load", "transactions", path) print(out) print(err) assert code == 3 assert out == "" assert len(db.transactions.list()) == before assert db.transactions.get(txn_id=first_id) is None assert db.transactions.get(txn_id=second_id) is None === END AC balance-rule-load ===

User Acceptance

  • None.

Guardrails

  • Every check happens before the command's first write; a rejected command changes no table.
  • Balances are computed from stored transactions in integer cents; no floating point is used.
  • A rejected command writes nothing to standard output and one diagnostic line to standard error.
