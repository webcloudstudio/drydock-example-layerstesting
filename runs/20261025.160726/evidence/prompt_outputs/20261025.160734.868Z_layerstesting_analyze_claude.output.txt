## Planning Instructions

### Delivery Shape

The system is a single executable `ledger` at the application root, implemented in Python 3.11+ over SQLite, with PostgreSQL reachable through the shipped persistence library via `DATABASE_URL`. Inputs are CLI arguments and CSV files; outputs are CSV on stdout and one diagnostic line on stderr for failures. Persistence is three tables (`accounts`, `categories`, `transactions`) reached only through the shipped library. Execution flow: `init` → `load` seeds → commands and reports → grader.

# COMPASS: drydock Layers Testing Uat Case

## Compass
A command-line cash ledger for a small shop that keeps cash in drawers, a safe, and petty cash. It records every receipt and payment against one of those places and produces balance, category, and monthly reports. It exists so the shop can trust its cash position: every command either completes in full or changes nothing. Operators use it from the shell; the shell contract (commands, CSV output, exit codes) is the interface.

## Constraints
- Executable named `ledger` at the application root; no other entry point is required.
- Python 3.11 or newer; SQLite default, PostgreSQL via `DATABASE_URL`.
- All database access goes through the shipped persistence library and its generated relational layer; application code never opens a database driver directly.
- Three tables only: `accounts`, `categories`, `transactions`, with the columns and keys in the sources.
- Amounts are stored as integer cents, never floating point.
- Output is CSV, comma-separated, unquoted, LF line endings, exactly two decimal places for amounts.
- Exit codes: 0 success, 1 operational, 2 usage, 3 rejected, 4 not found.
- Standard error is never compared by the grader; stdout is.
- `sources/run.sh` and the seed CSVs are read-only scoring assets; they are staged verbatim and never modified.

## Guardrails
- Never read `sources/run.sh` from application code; never embed a report answer in application code.
- A rejected command changes nothing; a transfer stores both rows or neither.
- No command may leave any account balance below zero.
- Never write floating-point amounts to storage.
- Never modify, regenerate, or substitute the scoring assets.
- Never compare, suppress, or reinterpret the grader's checks to make them pass.
