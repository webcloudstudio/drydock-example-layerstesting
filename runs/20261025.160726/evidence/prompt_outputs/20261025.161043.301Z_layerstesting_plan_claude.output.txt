# ARCHITECTURE: LayersTesting

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Module layout, boundaries, exit-code and output contracts for the `ledger` command-line cash ledger. |
| Provides | ledger executable, bin/test.sh launcher contract |

## Questions

- None.

## Purpose

`ledger` is a single command-line executable at the application root. It keeps accounts,
categories, and cash transactions in a relational database reached only through the shipped
persistence library. Every command either completes in full or changes nothing. Balances never go
below zero. Money is stored and computed as integer cents at every layer.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; it is the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python 3.11+ | All application code, the `ledger` launcher, and the tests. |
| SQLite | Default database, reached through the shipped persistence library. PostgreSQL is selected by DSN and goes through the same library. |
| CLI foundation | The `cli` package and the `ledger` executable at the application root. |
| pytest | The test runner behind `bin/test.sh`. |
| POSIX sh | `bin/test.sh` and the supplied grader. |

## Modules

| Path | Responsibility |
|------|----------------|
| `ledger` | Executable launcher at the application root. Activates the environment, calls `cli.main(sys.argv[1:])`, exits with its return value. |
| `cli/__init__.py` | `main(argv) -> int`: dispatch, exit-code mapping, CSV output, diagnostic line. |
| `cli/errors.py` | `LedgerError` and its subclasses `OperationalError` (1), `UsageError` (2), `Rejected` (3), `NotFound` (4). |
| `cli/registry.py` | `register(words, handler, nargs)`: the command table. |
| `cli/config.py` | `resolve_dsn(environ)`: database location. |
| `cli/context.py` | `open_store()`: opens the database through `persistence.open_database`. |
| `cli/core.py` | Shared amount, text, date, and balance rules. |
| `cli/commands/` | One module per command family. Each registers its handlers on import. |
| `cli/testing.py` | `cli_runner(*args) -> (exit_code, stdout, stderr)`. |
| `persistence/` | Shipped and generated by Drydock. Never hand-written. |
| `bin/test.sh`, `tests/` | The application's own pytest suite and its POSIX launcher. |

## Module Ownership

| Boundary | Owner | Allowed low-level access |
|----------|-------|--------------------------|
| Persistence | `persistence/` package | The database drivers. Nothing else imports a driver. |
| Configuration | `cli/config.py` | `os.environ` for `DATABASE_URL` and `DATABASE_PATH`. |
| File stores | `cli/commands/load_*.py` | Reads the CSV file named on the command line. Never reads anything under `sources/` by fixed path. |
| External services | None | A PostgreSQL server only, and only through the persistence library. |

## Command Flow

1. `main` parses `argv`, finds the longest registered command prefix, and checks argument count.
2. The handler checks every input and every rule, computes the full change, and only then writes.
3. The handler returns rows (a header row and data rows) or `None`.
4. `main` writes the rows to standard output as CSV only after the handler has returned.
5. A raised `LedgerError` becomes its exit code and one line on standard error; standard output stays empty.

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success. |
| 1 | Operational failure: database unreachable, tables missing, file unreadable, or any unexpected exception. |
| 2 | Usage error: unknown command, table, or report; wrong argument count. |
| 3 | Rejected: invalid input, duplicate key, unknown reference, account in use, or a change that would leave a negative balance. |
| 4 | Not found: an absent account or transaction id. |

## Output Contract

Successful commands except `init` write CSV: one header row, then data rows, comma-separated, no
quoting, no trailing spaces, `\n` line endings. Amounts print with exactly two decimals, a leading
`-` when negative, and no thousands separator. Failures write nothing to standard output and one
diagnostic line to standard error.

## Guardrails on Design

- Report values, counts, and totals are always computed from database reads, never embedded.
- No floating point for money at any layer.
- Application code never reads `sources/run.sh` or any seed file; seed files reach the database only through `ledger load`.

import ast
import os

forbidden = {"sqlite3", "psycopg", "psycopg2"}
skip = {".venv", "persistence", "sources", "tests", "__pycache__", ".git", "blueprint"}
offenders = []
for root, dirs, files in os.walk("."):
    dirs[:] = [d for d in dirs if d not in skip]
    for name in files:
        if not (name.endswith(".py") or name == "ledger"):
            continue
        path = os.path.join(root, name)
        with open(path, "rb") as fh:
            src = fh.read()
        try:
            tree = ast.parse(src)
        except SyntaxError:
            continue
        for node in ast.walk(tree):
            if isinstance(node, ast.Import):
                mods = [a.name.split(".")[0] for a in node.names]
            elif isinstance(node, ast.ImportFrom):
                mods = [(node.module or "").split(".")[0]]
            else:
                continue
            offenders += [(path, m) for m in mods if m in forbidden]
assert offenders == []

# FEATURE: Cli Entry

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | The cli package entry point: command registry, dispatch, exit-code mapping, CSV output, diagnostics, and database location. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | cli.main, cli.testing.cli_runner, cli.registry.register, cli.errors, cli.config.resolve_dsn, cli.context.open_store |

## Questions

- None.

## Purpose

Every command in the ledger plugs into one dispatcher. This story builds the dispatcher and registers no command. Later stories add modules under `cli/commands/` that call `register`. `main` imports every module in the `cli.commands` package (for example with `pkgutil.iter_modules`) before dispatching, so adding a command never edits `main`.

## Interface

| Symbol | Contract |
|--------|----------|
| `cli.main(argv=None) -> int` | Runs one command and returns its exit code. `None` means `sys.argv[1:]`. |
| `cli.registry.register(words, handler, nargs)` | `words` is a tuple such as `("account", "add")`. `handler(args: list[str])` returns a list of rows (each a list of strings) or `None`. `nargs` is `(min, max)` for the arguments after the words. |
| `cli.errors.LedgerError(message)` | Base class with an integer `code`. Subclasses: `OperationalError` 1, `UsageError` 2, `Rejected` 3, `NotFound` 4. |
| `cli.config.resolve_dsn(environ) -> str` | Returns `DATABASE_URL`, else `DATABASE_PATH`, else the absolute path of `data/app.db` under the application root. An empty value counts as unset. The value is returned as written; the persistence library selects the engine and strips an optional `sqlite://` prefix. |
| `cli.context.open_store()` | Calls `persistence.open_database(resolve_dsn(os.environ))`. For a SQLite file it creates a missing parent directory first. |
| `cli.testing.cli_runner(*args)` | Returns `(exit_code, stdout, stderr)` by calling `main` in process. |

## Dispatch Rules

- The longest registered word prefix of `argv` selects the handler. No match, or no arguments at all, is a usage error (exit 2).
- An argument count outside `nargs` is a usage error (exit 2) and the handler is not called.
- The handler runs to completion before anything is written to standard output. Rows are then written with `csv.writer` semantics but unquoted fields, `\n` line endings, and `sys.stdout` looked up at call time.
- A `LedgerError` becomes its `code`, one diagnostic line on standard error, and nothing on standard output.
- A `persistence.PersistenceError` and any other unexpected exception become exit 1 with one diagnostic line.
- Diagnostics are never part of any contract; only the exit code and standard output are.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Ledger Core

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Shared integer-cent amount parsing and formatting, field and date validators, and the projected-balance guard. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliEntry.md |
| Provides | cli.core.parse_amount, cli.core.format_amount, cli.core.validate_code, cli.core.validate_text, cli.core.validate_name, cli.core.validate_memo, cli.core.validate_date, cli.core.account_balance, cli.core.balance_guard |

## Questions

- None.

## Purpose

Every command shares the same input rules. They live in `cli/core.py` so that no command repeats or contradicts them. All validators raise `cli.errors.Rejected` (exit 3) and perform no database write.

## Rules

| Function | Contract |
|----------|----------|
| `parse_amount(text) -> int` | Accepts only ASCII text matching `-?DIGITS[.D[D]]`. Returns integer cents using integer arithmetic only. Zero (such as `0`, `0.00`, `-0.0`) is rejected. More than two decimals, a missing integer part, a plus sign, spaces, or a thousands separator is rejected. |
| `format_amount(cents) -> str` | Exactly two decimals, a leading `-` when negative, no thousands separator. `0` prints as the zero amount with two decimals. |
| `validate_code(text) -> str` | 1 to 12 characters from `A-Z` and `0-9`. |
| `validate_text(text, min_len, max_len) -> str` | Length within bounds; no comma, `\n`, or `\r`. |
| `validate_name(text)` | `validate_text` with 1 to 40 characters. Used for account names and category descriptions. |
| `validate_memo(text)` | `validate_text` with 0 to 60 characters. |
| `validate_date(text) -> str` | Matches `YYYY-MM-DD` with four-digit year, two-digit month and day, and is a real calendar date. A date such as the thirtieth of February is rejected. |
| `account_balance(db, account) -> int` | Sum of the account's transaction amounts, read with `db.transactions.list(account=...)`. Zero when it has none. |
| `balance_guard(db, deltas) -> None` | `deltas` maps account code to a net change in cents. Computes each account's balance after applying its delta and raises `Rejected` when any resulting balance is below zero. It never writes. |

Commands call `balance_guard` with the full change set before their first write. A load passes the summed delta per account for the whole file; a transfer passes both accounts; amend passes the new amount minus the old; delete passes the negated old amount.

## Database Interface

- `FEATURE-TXN-002` — read: list transactions to compute balances - returns: `amount`

# FEATURE: Init

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | The `ledger init` command that returns the three ledger tables to an empty state. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliEntry.md, FEATURE-LedgerCore.md |
| Provides | ledger init |
| Consumes | cli.registry.register, cli.context.open_store |

## Questions

- None.

## Purpose

`ledger init` drops all three tables if present and recreates them empty, writing nothing to standard output. It takes no arguments; any argument is a usage error (exit 2) and changes nothing. This is the contract surfaced in the commands table of the source instructions.

## Behavior

1. Open the store with `cli.context.open_store()`.
2. Make sure the three tables exist. If opening a store that has no tables does not already create them, apply the generated idempotent `schema.sql` through the persistence library's own facility. Application code never executes driver calls itself. The grader runs `ledger init` against a brand-new database file, so this step must work on an empty store.
3. Empty the tables in foreign-key order with the declared clear operations: transactions first, then accounts, then categories.
4. Return `None` so standard output stays empty; exit 0.
5. An unreachable database exits 1.

The registration is `register(("init",), handler, (0, 0))` in `cli/commands/init.py`.

## Database Interface

- `FEATURE-ACCOUNT-006` — write: remove every account - supplies: `first_code`
- `FEATURE-CATEGORY-004` — write: remove every category - supplies: `first_code`
- `FEATURE-TXN-006` — write: remove every transaction - supplies: `min_id`

# FEATURE: Count

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | The `ledger count` command that reports the row count of each ledger table. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliEntry.md, FEATURE-Init.md |
| Provides | ledger count |
| Consumes | cli.registry.register, cli.context.open_store |

## Questions

- None.

## Purpose

`ledger count` prints the number of rows in `accounts`, `categories`, and `transactions`, in that order.

Output is CSV: the header `table,rows`, then one row per table. The counts are read from the database on every call. `count` takes no arguments; the surfaced criterion that `count` with arguments beyond `count` is a usage error means any extra argument exits 2 with nothing on standard output. Tables missing from the database exit 1.

The registration is `register(("count",), handler, (0, 0))` in `cli/commands/count.py`. The handler computes each count as the length of the table's `list` result.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: list accounts to count them - returns: `account`
- `FEATURE-CATEGORY-002` — read: list categories to count them - returns: `category`
- `FEATURE-TXN-002` — read: list transactions to count them - returns: `txn_id`

## Programmatic Acceptance

=== AC count-reports-tables ===

import csv
import io

from cli.testing import cli_runner
from persistence.testing import db_session

with db_session() as db:
    before = [
        len(db.accounts.list()),
        len(db.categories.list()),
        len(db.transactions.list()),
    ]
    acct_a = "ACPTCN1"
    acct_b = "ACPTCN2"
    cat = "ACPTCNC"
    db.accounts.create(account=acct_a, name="Count A")
    db.accounts.create(account=acct_b, name="Count B")
    db.categories.create(category=cat, description="Count Category")
    base = max([t.txn_id for t in db.transactions.list()], default=0)
    for offset in (1, 2, 3):
        db.transactions.create(
            txn_id=base + offset, date="2026-06-03", account=acct_a, category=cat,
            amount=100, memo=""
        )
    code, out, err = cli_runner("count")
    print(out, err)
    assert code == 0
    rows = list(csv.reader(io.StringIO(out, newline="")))
    assert rows[0] == ["table", "rows"]
    assert [r[0] for r in rows[1:]] == ["accounts", "categories", "transactions"]
    counts = [int(r[1]) for r in rows[1:]]
    assert counts == [before[0] + 2, before[1] + 1, before[2] + 3]
    assert "\r" not in out
