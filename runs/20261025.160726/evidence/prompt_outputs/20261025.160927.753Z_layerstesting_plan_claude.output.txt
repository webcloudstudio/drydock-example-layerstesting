## Questions

## Persistence Boundary

| Boundary | Rule |
|----------|------|
| Raw storage access | Only the generated `persistence/` package reaches the store. |
| Caller dependency | Features depend on declared access patterns and their DTOs, not on schemas. |
| Implementation | Generated from this file at the DATABASE build step; never written by hand. |
| Money | Amounts are integer cents in the `amount` column; no floating point at any layer. |
| Aggregates | Counts, balances, and report totals are computed by callers from `list` results; no aggregate operation exists. |
| Re-initialization | `ledger init` empties the three tables through the `clear` operations (transactions first, then accounts, then categories), because schema is provisioned only at the DATABASE step. |

## Schemas

## `accounts`

| Field | Type | Notes |
|-------|------|-------|
| account | VARCHAR(12) PK | Account code, 1 to 12 characters of A-Z and 0-9. |
| name | VARCHAR(40) NOT NULL | 1 to 40 characters, no comma or newline. |

## `categories`

| Field | Type | Notes |
|-------|------|-------|
| category | VARCHAR(12) PK | Category code, 1 to 12 characters of A-Z and 0-9. |
| description | VARCHAR(40) NOT NULL | 1 to 40 characters, no comma or newline. |

## `transactions`

| Field | Type | Notes |
|-------|------|-------|
| txn_id | INTEGER PK | Kept from the load file, or max plus one when posted. |
| date | VARCHAR(10) NOT NULL | Real calendar date written YYYY-MM-DD. |
| account | VARCHAR(12) NOT NULL REFERENCES accounts(account) | Owning account. |
| category | VARCHAR(12) NOT NULL REFERENCES categories(category) | Category. |
| amount | INTEGER NOT NULL | Signed integer cents, never zero. |
| memo | VARCHAR(60) NOT NULL DEFAULT '' | 0 to 60 characters, no comma or newline. |

## Migrations

Each relational change has one staged record in `migrations/MIGRATION-<AccessPatternId>.md`.
The record carries Alembic `upgrade`/`downgrade` snippets and progresses from `planned` to `built`
only when its DATABASE build story completes. Alembic records deployment application separately.

from persistence.testing import db_session

with db_session() as db:
    acct_a = "ACPTTLA"
    acct_b = "ACPTTLB"
    cat = "ACPTTLC"
    db.accounts.create(account=acct_a, name="List A")
    db.accounts.create(account=acct_b, name="List B")
    db.categories.create(category=cat, description="List Category")
    base = max([t.txn_id for t in db.transactions.list()], default=0)
    id_a = base + 1
    id_b = base + 2
    db.transactions.create(txn_id=id_b, date="2026-05-03", account=acct_b, category=cat, amount=200, memo="")
    db.transactions.create(txn_id=id_a, date="2026-05-03", account=acct_a, category=cat, amount=100, memo="")
    ids = [t.txn_id for t in db.transactions.list()]
    assert ids == sorted(ids)
    assert id_a in ids and id_b in ids
    only_a = db.transactions.list(account=acct_a)
    assert [t.txn_id for t in only_a] == [id_a]
    assert all(t.account == acct_a for t in only_a)
