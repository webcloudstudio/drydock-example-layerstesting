# FEATURE: Load Accounts

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger load accounts <csv>`, which loads accounts from a CSV file all-or-nothing. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliEntry.md, FEATURE-LedgerCore.md, FEATURE-Init.md, FEATURE-Count.md |
| Provides | ledger load accounts |
| Consumes | cli.main, parse_amount, validate_code, validate_text |

## Questions

- None.

## Purpose

Bulk-load account rows from a CSV file so the shop's drawers, safe, and petty cash exist before
transactions are loaded. The command either stores every row or stores nothing.

## Command Contract

`ledger load accounts <csv>` registers under the `load` command in the cli command table.

| Condition | Result |
|---|---|
| File readable, header equals `account,name`, every row valid | Exit 0. Stdout is `table,loaded` then `accounts,<rows>`. |
| Missing `<csv>` argument or extra arguments | Exit 2, nothing on stdout. |
| File missing or unreadable | Exit 1, nothing on stdout. |
| Header differs from the table columns in name or order | Exit 3, nothing stored. |
| A row has an invalid code or name (see Rules 3 and 4) | Exit 3, nothing stored. |
| A code repeats within the file | Exit 3, nothing stored. |
| A code already exists in the `accounts` table | Exit 3, nothing stored. |

## Behavior

1. Read the whole file and parse it with the standard `csv` module.
2. Check the header, then check every row with the `ledger-core` validators, the duplicate-in-file
   rule, and the duplicate-in-table rule. All checks complete before the first write.
3. Write every row in one transaction through the persistence library, then print the result.
4. A failing command writes one diagnostic line to standard error and nothing to standard output.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: detect codes already stored - supplies: `account` - returns: `account`, `name`

Rows are written through `db.accounts.create`, the operation declared for the account feature in
`DATABASE.md`; this feature reuses it and declares no operation of its own.

import csv
import io
import os
import tempfile
from cli.testing import cli_runner
from persistence.testing import db_session

def counts():
    rc, out, err = cli_runner("count")
    assert rc == 0
    return {r[0]: int(r[1]) for r in list(csv.reader(io.StringIO(out)))[1:]}

codes = ["LDACC1", "LDACC2", "LDACC3"]
with tempfile.TemporaryDirectory() as tmp:
    path = os.path.join(tmp, "accounts.csv")
    with open(path, "w", newline="") as fh:
        w = csv.writer(fh, lineterminator="\n")
        w.writerow(["account", "name"])
        w.writerows([[c, "Name " + c] for c in codes])
    before = counts()
    rc, out, err = cli_runner("load", "accounts", path)
print(out)
print(err)
assert rc == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows == [["table", "loaded"], ["accounts", str(len(codes))]]
assert counts()["accounts"] == before["accounts"] + len(codes)
with db_session() as db:
    for c in codes:
        got = db.accounts.get(account=c)
        assert got is not None
        assert got.name == "Name " + c

# FEATURE: Load Transactions

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger load transactions <csv>`, which loads transactions keeping their file ids, all-or-nothing. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliEntry.md, FEATURE-LedgerCore.md, FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md |
| Provides | ledger load transactions |
| Consumes | cli.main, parse_amount, validate_text, validate_date, balance_guard, ledger load accounts, ledger load categories |

## Questions

- None.

## Purpose

Bulk-load transaction rows. Each loaded transaction keeps the `txn_id` written in its file. The
command either stores every row or stores nothing.

## Command Contract

`ledger load transactions <csv>` registers under the `load` command in the cli command table.

| Condition | Result |
|---|---|
| File readable, header equals `txn_id,date,account,category,amount,memo`, every row valid, resulting balances non-negative | Exit 0. Stdout is `table,loaded` then `transactions,<rows>`. |
| Missing `<csv>` argument or extra arguments | Exit 2, nothing on stdout. |
| File missing or unreadable | Exit 1, nothing on stdout. |
| Header mismatch; non-integer `txn_id`; bad date, amount, or memo | Exit 3, nothing stored. |
| Unknown account or unknown category | Exit 3, nothing stored. |
| A `txn_id` repeats within the file or already exists in the table | Exit 3, nothing stored. |
| Loading would leave any account balance below zero | Exit 3, nothing stored. |

## Behavior

1. Read the whole file with the standard `csv` module and check the header.
2. For each row validate the id, the date (a real calendar date), the amount (`-?DIGITS[.D[D]]`,
   never zero, parsed to integer cents), the memo (0 to 60 characters, no comma or newline), and
   that the account and category exist.
3. Reject repeated ids within the file and ids already stored.
4. Compute each touched account's stored balance plus the file's amounts with `balance_guard`; any
   result below zero rejects the file.
5. Only after every check passes, write all rows in one transaction, then print the result.

## Database Interface

- `FEATURE-ACCOUNT-002` — read: confirm every named account exists - supplies: `account` - returns: `account`, `name`
- `FEATURE-CATEGORY-002` — read: confirm every named category exists - supplies: `category` - returns: `category`, `description`
- `FEATURE-TXN-002` — read: read existing ids and balances - supplies: `account`, `category` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

Rows are written through `db.transactions.create`, the operation declared for the post feature in
`DATABASE.md`; this feature reuses it and declares no operation of its own.

# FEATURE: Load Rejection

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Guarantees that a rejected `ledger load` exits 3 and leaves every table exactly as it was. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-LoadAccounts.md, FEATURE-LoadCategories.md, FEATURE-LoadTransactions.md, FEATURE-Count.md |

## Questions

- None.

## Purpose

Prove and enforce the all-or-nothing rule for loads: a file with one invalid row stores none of
its rows. A file of ten valid rows followed by an eleventh naming an unknown account stores none
of the eleven.

## Behavior

| Scenario | Result |
|---|---|
| Transactions file whose last row names an unknown account | Exit 3, nothing on stdout, no table changes. |
| Transactions file with an invalid amount, date, or duplicate id on a late row | Exit 3, no table changes. |
| Accounts file reloaded after it was loaded | Exit 3, no table changes. |
| Categories file reloaded after it was loaded | Exit 3, no table changes. |

Row counts of all three tables read through `ledger count` are identical before and after every
rejected command.

- `FEATURE-TXN-002` — read: verify no transaction row was stored - supplies: `account` - returns: `txn_id`, `account`, `amount`
- `FEATURE-ACCOUNT-002` — read: verify no account row was stored - supplies: `account` - returns: `account`, `name`

# FEATURE: Account Add

| Field | Value |
|-------|-------|
| Version | 20261025 V1 |
| Description | Implements `ledger account add <code> <name>`, which creates one validated account. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-CliEntry.md, FEATURE-LedgerCore.md, FEATURE-Init.md, FEATURE-Count.md |
| Provides | ledger account add |
| Consumes | cli.main, format_amount, validate_code, validate_text |

## Questions

- None.

## Purpose

Add a new place where the shop keeps cash. A new account has no transactions and a zero balance.

## Command Contract

`ledger account add <code> <name>` registers under the `account` command in the cli command table.

| Condition | Result |
|---|---|
| Valid code and name, code not in use | Exit 0. Stdout is `account,name,transactions,balance` then the new row with `0` transactions and balance `0.00`. |
| Wrong argument count | Exit 2, nothing on stdout. |
| Code not 1 to 12 characters of `A-Z0-9` | Exit 3, nothing stored. |
| Name empty, longer than 40 characters, or containing a comma or newline | Exit 3, nothing stored. |
| Code already exists | Exit 3, nothing stored. |

## Behavior

1. Validate the code and name with the `ledger-core` validators.
2. Confirm the code is not already stored.
3. Create the row, then print the account row. The transaction count and balance are computed from
   the database, never hard-coded, and formatted from integer cents with two decimal places.
4. A failing command writes one diagnostic line to standard error and nothing to standard output.

## Database Interface

- `FEATURE-ACCOUNT-003` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-ACCOUNT-002` — read: detect an existing code - supplies: `account` - returns: `account`, `name`
- `FEATURE-TXN-002` — read: count the account's transactions and sum its balance - supplies: `account` - returns: `txn_id`, `amount`
