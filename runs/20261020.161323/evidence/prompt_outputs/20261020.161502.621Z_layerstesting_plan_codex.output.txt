# FEATURE: Bulk Transaction Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Loads validated transaction CSV files atomically into the ledger. |
| Depends On  | DATABASE.md, FEATURE-Validation.md, FEATURE-Bulk-Reference-Loading.md |
| Provides    | `ledger load transactions` |
| Consumes    | domain validation, relational ledger schema, transaction persistence operations |

## Questions

- None.

## Purpose

Load a transaction CSV file only after validating its complete contents, references, identifiers, and resulting account balances.

## Workflow

1. Validate the file header and every row.
2. Reject duplicate transaction identifiers and invalid values.
3. Resolve every account and category reference.
4. Evaluate balances after applying the complete batch.
5. Insert all rows in one transaction.
6. Emit the loaded-row result only after commit.

A rejected file changes no table.

## Database Interface

- `FEATURE-LEDGER-005` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-006` — read: retrieve transaction references - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

=== AC load-transactions-valid ===
Intent: A valid transaction CSV is loaded and its supplied row count is reported.
from pathlib import Path
import csv
import tempfile
from cli.testing import cli_runner

rows = [
    ["txn_id", "date", "account", "category", "amount", "memo"],
    ["1", "2026-01-01", "A", "C", "10.00", "opening"],
]
with tempfile.TemporaryDirectory() as directory:
    path = Path(directory) / "transactions.csv"
    path.write_text("\n".join(",".join(row) for row in rows) + "\n")
    code, stdout, stderr = cli_runner("load", "transactions", str(path))
    parsed = list(csv.reader(stdout.splitlines()))
    assert code == 0
    assert parsed[0] == ["table", "loaded"]
    assert parsed[1] == ["transactions", str(len(rows) - 1)]
=== END AC load-transactions-valid ===

=== AC load-transactions-invalid-is-atomic ===
Intent: A transaction file with an unknown account is rejected before any row is written.

import tempfile
from cli.testing import cli_runner

rows = [
    "txn_id,date,account,category,amount,memo",
    "1,2026-01-01,A,C,10.00,valid",

]
with tempfile.TemporaryDirectory() as directory:
    path = Path(directory) / "transactions.csv"

=== END AC load-transactions-invalid-is-atomic ===

## User Acceptance

- None.

## Guardrails

- Validate the entire file before the first insert.
- Never read or modify supplied source fixtures from application code.
- Store amounts as integer cents.
- Preserve transaction identifiers supplied by the file.

# FEATURE: Accounts

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Provides account creation, retrieval, renaming, and deletion through the CLI. |
| Depends On  | DATABASE.md, FEATURE-Validation.md, FEATURE-Bulk-Reference-Loading.md |
| Provides    | `ledger account add`, `ledger account get`, `ledger account rename`, `ledger account delete` |
| Consumes    | domain validation, relational ledger schema, account persistence operations |

## Questions

- None.

## Purpose

Manage account records while deriving transaction counts and balances from persisted transactions.

## Workflows

- `account add` creates a unique validated account.
- `account get` returns an existing account row.
- `account rename` changes only the account name.
- `account delete` removes an account only when it has no transactions.

Missing accounts return exit code `4`; rejected changes return exit code `3`.

## Database Interface

- `FEATURE-LEDGER-001` — write: create an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-LEDGER-002` — read: retrieve an account - supplies: `account` - returns: `account`, `name`
- `FEATURE-LEDGER-003` — write: update an account - supplies: `account`, `name` - returns: `account`, `name`
- `FEATURE-LEDGER-004` — write: delete an account - supplies: `account` - returns: `deleted`

# FEATURE: Transaction Posting

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Posts and retrieves individual ledger transactions. |
| Depends On  | DATABASE.md, FEATURE-Accounts.md, FEATURE-Bulk-Transaction-Loading.md, FEATURE-Validation.md |
| Provides    | `ledger txn post`, `ledger txn get` |
| Consumes    | domain validation, relational ledger schema, transaction persistence operations |

## Questions

- None.

## Purpose

Post a new transaction with the next available identifier and retrieve transactions by identifier.

## Workflows

`txn post` validates the account, category, amount, date, memo, and resulting balance before inserting. The identifier is one greater than the current maximum, or `1` when empty. `txn get` returns the persisted transaction or exit code `4` when absent.

## Database Interface

- `FEATURE-LEDGER-005` — write: create a transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`
- `FEATURE-LEDGER-006` — read: retrieve transaction - supplies: `txn_id` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

# FEATURE: Transfers

| Field       | Value |
|-------------|-------|
| Version     | 20261020 V1 |
| Description | Transfers funds atomically between two ledger accounts. |
| Depends On  | DATABASE.md, FEATURE-Accounts.md, FEATURE-Transaction-Posting.md, FEATURE-Validation.md |
| Provides    | `ledger transfer` |
| Consumes    | domain validation, relational ledger schema, transaction persistence operations |

## Questions

- None.

## Purpose

Move a positive amount between distinct accounts using two consecutive `TRANSFER` transactions.

## Workflow

The outgoing row uses the next transaction identifier, a negative amount, and memo `transfer to <account>`. The incoming row uses the following identifier, a positive amount, and memo `transfer from <account>`. Both rows are committed together only after validating all inputs and resulting balances.

## Database Interface

- `FEATURE-LEDGER-005` — write: create transaction - supplies: `txn_id`, `date`, `account`, `category`, `amount`, `memo` - returns: `txn_id`, `date`, `account`, `category`, `amount`, `memo`

## Programmatic Acceptance

Intent: A valid transfer creates consecutive outgoing and incoming transaction rows.

seed_code, _, _ = cli_runner("txn", "post", "A", "SALES", "10.00", "2026-01-01")
