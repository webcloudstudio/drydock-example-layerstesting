<requirement name="build-ledger-cli" stories="architecture">
Build a command-line cash ledger for a small shop.
</requirement>
<requirement name="use-python-sqlite-persistence" stories="architecture,persist-001">
Implement in Python 3.11 or newer over SQLite, through the shipped Python persistence library.
</requirement>
<requirement name="configure-database" stories="persist-001">
`DATABASE_URL` names the database. A value beginning `postgres://` or `postgresql://` is a PostgreSQL DSN. Any other value is a SQLite file path, optionally prefixed `sqlite://`. When `DATABASE_URL` is unset, `DATABASE_PATH` is used, then `data/app.db`.
</requirement>
<requirement name="initialize-and-count-database" stories="persist-002">
`ledger init` | Drops all three tables if present and creates them empty. Nothing written.
</requirement>
<requirement name="count-tables" stories="persist-002">
`ledger count` | `table,rows`, then `accounts`, `categories`, `transactions` rows in that order.
</requirement>
<requirement name="validate-ledger-data" stories="persist-003">
Codes (`account`, `category`) are 1 to 12 characters from `A-Z` and `0-9`.
</requirement>
<requirement name="load-reference-data" stories="load-001">
`ledger load <table> <csv>` | Loads `accounts`, `categories`, or `transactions` from a file whose header matches the table's columns in the order above. Writes `table,loaded` and `<table>,<rows>`.
</requirement>
<requirement name="load-transactions-atomically" stories="load-002">
A load that rejects row 11 stores none of rows 1 to 10.
</requirement>
<requirement name="manage-accounts" stories="ledger-001">
`ledger account add <code> <name>` | The new account row.
</requirement>
<requirement name="post-and-retrieve-transactions" stories="ledger-002">
`ledger txn post <account> <category> <amount> <date> [<memo>]` | The new transaction row.
</requirement>
<requirement name="amend-and-delete-transactions" stories="ledger-003">
`ledger txn amend <id> <amount>` | The updated transaction row. Only the amount changes.
</requirement>
<requirement name="transfer-funds" stories="ledger-004">
`ledger transfer <from> <to> <amount> <date>` | Two transaction rows in category `TRANSFER`: `-amount` on `<from>` with memo `transfer to <to>`, then `+amount` on `<to>` with memo `transfer from <from>`. The amount is positive and the accounts differ.
</requirement>
<requirement name="report-account-balances" stories="report-001">
`ledger report balances` | `account,name,transactions,balance` per account ordered by code, then `TOTAL,,<count>,<sum>`.
</requirement>
<requirement name="report-category-totals" stories="report-002">
`ledger report categories` | `category,description,transactions,inflow,outflow,net` per category ordered by code, including categories with no transactions, then `TOTAL,,<count>,<inflow>,<outflow>,<net>`.
</requirement>
<requirement name="report-monthly-totals" stories="report-003">
`ledger report monthly` | `month,transactions,inflow,outflow,net` per `YYYY-MM` that has transactions, ascending, then `TOTAL,<count>,<inflow>,<outflow>,<net>`.
</requirement>
<requirement name="provide-test-runner" stories="verify-001">
The completed application provides a POSIX-compatible `bin/test.sh` that runs its own automated test suite from the application root and exits zero only when every test passes.
</requirement>
<requirement name="pass-conformance-harness" stories="verify-002">
The harness creates a fresh database, runs `./ledger init`, loads the seed files, and then runs a fixed sequence of 43 checks.
</requirement>
