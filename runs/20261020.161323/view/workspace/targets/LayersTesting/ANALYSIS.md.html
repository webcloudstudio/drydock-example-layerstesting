The system is a local executable CLI backed by a relational SQLite database through the shipped persistence library. Inputs are command arguments and CSV files; outputs are deterministic CSV reports or diagnostics. The required flow is schema initialization, validated loading and mutation, reporting, focused tests, then complete conformance verification.

Test and Acceptance Strategy

Implementation stories use focused tests for their command, validation, persistence, and report behavior. VERIFY-001 runs the project test suite through bin/test.sh and remains scoped to the automated tests. VERIFY-002 is the single terminal full-suite story and runs sh sources/run.sh unfiltered with Suite: full.

Sequencing and Dependencies

Build the persistence boundary and schema before command handlers. Implement validation before loaders and mutations. Stage fixtures before verification. Reports depend on the completed persistence queries and mutation rules. VERIFY-001 follows implementation stories; VERIFY-002 depends on every implementation and test-runner story.
